상담관리 사용자 매뉴얼

운영 콘솔의 상담 관리 메뉴(/admin/csl)에서 신규 상담 접수부터 수강 시작까지의 6단계 파이프라인을 운영하는 방법을 안내합니다. 화면 라벨·옵션은 실제 UI(한국어)와 동일하게 기재했습니다.

0 한눈에 보기

상담은 항상 접수에서 시작해 6단계를 정방향으로 진행합니다. 어느 단계에서든 이탈(DROPPED) 처리가 가능하며, 이탈 상태에서는 재활성화로 직전 단계로 복귀할 수 있습니다.

접수 → 청강 (건너뛰기)MAP "이전 점수 보유" ✔, 또는 응시료 납부/면제, 또는 점수(읽기·수학·언어) 중 1개 이상 입력 (Q-CSL-003)
MAP 테스트 → 청강위와 동일 (이전 점수 보유 / 응시료 납부·면제 / 점수 입력 중 하나)
청강 → 등록 상담청강 일정이 1건 이상 등록됨
등록 상담 → 결제등록 정보의 "등록 상담 완료" = 완료(YES)

어느 단계 → 이탈이탈 사유 코드 선택 (기타 선택 시 상세 사유 필수)
이탈 → 재활성화직전 단계로 복귀 (직전 단계 정보가 없으면 접수로)
진행 버튼은 현재 단계에서 허용된 다음 단계만 표시됩니다. 조건 미충족 시 버튼을 눌러도 오류 메시지가 뜨고 단계가 바뀌지 않습니다.

1 화면 구성

1.1 상담 목록 /admin/csl

  • 컬럼: No. / 학생 / 학교·학년 / 단계 / 유입 / 신청 / 등록일 / 후속 일정
  • 단계는 색상 배지로 표시되며, 행을 클릭하면 상담 상세로 이동합니다.
  • 우측 상단 "+ 신규 상담" 버튼으로 접수 등록 다이얼로그를 엽니다.

1.2 상담 상세 /admin/csl/:id

세 영역으로 구성됩니다.

  1. 상단 헤더 — 학생 정보 + 단계 진행 버튼(허용된 다음 단계만 노출) + 이탈 처리 / 재활성화 버튼
  2. 단계 스테퍼 — 6단계 진행 상태를 시각적으로 표시
  3. 본문 2단
    • 왼쪽: 현재 단계에 해당하는 입력 패널(MAP 테스트 / 청강 / 등록·결제 등)
    • 오른쪽: 기록 / 타임라인(단계 변경 이력 + 메모). 메모는 추가만 가능하고 이력은 삭제되지 않습니다.

단계 1

접수

INTAKE

목적 — 신규 상담을 시스템에 등록합니다. 모든 상담은 접수에서 시작합니다.

익명 문의는 이탈 외에는 진행 불가 — 진행하려면 먼저 학생 정보를 입력해 익명을 해제하세요.

단계 5

결제

PAYMENT

목적 — 수강료 수납을 확정합니다. 별도 입력 화면 없이 등록 / 결제 패널의 "수강료 납부 완료" 체크로 처리합니다.

핵심 규칙 (BR-CSL-012)
• "수강료 납부 완료" 체크는 책임자만 표시할 수 있습니다. (UI 안내: "※ 결제 확정은 책임자만 표시할 수 있습니다.")
• 허용 권한: ADMIN, APP_ADMIN. 그 외(TEACHER/STAFF)가 시도하면 403 오류가 발생하며 저장되지 않습니다.
• 납부 완료로 표시되면 처리자·처리시각이 자동 기록됩니다.
→ 다음 단계 진행 조건 · → 수강 시작
  • 등록 정보의 "수강료 납부 완료"가 체크되어 있어야 함.
미충족 시: "수강 시작 진입에는 수강료 납부가 필요합니다" 오류.
단계 6

수강 시작

CLASS_STARTED

목적 — 정식 등록 완료 상태. 이 단계로 전환되면 상담의 등록일(enrolledAt)이 자동 기록되고, 이후 수업 운영은 반/수업(CLS) 모듈이 담당합니다.

관련 정보 (등록 / 결제 패널) — 수강 시작일, 수강 시작 여부.

수강 시작은 파이프라인의 마지막 정방향 단계입니다(이후 정방향 진행 없음, 이탈만 가능).

3 공통 작업

3.1 단계 진행 (정방향)

  • 상단 헤더의 단계 진행 버튼(허용된 다음 단계만 노출)을 클릭합니다.
  • 진행 조건 미충족 시 오류 메시지가 표시되고 단계는 변경되지 않습니다 → 해당 단계 패널에서 필요한 정보를 먼저 입력하세요.

3.2 단계 되돌리기 (역방향) 관리자 전용

  • ADMIN / APP_ADMIN 권한만 가능하며, 사유(2~500자) 입력이 필수입니다(C-12).
  • 잘못 진행한 단계를 이전 단계로 되돌릴 때 사용합니다. 모든 역방향 이력은 타임라인에 남습니다.

3.3 이탈 처리 (DROPPED)

  • 헤더의 "이탈 처리" 버튼 → 사유 코드 선택: 학원 사정으로 취소 / 학생 건강 / 학생 일정 변경 / 결제 거절 / 타 학원 등록 / 기타
  • "기타" 선택 시 상세 사유 필수.
  • 이탈 시 종료시각(closedAt)이 기록되며, 이탈 이력은 삭제 불가(append-only, Q-CSL-006).

3.4 재활성화 (REACTIVATE)

  • 이탈 상태에서만 가능. 직전 단계로 복귀합니다(직전 단계 정보가 없으면 접수로). 종료시각은 초기화됩니다.

3.5 메모 / 타임라인

  • 오른쪽 기록 / 타임라인 패널에서 메모(최대 2000자)를 추가합니다. 단계 변경 이력과 함께 시간순으로 표시되며 삭제되지 않습니다.

3.6 전화번호 보기 (PII)

  • 보호자 전화번호는 암호화 저장됩니다. 보기 동작은 감사 로그(처리자·IP·브라우저)로 기록됩니다(C-07). 업무상 필요한 경우에만 조회하세요.

3.7 상담 삭제 / 복원

  • 상담 삭제는 소프트 삭제이며 90일 이내 복원 가능합니다(C-06).

4 권한 요약

작업허용 권한
상담 조회·생성·수정, 단계 정방향 진행, MAP/청강/등록 입력, 메모로그인한 운영자(해당 테넌트)
수강료 납부 완료 표시(BR-CSL-012)ADMIN, APP_ADMIN

모든 데이터는 소속 학원(테넌트) 단위로 격리됩니다. 다른 학원의 상담은 보이지 않습니다.

5 자주 묻는 문제

증상원인 / 해결
진행 버튼을 눌렀는데 단계가 안 바뀜해당 단계의 진행 조건 미충족. 0장·각 단계의 "다음 단계 진행 조건" 확인 후 필요한 정보 입력.
"수강료 납부 완료" 저장 시 403권한 부족. ADMIN/APP_ADMIN 계정으로 처리해야 함(BR-CSL-012).
익명 문의가 접수에서 안 넘어감익명은 접수 이후 진행 불가. 학생 정보를 입력해 익명을 해제하세요.
청강 "추가" 버튼이 비활성화청강일(날짜)을 먼저 선택해야 활성화됩니다.
면제 저장이 안 됨응시료 상태가 "면제"면 면제 사유가 필수입니다.
이탈 저장이 안 됨사유 코드가 "기타"면 상세 사유가 필수입니다.
