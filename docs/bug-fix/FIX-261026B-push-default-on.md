# FIX-261026B Mobile push silently turned off (모바일 알림이 저절로 꺼짐)

## 1. Report (제보)
"최근까지 모바일 알림 잘 떴는데 오늘 알림이 안 떠서 들어가보니 알림이 풀려있고, 켜기 누르니 다시 되었음. 점검 필요 — 알람 기본으로 켜기 설정"

## 2. Findings (운영 DB 읽기 전용, 2026-10-26)
- tpijung 콘솔·강사 포털, 아이폰 구독이 모두 **오늘 15:49~16:00(KST)** 에 새로 생김(= [켜기]). 이전 구독은 그 전에 없어졌다. tpimorgan 은 구독 없음.
- 10-21 이후 두 사람 모두 로그아웃 기록 없음 → 로그아웃이 아닌 다른 경로로 삭제.

## 3. Root cause (원인)
1. **사라진 구독을 다시 만들지 않음**: Apple 이 410/404(만료·취소)를 돌려주면 서버가 구독 행을 지운다(`push.service.ts deliver`). 앱을 열 때 동기화(`PushSessionSync`)는 **남아 있는 구독만** 다시 등록하고 없으면 아무것도 하지 않아, [켜기] 전까지 꺼진 상태로 남았다.
2. **조용히 버리는 푸시**: 서비스워커가 이 기기의 현재 계정이 아닌 알림을 화면에 띄우지 않고 버린다(`acm-sw.js` push). 콘솔·강사 포털을 한 기기에서 함께 쓰면 계정 연결이 마지막 쓴 쪽으로 바뀌어 이런 푸시가 생긴다. iOS 는 아무것도 띄우지 않는 푸시가 반복되면 구독을 취소하는 것으로 알려져 있다(일반 iOS 동작 — 로그로 확인하지는 못함).
3. 로그아웃하면 기기 구독 자체를 해지 → 다시 로그인해도 [켜기] 전까지 꺼짐. "기본 켜짐" 경로가 없었다.

## 4. Fix (수정, 사용자 승인 권장안 4가지)
1. **자동 복구**: 권한이 허용된 기기에서 앱을 열 때 구독이 없으면 새로 만들어 등록(사용자가 이 기기에서 [끄기]를 누른 경우만 제외 — `acm-push-optout:<mode>`).
2. **푸시를 버리지 않음**: 현재 계정 것이 아니거나 데이터가 없어도 내용 없는 "새 알림이 있습니다" 를 띄운다(다른 계정 내용은 노출하지 않음). 누르면 `/app`.
3. **로그아웃해도 유지**: 로그아웃은 서버 연결만 끊고(로그아웃한 계정 알림이 오지 않게) 브라우저 구독은 남긴다 → 다시 로그인하면 자동 재연결.
4. **로그인 직후 한 번 안내**: 권한을 아직 묻지 않은 기기에 "이 기기에서 알림 받기 [켜기] [나중에]"(이번 로그인 동안 한 번). iOS 는 첫 권한에 사용자 탭이 필요.

## 5. Verification
- 타입 검사·빌드, 서비스워커 문법 검사. 실기기 확인은 배포 후 사용자(iPhone) — 앱 재설치 불필요(서비스워커 업데이트는 화면 [새로고침] 안내).
