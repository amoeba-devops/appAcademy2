# FIX-261026 Dashboard counting — 지원 & 스케줄 조율/완료 (대시보드 지원·스케줄 집계)

## 1. Reports (제보)
1. "맵테스트 문의가 들어온 날짜로 대시보드-지원이 카운팅 되어야하는데 10월 모두 되지 않았음"
2. "스케줄 완료 버튼을 누르면 지정한 날짜부터 학생 수업 예정일까지의 날짜가 모두 카운팅 됨. 스케줄 조율/완료는 지정한 날짜만 카운팅이 되어야 함"

## 2. Root cause (원인)
| # | 원인 | 근거 |
| --- | --- | --- |
| 1 | '지원'(`cs_apply`)은 상담 수강 정보의 **지원 표시(`enr_applied`) + 그 행의 수정일**만 셌다. 맵테스트 문의는 이 표시를 쓰지 않아 어느 날짜에도 잡히지 않았다(규칙 누락, 10월 회귀 아님) | 운영 10월: 맵테스트 문의 3건(10-07·08·20, 웹 신청서), `enr_applied` 0건 → 지원 0, 같은 문의는 '상담'에만 |
| 2 | 스케줄 조율/완료가 **상태 스냅숏**(STATUS_SNAPSHOT)이라 기록한 날부터 종료/취소 기록이 있을 때까지 **매일** 셌다(REQ-260929 정의: 수업 시작 후에도 유지) | `lifecycle-calculation.ts` — 그날까지의 모든 기록 중 마지막 상태로 판정. 운영 기록 7건(10-01~10-08)은 모두 취소된 상태 |

## 3. Fix (수정)
- **지원** = 그날 등록된 **맵테스트 문의**(`inq_kind='MAP_TEST'`, `inq_registered_at`, 삭제 제외). 일별 전체·사이트별(`daily-kpi.service.ts`)·오늘 실시간(`today-live.service.ts`). 기존 지원 표시 규칙은 대체(사용자 결정).
- **스케줄 조율/완료** = **기록한 날짜(`effective_date`) 하루만**. 같은 날 같은 과목은 마지막 기록 상태, 조율·완료가 같은 날이면 둘 다 센다. 이후 종료 기록은 지난 날 수치를 지우지 않는다. 기간 합계는 고유 인원(`DAILY_DISTINCT`). 지표 이름 '스케줄 조율 중' → '스케줄 조율'.
- 10월 재계산: 야간 KPI 재계산(최근 31일)이 배포 후 첫 실행에서 반영. **수동 입력값이 있는 날은 유지**(사용자 결정). 스케줄 지표는 저장값이 아니라 조회 시 계산이라 즉시 반영.

## 4. Tests
- unit `lifecycle-calculation.spec.ts`: 기록일만 집계·다음 날 0·기간 합계 고유 인원, 같은 날 조율+완료 둘 다, 이후 종료가 지난 날을 지우지 않음·같은 날 마지막 기록 우선
- integration `it-dsh-apply-map-test`: 맵테스트 문의 등록일 기준, 삭제·튜터링 제외, 상담 수 별도
