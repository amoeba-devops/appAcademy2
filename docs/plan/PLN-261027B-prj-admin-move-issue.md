# PLN-261027B Project admin & move issue (프로젝트 관리자 수정·삭제 · 이슈 프로젝트 변경)

## 1. Requirement (요구사항)
"이슈 - 수정 화면에서 프로젝트 수정 기능 추가. 서비스 관리자는 프로젝트 수정 / 삭제 기능, 이슈 수정 기능 (프로젝트 변경기능) 구현"

## 2. As-Is (현황, main `c064d1a`)
| 항목 | 현황 |
| --- | --- |
| 접근 권한 | 프로젝트·이슈 조회·수정은 모두 **소유자 또는 참여자만**(`ProjectService.access`, `IssueService.ACCESSIBLE`). 관리자 등급·서비스 운영자도 참여하지 않은 프로젝트는 404 |
| 프로젝트 수정 | `PUT projects/:id` — 소유자 또는 MANAGER 참여자만. 저장할 때 수정한 사람을 참여자로 자동 추가 |
| 프로젝트 삭제 | **없음**. 상태 '보관(ARCHIVED)' 만. 보관된 프로젝트는 수정 불가 |
| 이슈 수정 | `PUT projects/:id/items/:item` — 참여자 누구나. **프로젝트는 바꿀 수 없음**(경로의 프로젝트로만 저장, 수정 화면 프로젝트 칸 잠김) |
| 이슈에 묶인 것 | 담당자·참여자(그 프로젝트 참여자여야 함), 상위 이슈(같은 프로젝트), 하위 이슈, 첨부 파일(그 프로젝트 파일), 댓글·이력(이슈에 붙어 함께 이동), 번호 ISS-n(테넌트 공통 — 그대로) |
| 운영 | 프로젝트 3개(학원운영 활성·이슈 5, 학원 보관·이슈 1, 업무 활성·이슈 1). 서비스 운영자/테넌트 마스터: admin@tpi.co.kr · fremd@naver.com · tpiyeri |

## 3. Functional Requirements (기능 요구사항)
| ID | 요구사항 |
| --- | --- |
| FR-1 | **서비스 관리자** = 관리자 등급 + (서비스 운영자 또는 테넌트 마스터) — 상담·학생 삭제 권한과 같은 기준 (Q1) |
| FR-2 | 서비스 관리자는 **모든 프로젝트**를 목록에서 보고 열 수 있다(참여하지 않은 프로젝트는 '참여 안 함' 표시). 수정해도 자신을 참여자로 자동 추가하지 않음 (Q6) |
| FR-3 | 서비스 관리자는 모든 프로젝트를 **수정**(이름·설명·소유자·참여자·상태) — 보관된 프로젝트도 수정·보관 해제 가능 |
| FR-4 | 서비스 관리자는 프로젝트를 **삭제**(숨김 삭제 — 목록·이슈·내 업무·검색에서 사라짐, DB 에는 남아 복구 가능). 확인 창에 이슈·파일 수 표시. Google Drive 폴더는 건드리지 않음 (Q2) |
| FR-5 | **이슈 수정 화면에서 프로젝트 변경**: 프로젝트 칸을 열어 다른 프로젝트 선택 → 저장 시 이동. 권한: 두 프로젝트 모두 수정할 수 있는 참여자, 또는 서비스 관리자 (Q3) |
| FR-6 | 이동 시 처리: 번호(ISS-n)·댓글·이력 유지 / 담당자·참여자 중 새 프로젝트 참여자가 아닌 사람은 빠짐 / 상위 이슈 연결 해제 / 하위 이슈는 연결 해제 (Q4) / 첨부 파일은 새 프로젝트로 함께 이동 (Q5) / 이력에 "프로젝트 변경 A → B" 기록 |
| FR-7 | 서비스 관리자는 모든 이슈를 수정(프로젝트 변경 포함)·삭제 |
| FR-8 | 감사 활동 로그 자동 기록, 4개 언어 |

## 5. Design (설계)
- 공통 판정 `canOperateProjects(user)` = `canDeleteRecords` 와 같은 기준(FR-1). `ProjectService.access`·`list`·`save`(UPDATE WHERE 포함)·`IssueService.ACCESSIBLE/remove` 에 "서비스 관리자면 통과" 조건 추가, `can_manage` 에 반영 → 화면은 기존 `can_manage` 로 버튼 노출.
- 마이그레이션 `1055`: `amb_acm_prj_project.prj_deleted_at TIMESTAMPTZ`·`prj_deleted_by UUID`, 이력 `psl_kind` CHECK 에 `'PROJECT'` 추가(+ `psl_note` 에 A→B).
- `DELETE /api/acm/prj/projects/:id` (서비스 관리자): 숨김 삭제 — 모든 조회에 `prj_deleted_at IS NULL`.
- `PATCH /api/acm/prj/issues/:id/project {projectId}`: 한 트랜잭션 — 원본·대상 쓰기 권한 확인 → `prj_id` 변경 → 상위 해제·하위의 상위 해제 → 비참여 담당자·참여자 제거 → 이 이슈만 쓰는 첨부 파일 항목(`pit_kind='FILE'`)만 새 프로젝트로 이동(다른 이슈와 함께 쓰는 파일은 원래 프로젝트에 남고, 옮긴 이슈에서는 '파일 없음'으로 표시) → 이력 → 양쪽 `updated_at`.
- 화면: `issue-form-dialog.tsx` 편집 시 프로젝트 칸 열기 + 안내, 바뀌었으면 이동 API → 새 프로젝트 경로로 나머지 저장. `project-page.tsx` 상세 [삭제], 목록 '참여 안 함' 배지.
- Tests: 통합 — 비참여 서비스 관리자 조회·수정·삭제 200 / 일반 관리자 404, 삭제 후 숨김, 이동(권한·담당자/참여자 정리·상위/하위 해제·첨부 이동·이력), 보관 프로젝트 관리자 수정.
