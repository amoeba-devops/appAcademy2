# Chat Participants Plan (채팅 참여자 패널 구현 계획)

## 1. UI Layout (화면 구성안)

```text
대화방 목록               대화 내용                      우측 패널
┌──────────────────┬──────────────────────────┬──────────────────────┐
│ [대화방] [보관함] │ 강사 운영 단체방      [⋯] │ 참여자 4명   [가리기] │
│ 강사 운영 단체방 │                          │ [참여자 초대]        │
│ ♛ 배예리 (나)    │ 메시지                   │ ♛ 배예리 (나) · 운영자│
│ 마지막 메시지…   │                          │ 김강사 · 강사        │
│                  │                          │    [DM] [내보내기]   │
│ 다른 단체방      │                          │ 이강사 · 강사        │
│ ♛ 김운영         │                          │    [DM] [내보내기]   │
│                  │                          │ 박운영 · 운영자      │
│                  │                          │    [DM] [내보내기]   │
│                  │ [메시지 입력] [전송]     │                      │
└──────────────────┴──────────────────────────┴──────────────────────┘
```

위 화면은 방장 기준이다. 일반 참여자의 우측 패널에는 이름/역할/왕관과 본인 외 참여자의 `[DM]`만 표시한다. 루시드 Crown 아이콘에 `방장: 이름` 접근성 설명을 제공한다. 본인이 방장인 방만 표시하는 방식이 아니라 모든 단체방의 현재 방장 이름을 보여준다.

```text
참여자 초대
[이름 검색________________]
[ ] 김강사 · 강사
[ ] 최운영 · 운영자           [취소] [초대]

참여자 내보내기
김강사님을 이 방에서 내보낼까요?
이후 이 방의 메시지·파일과 멘션 알림에 접근할 수 없습니다.
기존 대화 기록은 남은 참여자에게 보존됩니다.
                              [취소] [내보내기]
```

기존 우측 패널의 가리기/다시 보기 및 사용자별 저장을 유지한다. 방 미선택 시 `대화방을 선택하세요`를 표시하고, 로딩/권한 오류/삭제된 방은 이전 멤버를 남겨두지 않는다. 우측 패널 공간이 부족하면 헤더 `[참여자 4]` 버튼으로 여는 대화상자/패널로 전환한다. 강사 포털은 같은 참여자 컴포넌트를 사용한다. 다른 페이지의 이용 팁 패널은 유지한다.

## 2. Implementation (구현 절차)

1. 최신 main 독립 브랜치에서 시작한다. 기존 SDLC/실시간 알림·나가기 구현을 재사용한다.
2. OWNER와 본인 판별을 공통 함수로 정리하고 목록/패널에 왕관·이름·역할을 표시한다. MEMBER가 없는 단독 방장도 정상 표시한다. DM에는 그룹 방장 관리 UI를 적용하지 않는다.
3. `AdminContentLayout`에 현재 페이지가 등록하는 우측 콘텐츠 슬롯을 추가한다. 페이지/방 변경 및 로그아웃 시 정리하고 선택 방 ID로 공유 Query 캐시를 구독한다. 사용자/테넌트별 키와 기존 패널 표시 설정을 유지한다.
4. 공용 `TalkParticipantsPanel`과 초대/내보내기 확인 UI를 구현한다. 권한을 서버와 UI 양쪽에서 확인한다. 일반 참여자의 패널에는 관리 버튼을 렌더링하지 않는다.
5. 그룹 방장용 부분 변경 API를 추가한다(예: POST `channels/:id/invitations`, DELETE `channels/:id/members/:kind/:refId`). 현재 채널과 멤버를 트랜잭션에서 잠그고 신규 참여자만 추가하거나 특정 참여자만 종료한다. 기존 전체 교체 API는 호환 유지하되 새 패널에서는 사용하지 않는다. 자기 자신/방장 제거, 다른 테넌트 대상은 거부한다. 빈 일반 참여자 목록을 허용해 마지막 참여자도 개별 내보낼 수 있게 한다.
6. 같은 방 멤버에 대한 DM 시작 API를 관리자/강사 양쪽에 추가한다(예: POST `channels/:id/dm`). 호출자의 현재 참여와 대상의 현재 참여/계정 유효성을 서버에서 재확인한다. 강사 후보 목록을 전역으로 공개하지 않는다.
7. DM 생성 코드를 USER/TEACHER actor 공용으로 분리한다. 채널 생성자 kind/refId를 저장하는 필드를 추가하고 기존 `tlc_created_by`는 USER 기록으로 보존한다. 강사가 만든 DM에서는 기존 USER 전용 필드를 nullable로 허용하고 TEACHER 식별자를 별도 저장한다. 강사 UUID를 USER ID인 것처럼 저장하지 않는다. 단체방 생성자/방장 정책은 유지한다.
8. DM은 같은 학원·정렬된 두 actor 키로 트랜잭션 잠금을 적용하여 동시 요청에도 중복 생성하지 않는다. 활성 두 참여자의 기존 DM을 재사용하고, 상대가 이미 나간 방은 기존 정책대로 새로 생성한다. 본인에게만 보관 해제를 적용하고 해당 DM으로 이동한다.
9. 초대/내보내기/위임 후 참여자 패널·방 목록·왕관·미읽음 캐시를 SSE로 갱신한다. 강제 퇴장한 사용자의 메시지·파일·멘션 접근과 진행 중 다운로드 종료는 기존 철회 경로를 재사용한다.
10. 4개 언어, 키보드 접근, 작은 화면 동작을 구현하고 결과 보고서와 테스트 화면을 작성한다.

## 3. Validation (검증 계획)

- 방장·일반 운영자·강사별 왕관, 본인 표시와 버튼 노출/직접 API 권한.
- 초대 중복/비활성/타 학원 대상, 자기 자신 및 OWNER 강제 퇴장 차단.
- 마지막 일반 참여자 내보내기, 퇴장 후 메시지·첨부·멘션 접근 차단 및 재초대.
- 두 관리 화면의 동시 초대/퇴장과 기존 전체 교체 API의 동시성.
- DM 3방향, 본인/비참여자/타 학원 차단, 동시 시작 중복 방지, 보관된 DM 복원, 탈퇴한 DM 재개설.
- 멤버 목록/왕관 실시간 갱신, 패널 가리기·다시 보기, 페이지·계정 전환 시 캐시 누출 방지.
- PG 마이그레이션 재실행과 기존 개설자 기록 보존; 관련 단위/PG 통합 테스트 및 프런트·백엔드 빌드.
- 브라우저 운영자/강사 데스크톱·모바일 흐름 검증 및 화면 캡처.

## 4. Approval and Delivery (승인 및 적용)

사용자가 계획과 이용 팁 자리 사용 조건을 승인하여 구현을 진행한다. 운영 배포는 별도 요청 시 테스트 통과와 데이터 보존 마이그레이션 검증을 거쳐 진행한다.

## Approved Layout Constraint (승인된 화면 조건)

2026-10-06 사용자 구현 승인. 관리자 채팅 참여자 목록은 **현재 우측 이용 팁 자리**를 교체하여 표시한다. 기존 패널 가리기/다시 보기 및 다른 페이지 이용 팁은 유지한다. 좁은 관리자 화면은 기존 패널 반응형 배치를 사용하며, 강사 포털은 참여자 대화상자를 사용한다. 운영 배포는 별도 요청 시 진행한다.
