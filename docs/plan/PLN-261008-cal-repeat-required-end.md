# Implementation Plan (구현 계획)

## 1. Finding and Scope (확인 및 범위)

종료일 기능은 기존에 있지만 기본값 NEVER 및 COUNT 방식으로 날짜 미지정 저장이 가능했다. 사용자의 “종료시점이 지정되어야 함 … 없으면 기능 추가 작업” 지시에 따라 기존 반복 등록의 종료일 필수 조건을 보완한다. 일/주/월 반복은 종료일 입력을 필수화하고 신규 등록의 종료 없음/횟수 선택은 제거한다. 특정일자 선택은 유한한 목록의 마지막 날짜를 종료시점으로 표시한다.

## 2. UI Layout (화면 구성)

```text
반복 [매일/매주/매월/특정일자]
반복 종료일 (필수) [날짜 선택]
시작일 이후(당일 포함)의 반복 종료일을 지정하세요.
다음 일정 미리보기 …
[저장: 종료일 누락/시작일 이전/미리보기 오류 시 비활성]

특정일자: [선택 날짜들] · 반복 종료: 마지막 선택 날짜
```

## 3. Changes and Validation (변경 및 검증)

화면과 신규 미리보기/생성 API 양쪽에서 종료일 검증. 학원 시간대의 시작일과 비교하며 종료일 당일을 포함한다. 잘못된 달력 날짜도 서버에서 거부한다. 기존 저장된 NEVER/COUNT 규칙의 반복 계산·자동 생성, 기존 ICS 가져오기와 단건/시리즈 편집은 그대로 유지한다. 기존 일정 삭제·수정 및 운영 배포는 포함하지 않는다.

검증: 종료일 누락/잘못된 날짜/시작일 이전/당일/시간대 경계, 유한 날짜 목록, 기존 무기한 일정 호환 테스트 및 로컬 브라우저 등록 흐름. 기존 IDE 변경을 보존하는 독립 브랜치에서 작업한다.
