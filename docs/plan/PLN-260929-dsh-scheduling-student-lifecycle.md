### 3.1 Storage Design (저장 구조 제안)

- 신규 구조 후보: `amb_acm_csl_schedule_history`, `amb_acm_std_return_event`, `amb_acm_csl_referral`. 모든 행에 UUID PK·ent_id·발생일/시각·작성자·created_at/updated_at·취소/정정 정보를 둔다. 최종 컬럼·마이그레이션 번호는 구현 시 확정한다.
- 일정 이력은 상담/수강신청의 회차를 연결하고, 예정일 변경·취소·재확정도 기록한다. CAL/CLS 중복 집계 방지를 위해 원본 일정/세션 식별자를 연결한다. 상태 변경 시 다른 과거 날짜를 덮어쓰지 않는다.
- 복귀는 기존 재원기간을 연결한다. 기존 기간을 삭제하거나 새 학생을 매번 생성하지 않는다. 과거 상담만 있는 경우 학생 연결 전용 흐름으로 통합 식별자를 확정한다.
- 소개는 소개받은 상담/학생과 소개한 학생 또는 학부모를 연결한다. 유형별 FK·동일 테넌트·자기소개 금지·중복 유입 방지를 검증한다. 단순 boolean만 저장하지 않는다.
- 일반 `updated_at`으로 지표 날짜를 계산하지 않는다. 현행 Apply의 수정일 기반 집계는 확인된 별도 개선 후보이며 이번 정의와 혼용하지 않는다.
- 신규 집계는 공통 서비스 결과를 표·요약·내보내기에 공급한다. 전체 수기 덮어쓰기 플래그가 신규 자동 지표를 막지 않게 분리하고, 원천 정정 시 과거/현재 영향 구간을 재계산한다.
- 내부 카테고리 `CS` 키는 호환성을 위해 유지하고 표시명만 Scheduled로 바꾼다. New St.는 정의 버전을 달리하여 과거 수기·자동값과 오해를 막는다.

### 3.2 Today Live API and Panel (오늘 실시간 API·패널)

- `source-current-panel.tsx`, `types/source-current.ts`, `source-current.service.ts` 및 controller를 확장한다. 기존 4개 원장 수치와 그룹별 전체 지표를 포함하고 definitionVersion·today·asOf·원천 갱신시각·품질 상태를 반환한다.
- 공통 지표 목록을 순회하여 마케팅/스케줄/운영/수업 모든 항목을 렌더링한다. 오늘 전용 조회에는 기간 필터를 전달하지 않는다. 현행 통합 화면 패널의 ALL 범위를 명시한다.
- 오늘 데이터는 내부 원천의 현재 기록으로 계산한다. 기존 수기값 병기·명시적 덮어쓰기 정책을 공통 집계 서비스와 일치시키고 오늘 수기 수정도 반영한다. 외부 연동 지표는 저장된 최신 동기화 자료를 읽고 동기화 상태를 노출한다.
- 5초 폴링·수동 갱신·포커스 복귀 갱신을 유지하되 서버에서 조회를 묶고 외부 API 직접 호출을 분리한다. 캐시를 사용하면 갱신 지연을 표시하고, 원천 저장 시 무효화한다. 실패 시 이전 성공 시각과 오류를 보여준다.
- New Class는 학생정보 `std_start_date` 조회·학생 상세 연결로 구현한다. 실제 수업 진행 여부를 조건으로 사용하지 않는다. 날짜 수정 시 이전/새 날짜 모두 재계산한다.

## 4. Verification (검증)

1. 첫 납부 전/후, 첫 수업 전/당일/완료, 여러 결제·분납·전액 환불, 시험비/체험비, 기존 수강자 재납부, 첫 납부 과거 자료 누락.
2. 조율 중→조율 완료→취소→재조율, 수업 시작 후 조율 완료 유지, 다중 수강건 상태 우선순위와 중복 제거. New Class는 학생 수업시작일 당일 포함, 실제 수업 미진행도 포함, 시작일 수정·누락·동명이인 검증.
3. 상담 후 중단·복귀, 수강 중단·복귀, 반복 복귀, 이름 동일한 다른 학생, 단순 사이트 이동 제외, 신규 학생과 기존 상담 연결.
4. 학생 소개·학부모 소개·수기 미확인 소개자, 타 테넌트/자기소개 차단, 한 학생의 중복 상담/반복 소개 등록.
5. 월말 조회·기간 이전 대기자·KST 자정·미래 종료일, ALL/사이트 귀속, 일별 합산과 기간 고유 수 차이, 누락과 0, 수기 0 보존.
6. PostgreSQL 통합 테스트로 이력 조회·동시 변경·멱등성·테넌트 격리 검증. UI에서 원천 입력→대시보드→CSV 동일값 확인, 기존 입학 기준 학생수·강사·광고비 회귀 검증.

7. 오늘 패널에서 공통 지표 목록과 항목 수/코드 완전 일치, 과거 기간 필터에도 오늘 유지, 자정 전환, 5초·수동·포커스 갱신, 원천 수정 즉시 반영, 외부 동기화 지연·오류·분모 0 표시, 기존 4개 카드 유지 검증.

## 5. Migration and Release (이행·배포)

- 과거 상담·납부·수업·기간 연결로 입증 가능한 건만 보완한다. 추정 날짜·이름 일치만으로 복귀/소개를 확정하지 않는다.
- 이력 수집 시작 이전 자료는 품질 상태를 표시한다. 운영자가 확인한 과거 기록에 한해 발생일과 확인일을 구분하여 보완한다.
- additive migration → 원천 입력/API → 검증된 신규 집계·화면 순서로 활성화한다. 배포 전 백업, migration dry-run, 대표 명부 대사를 실시한다.
- 기능 플래그/지표 정의 버전으로 이전 표시를 복구할 수 있게 한다. 롤백 시 신규 기록을 삭제하지 않는다.
- 단순 열 추가보다 원천 연결·최초 납부 검증이 작업량을 좌우한다. 1단계 대사 후 구현 규모를 확정한다.
