│                                [수납] [저장] [삭제]           │
│ ─────────────────────────────────────────────────────────── │
│ [+ 청구 추가]                                                 │
│ 사유(선택) [                    ]                             │
│ ▾ 수납 (펼침: 수납 입력·환불·이력 — 기존 기능)               │

- [삭제] → "이 청구를 삭제할까요?" 확인 → 목록·합계에서 제외. 수납 기록이 있으면 비활성 + 안내.

## 3. Verification (검증)
- 로컬(빈 DB + sql/acm 전체): 간편 작성 저장 1회, 줄별 수정·삭제, 수납 있는 청구 삭제 차단, 월별 합계 반영.
- 마이그레이션 없음.

## 4. Result (결과) — 2026-10-30
- 통합 테스트 8건 통과(신규: 종류 변경·수납 없는 청구 삭제 → 목록·월별 건수 제외, 수납 후 삭제 거부 `PAY_HAS_COLLECTIONS`).
- 로컬(빈 DB + sql/acm 전체, 한국어): 목록 마지막 열 [+ 청구](청구 없음)·[수정 (n)](청구 있음) → 같은 창. 간편 추가(종류·청구액만, 제목 자동 "10월 교재"), 줄별 수정(종류 재료·금액 30,000 저장), 삭제(확인 1회 → 1건으로 감소), [수납] → 수납 기록 창 → 닫으면 수정 창 복귀, 수납 후 [삭제] 비활성 + 안내.
- 계획 대비 변경: 청구가 있는 행은 [수정 (n)] 하나만 두고 창 안의 [청구 추가]로 추가(행에 [+] 별도 버튼 없음). 백엔드 사유는 필수 유지, 화면에서 비우면 자동 사유("청구 수정"/"청구 삭제")를 보냄. 삭제 API `POST /bills/:id/delete`(ADMIN·APP_ADMIN·STAFF).
- 수정 창으로 옮기며 기존 상세 창의 '청구 수정·청구 취소' 칸은 제거(수납 기록·이력만 남김).
