# Student Navigation Implementation Plan (학생관리 하위 메뉴·퇴원 목록 작업계획)

## 1. Objective (목표)

[요구사항 분석서](../analysis/REQ-260920B-std-navigation-withdrawn-list.md)에 따라 학생관리를 사이트별 현재 학생과 퇴원생 전용 화면으로 구분한다. 사용자 요청대로 화면구성도를 포함한다. **3개 사이트 전체 통합 보기를 유지**하며, 상위 학생관리에서 통합 목록에 접근하고 세 사이트 하위 메뉴에서 개별 목록을 조회한다.

## 2. Screen Layouts (화면구성도)

### 2.1 Desktop Navigation (데스크톱 메뉴)

```text
┌─────────────────────┬──────────────────────────────────────────────┐
│ ACM                 │ TPI 학생관리                [엑셀 업로드]    │
│                     │                              [학생 등록]      │
│ 대시보드            │                                              │
│ 신규 상담           │ [이름·영문명·학교 검색] [재원 ▾]              │
│ 학생관리         ▾  │ [학교] [학년] [담당강사] [수업 시작일 범위]   │
│   ● TPI             │ [초기화]                                     │
│     Trinity Academy │                                              │
│     Santa Croce     │ 검색 결과 n명                                │
│     퇴원            │ 이름 / 학교 / 학년 / 담당강사 / 상태         │
│ 학부모 관리         │ 수업 시작일 / 시스템 등록일                  │
│ 교사 관리           │                                              │
│ …                   │ [25/50/100명 ▾]                [이전] [다음]  │
└─────────────────────┴──────────────────────────────────────────────┘
```

- 상위 ‘학생관리’ 텍스트는 TPI·Trinity Academy·Santa Croce의 **전체 통합 목록**으로 이동한다. 펼침 버튼은 하위 메뉴를 열고 닫는다.
- 하위 메뉴는 요청한 4개만 둔다. 미분류 현재 학생은 상위 화면의 필터에서 확인한다.
- 사이트 화면에는 ‘전체 통합 보기’ 링크를 제공한다. 해당 사이트를 제목에 표시하고 중복 사이트 탭은 제거한다. 상태 선택은 재원·휴원·현재 학생 전체로 제한한다.
- 학생관리 그룹은 기존 메뉴 숨김/순서 설정을 상속한다. 별도 ‘학부모 관리’ 메뉴를 학생관리 하위 메뉴의 활성 상태로 잘못 표시하지 않는다.

### 2.2 Withdrawn List (퇴원 전용 목록)

```text
학생관리 > 퇴원
퇴원생 관리                                         [퇴원생 등록]

[이름·영문명·학교 검색]
[사이트: 전체 ▾] [학교] [학년] [담당강사]
[퇴원일: 시작 ~ 종료] [초기화]

검색 결과 n명                                      상태: 퇴원
┌───────────────┬──────────┬─────────┬──────┬────────────┬─────────────┐
│사이트         │이름      │학교     │학년  │퇴원일      │퇴원사유     │
├───────────────┼──────────┼─────────┼──────┼────────────┼─────────────┤
│미분류         │학생 A    │기존 값  │기존 값│2026-08-11 │—            │
│TPI            │학생 B    │기존 값  │기존 값│2026-09-04 │기존 사유    │
└───────────────┴──────────┴─────────┴──────┴────────────┴─────────────┘
담당강사·시스템 등록일 등 기존 목록 항목 유지, 필요한 경우 가로 스크롤
[25/50/100명 ▾]                                      [이전] [다음]
```

- 퇴원 상태는 고정하여 표시한다. 재원/휴원 상태를 선택하는 필터는 제공하지 않는다.
- 사이트 필터는 전체 / TPI / Trinity Academy / Santa Croce / 미분류이다.
- **퇴원생 엑셀 업로드 버튼은 모든 학생관리 화면에서 제거한다.** 퇴원 화면에는 일반 엑셀 업로드도 표시하지 않는다.
- ‘퇴원생 등록’은 기존 학생 등록 폼을 재사용하되 초기 상태를 WITHDRAWN으로 설정한다. 이메일/사이트 선택 입력 규칙을 유지한다.
- 이름 선택 시 기존 학생 상세로 이동한다. 원본 행정정보와 퇴원 이력을 계속 조회·수정할 수 있다.

### 2.3 Integrated List and Detail Return (3개 사이트 전체 통합 보기·상세 복귀)

```text
학생관리 ← 클릭하면 전체 통합 보기
  ├ TPI
  ├ Trinity Academy
  ├ Santa Croce
  └ 퇴원 (기존 별도 목록 요구 유지)

학생관리 — 전체 통합 보기                   [엑셀 업로드] [학생 등록]
[통합 n] [TPI n] [Trinity Academy n] [Santa Croce n] [미분류 n]
[이름·영문명·학교 검색] [상태: 재원 ▾] [학교] [학년] [담당강사]
사이트 / 이름 / 학교 / 학년 / 담당강사 / 상태 / 수업 시작일
TPI 학생 + Trinity Academy 학생 + Santa Croce 학생 + 미분류 학생
[25/50/100명 ▾]                                      [이전] [다음]

사이트별 목록 상단: [← 전체 통합 보기]

통합 목록 ─────┐
TPI 목록 ──────┤ ──────┐
Trinity 목록 ──┼→ 학생 상세 → [목록으로] → 출발 목록·필터·페이지 복귀
Santa 목록 ────┤
퇴원 목록 ─────┘
```

통합 보기는 기존 검색·정렬·건수·페이지 이동을 제공하는 실제 학생 목록으로 유지한다. 사이트별 화면에서 상위 메뉴나 ‘전체 통합 보기’ 링크로 언제든 돌아갈 수 있다. 퇴원생은 이전 요구대로 별도 목록에서 관리한다.

사이트/현재 상태가 변경되어 출발 목록에서 사라지는 경우에도 목록 필터는 유지하고 결과를 갱신한다. 상세의 13px/Bold 제목과 미입력 ‘입력필요’ 규칙은 유지한다.

### 2.4 Mobile and Collapsed Sidebar (모바일·접힌 메뉴)

```text
┌───────────────────────────┐
│ ☰  ACM             한국어 │
│ 학생관리                ▾ │
│   TPI                     │
│   Trinity Academy         │
│   Santa Croce             │
│   퇴원                    │
└───────────────────────────┘
메뉴 선택 → 드로어 닫기 → 해당 목록

┌───────────────────────────┐
```

데스크톱/태블릿 아이콘 모드에서 학생관리 아이콘을 누르면 이름이 보이는 하위 메뉴를 연다. 키보드 이동, Escape 닫기, aria-expanded/현재 메뉴 표시를 지원한다.

## 3. Routes and Query Rules (경로·조회 규칙)

| 경로 | 화면 | 서버 조회 범위 |
| --- | --- | --- |
| `/admin/std` | 3개 사이트 전체 통합 목록·미분류 | CURRENT, 기본 site=ALL, 통합/사이트 탭 유지 |
| `/admin/std/tpi` | TPI 학생 | CURRENT + TPI 고정 |
| `/admin/std/trinity` | Trinity Academy 학생 | CURRENT + TRINITY 고정 |
| `/admin/std/santa-croce` | Santa Croce 학생 | CURRENT + SANTACROCE 고정 |
| `/admin/std/withdrawn` | 퇴원생 | WITHDRAWN 고정 + 사이트 필터 |
| `/admin/std/:id` | 공통 학생 상세 | 기존 학생 UUID |
| `/admin/std/parents` | 학부모 관리 | 기존 동작 |

- 학생 목록 API에 선택적 `scope=CURRENT|WITHDRAWN`을 추가한다. CURRENT는 ACTIVE/INACTIVE 범위, WITHDRAWN은 퇴원만 포함한다. 기존 scope 미지정 소비자의 동작은 유지한다.
- 범위와 충돌하는 상태 조건은 서버에서도 검증한다. 행 조회와 사이트별 건수는 동일 범위 조건을 사용한다.
- 기존 `/admin/std?status=WITHDRAWN`은 새 퇴원 경로로 전환한다. 사이트·검색·기간·정렬은 유지한다. 기존 사이트 쿼리 링크도 대응 사이트 경로로 전환하며 미분류/통합은 상위 화면에 남긴다.
- 새로운 고정 경로가 학생 UUID 라우트나 학부모 경로와 충돌하지 않게 구성한다. 상세 returnTo는 허용된 학생 목록 경로만 검증하여 사용한다.

## 4. Implementation Steps (구현 순서)

1. 본 분석·계획 확인 후 구현 시작.
2. `app-shell.tsx`: std 메뉴 그룹·4개 하위 링크·활성 표시·접힌 메뉴/모바일 동작 추가.
3. `routes/router.tsx`: 고정 목록 경로 추가, 기존 쿼리 URL 호환 처리.
4. `std-list-page.tsx`: 공통 목록에 CURRENT/WITHDRAWN 및 고정 사이트 옵션을 제공한다. 통합 목록과 기존 통합/사이트 탭을 유지하고, 사이트별 화면에 전체 통합 보기 링크를 제공한다. 페이지별 제목·필터·열·등록 초기 상태를 구성한다.
5. 퇴원생 엑셀 버튼과 모달 연결 상태를 제거한다. 기존 원본 정보 조회/편집 API와 기록은 보존한다.
6. 학생 API DTO/서비스/types/hooks: scope 검증과 사이트별 건수 일치, 기존 소비자 회귀 확인.
7. `std-detail-page.tsx`와 테이블 이동: 신규 목록 경로의 검색/페이지 복귀, 상태 변경 후 목록 갱신.
8. ko/en/vi/zh-CN 번역 및 접근성 검증, CI·스테이징·운영 배포와 실제 화면 확인.

이번 변경은 조회·메뉴 구성 중심이며 DB 마이그레이션이나 학생 일괄 상태 변경이 필요하지 않다.

## 5. Validation and Rollback (검증·복구)

| 검증 | 기대 결과 |
| --- | --- |
| 하위 메뉴 | 4개가 요청 순서로 노출, 현재 화면 하나만 강조 |
| 사이트 목록 | 다른 사이트와 퇴원생이 섞이지 않음 |
| 3개 사이트 통합 | 상위 학생관리와 전체 통합 보기 링크로 접근, 3개 사이트 학생을 한 목록에서 조회·검색·정렬·페이지 이동 |
| CURRENT 전체 | 선택한 상태 범위 내 3개 사이트+미분류 건수 일치, 재원/휴원 전체 선택 시 퇴원 제외 |
| 퇴원 목록 | 전체 사이트·미분류 퇴원생만 조회, 날짜 범위·건수 일치 |
| 업로드 제거 | 루트·사이트·퇴원 화면에서 퇴원생 엑셀 버튼 없음 |
| URL 호환 | 구형 링크와 상세 직접 진입, 목록 복귀 조건 정상 |
| 상태 변경 | 명시적 수정 후 해당 목록 갱신, 메뉴 이동만으로 DB 변경 없음 |
| 메뉴 설정 | std 숨김·역할·순서·학부모 메뉴 동작 유지 |
| 반응형 | 펼친/접힌 사이드바와 모바일 드로어에서 모두 접근 가능 |
| 회귀 | 일반 학생 엑셀 업로드·상세 원본 편집·기존 학생 API 유지 |

문제 발생 시 이전 앱 이미지로 복구한다. 목록 분리에 따른 학생 데이터 이동/복제/삭제가 없으므로 데이터 복구 작업은 필요하지 않다.
