# Calendar Import Plan (캘린더 일괄 입력 계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-260930-cal-ics-import.md)에 따라 19개 파일 전체를 이관한다. 단순 개별 일정 INSERT로는 무기한 반복을 유지할 수 없어 CAL 반복 원본 저장과 자동 전개를 보완한다. 별도 범용 업로드 화면은 이번 범위에 포함하지 않고 검증 가능한 일회성 운영 도구를 사용한다.

## 2. Storage and Import (저장·이관)

1. 최신 main의 독립 브랜치에서 작업한다. 원본 파일은 비공개 입력으로 취급하고 저장소에 커밋하지 않는다. 파일 해시와 import batch ID를 기록한다.
2. 테넌트별 ICS 원본/시리즈·예외·생성 이벤트 연결 정보를 `amb_acm_cal_*` 테이블에 추가한다. UID, RECURRENCE-ID 원래 시각, 원본 캘린더 식별자, RRULE/RDATE/EXDATE, TZID 및 VTIMEZONE을 유지한다.
3. 검증된 iCalendar 파서로 단일 일정과 유한 반복 전체를 전개한다. 무기한 반복은 원본 규칙을 영구 보존하고 최초 과거 전체+향후 12개월을 생성한다. 매일 작업이 향후 12개월 구간을 확장하며 사용자 조회가 생성 구간 밖이면 해당 조회 범위를 보충한다. 12개월은 생성 버퍼이며 반복 종료일이 아니다.
4. 변경된 단일 회차는 기존 회차를 대체한다. EXDATE/취소 및 이동된 회차, 종일/시간대/서머타임을 먼저 반영한다. 지원하지 못하는 규칙은 실패 내역으로 분리해 누락을 숨기지 않는다.
5. 테넌트+원본 캘린더+UID+원래 회차 키로 멱등성을 보장한다. 기존 운영 일정과 제목/시작/종료/담당자 일치 후보는 별도 대사하여 중복 등록을 막되 불명확한 자료를 자동 덮어쓰지 않는다.
6. 작성자는 기존 배예리 이메일 계정에 연결하고 표시 이름을 배예리로 수정한다. 이름이 일치하는 강사만 담당자로 연결한다. 미매칭 김세희·임마이클은 원본 이름 보존 및 담당자 미지정으로 입력한다.
7. 원본 Google Meet URL은 그대로 보존한다. 가져오기 과정에서 참석자 초대·메일·BODA 방 발급은 하지 않는다. 과거 수업의 진행/출석/결제 사실을 일정만으로 생성하지 않는다. 카테고리는 원본 캘린더와 명시적 근거로 매핑하며 애매한 이벤트는 OTHER로 보존한다.
8. 개별 회차의 사용자 수정/삭제가 자동 생성으로 되돌아가지 않도록 수정·삭제 회차 키를 보존한다. 시리즈 중단 기능을 마련해 원본 무기한 일정도 운영자가 종료할 수 있게 한다.

## 3. UI Layout (화면 구성안)

기존 수업일정 월/주/일 보기를 사용하고, 가져온 일정의 상세에서 원본·반복 여부를 확인한다.

```text
수업일정                    [담당자] [작성자] [월/주/일]
┌───────────────────────────────────────────────────┐
│ 기존 달력: 가져온 일정도 동일하게 표시               │
└───────────────────────────────────────────────────┘
일정 상세
  제목 / 시작 / 종료 / 장소 / 회의 링크
  작성자: 배예리 · tpiyeri@tpiglobal.network
  담당자: 일치 강사 또는 미지정
  원본 캘린더: 정성경 선생님
  반복: 원본 규칙 표시 · 종료일 없음
  [이번 일정 수정] [이번 일정 삭제] [반복 종료]
```

## 4. Validation and Rollout (검증·적용)

- 단위/통합 테스트: 반복 675개와 예외 1,657개의 전개, 날짜 이동, EXDATE, 종일 종료일 제외, Sydney DST, 매일 재실행 중복 방지, 작업 동시 실행, 사용자 수정·삭제 보존, 테넌트 격리.
- 원본별 dry-run 보고: 단일/유한/무기한 반복의 생성 수, 제외 수, 미매칭 담당자, 기존 일정 중복 후보, 파싱 실패. 최종 생성 수는 이 단계에서 확정한다.
- 스테이징 검증 → 운영 DB 백업 → 반복 지원 배포 → 배치 등록 → 작성자/담당자/시간대·예외 표본을 실제 화면에서 대사한다.
- 실패 시 해당 import batch만 되돌릴 수 있는 기록을 남긴다. 기존 68개 운영 일정은 보존한다.

## 5. Approval Gate (구현 확인)

사용자의 일괄 입력과 무기한 반복 유지 의사는 확인했다. 현재 기능에 없는 반복 저장·자동 확장 구현이 필요하므로 프로젝트 AGENTS.md §9.2에 따라 요구사항 분석서와 본 작업 계획서 확인 후 구현한다. 사용자 “진행”으로 구현·일괄 등록 승인을 받았다. 구현과 로컬 검증을 완료했으며 운영 적용은 배포 단계에서 수행한다.
