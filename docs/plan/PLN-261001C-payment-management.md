# Payment Management Plan (수납관리 작업 계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-261001C-payment-management.md)의 Phase 1을 기본 승인안으로 제안한다. 제공 링크의 상세수납을 우선 구현하고 영수증 발급·실제 환불·자동결제·문자 등 외부 연동은 Phase 2로 구분한다. 범위 답변에 따라 계획을 갱신한다. 2026-10-01 사용자의 “구현 진행” 승인에 따라 Phase 1 구현 및 로컬 검증 완료. 운영 배포는 별도 진행한다.

월별 생성 모달: 대상 월 → 재원 학생/수업 선택 → 청구 항목·금액·납기 지정 → 중복/제외 사유 포함 미리보기 → 생성. 기존 상담 금액을 매월 자동 복제하지 않는다. 휴·퇴원/중도수업은 자동 일할 계산하지 않고 미리보기에서 조정한다.

## 3. Data and API (데이터 및 API 설계안)

기존 `amb_acm_pay_order`는 실제 PG 주문용으로 보존한다. 신규 테이블의 모든 행에 ent_id UUID, created_at/updated_at 및 테넌트 포함 인덱스를 적용한다.

| 제안 테이블 | 역할 |
|---|---|
| amb_acm_pay_bill | pbl_id, 학생·사이트·수업/수강 연결, 청구월·납기·구분·명칭, 원금·할인, 통화, 메모, 버전, 취소 상태 |
| amb_acm_pay_collection | pcl_id, 청구·원거래 참조, 납부/환불/취소 유형, 금액, 실제 날짜, 수단, 처리자·사유, 멱등키, 선택적 PG 주문 연결 |
| amb_acm_pay_bill_adjustment | pba_id, 청구 감액/복구, 금액·사유·원환불 연결, 처리자. 정정도 추가 기록 |
| amb_acm_pay_bill_audit | pbu_id, 변경 전후·처리자·시각·요청 식별자. 민감정보 최소 저장 |

FK는 같은 테넌트의 학생·수업·청구인지 검증한다. 금액 NUMERIC 정수, 계산은 서버에서 수행한다. 변경/수납은 청구 행 잠금 및 버전 충돌 검사, 원장·이력·합계 일괄 트랜잭션. 실제 마이그레이션 번호는 구현 시작 시 충돌 없이 할당한다.

API 제안: `/api/acm/pay/bills` 목록/생성/상세/수정, `/summary`, `/batch-preview`, `/batch-create`, `/:id/collections`, `/:id/refunds`, `/:id/adjustments`, `/:id/cancel`, `/:id/restore`, `/export`. 일괄 편집은 상한 및 멱등키를 적용하며 동일 요청 범위는 원자적으로 저장한다. 서버 오류 시 편집 데이터는 유지한다.

권한 제안: ADMIN/APP_ADMIN 전체, STAFF 조회·청구 편집·수납 기록, 환불·수납취소·기존 납부 정정은 ADMIN/APP_ADMIN. 강사·학부모는 관리자 수납 메뉴 접근 제외. 기존 상담 승인 권한은 확대하지 않는다.

## 4. Implementation Steps (구현 순서)

1. 최신 main의 격리 작업 공간에서 DB 스키마·기존 결제 호출부를 확정하고 마이그레이션 작성.
2. 청구·수납·조정·환불 기록 서비스 및 controller/DTO, 권한·동시성·멱등성 구현.
3. 수납관리 메뉴/라우트와 필터·요약·표·편집·상세 패널·4개 언어 구현.
4. 월별 청구 미리보기/생성, 일괄 변경, 검색조건/열 설정, XLSX 구현. CSV/엑셀 수식 주입 방지.
5. 상담 원본 연결 조회·중복 표시. 기존 금액 이관은 승인된 대상만 별도 처리하고 PG/상담 통계 이중 계산을 방지.
6. PostgreSQL 통합·API·브라우저 검증, 구현 보고서 작성.
7. 배포 요청 후 백업 → 스테이징 → 격리 데이터 검증 → 운영 배포·조회 확인.

## 5. Verification (검증 계획)

- 미납·부분납·완납·연체·0원, 할인·감액·환불·납부취소 계산.
- 복수 납부, 환불 상한, 중복 요청, 동시 요청, 잠금·버전 충돌 및 롤백.
- 테넌트·역할·연관 데이터 권한, 다운로드 개인정보 접근 및 필터 합계 일치.
- 월별 생성 중복/대상 제외/특정 학생 실패 시 정책, 취소·복구·변경 이력.
- 콤마 입력/붙여넣기, 키보드 편집, 미저장 변경 이탈, 좁은 화면, 오류/빈 상태.
- 기존 상담 납부 승인·학생 통계·학부모 PG 주문 조회 회귀, 실제 외부 결제·문자 발송 없이 검증.

## 6. Approval (사용자 확인)

2026-10-01 사용자 “구현 진행”으로 Phase 1 승인. 구현 결과와 검증 증빙은 [구현 보고서](../report/RPT-261001C-payment-management.md)를 참조한다. Phase 2 및 운영 배포는 이번 작업에 포함하지 않았다.

Phase 1 구현 및 로컬 검증 완료. [구현 보고서](../report/RPT-261001C-payment-management.md)에 실제 API·권한·화면 구성 및 배포 준비사항을 기록했다. 상세는 공통 모달, 목록은 순수납액 중심으로 제공하고 원납부/환불 합계는 상세·엑셀에서 확인한다. 외부 결제 및 데이터 이관은 수행하지 않았다.
