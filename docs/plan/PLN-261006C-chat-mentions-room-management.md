# Chat Management Plan (채팅 관리 구현 계획)

## 1. UI Layout (화면 구성안)

```text
ACM                                           [🔔 3] [언어]
채팅
┌─────────────────────┬────────────────────────────────────┐
│ [대화방] [보관함 2] │ 강사 운영 단체방   참여자 5    [⋯]  │
│ [새 단체방] [새 DM] │                        ┌───────────┤
│ 강사 운영 단체방  2 │                        │ 제목 변경 │
│ 배예리             │                        │ 참여자 관리│
│                    │                        │ 보관      │
│                    │                        │ 나가기    │
│                    │                        └───────────┤
│                    │ @강사명 다음 일정을 확인해주세요.   │
│                    │ [메시지 입력 / @참여자 선택] [전송] │
└─────────────────────┴────────────────────────────────────┘
제목 변경: [강사 운영 단체방________________] [취소] [저장]
나가기: 이후 메시지와 알림을 받을 수 없습니다. [취소] [나가기]
방장 나가기: [다음 방장 선택 ▼] [취소] [위임 후 나가기]
보관함: 방 목록 및 미읽음 수 / 선택한 방 [목록으로 복원]
알림: “배예리님이 강사 운영 단체방에서 회원님을 멘션했습니다.”
```

제목/참여자 관리는 운영자 방장에게만 표시한다. 강사 포털에도 종 아이콘 및 본인 멘션 목록, 보관/복원/나가기 메뉴를 제공한다. 삭제는 기존 방장 기능이며 나가기와 구별한다. 작은 화면에서 목록/대화 전환과 메뉴 키보드 접근, 확인창 포커스 복귀를 지원한다.

## 2. Data and API (데이터 및 API)

1. 최신 main 기준 독립 작업 브랜치에서 구현한다. 기존 소스 및 운영 데이터는 보존한다.
2. amb_acm_talk_member에 nullable tlm_archived_at을 추가한다. 목록 API에 active/archived 구분을 추가하고 기본값은 active로 한다. 보관방 직접 조회 경로를 추가하여 알림 링크가 동작하도록 한다.
3. 운영자 API에 단체방 제목 PATCH를 추가한다. 양쪽 채팅 API에 본인 archive/restore/leave 작업을 추가한다. 방장 위임/나가기는 한 트랜잭션으로 처리한다. 참여 변경·전송과 채널/참여 잠금 순서를 통일해 동시 요청에서도 방장 유실 및 나간 뒤 전송을 막는다.
4. 강사 수신자를 포털 로그인 계정과 서버에서 연결한다. 이메일/이름 추측 매핑은 사용하지 않는다. 기존 usr_id 수신자를 USER로 유지하고 inbox/outbox에 수신자 종류와 식별자(예: USER/TEACHER)를 추가한다. TEACHER 식별자는 tch_id로 고정하며 포털 JWT의 entId/kind/refId와 활성 계정·교사·멤버 상태를 검증한다. 기존 알림 행과 미읽음 상태를 보존하고 새 수신자 키에 중복 방지 인덱스를 둔다.
5. 포털 전용 inbox 조회/미읽음/읽음/실시간 API를 추가한다. 기존 운영자 inbox와 동일한 비즈니스 전달 로직을 사용하되 인증 주체 해석은 각각의 Guard에서 수행한다. TEACHER 이외 포털 계정은 접근 차단한다.
6. 전송자도 kind/refId로 정규화하여 강사 본인 멘션을 제외한다. outbox의 기존 USER 수신자 형식과 배포 전 미처리 이벤트를 호환 처리한다. 메시지별·수신자별 중복 전달을 방지한다.
7. 알림 조회/count/read/deep link 모두 현재 참여 권한을 재확인한다. 삭제 메시지/삭제 방/탈퇴자의 알림을 노출하지 않는다. 포털에 대상 메시지 조회·이동을 구현한다.
8. 제목/보관/나가기/위임 후 SSE 및 React Query 캐시를 갱신한다. 나간 사용자의 열린 화면과 첨부파일·진행 중 스트림에도 권한 종료가 반영되도록 확인한다. 캐시 키는 테넌트/사용자/모드/보관 상태를 포함한다.

## 3. Validation (검증)

- 멘션 전달 방향 3종, 자기 자신/중복/비참여자/다른 학원, outbox 재시도 및 기존 이벤트 호환.
- 제목 권한과 빈 문자열/100자 한도, 단체방 전용 제약.
- 개인별 보관 격리, 재로그인 유지, 보관방 알림 이동, 복원/미읽음 합계.
- 멤버 나가기, 방장 위임, 마지막 참여자, DM 재개설, 재초대, 전송과 동시 나가기.
- 탈퇴 후 메시지/파일/알림 접근 차단, 포털 학생·학부모 접근 차단.
- 기존 상담/일정 알림 회귀, 백엔드 관련 단위·PG 통합 테스트, 프런트 타입 검사·빌드 및 운영자/강사 UI 확인.

## 4. Delivery (적용 절차)

계획 승인 → 구현 및 검증 → 결과 보고. 운영 배포 시 DB 백업 후 기존 데이터를 보존하는 확장 마이그레이션을 적용하고 운영자/강사 로그인별 기능을 확인한다. 이 요구사항 검토 단계에서는 코드 변경·배포·실제 알림 전송을 하지 않았다.

2026-10-06 사용자의 “구현” 승인에 따라 구현 및 로컬 검증을 완료했다. 상세 결과는 [구현 보고서](../report/RPT-261006C-chat-mentions-room-management.md)를 참조한다. 운영 배포 및 실제 계정으로의 메시지 전송은 수행하지 않았다.
