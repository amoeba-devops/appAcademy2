# Teacher Profile Implementation Plan (교사 상세 개선 및 등록 계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-260919-tch-profile-import.md)에 따라 사용자 제공 엑셀의 강사 21명을 등록·보완한다. 운영 화면 기준 예상 신규 20명, 정성경 보완 1명이다. 실행 직전 대조 결과로 확정하며 예상 인원에 맞추기 위해 중복 검증을 생략하지 않는다.

2026-09-19 사용자의 “진행” 승인에 따라 구현·검증을 진행한다. Google 인증은 사용자 제공 대체 엑셀로 해결되어 이번 작업의 진행 조건이 아니다.

## 2. Screen Layout (화면 구성안)

### 2.1 List and Navigation (목록과 이동 흐름)

```text
교사 관리                                      [교사 등록]
[이름·이메일 검색                         ] [재직상태 ▾]
총 n명
┌──────────┬────────┬────────┬──────────────────────────┐
│ 이름     │강사여부│고용형태│기존 연락처·계정·재직 열  │
├──────────┼────────┼────────┼──────────────────────────┤
│ 정성경   │ 강사   │ 정규   │ 기존 값                  │
│ 강사명   │ 강사   │ —      │ 등록된 값 / 미입력 —     │
└──────────┴────────┴────────┴──────────────────────────┘
행 선택 → 교사 정보 수정 모달
교사 등록 → 신규 등록 모달
저장 성공 → 모달 닫기 → 현재 검색·필터를 유지한 목록 갱신
```

목록의 기존 12개 열은 유지하며 위 도식의 마지막 열은 기존 열들을 축약한 것이다. 넓은 표는 가로 스크롤을 제공한다. 이름 영역은 키보드로도 상세를 열 수 있게 한다.

### 2.2 Desktop Detail (데스크톱 상세)

기존 목록에서 교사 행을 선택하면 넓어진 상세 편집 모달을 연다. 데스크톱 최대 폭 약 960px, 모바일 한 열, 본문 스크롤과 저장 영역을 분리한다. 기존 목록 열은 유지한다.

```text
교사 정보 수정 · 정성경                              [닫기]
────────────────────────────────────────────────────────
기본 정보
이름 *             [정성경       ]   영문명 [기존 값      ]
이메일             [기존 값      ]   연락처 [             ]
카카오톡 ID        [             ]
성별               [남 ▾         ]   거주지역 [서울       ]
생년월일           [             ]   재직상태 [재직 ▾     ]
고용형태           [미입력 ▾     ]   입사일자 [           ]
출결번호           [             ]   [✓] 강사 여부

학력·경력
학력               [학교·전공·학위·재학 상태, 여러 줄      ]
경력               [원본에 기재된 경력                    ]

담당 과목·프로필
담당 과목          [MAP] [SSAT] [ISEE] ...
담당 과목 상세     [영어                                  ]
상세 프로필        [전문 수업 / 입시 지도 / 지도 학교      ]
                   [원문 줄바꿈을 유지하는 여러 줄 입력    ]
내부 메모          [기존 메모                             ]

이력서·첨부파일     [기존 파일 목록] [파일 업로드]
포털 계정          [기존 계정 상태 및 제어 영역]
────────────────────────────────────────────────────────
[삭제]                                      [취소] [저장]
```

모형의 값은 구성 예시이며 기존 값을 덮어쓰는 지시가 아니다. 신규 등록 시 이메일에는 `로그인 계정을 발급할 때 필요합니다` 안내를 제공한다. 고용형태 미입력과 프로필 없음은 `—`로 표시한다. 기존 정성경의 고용형태와 계정 정보는 그대로 표시한다.

### 2.3 New Teacher (신규 등록)

```text
교사 등록                                         [닫기]
[기본 정보]  이름 * / 영문명 / 이메일 / 전화번호 / 카카오톡 ID
             성별 / 거주지역 / 생년월일
             재직상태 [재직 ▾]  고용형태 [미입력 ▾]
             입사일자 / 출결번호 / [✓] 강사 여부
[학력·경력]  학력 / 경력
[과목·프로필] 담당 과목 / 담당 과목 상세 / 상세 프로필 / 메모
[첨부파일]   [파일 선택] 선택한 파일명
[포털 계정]  [ ] 로그인 계정 발급
             선택 시 기존 이메일·비밀번호 입력 요건 표시
────────────────────────────────────────────────────────
                                       [취소] [등록]
```

신규 화면은 상세와 동일한 필드 배치를 사용하며 삭제 버튼은 없다. 이름 외 원본에 없는 인적 사항은 미입력으로 둔다. 이번 일괄 등록에서는 로그인 계정을 발급하지 않는다.

최한나     신규 후보    정상 필드            과목 값 검토

## 3. Implementation Steps (구현 순서)

### Phase 1. Schema and API (스키마·API)

- `amb_acm_tch_teacher`에 요구사항의 nullable 필드를 추가한다. 기존 레코드는 NULL로 유지한다. PG `ACM_DS`, 테넌트 `ent_id`, 기존 감사 체계를 따른다.
- 교사 연락 이메일과 고용형태의 NULL을 지원한다. 기존 고용형태 데이터는 바꾸지 않는다. 신규 저장 시 명시되지 않은 고용형태를 FULL_TIME으로 자동 대입하지 않는다.
- DTO·엔티티·create/update/toDetail 및 프론트 타입을 함께 수정한다. PATCH 미전달은 유지, 명시 NULL은 허용 필드 지우기로 구분한다. 연락 이메일 변경으로 연결 로그인 계정을 변경하지 않는다.
- `email.trim()`과 고용형태 enum을 가정하는 교사 생성·중복 검사·계정·AMA 연동 및 소비 코드를 검색하고 NULL 안전성을 보장한다. 계정 발급 필수 검증은 유지한다.
- 신규 텍스트 필드는 서버/클라이언트 동일 길이 제한(학력·과목 상세·경력 4,000자, 프로필 20,000자 제안)을 적용한다. 초과 원문은 자르지 않고 보류한다. 기존 텍스트 렌더링으로 XSS를 방지한다.

### Phase 2. Detail Screen (상세화면)

- `frontend-acm/src/modules/tch/components/tch-form-modal.tsx`를 위 구성으로 확장한다. 필요하면 섹션별 컴포넌트로 분리한다.
- `types.ts`, 교사 hooks, 목록의 NULL 표시와 4개 언어 번역을 갱신한다.
- 기존 첨부파일·계정 패널을 재사용한다. 프로필 저장이 계정/파일 API를 호출하지 않는지 확인한다.

### Phase 3. Import Preparation (반영 준비)

- 파일 해시 및 정확한 두 시트 이름을 확인한다. A3:H23의 이름 행과 현 프로필의 병합 셀 좌상단을 파싱한다. No. 중복과 서식 잔여 셀은 제외한다.
- 연락 수단을 전화번호와 카카오톡 ID로 분리한다. 전화번호의 방향 제어문자·불필요한 줄바꿈을 제거하되 앞자리 0과 국제번호를 보존한다.
- 사용자 제공 기본 명단과 프로필 표를 최신 입력으로 사용하고 엑셀을 대조한다. 프로필 별도 열의 전공도 학력에 중복 없이 반영한다. `<br>`는 줄바꿈으로 변환하며 HTML을 렌더링하지 않는다.
- 원본 이름 21개, 프로필 12개 부분집합을 검증한다. 현재 프로필이 없는 9명도 명단 기준으로 유지한다.
- 동일 테넌트의 전체 상태 및 삭제 기록과 대조하고 기존 ID를 확정한다. 정성경은 신규 생성 금지 조건을 별도로 둔다. 이름 외 정보가 충돌하면 보류한다.
- 필드별 추가/유지/충돌과 원본 셀을 가진 dry-run을 만든다. 조혜수 학력·최한나 과목 등 오류 필드는 제외하고 나머지 정상 정보는 반영 가능하게 한다.
- 원본 자료와 실행 상세는 Git에 올리지 않는다. 저장소에는 스크립트·비식별 테스트 fixture·집계 보고서만 남긴다.

### Phase 4. Deploy and Apply (배포 및 데이터 반영)

- 승인된 범위의 코드 검사와 배포 절차를 완료한 뒤 운영 필드 조회·저장을 확인한다.
- 운영 반영 전 서버 측 백업을 생성하고 dry-run 이후 변경 여부를 재확인한다. tenant/teacher ID와 기존 값 조건으로 대상 행을 잠그고 트랜잭션으로 반영한다.
- 신규 20명·보완 1명은 예상치이며 대조가 달라지면 사유를 보고한다. 기존 교사의 비어 있지 않은 값은 덮어쓰지 않는다. 계정 발급·알림 전송은 실행하지 않는다.
- 반영 후 필드별 비교, 관계·계정·첨부파일 불변, 비대상/다른 테넌트 변경 0건 및 동일 파일 재실행 0건 추가를 검증한다.
- 실패 시 트랜잭션을 롤백한다. 커밋 이후 복구는 이번 변경 집합만 대상으로 하며 실행 후 사용자 수정/신규 연결이 있으면 자동 복구하지 않는다. 이전 앱 버전으로 되돌릴 때 NULL 이메일·고용형태 호환성을 먼저 확인한다.

## 4. Validation (검증)

| 검증 | 기대 결과 |
| --- | --- |
| 이메일 없는 생성/수정 | 교사 저장 성공, 계정 동시 발급은 이메일 누락 오류 |
| 정성경 보완 | ID·기존 값·계정 연결·관계·첨부 유지, 새 정보만 추가 |
| 연락 수단 | 전화번호 18명·카카오톡 ID만 1명·미입력 2명 구분, 제어문자 정리 후 숫자 보존 |
| 프로필 입력 | 12명 본문·줄바꿈 및 별도 전공 보존, 나머지 9명 소개문 자동 생성 없음 |
| 원본 파서 | 21명/프로필 12명, 병합 셀 중복 없음, 다른 시트 제외 |
| 충돌 및 재실행 | 동명이인/삭제 후보 보류, 오류 필드 보류, 재실행 중복 0 |
| API 권한 | 기존 관리자 권한 유지, 타 테넌트 조회·수정 불가 |
| UI | 긴 프로필 줄바꿈, 모바일 스크롤, 입력 오류 위치, 기존 파일/계정 기능 유지 |
| 회귀 | 기존 교사 중복 검사·AMA upsert 테스트 및 수정 범위 타입 검사·빌드 통과 |

## 5. Deliverables and Approval (산출물과 승인)

사용자가 계획을 승인했으며 스키마·API·화면·반영 스크립트를 구현하고 운영 반영 결과 및 보류 필드를 보고서에 기록한다. 현재 운영 교사 데이터는 변경하지 않았다.
