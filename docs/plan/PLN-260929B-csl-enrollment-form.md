# Enrollment Counseling Plan (등록 상담 수정 계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-260929B-csl-enrollment-form.md)에 따라 신규/기존 상담의 공용 4단계 폼을 수정한다. 기존 대시보드 구현은 보존한다. 사용자 “진행” 승인으로 구현 완료했다.

## 2. Screen Layout (화면 구성안)

```text
4. 등록 상담
상담 메모       [                                      ]
강좌 코스       [강좌 검색                             ]
                [✓ 강좌 A] [✓ 강좌 B] [□ 강좌 C]
선택한 강좌     [강좌 A ×] [강좌 B ×]
기타 강좌       [                                      ]
시작일          [YYYY-MM-DD]
상담 완료       [선택]
납부 안내 발송  [선택]
수업 시간       [60분] [90분] [120분] [직접 입력]
수강료          [1,500,000] 원
                선택 강좌 전체 수강료
                                      [저장] [기존 다음 단계 버튼]
```

수강회수·수강 신청·종료일 입력은 제거한다. 기존 다음 단계 전환/납부 승인 권한은 유지한다. 강좌별 추가 카드나 종료일 미정 체크박스를 새로 만들지 않는다. 모바일에서는 선택 강좌 태그를 줄바꿈한다.

## 3. Implementation Steps (구현 단계)

1. **DB/API**: 테넌트별 강좌 연결 테이블과 복합 FK/unique index 추가. 기존 단일 강좌를 멱등 이관한다. DTO에 UUID 배열·중복 검사·테넌트 검증을 추가하고 저장 트랜잭션에서 선택 목록을 교체한다. 기존 단일 필드 호환 처리와 `[]` 해제 의미를 명시한다.
2. **폼**: `enrollment-panel.tsx`의 단일 select를 검색 가능한 체크 목록과 선택 태그로 변경한다. 초기값/reset/저장 payload를 `courseIds` 기준으로 바꾼다. 제거 항목의 폼 상태·입력·직렬화를 정리한다.
3. **금액**: `type=text`, `inputMode=numeric` 기반 포맷 입력을 사용한다. 숫자 원본을 유지하면서 세 자리 쉼표를 표시하고, 입력 위치가 튀지 않도록 커서 기준을 보정한다. 0 및 빈 값과 최대값을 검증한다. 기존 숫자 API 계약을 유지한다.
4. **연동**: 상담 상세 재조회, 기존 상담 수정, 학생 등록/퇴원 흐름, 상담 상태 전환을 확인한다. 삭제 입력 항목이 기존 값이나 Apply 통계를 자동으로 바꾸지 않도록 검증한다.
5. **문서/배포 준비**: 이관 전후 선택 강좌 건수 대사, 빌드·관련 테스트, 구현 보고서 작성. 운영 배포는 별도 진행한다.

## 4. Validation (검증)

- 기존 단일 강좌 로딩, 2개 이상 선택·저장·재조회, 중복 방지, 개별 해제, 전체 해제, 기존 비활성 강좌 보존, 타 테넌트 강좌 차단.
- 수강회수/신청/종료일 미노출 및 payload 누락. 다른 필드 저장 시 기존 3개 값이 변경되지 않는지 확인.
- 금액 `0`, `999`, `1000`, `1500000`, `50000000`, 범위 초과, 빈칸, `1,500,000` 붙여넣기, 전체 삭제, 중간 삽입·선택 영역 교체, 유효하지 않은 문자 입력 검증.
- 저장 요청의 금액은 숫자이며 쉼표 미포함. 여러 강좌 선택으로 총 수강료가 임의 곱셈/분배되지 않음.
- 기존 학생 퇴원 처리, 등록 상담 완료 후 단계 이동, 납부 승인 권한과 대시보드 기존 이력 회귀 확인.

## 5. Review Note (확인 사항)

‘수강 신청’ 제거와 연결된 대시보드 Apply의 향후 정의는 별도 결정 대상이다. 이번 구현에서는 새 신청 여부를 자동 생성하지 않고 기존 자료를 보존하는 방안이다.
