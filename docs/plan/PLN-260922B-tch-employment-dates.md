# Teacher Employment Dates Plan (교사 입사일·퇴사일 작업계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-260922B-tch-employment-dates.md)에 따라 교사 목록의 기존 입사일 열을 앞쪽으로 이동하고, 교사 정보 수정 화면에 퇴사일을 추가한다. 기존 `tch_ended_at` 컬럼과 재직 기간 집계 구조를 활용한다. 2026-09-22 사용자의 “구현” 승인에 따라 별도 작업트리에서 구현과 로컬 검증을 완료했다. 운영 배포와 운영 데이터 수정은 수행하지 않았다.

## 2. Screen Layout (화면 구성안)

### 2.1 Teacher List (교사 목록)

```text
교사 관리                                      [교사 등록]
[이름·이메일 검색                        ] [재직상태 ▾]
┌──────────┬────────────┬──────────┬──────────┬───────────┐
│ 이름     │ 입사일     │ 강사여부 │ 고용형태 │ 기존 열…  │
├──────────┼────────────┼──────────┼──────────┼───────────┤
│ 교사 A   │ 2026-09-01 │ 강사     │ 정규     │ …         │
│ 교사 B   │            │ 강사     │ 시간제   │ …         │
└──────────┴────────────┴──────────┴──────────┴───────────┘
행 선택 → 교사 정보 수정
```

기존 이름 고정 열, 검색·필터·페이지 이동은 유지한다. 모바일에서도 이름 바로 다음에 입사일이 보이도록 배치하고, 나머지 열은 표 내부에서 가로 스크롤한다. 페이지 회색 배경과 흰색 표·입력 영역을 유지한다.

### 2.2 Teacher Edit (교사 정보 수정)

```text
교사 정보 수정 · 교사 A                         [닫기]
┌ 기본 정보 ──────────────────────────────────────────┐
│ 이름       [기존 값          ]                       │
│ 고용형태   [기존 값 ▾        ] 재직상태 [기존 값 ▾]  │
│ 입사일     [2026-09-01    📅] 퇴사일   [          📅] │
│                                  입력하세요         │
│ 기존 연락처·학력·프로필 항목 …                       │
└─────────────────────────────────────────────────────┘
                                    [취소] [저장]
┌ 재직 기간 ──────────────────────────────────────────┐
│ 기존 기간 이력 및 개별 편집 기능                    │
└─────────────────────────────────────────────────────┘
```

날짜는 데스크톱에서 2열, 모바일에서는 세로 배치한다. 빈 날짜 안내는 회색 이탤릭이며 값으로 저장하지 않는다. 네이티브 date 입력의 placeholder 지원이 제한되면 빈 입력 옆 보조 문구로 표현한다. 제목은 기존 기본 정보 박스의 강조 스타일을 따른다.

## 3. Implementation Steps (구현 순서)

1. 최신 배포 기준 별도 작업트리에서 시작한다. 현재 사용자 작업트리의 다른 변경사항은 보존한다.
2. 교사 TypeORM 엔티티에 기존 `tch_ended_at` → `endedAt`을 매핑하고 DTO의 `tchEndedAt`, 응답 및 프론트 타입을 연결한다. 입사·퇴사 날짜의 미전송/null 의미를 일치시킨다.
3. 서버에서 날짜 형식과 실제 날짜, 합쳐진 최종 날짜 쌍을 검증한다. 날짜 변경 요청에 검증을 적용하고 기존 정보만 수정하는 요청은 허용한다.
4. 재직 이력과 대표 날짜 변경을 같은 트랜잭션에서 처리한다. 현재 트리거는 기존 입사일과 일치하는 기간 한 건을 갱신하므로 이를 재사용하되, 해당 기간 revision·겹침 검증과 감사 기록을 확인한다. 중복 쓰기로 revision이 두 번 증가하지 않도록 한다.
5. 기간 편집기가 대표 기간을 수정할 때는 이전 대표 날짜와 일치하는 기간인지 확인하고 교사 대표 날짜도 원자적으로 갱신한다. 다른 기간 추가·취소·수정 시 최신 기간을 자동 대표로 승격하지 않는다. 매칭 불가·동시 수정은 명확한 충돌 메시지를 반환한다.
6. 이력이 없는 교사는 날짜 지우기를 허용한다. 명시적 이력이 있는 교사의 입사일 제거는 기간 시작일 필수 규칙과 충돌하므로 기간 편집에서 취소하도록 안내한다. 퇴사일 지우기는 기간 재개에 따른 겹침 검증 후 허용한다.
7. 목록 입사일 열을 이동하고 수정 모달에 퇴사일을 추가한다. 저장 성공 시 교사 목록·상세·재직 기간·대시보드 쿼리를 갱신한다. 네 개 언어의 라벨·오류 안내를 추가한다.
8. 검증 결과를 보고서에 기록하고 배포 시 스키마 선행 적용 여부를 확인한다. 기존 날짜를 일괄 보정하는 데이터 작업은 포함하지 않는다.

## 4. Side Effects (영향 및 대응)

| 영향 | 대응 |
| --- | --- |
| 교사 퇴사 집계 변경 | 퇴사일 기준 계산 통계만 갱신. 기존 수기값 보존 |
| 재입사 이력 손실 | 매칭된 기간 한 건만 변경, 다른 기간 유지 |
| 기간 편집 후 목록 값 불일치 | 대표 기간과 원장 날짜의 양방향 갱신을 같은 트랜잭션으로 보장 |
| 트리거 실패·겹치는 기간 | 서비스 검증 및 충돌 안내, 전체 롤백 |
| 이전 화면의 오래된 날짜 덮어쓰기 | 날짜 변경분만 전송하고 기간 revision 비교 |
| 계정 상태 변화 | 날짜 저장으로 상태·권한·AMA 동기화 동작을 추가하지 않음 |
| 학생 통계 회귀 | 공통 기간 서비스 수정 시 STUDENT 경로도 회귀 검증 |

## 5. Verification (검증)

- 백엔드: 퇴사일 저장·조회·null 지우기, 날짜 역전·불가능한 날짜 거절, 미전송 값 보존, 기존 정보 수정 허용.
- PostgreSQL 통합: 대표 기간 갱신과 감사 기록, 다른 재입사 기간 보존, 기간 편집 후 원장 일치, revision 충돌·겹침·실패 롤백·테넌트 격리.
- 화면: 목록 입사일 위치, 데스크톱·모바일 입력 배치, 저장·재열기·지우기, 오류 문구, 검색·필터 유지.
- 대시보드: 변경 일자의 교사 신규·퇴사·누적 계산과 수기값 병기 유지, 학생 통계 회귀 확인.
- 빌드 및 관련 테스트 통과 후 결과를 기록한다. 배포 후 운영 데이터는 읽기 검증하고 테스트 목적으로 실제 교사 날짜를 변경하지 않는다.
