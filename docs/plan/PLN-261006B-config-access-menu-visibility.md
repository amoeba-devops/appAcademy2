# Configuration Access Plan (설정 권한 구현 계획)

## 1. UI Layout (화면 구성안)

```text
설정                                 설정 관리자 (CONFIG_ADMIN)
소속 학원: 현재 로그인 계정의 학원

좌측 메뉴 노출 설정
메뉴                  노출
대시보드              항상 노출 (고정)
상담관리              [켜짐]
학생관리              [켜짐]
수업일정              [켜짐]
수업통계              [켜짐]
고객불만              [켜짐]
수납관리              [켜짐]
… 기존 전체 메뉴 …
설정                  권한 보유자만 노출 (고정)

이 설정은 해당 학원의 사용자에게 공통으로 적용됩니다.
                                   [변경 취소] [저장]

[광고 플랫폼] [AI] [AMA] [화상강의]
```

권한이 없는 사용자에게는 좌측 설정 메뉴를 표시하지 않고, 직접 주소 진입 시 접근 권한 없음 화면을 제공한다. 작은 화면은 메뉴명/토글 2열로 유지한다.

## 2. Implementation (구현 절차)

1. 최신 main 독립 브랜치에서 설정 경로/API 소비처와 로그인·SSO 경로를 전수 확인한다.
2. PG 기준 추가 권한 저장소(예: `amb_acm_user_permission`, ent_id/user FK/permission unique/생성·수정·부여자)를 만든다. 사용자 기본 role은 유지한다.
3. 인증 사용자 응답에 최신 권한을 포함하고 CONFIG_ADMIN guard를 추가한다. JWT에 담긴 오래된 값만으로 관리 API 접근을 결정하지 않는다. SSO 갱신 시 추가 권한은 유지한다.
4. 관리 API별 기존 ADMIN 검사와 CONFIG_ADMIN의 결합/대체를 명시하여 대상 계정이 모든 설정 카드에서 정상 동작하도록 한다. 일반 소비용 API 접근은 보존한다.
5. 자기 테넌트 전용 메뉴 설정 GET/PUT을 추가한다. entId를 사용자 입력에서 받지 않는다. 기존 시스템 관리자 메뉴 API와 같은 데이터를 재사용한다.
6. 기존 메뉴 순서/숨김 데이터를 보존하며 노출값만 갱신한다. 대시보드/권한 보유자의 설정 진입점 고정 정책을 서버와 화면에서 일치시킨다.
7. `/admin/config` 메뉴 노출 UI, 라우트 보호, AppShell 표시 조건 및 한국어/영어/베트남어/중국어 문구를 반영한다. 캐시를 user/tenant 단위로 분리한다.
8. 배포 적용 시 확인된 대상 계정 UUID·테넌트·이메일·활성 상태를 모두 재검증하고 CONFIG_ADMIN을 멱등 부여한다. 계정 0개/복수/불일치면 잘못된 계정에 적용하지 않고 중단한다. 기존 ADMIN 역할은 변경하지 않는다.
9. 테스트 후 보고서 작성. 권한 철회·코드 롤백 절차와 적용 전후 조회를 기록한다.

## 3. Validation (검증)

- 전용 권한 없음: 메뉴 비노출, 하위 URL 접근 거부, 관리 API 403.
- 권한 있음: 설정 조회/저장, 메뉴 표시·숨김, 저장 후 좌측 메뉴 반영.
- 다른 테넌트 수정 거부, 미인증 401, 잘못된 메뉴키 거부.
- CONFIG_ADMIN 보유/미보유 ADMIN 및 APP_ADMIN 정책 확인. 기존 일반 업무 기능과 공용 설정 조회 회귀 검증.
- AMA 재로그인 후 권한 유지, 철회 후 기존 세션 관리 API 차단.
- 기존 메뉴 순서 유지, 대상 계정 외 권한 미부여, 서버 오류 시 미저장 값/오류 표시.
- FE/BE 빌드, 관련 단위/통합 테스트, 실제 권한별 브라우저 확인.

## 4. Approval and Application (확인 및 적용)

AGENTS.md §9.2: “요구사항 분석서 + 작업 계획서 작성 후 반드시 사용자 확인을 받은 후 구현으로 진행한다.”
사용자의 “구현” 승인 후 코드와 검증을 완료했다. 운영 권한 부여는 관련 코드/마이그레이션이 준비된 배포 단계에서 실행한다. 기존 다른 기능의 배포 승인은 이번 새 기능의 배포 승인으로 간주하지 않는다.


구현 메모: 최신 권한은 `/acm/me/config-access`에서 조회하며 관리 API는 매 요청 DB 권한을 검사한다. 기존 로그인/JWT/AMA 기본 역할은 변경하지 않는다. 운영 권한 부여 스크립트는 준비됐으며 아직 실행하지 않았다.
