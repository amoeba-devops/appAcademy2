# Admission Dates and GA4 Plan (입학일 및 GA4 작업계획)

## 1. Scope and Approval (범위와 승인)

[요구사항](../analysis/REQ-260922C-std-admission-ga4.md)에 대한 계획이다. AGENTS.md §9.2에 따라 화면 구성안을 포함한 계획 확인 후 구현한다. 현재는 소스와 운영 읽기 조사만 수행했으며 데이터 수정·코드 배포는 하지 않았다.

이전 교사 입사일·퇴사일 기능은 별도 브랜치에 구현되었으나 미배포 상태다. 이번 작업은 최신 운영 기준에서 별도 변경으로 관리하고 병합 시 공통 Operating 코드 충돌을 검증한다.

## 2. Screen Layout (화면 구성안)

```text

[검색                       ] [기존 필터]
이름    | 입학일     | 사이트 | 학교·학년 | 담당강사 | 상태 | 수업시작일 | …

퇴원 목록
```

목록은 기존 회색 페이지·흰색 표를 유지한다. 이름 가까이에 입학일을 넣고 모바일은 표 내부 스크롤을 사용한다. 수업시작일을 입학일로 이름만 바꾸지 않는다. 학생수 기준 문구는 확인 결과에 맞춰 확정한다. GA 동기화 성공 시각과 데이터 마지막 날짜를 구별하여 오래된 데이터가 최신처럼 보이지 않게 한다.

## 3. Implementation (구현 순서)

1. 공통 학생 표에 입학일 열 추가. 재원·퇴원·사이트 필터별 동일한 API 필드를 사용한다. 정렬을 제공할 경우 프론트 정렬 타입과 서버 allowlist를 함께 확장한다.
2. 보완 전 대상 ID·기존 날짜·updated_at을 접근 제한 백업에 저장한다. 대상 테넌트를 명시한 트랜잭션으로 NULL 입학일만 채우고 적용 건수와 반환 ID를 검증한다. 스크립트는 반복 실행 시 이미 채운 값을 바꾸지 않게 한다. 재실행 시 조회 이후 변경된 값은 건너뛴다.
3. 신규학생용 입학일 이벤트를 기존 수업 기간 이벤트와 분리한다. 현재 상태가 퇴원이어도 과거 입학일은 과거 신규학생 집계에 포함한다. 기간 조회 시작 전 누적이 필요한 경우 전체 과거 기록에서 계산한다.
4. 학생수 기준에 대한 답변 반영. 입학일 누적으로 함께 바꾸는 경우 재입사·복수 퇴원 처리 규칙과 음수/중복 검사를 먼저 확정한다. 임의로 기존 90개 수업 기간을 87명 입학 원장과 동일한 모집단으로 취급하지 않는다.
5. GA 배치와 API의 UTC 날짜 도우미를 공통 KST 업무일 함수로 교체한다. 월말·연말·윤년·00시·04시·08시·09시 경계에서도 전일이 동일하도록 테스트한다. 사용자가 미래 종료일을 보내면 KST 전일까지 제한한다.
6. 배포 후 2026-09-19부터 KST 전일까지 재수집하여 지연 보정 구간과 9월 21일을 복구한다. GA 응답의 날짜/사이트 합계, site_visit 저장 행, daily_kpi, 프론트 표시를 대조한다. 원본에 데이터가 없으면 조회 성공과 미제공 상태를 기록하고 0으로 추정하지 않는다.
7. 운영 집계·마케팅·수동 입력 보존 회귀 테스트 후 보고서를 작성한다.

## 4. Side Effects and Rollback (영향과 복구)

| 영향 | 대응 |
| --- | --- |
| 기존 통계와 입학일 통계 차이 | 변경 전후 일자·사이트별 차이를 기록; 임의로 기존 합계에 맞추지 않음 |
| 재입사 이력 중복 | 신규학생은 학생 ID 단위; 수업 기간 이력은 원형 보존 |
| 빈 입학일이 남은 퇴원생 | 이번 자동 보완 대상에서 제외; 누락 수를 품질 정보로 제공 |
| 다른 테넌트 수정 | ent_id 고정 및 동일 테넌트 조건 재확인 |
| 보완 후 사용자 직접 수정 | 롤백은 백업 원본과 이번 입력값이 일치하는 대상만 조건부 복원 |
| GA 재계산으로 수기값 손실 | 수기 방문자·비용·운영값을 전후 대조하고 기존 우선순위 유지 |
| 공유 날짜 함수로 다른 집계 변경 | GA 관련 경로에 먼저 제한하고 기존 대시보드 날짜 처리 회귀 검증 |

GA 재수집 전 해당 날짜의 저장 값과 KPI를 백업한다. 코드 롤백과 보완 데이터 복원은 별도로 수행하며 이후 사용자 변경을 덮어쓰지 않는다.

## 5. Validation (검증)

- 목록 두 경로 및 3사이트·모바일 입학일 표시.
- 재원 NULL만 업데이트, 기존 입학일 보존, 다른 테넌트/퇴원생 제외, 재실행 멱등.
- 입학일과 수업시작일이 다른 학생, 입학일 누락, 재입사, 입학·퇴원 같은 날, 기간 시작 전 입학, ALL=사이트 합, 수기 0 및 괄호 표시.
- GA 2026-09-22 04:00 KST의 배치 범위는 09-19~09-21. 같은 시각 수동 API도 09-21까지 허용.
- 실제 GA 응답과 저장·표시 대조, 실패 시 오류 상태, 성공/미수집 구분 및 수기값 보존.
- 백엔드·프론트 빌드와 관련 단위/통합 테스트, staging 검증 후 배포.

## 6. Teacher Screen Addition (교사 화면 추가)

```text
교사관리
이름   | 입사일자   | 퇴사일자   | 강사여부 | 고용형태 | 기존 열…
교사 A | 2025-03-01 |            | 강사     | 정규     | …
교사 B | 2025-03-01 | 2026-08-31 | 강사     | 시간제   | …

교사 정보 수정 · 기본 정보
입사일자 [2025-03-01 📅]   퇴사일자 [           📅]
                                  입력하세요
                                    [취소] [저장]
```

- 앞서 구현한 교사 날짜 브랜치를 통합하고 목록의 이름 다음에 입사일자·퇴사일자 열을 배치한다. 기존 입사일 열은 이동하며 중복하지 않는다.
- 수정 모달의 기존 퇴사일 입력을 사용하고 목록·입력 라벨을 `입사일자`, `퇴사일자`로 통일한다. 신규 등록 모달과 공통 컴포넌트도 일치시킨다.
- `hiredAt`, `endedAt` 응답을 사용하며 미입력 날짜는 빈칸으로 표시한다. 날짜를 추정하거나 퇴사일만으로 재직 상태·계정 권한을 바꾸지 않는다.
- 모바일은 표 내부 가로 스크롤, 수정 날짜 입력은 세로 배치를 유지한다.
- 검증: 재직/퇴사 교사의 날짜 표시, 날짜 없는 행, 저장 후 목록 갱신, 퇴사일 삭제 후 빈칸, 재직 이력 및 대시보드 연동을 확인한다.
- 교사 기존 구현과 이번 추가분 모두 운영 배포 전 단계다. 이 추가 요구만으로 학생수 산식의 미결 사항을 확정하지 않는다.

## Execution Update (진행 현황)

2026-09-22 “작업 진행” 승인으로 구현했다. 학생수 산식의 별도 답변은 아직 없으므로 요청된 신규학생만 입학일로 변경하고 학생수는 수업기간 기준을 유지한다. 화면에 두 기준을 구분했다. 교사 날짜 기존 구현 및 추가 목록 퇴사일을 함께 반영한다. 재원생 49명 입학일 보완 완료(TPI 32·TA 3·SC 14), 기존 입학일 1명 유지. 운영 코드 배포 및 GA 재수집은 진행 중이다.
