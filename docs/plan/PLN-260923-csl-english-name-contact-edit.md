## 3. Implementation (구현 순서)
1. nullable 영문명 암호화 필드·DTO·응답 계약을 추가하고 독립 Update DTO 또는 동등한 검증으로 부분 수정/삭제 의미를 명확히 한다.
2. 상담/맵테스트 접수의 영문명 저장·조회·수정 경로를 통합한다. 기존 MAP 영문명 이관 스크립트에 dry-run, 충돌 집계, 재실행 안전성을 포함한다. 길이 제한은 기존 MAP 계약과 통일한다.
3. 신규 상담 MAP 입력과 접수정보 영문명 출력을 구현한다. 구분을 전환해도 입력된 영문명을 자동 삭제하지 않는다.
4. 기본정보 폼을 요청한 항목으로 확장한다. 서버 원본 값으로 초기화하고 변경된 항목만 전송한다. 미입력 삭제와 요청 생략을 분리한다. 전화 제공 상태·학교 FK를 함께 처리한다.
5. 예상 updatedAt 검증과 상담/MAP 트랜잭션·관련 캐시 갱신을 적용한다. 한쪽 저장 실패 시 전체 롤백한다.
6. 단위 및 PostgreSQL 통합 검증, 프론트/백 빌드, 스테이징에서 등록→표시→수정→새로고침 확인. 운영 데이터 원본은 QA 목적으로 변경하지 않는다.
7. 스키마 확장→호환 앱 배포→dry-run 결과 확인 후 영문명 이관→운영 조회 확인 순서로 반영한다. 실패 시 원본 MAP 영문명은 유지하고 nullable 컬럼은 남겨 구버전 앱 롤백을 지원한다.

## 4. Verification (검증)
- MAP 신규 입력/생략, 하이픈·공백 영문명, 기존 영문명 미손실, 튜터링에서 수정 후 MAP 부속 행 미생성.
- 보호자·이메일·전화 암호화 저장, 미변경 보존·명시 삭제, 형식 오류 및 빈 학교.
- 학교 선택→직접입력→삭제, 구분 전환 시 영문명/시험 결과 보존.
- 기존 MAP 상세 수정과 상담 상세 수정의 일치, 외부 접수·이관 경로, 동시 수정 409 및 실패 롤백, 다른 테넌트 차단.
- 일정 초기화/레벨테스트 결과/대시보드 및 연결 학생 원장 비영향.
