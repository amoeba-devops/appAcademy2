# Teacher Class Information Plan (강사별 수업정보 작업계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-260920C-std-teacher-class-info.md)에 따라 학생 상세 및 등록/수정 폼, 학생 API와 저장 구조를 개선한다. 계획 승인 후 구현·검증·배포한다.

## 2. Screen Layout (화면구성도)

### 2.1 Detail (상세)

```text
학생 상세                                           [목록으로] [수정]
페이지 배경: 옅은 회색(bg-canvas)

┌ 기본 인적사항 ─────────────────────────────────────────────┐
│ 박스 내부 흰색                 이름 : 학생 A   소속 : TPI │
└───────────────────────────────────────────────────────────┘
┌ MAP 점수 ─────────────────────────────────────────────────┐
│ Reading : 입력필요   Math : 입력필요   Language : 입력필요 │
└───────────────────────────────────────────────────────────┘

수업 정보 (담당강사 2명)
┌ 강사 A · 수업정보 ─────────────────────────────────────────┐
│ 담당강사 : 강사 A       과목 : 영어                         │
│ 교재 : ISEE                                                │
│ 추가교재 : 입력된 추가교재                                  │
│ 이동수단 : 입력필요     GPA : 입력필요                      │
│ SSAT/ISEE : 입력필요                                        │
└───────────────────────────────────────────────────────────┘
┌ 강사 B · 수업정보 ─────────────────────────────────────────┐
│ 담당강사 : 강사 B       과목 : 수학                         │
│ 교재 : 별도 수학 교재                                      │
│ 추가교재 : 입력필요                                        │
│ 이동수단 : 입력필요     GPA : 입력필요                      │
│ SSAT/ISEE : 입력필요                                        │
└───────────────────────────────────────────────────────────┘
┌ 기존 수업정보 · 강사 연결 필요 (해당하는 경우만 표시) ──────┐
│ 기존 공통 정보 표시              [강사별 정보에 배정]       │
└───────────────────────────────────────────────────────────┘
┌ 메모 / 상태 ──────────────────────────────────────────────┐
│ 학생 공통 목표·특이사항 등                                 │
└───────────────────────────────────────────────────────────┘
[포털 계정: 흰색 박스]          [학부모 정보: 흰색 박스]
```

- 실제 지정 학생처럼 담당강사가 1명이면 수업 카드도 1개만 표시한다. 목업의 두 강사와 값은 구조 설명용 예시다.
- 모든 카드 `bg-surface`(현재 흰색 토큰), 페이지 `bg-canvas`, 기존 테두리와 모서리 유지. 다른 관리자 페이지의 배경은 변경하지 않는다.
- 박스 제목 13px/Bold, 항목명 12px, 값 14px 유지. 카드 간 간격 16px, 내부 여백 16px.
- 강사 카드는 세로로 배치한다. 내부는 넓은 화면 2~3열, 모바일 1열. 긴 교재·메모는 줄바꿈하며 모바일에서 가로 넘침을 만들지 않는다.
- 목업의 `입력필요`는 실제 데이터가 아닌 **회색 이탤릭 안내**다. 조회 화면의 비어 있는 값 위치에만 표시한다.
- 입력창은 값이 비어 있을 때 `입력하세요`를 native placeholder로 표시한다. `placeholder:italic`과 회색 텍스트 토큰을 적용하며, 입력된 실제 값은 일반 글꼴·본문 색상을 유지한다.
- 숫자 0과 boolean false는 미입력으로 취급하지 않는다. placeholder 문구를 폼 기본값·API payload·DB 값으로 저장하지 않는다.
- 날짜·선택형 컨트롤은 native 형식/미선택 안내를 유지한다. placeholder로 항목 label을 대체하지 않는다. 흰색 배경에서 회색 안내의 가독성을 검증한다.

### 2.2 Edit (등록·수정)

```text
수업 정보
담당강사 [강사 A ×] [강사 B ×] [강사 검색/추가]
최대 5명 · 첫 번째가 대표 강사

┌ 강사 A · 수업정보 (흰색) ──────────────────────────────────┐
│ 과목       [입력하세요        ]                           │
│ 교재       [입력하세요                                  ] │
│ 추가교재   [입력하세요                                  ] │
│ 이동수단   [                  ]  GPA [                  ] │
│ SSAT/ISEE  [                                            ] │
└───────────────────────────────────────────────────────────┘
┌ 강사 B · 수업정보 (흰색) ──────────────────────────────────┐
│ 동일한 입력 항목, 값은 강사 A와 독립적                     │
└───────────────────────────────────────────────────────────┘
                                              [취소] [저장]
```

입력 목업의 `입력하세요`는 빈 입력창에만 표시되는 회색 이탤릭 placeholder이다.

강사 해제는 “담당 연결은 해제하고 수업정보는 보관합니다” 안내를 제공한다. 저장 전 취소 시 서버 데이터는 바뀌지 않는다. 기존 정보 배정은 대상 강사를 선택하고 항목별 값을 검토한 뒤 저장하며, 이미 입력된 값을 자동 덮어쓰지 않는다. 강사 없는 상태에서는 연결 안내와 기존 공통 정보만 보여준다.

## 3. Storage and API (저장·API 설계)

- 별도 `amb_acm_std_teacher_class_info` 테이블에 `tci_id`, `ent_id`, `std_id`, `tch_id`, 검증된 과목·교재·추가교재·이동수단·GPA·SSAT/ISEE를 담은 `info` JSONB, 배정한 원본 스냅샷 `legacy_source`, 생성/수정 시각을 저장한다. 학생별 강사 프로필의 유니크 키는 `(ent_id, std_id, tch_id)`로 한다.
- 연결 테이블 `st_id`에 삭제 전파되는 FK를 두지 않는다. 담당 연결 해제 시에도 프로필을 보관하고, 현재 `student_teacher` 연결과 조인해 현재 카드만 조회한다. 재연결하면 보관된 프로필을 재사용한다.
- 학생/강사가 동일 테넌트인지 서버에서 확인한다. 테넌트 FK/유니크 구성은 기존 실제 DDL을 대조하여 적용한다.
- 학생 상세에 `teacherClassInfos` 배열을 추가한다. 기존 `teachers`/대표강사 미러 응답은 유지하여 목록·포털 접근 호환성을 지킨다.
- 등록/수정 DTO에 강사 ID와 정보 배열을 추가한다. 최종 담당강사 목록과 카드의 강사 ID가 정확히 일치해야 하며 중복·초과·타 테넌트 강사는 거절한다. 필드별 길이 제한은 현재 학생 필드와 정렬한다.
- `syncTeacherLinks`의 전체 삭제/재생성은 변경분 반영 방식으로 바꾸고, 학생 갱신·강사 연결·프로필 저장을 동일 트랜잭션에서 처리한다. 동일 학생 동시 저장은 행 잠금 또는 버전 검증으로 일관성을 보장한다.
- 기존 API 소비자가 새 배열을 생략하면 저장된 강사별 내용을 지우지 않는다. 기존 단일 수업 필드 입력은 실제 강사가 1명인 경우만 그 프로필에 반영하고, 여러 명이면 기존 공통 정보로 보존한다. 응답에서 임의 강사 값을 공통 값으로 합치지 않는다.
- API/엑셀 import/외부 접수 등 학생정보 쓰기 경로를 검색하여 동일 규칙을 적용한다. 엑셀 원본 기록은 별도 보존한다.

## 4. Migration (기존 데이터 이행)

1. 테넌트별 연결 강사 수 및 기존 수업정보 유무를 집계한다. 이름만 있는 레거시 강사는 자동 매칭하지 않는다.
2. 실제 연결 강사 1명: 학생의 기존 수업 값을 신규 프로필로 멱등 백필한다. 기존 프로필을 덮어쓰지 않는다.
3. 실제 연결 강사 복수: 강사별 빈 프로필을 준비하고 공통 값은 ‘강사 연결 필요’ 영역에 보존한다. 원본을 모든 강사에게 복제하지 않는다.
4. 강사 미연결: 기존 공통 값 보존, 강사 지정 후 운영자가 배정한다.
5. 연결 대기 정보의 배정 결과를 기록하여 재배포·재백필로 중복 반영되지 않게 한다. 기존 컬럼은 이번 배포에서 삭제하지 않는다.
6. 운영 적용 전 백업, 적용 전후 건수·단일 연결 값 일치·중복 없음 검증. 학생 상태와 소속은 변경하지 않는다.

## 5. Implementation (구현 순서)

1. 계획 승인 → 현재 DDL/사용 경로 재확인 → migration·entity·DTO·서비스 구현.
2. 강사별 읽기/쓰기와 기존 호출 호환, 트랜잭션 및 정보 보존 구현.
3. 공통 강사별 폼 컴포넌트, 상세 카드, 연결 대기 정보 배정 화면 구현.
4. 상세 `Section`, 원본정보 패널, 포털 계정·학부모 박스에 흰색 표면 적용. 기존 13px/Bold 유지, 미입력 조회 안내·입력 placeholder를 회색 이탤릭으로 적용.
5. ko/en/vi/zh-CN 번역, 테스트와 빌드, PR/CI.
6. 스테이징 migration·백필 검증 → 운영 백업·migration·배포 → 요청 학생과 복수강사 사례 검증 → 보고서 작성.

## 6. Verification and Rollback (검증·복구)

| 검증 | 기대 결과 |
| --- | --- |
| 강사 1명 / 2명 / 5명 | 선택 수와 현재 카드 수 일치, 독립 입력·저장·재조회 |
| 추가·순서 변경·해제·재연결 | 다른 강사 값 보존, 보관 프로필 복원 |
| 중복·타 테넌트·6명·불일치 배열 | 서버에서 거절, 부분 저장 없음 |
| 저장 실패/동시 수정 | 연결과 수업정보 일관성 유지 |
| 단일 강사 백필 | 기존 과목·교재 등 값 일치, 재실행 시 중복/덮어쓰기 없음 |
| 복수/미연결 백필 | 공통 정보 보존, 임의 연결/복제 없음 |
| 기존 API·엑셀·포털 | 기존 호출 동작 및 강사별 정보 보존, 담당학생 접근 유지 |
| 화면 | 모든 박스 흰색·페이지 회색, 제목 유지, 빈 값의 안내만 회색 이탤릭 표시 |
| 미입력 안내 | 조회 `입력필요`·입력 `입력하세요`, 실제 값 입력 시 안내 사라짐, 안내 문구 미저장, 0/false 보존 |
| 반응형 | 데스크톱/모바일 카드 구분, 긴 값 줄바꿈, 키보드 조작 |

앱 롤백 시 신규 테이블과 프로필은 삭제하지 않는다. 이전 앱은 학생 공통 값만 보여줄 수 있으므로 운영 편집을 잠시 제한하고 정합성을 점검한다. 새 프로필을 단일 공통 값으로 역병합하지 않는다. 기존 컬럼·백업을 보존하여 복구 가능하게 한다.
