# Active Student Draft Plan (재원생 일괄 등록 계획)

## 1. UI Layout (화면 구성안)

```text
수납관리  [청구 등록 / 월별 생성] [재원생 일괄 등록]
청구월 [2026-10]   금액 미입력 [N건]
학생        수납명       청구액       납기        상태
예시 학생   월 수업료   [금액 입력]  [날짜 선택]  금액 미입력
[선택 항목 일괄 입력] [확정 저장]

재원생 일괄 등록
청구월 [2026-10]  수납명 [월 수업료]
대상 N명 / 신규 N명 / 기존 청구·중복 제외 N명
금액과 납기는 미입력 상태로 등록됩니다.
[미리보기] [일괄 등록]

일반 청구 등록 — 학생 검색
상태 [재원▼]  학생 이름 [검색]
검색 결과 [추가] → 선택 목록 (한 명씩 추가)
```

## 2. Implementation (구현 순서)

1. 기존 운영 버전에서 격리 브랜치 생성. 청구액/납기 nullable과 DRAFT 상태 마이그레이션 설계. 기존 확정 청구는 변경하지 않는다.
2. 서버 조회·요약·엑셀의 null 처리, 준비 행 확정 및 납부 차단 규칙 구현. 학생 상태 필터를 options 조회에 적용.
3. 테넌트 재원생 전체 대상 일괄 미리보기/등록 API 구현. 기존 권한 기준 적용, 반복 실행·동시성·상태 변경 재검증 및 누락 없는 배치 처리.
4. 화면의 빈 금액 입력·미입력 건수·확정 저장·재원 기본 검색·일괄 등록과 4개 언어 반영.
5. 실제 PostgreSQL 및 HTTP로 null과 0 구별, 중복/동시 등록, 100명 초과, 다른 테넌트 차단, 기존 원장 회귀 검증. 브라우저 개별 검색·일괄 미리보기·확정 검증.
6. 사용자 배포 요청에 따라 스테이징→운영 배포. 최초 운영 등록은 확인된 대상 월과 대상 건수를 검증한 뒤 실행하고 등록/제외 결과를 보고한다.

## 3. Approval (확인)

AGENTS.md §9.2에 따라 위 요구사항·화면 구성 확인 후 구현한다. 초기 운영 등록안은 **2026년 10월, 전체 재원생, 월 수업료, 금액·납기 미입력**이다. 실제 대상 수는 실행 직전 조회로 확정하며 이 문서 작성 시 운영 데이터는 변경하지 않았다.

2026-10-02 사용자 “진행” 승인 후 구현 및 로컬 검증 완료. 사용자 “운영배포 재원생 등록 진행” 승인에 따라 운영 배포 및 2026-10 재원생 51명 등록 완료. 금액·납기 미입력 51건, 생성된 납부 내역 0건. 상세 증빙은 RPT-261002를 참조한다.
