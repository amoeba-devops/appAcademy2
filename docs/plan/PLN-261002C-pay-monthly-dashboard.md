# Monthly Payment View Plan (월별 수납 및 통계 구현 계획)

```text
수납관리                         [청구 등록] [재원생 일괄 등록]
[월별 보기] [기간 상세조회] [통계 대시보드]
[◀] [2026-10 ▼] [▶] [이번 달]
사이트 [전체 ▼]  대상 [해당 월 재원생 ▼]  학생 [검색]

[재원생] [청구 미등록] [금액 미입력] [미납 학생] [기간 확인 필요]
[순청구액] [누적 순수납액] [현재 미납액] [수납률]

```

```text
통계 대시보드                  같은 월·사이트 선택 유지
[월 청구 기준] 순청구 / 누적 순수납 / 현재 미납 / 수납률
```

모바일은 카드 줄바꿈과 표 내부 스크롤, 공통 우측 패널 가리기와 호환한다. 통계 카드 선택 시 해당 필터 목록으로 이동한다. 빈 데이터와 집계 실패를 구분하고 오류를 0으로 표시하지 않는다.

## 2. Implementation (구현 순서)

1. 기존 operating.service 재원 판정 로직 및 실제 기간 데이터 품질을 확인한다. 날짜 누락/휴원/복귀/사이트 변경의 판정 근거를 정리하고 공통 로직을 재사용한다. 확인되지 않은 과거 이력은 자동 보정하지 않는다.
2. 월·사이트·재원 범위 DTO와 학생 중심 조회 API를 추가한다. 월 재원 대상과 청구를 각각 집계 후 연결해 청구 미등록 학생도 제공한다. 기존 원장 조회·수정 API는 보존한다.
3. 월 통계/사이트 비교/최근 12개월 API를 추가한다. 청구월과 수납일 집계 경로를 분리하고 페이지와 무관한 전체 결과를 집계한다. 원장 금액과 인원 중복, 통화 혼합을 방지한다.
4. 월 선택과 상단 사이트 필터, 학생별 월 목록/복수 청구 상세, 통계 탭을 구현한다. URL에 월·사이트·탭을 보존한다. 다른 월로 이동할 때 미저장 편집 보호를 적용한다.
5. 기존 명시적 일괄 등록 동작에 선택 월·사이트가 정확히 전달되도록 확장하고 대상 미리보기를 제공한다. 단순 조회에서는 자동 생성하지 않는다. 기간 확인 필요 학생은 검토 대상으로 분리한다.
6. 월 경계 입퇴원, 재입원, 휴원, 사이트 이동, 날짜 누락, 복수 청구, DRAFT/0원, 퇴원생 미납, 납부·환불이 다른 달인 경우, 취소, 테넌트 격리 검증. 집계/목록/엑셀 일치와 DB 실행계획을 확인한다.
7. frontend/backend 빌드, PG 통합 및 브라우저 반응형 검증, 결과 보고서 작성. 배포는 별도 사용자 요청 시 진행한다.

## 3. Approval (확인할 제안)

월별 재원생은 ‘해당 월 하루 이상 재원’ 기준으로 제안한다. 날짜 불명은 확인 필요, 청구 없는 학생도 월 목록에 표시하되 조회로 생성하지 않는다. 이 기준 및 화면 구성 승인 후 구현한다.

AGENTS.md §9.2: “요구사항 분석서 + 작업 계획서 작성 후 반드시 사용자 확인을 받은 후 구현으로 진행한다.”


## Implementation Update (구현 반영)

2026-10-02 사용자 “구현” 승인 후 구현 완료. 첫 재원 경계는 기존 대시보드와 같은 입원일 기준이며, 복귀 이후 확정 기간 및 종료일 제외 규칙을 공통 함수로 사용한다. 입원일 누락·확정되지 않은 기간·종료일 없는 비재원·중복 기간은 확인 필요로 구분한다. 사이트 미지정 조회와 과거 월 재원생 청구 생성도 지원한다. 수납 원장은 현재 KRW 단일 통화 구조로 유지한다.

운영 읽기 전용 점검: 전체 학생 299명, 현재 재원 51명, 현재 재원생 입원일 누락 0명. 전체 입원일 누락 177명, 비재원 중 학생 마스터 종료일 누락 175명, 운영 재원 이력 91건 중 미확정 1건. 이 수치는 원천 필드 점검이며 해당 월 최종 재원/확인 필요 인원과 동일하지 않다. 원천 데이터 자동 보정은 수행하지 않았다.

검증과 제한은 [구현 보고서](../report/RPT-261002C-pay-monthly-dashboard.md)를 참조한다. 운영 배포 전.
