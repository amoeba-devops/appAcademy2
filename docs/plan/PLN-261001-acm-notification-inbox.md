# Notification Inbox Plan (알림함 구현 계획)

## 1. UI Mockup (화면 구성안)

```text
ACM                                      [🔔 5] [언어 선택 ▾]
                                         ┌──────────────────────────────────┐
                                         │ 알림 5       [모두 읽음]           │
                                         │ [전체] [안 읽음]                   │
                                         │ ● 신규 상담이 접수되었습니다       │
                                         │   상담 #123 · 방금 전              │
                                         │ ● 상담 상태가 변경되었습니다       │
                                         │   접수 → 상담 중 · 3분 전          │
                                         │ ● 수업일정이 변경되었습니다         │
                                         │   시작 시간 변경 · 10분 전         │
                                         │ ● 채팅에서 나를 멘션했습니다        │
                                         │   운영방 · 보낸 사람 · 12분 전      │
                                         │             [전체 알림 보기]       │
                                         └──────────────────────────────────┘
```

모바일은 화면 폭 안의 패널로 표시한다. 키보드 열기·목록 이동·Esc 닫기·초점 복귀를 지원한다. 숫자와 안 읽음은 색에만 의존하지 않는다. 전체 목록은 `/admin/notification-inbox` 제안 경로를 사용하고 기존 발송 로그 화면을 보존한다.

채팅 입력에서 `@`를 입력하면 현재 방 구성원 목록을 제시한다. 선택한 이름은 식별 가능한 멘션으로 표시하고 서버에는 구성원 kind/refId를 저장한다. 문자열 이름만으로 수신자를 추정하지 않는다.

## 2. Backend and Storage (백엔드·저장)

- `acm-notification`에 개인 알림함과 사용자별 SSE 추가. 기존 테넌트 전체 SSE에 개인 멘션 내용이나 개인 목록을 방송하지 않는다.
- PostgreSQL `ACM_DS`, 신규 `amb_acm_notification_inbox` 제안: UUID PK, ent_id, 수신자 kind/refId, event key/type, actor, 대상 kind/id, 최소 표시 데이터, occurred_at, read_at, created_at. 수신자+event key 고유 제약으로 재시도 중복 방지. 테넌트·수신자·읽음·시간 인덱스.
- 업무 저장과 알림 이벤트 기록을 같은 트랜잭션으로 처리하는 outbox를 둔다. 트랜잭션 성공 후 수신자 확정·멱등 적재·SSE 발행, 실패 재시도. 인메모리 EventEmitter만으로 영속 알림을 보장하지 않는다.
- 상담 상태 변경의 실제 변경값, 일정 단건/반복/상담 연계 경로를 조사해 이벤트 발행점을 일원화한다. 동일 작업에서 상담·캘린더 연계 알림의 중복 여부를 명시적으로 처리한다.
- 채팅 멘션은 메시지와 함께 저장하고 같은 테넌트/채널의 구성원임을 서버 검증한다. 삭제 메시지·멤버 제거 시 노출 정책 반영.
- API 제안: `GET /api/acm/notifications/inbox`, `GET .../unread-count`, `PATCH .../inbox/:id/read`, `POST .../inbox/read-all` 및 개인 이벤트 스트림. 페이지 크기 상한과 커서 페이지네이션 적용. 수신자는 JWT로 결정하며 클라이언트가 임의 지정하지 못한다.
- 목록·건수·읽음·바로가기 모두 수신자 및 현재 원본 권한 확인. 원본 타입/ID로 허용된 내부 링크만 구성한다.
- SSE는 갱신 신호이며 DB가 기준이다. 단일 인스턴스 인메모리 연결의 한계는 재조회/폴링으로 보완하고 다중 인스턴스 전환 시 공유 버스 사용.

## 3. Frontend Integration (프론트엔드)

- 공통 헤더 LanguageSwitcher 바로 앞 NotificationBell, 목록 패널과 전체 목록 추가.
- 인증 사용자·테넌트별 쿼리 키 사용, 세션 변경 시 기존 계정 데이터 제거.
- 기존 AdminRealtime을 알림함 쿼리 갱신과 연계, 기존 상담/채팅 화면 캐시 갱신은 유지.
- 상담 상세는 `/admin/csl/:id`, 일정은 기존 상세 라우트 확인 후 연결. 채팅은 channelId/messageId 딥링크를 추가하고 과거 메시지라도 로드하여 강조한다. 경로 권한은 서버에서 재검증한다.
- ko/en/vi/zh-CN 번역. 빈 목록, 로딩, 조회 실패·재시도 UI 포함.

## 4. Verification (검증)

- 두 테넌트와 복수 사용자 간 알림 목록/건수/읽음 격리, 권한 없는 상담·일정·채팅 내용 미노출.
- 5개 이벤트, 자기 작업 제외, 상태 미변경, 실패·롤백, 재시도 중복, 반복 일정 요약/자동 연장 제외.
- 멘션 후보 및 서버 검증, 중복 이름, 비구성원 ID 조작, 본인 멘션, 메시지 삭제·구성원 제거.
- 읽음/모두 읽음 동시성, 재접속 복구, 새로고침 유지, 멀티탭 동기화, 99+ 표시.
- 정확한 상세 바로가기, 과거 채팅 메시지 이동, 모바일·키보드·기존 토스트 회귀.
- 백엔드 단위·PG 통합, 프론트 TypeScript/빌드, 화면 검증·캡처. 스테이징 테스트는 격리 데이터로 수행.
