사용자가 통합=세 사이트 합계 기준을 확정하고 작업 진행을 승인했다. 구현·검증·배포를 진행한다.

## 2. Screen Layout (화면 구성도)

```text

기간 [2025-12-01] ~ [2026-09-30]   [조회] [CSV]

[Marketing]       [CS]        [Operating]       [Class]
                              계산값 (수기값)
                              신규학생  n (m)
                              퇴원학생  n (m)
                              학생수    n (m)  ← 유효 종료일 인원
                              신규교사  n (m)
                              퇴직교사  n (m)
                              교사수    n (m)
                              [학생/교사 전환]
                              계산 실선 · 수기 점선/점

운영 · 일별                     기준선 2024-12-02 / 실제 기준일 YYYY-MM-DD
날짜        신규학생  퇴원학생  학생수   신규교사  퇴직교사  교사수
12-02       2 (2)     0 (0)    2 (2)     —        —       — (14)

...
범례: 앞 숫자=원장 계산 / 괄호=해당 항목의 수기 입력
[데이터 확인: 미연결 기간·날짜 누락·수기 출처 불명]
```

위 괄호 숫자는 표시 예시이며 실제 수기 실적으로 입력하지 않는다. 기존 4개 패널 한 줄 구성을 유지한다. 표는 가로 스크롤, 날짜 고정, 숫자 줄바꿈 방지. 흰색 카드/회색 배경 유지, 4개 언어 적용. 기존 ‘원장 현재 현황’은 현재 상태 기준이라는 구분을 유지해 기간 누적 인원과 혼동하지 않게 한다.

```text
학생 상세 > 수업 기간                       [기간 추가]
시작일         종료일         상태/출처       [수정] [취소]
2025-11-04     2026-05-27     확인된 이관
2026-06-18     2026-06-21     확인된 이관

교사 상세 > 재직 기간                       [기간 추가]
입사일         퇴직일         출처            [수정] [취소]
[YYYY-MM-DD]   [미입력 가능]
```

학생 기간은 강사별 수업정보 카드와 분리한다. 대표 시작/종료일 수정으로 다른 재등록 기간이 사라지지 않게 한다. 종료일 공란과 과거 종료일 삭제는 구분한다.

### 2.1 Site Dashboard (사이트별 화면 구성)

```text
대시보드  [통합] [TPI 선택] [TA] [SC]

[기존 사이트 Marketing / CS 지표 유지]

운영 · TPI                        계산값 (수기값)
[신규학생 n (m)]  [퇴원학생 n (m)]  [학생수 n (m)]
[학생 추이: 계산 실선 / 확인된 사이트 수기 점선]
날짜          신규학생        퇴원학생        학생수
YYYY-MM-DD   1 (1)          0 (0)          33 (32)
```

TA·SC도 동일 구성이다. 숫자는 표시 예시. 수기 입력 화면은 선택 사이트를 명시하고 해당 사이트의 운영 학생 항목만 편집한다. CSV 파일명·열에 사이트를 포함한다. 사이트 전환 시 이전 사이트 데이터가 새 사이트 제목 아래 잠시 보이지 않도록 로딩을 구분한다.

## 3. Implementation (구현 순서)

### P0 — Audit (대사·출처 확정)

1. 최신 main/운영 스키마, 학생 기간과 교사 날짜, 수기 입력 UI·일괄 이관·API 경로 확인.
2. 사이트별 기대값 TPI 63/30/33, TA 7/4/3, SC 20/6/14와 COMMON을 별도 대사한다. 사용자 원본 90기간을 비공개 staging에 정규화하고 사이트/이름/ID 연결. 재등록 3명은 두 기간 보존, 미연결·충돌은 검토 상태 유지.
3. 사용자 표의 모든 날짜/누적을 원본으로 재계산. 전체 운영 결과와 제공 명부 결과를 별도 대사하고 추가/누락 근거 기록.
4. 수기 원본 엑셀·입력 감사 기록에서 항목별 명시적 값/0/빈칸 복구. 행 override만 남은 자료는 출처 불명으로 분류하며 수기라고 단정하지 않는다.

### P1 — Period and Manual Provenance (기간·수기 출처 모델)

- PG 확장 테이블 제안: `amb_acm_std_class_period`, `amb_acm_tch_employment_period`. UUID PK, ent_id, 대상 FK, start_date/end_date, 학생 기간의 site 및 site_source, source/source_row_key, revision, 정정·취소 및 감사 시각. 테넌트 FK 검증, end>=start, 중복 source 키 방지. 겹친 기간은 무조건 합산하지 않고 검토한다.
- 원장 기간을 집계의 단일 기준으로 사용. 단일 기존 필드와 기간을 동시에 세지 않는다. UI/API/이관/직접 SQL writer별 동기화·복구 절차를 구현 전에 확정한다.
- 학생 종료일 DTO/API/상세·편집 연결, 여러 기간 UI 추가. 교사 입퇴사 기간 입력 추가. 기존 기록에 날짜를 새로 필수화해 메모 수정이 막히지 않게 한다.
- 항목별 수기 저장 제안: `amb_acm_dsh_manual_metric`의 tenant/date/site/metric/value/presence/source/revision. 기존 원본을 유지하고 출처 확인된 값만 이관. 모든 수기 입력 경로는 필드 존재 여부를 기록하고 기본 0을 자동 저장하지 않는다. 빈칸 지우기는 감사 가능한 입력 해제로 처리.

### P2 — Versioned Calculation (별도 버전 집계)

- 운영 전용 v2 API: site=ALL/TPI/TRINITY/SANTACROCE를 검증하고 응답에 선택 사이트를 포함한다. ALL은 운영 6개, 개별 사이트는 학생 3개를 제공하며 지원하지 않는 교사값을 0으로 반환하지 않는다. 날짜별 `{calculated, manual, manualPresent, quality}`, openingBalance, definitionVersion, asOf, actualThrough, 누락 수를 반환. 기존 API 숫자 계약은 유지한다.
- 시작 +1/종료 -1 이벤트를 일자별 집계하고 window sum으로 누적한다. 조회창 밖의 2024-12-02부터 사건도 openingBalance에 포함. 날짜별 반복 쿼리는 금지한다.
- 소급입력은 기존 KPI 행을 바꾸는 것이 아니라 기간 이력과 별도 버전 계산 범위를 기준선까지 확장하는 방식이다. 초기에는 set-based 읽기 집계로 구현하고 측정 후에만 별도 캐시/스냅샷을 도입한다.
- 운영 전용 최대 조회 길이는 1,096일 제안. 기존 GA4 동기화/다른 KPI의 365일 제한은 확대하지 않는다. 기간 필터의 전체 범위 요청을 운영/기존 API로 분리하고 긴 범위에서 다른 패널을 임의 축약하지 않는다. 지원 범위 안내를 표시한다.
- 같은 읽기 스냅샷으로 수기/기간 값을 조회. tenant/site/version 캐시 격리, 날짜 수정·삭제·복구·이관 후 갱신, 자정 KST 변경 반영. 캐시 사용 시 과거 수정일 이후 전체 누적 영향을 무효화한다.
- 교사 날짜가 부족하면 부분/미확정 표시. 현재 재직 강사 수를 과거 날짜마다 복제하지 않는다.

### P3 — Presentation (표·요약·그래프·CSV)

운영 6개 항목에 공통 셀 포맷터 적용. 수기 입력은 계산값을 덮어쓰지 않는다. 기간 신규/종료는 합계, 인원은 마지막 유효일 값. 요약 수기는 입력일만 합산하고 부분 기간은 입력일 수 표시; 인원 수기는 마지막 유효일에 값이 있을 때만 병기. 이전 수기 인원을 끝날 값으로 이월하지 않는다. CSV 계산/수기 열 분리. 통합 운영 6개와 TPI·TA·SC의 학생 운영 3개를 이번 전환 범위로 적용한다. 사이트 탭에 통합 수치를 복제하지 않는다.

### P4 — Verification and Release (검증·배포)

원천/수기 사전 백업 → 확장 마이그레이션 → 비노출 계산 대사 → 테스트·성능 → 통합·TPI·TA·SC 학생 통계 기능 플래그 활성화 → 운영 재조회 → 결과 보고. 원본 개인 명부는 Git에 올리지 않는다. 플래그 OFF 시 기존 조회로 복구하고 새 기간/수기 출처 데이터는 보존한다.

## 4. Tests and Side Effects (검증·영향 방지)

| 검증 | 기대 |
|---|---|
| 제공 표 전체/첫날/마지막 날 | 제공 명부 검증 시 2→신규90−종료40=50, 전행 차이 0 |
| 재등록 3명 | 각 두 기간의 시작/종료 모두 반영; 최신 날짜 덮어쓰기 없음 |
| 조회창 이전 사건 | 2025-12 시작 조회에도 이전 누적 포함 |
| 무사건일/동일일 시작·종료 | 0/0 및 전일 인원 유지; 동일일 두 사건 각각 집계 |
| 종료일 수정·취소·삭제/복구 | 기존/새 날짜 이후 누적 전부 갱신; 음수 숨김 보정 금지 |
| 명시적 수기0/미입력/출처 불명 | (0)/괄호 없음/확인 안내 구분 |
| 비용만 수기 입력한 행 | 운영의 기본0을 수기 괄호로 표시하지 않음 |
| 교사 계정 없음/재입사/날짜 누락 | 계정 독립·기간 보존·미확정 표시 |
| 현재 상태와 과거 기간 차이 | 현재 WITHDRAWN이어도 과거 시작/종료 집계 유지 |
| 미래일/월말/KST 경계 | actualThrough 일치, 미래 실제값 없음 |
| 원장 추가 인원 | 사용자50에 강제 맞추지 않고 차이 근거 기록 |
| 격리/다중 사이트/동시 입력 | 타 tenant 0건 노출, 통합 중복 없음, revision 검증 |
| 사이트별 기준표 | TPI 63/30/33, TA 7/4/3, SC 20/6/14; 제공 명부 합90/40/50 |
| 사이트 미지정/기간 귀속 정정 | ALL=세 사이트, 과거 현재소속 추정 없음, 정정 전후 사이트 재계산 |
| 사이트 수기 없음/명시적0 | 통합 수기 복제 없음, 괄호 생략/(0) 구분 |
| 사이트 전환·내보내기 | 카드/표/그래프/CSV 및 캐시 사이트 일치, 기존 사이트 CS·Marketing 유지 |
| 회귀 | 기존 방문자·비용·CS·Class·수기 원본 변경 0 |
| 부하/호환/롤백 | 31/365/전체 범위 EXPLAIN 및 응답 측정, 구 API 유지, 입력 보존 |

실제 PostgreSQL 테스트와 UI 표시 테스트를 수행한다. CI 통합 job은 이미지 pull 실패/continue-on-error를 로그로 구분한다. 신규 데이터 누락·미연결과 수기 출처 미확정이 남으면 해당 결과를 확정값으로 공개하지 않는다.

## 5. Approval (확인)

AGENTS.md §9.2: “요구사항 분석서 + 작업 계획서 작성 후 반드시 사용자 확인을 받은 후 구현으로 진행한다.” 본 계획 확인 후 구현한다. 이전 원장 연계 1차 배포와 별도로 이번 신규 기간 모델·수기 병기 요구의 계획 확인이 필요하다.

## Approved Update (승인된 변경)

2026-09-22 사용자 승인: 통합 학생 계산 통계는 날짜별 TPI+TA+SC의 합이다. COMMON은 통합 숫자에 포함하지 않는다. 수기 비교값은 출처를 보존하며 계산값과 혼합하지 않는다.
