## 2. UI Mockup (화면 구성안)
```text
[←] 프로젝트명   [현재 상태 ▾]
    프로젝트 코드
[개요 ━]  [문서]  [이슈]
─────────────────────────────────────────────────────────────
최근 등록 문서 (약 2/3)                   오른쪽 영역 (약 1/3)
┌메모──────┐ ┌스프레드시트┐ ┌구글Docs──┐  ┌멤버──────[멤버 추가]┐
│ 전체 보기│ │ 전체 보기 │ │전체 보기 │  │이름  [프로젝트 역할]│
│제목      │ │제목 [연동]│ │제목 [링크]│  │이메일          [×] │
│작성자·일시│ │작성자·일시│ │작성자·일시│  └────────────────────┘
└──────────┘ └───────────┘ └──────────┘  ┌배정 고객사──[추가]──┐
┌파일──────┐                            │고객사 또는 빈 상태  │
│ 전체 보기│                            └────────────────────┘
│파일명 [↓]│                            ┌관련 채팅방──────────┐

│일시      │                            └────────────────────┘
└──────────┘
```
- 첨부와 같이 배경·카드 테두리·간격·아이콘·탭 밑줄·버튼 크기를 조정한다. 내용 길이는 말줄임, 상세 제목은 툴팁 또는 접근 가능한 이름으로 제공한다.
- 최근 등록 기준으로 각 유형 최대 5건을 표시하고 전체 보기는 해당 유형 목록으로 이동한다.
- 프로젝트 번호는 저장된 안정적인 코드로 제공한다. 기존 프로젝트의 UUID 참조는 유지하고 코드 필드를 추가할 경우 중복 방지 제약으로 발급한다.
- 상태 배지는 ACM의 실제 상태를 표시한다. 승인됨 예시를 하드코딩하지 않는다.
- 우측 영역은 기존 공통 도움말 패널과 중복되지 않게 프로젝트 본문에 통합한다.
- 모바일은 문서 카드와 우측 카드가 순서대로 한 열로 표시되고, 페이지 전체 가로 넘침이 없어야 한다.

### 2.1 Documents (문서 목록)
```text
문서                              [+ 작성]
[메모] [시트(스프레드시트)] [문서(Docs)] [파일]
[검색........] [정렬 ▾] [권한 ▾] [공유 ▾]
문서명              프로젝트    최종 수정       권한    공유/Google 문서
제목 [연동]         프로젝트명  날짜·작성자     편집자  상태       [⋯]
```
- 독립 `/admin/documents`에서는 접근 가능한 프로젝트 자료를 모아 표시하고 프로젝트를 선택해 작성한다. 프로젝트 내부는 현재 프로젝트로 고정한다.
- 시트 정렬: 수정 최신/오래된 순, 생성 최신순, 이름 오름/내림차순. 권한: 전체/편집자/뷰어. 공유: 전체/공유/미공유. 문서 ID 복사 제공.
- 권한·공유 필터는 실제 서버 정책에 연결한다. 전체 자료를 프론트로 내려보낸 후 숨기는 방식은 사용하지 않는다.
- Docs는 Google 신규 생성/기존 연결을 우선 표시하고 내부 문서는 ‘ACM 문서’로 구별한다.
- 파일 컬럼·상세 메뉴와 공유 동작은 최신 AMA 파일 화면 또는 소스 확인 후 최종 확정한다.

### 2.2 Authoring (작성)
```text
시트 작성                         Docs 작성
[직접 작성 | 구글시트 연동]        [새로 만들기 | 기존 문서 연동]
프로젝트 [선택] / 제목 [입력]      프로젝트 [선택] / 제목 [입력]
연동: Google Sheets URL           연동: Google Docs URL
[취소] [작성/연결]                 [취소] [Google 생성/연결]
```
- Google 미연결 상태는 연결 관리로 안내하며 입력 내용을 유지한다.
- 생성 실패·중복 요청·인증 만료를 구분하고 기존 idempotency 처리를 유지한다.
- 실제 AMA 시트 편집 기능(수식·시트 탭·서식·공유 등)을 확인해 검증표를 작성한 후 구현 범위를 확정한다. 현재 기본 편집기를 동일 기능이라고 표시하지 않는다.

## 3. Work Packages (구현 순서)
1. AMA 소스 또는 브라우저 접근으로 세 문서 탭·작성창·편집기·파일 상세를 확인하고 기능 비교표를 확정한다.
2. 프로젝트 개요 카드, 헤더, 탭, 반응형 레이아웃을 분리 구현한다.
3. 프로젝트 코드·멤버 역할·고객사/채팅방 연결 모델을 기존 AMA 연동 및 ACM 모델과 대조한다. 역할 확대와 기존 데이터 변환 정책을 문서화한다.
4. 독립 문서 목록 및 프로젝트 공통 목록 API/컴포넌트, 검색·정렬·권한·공유 필터를 구현한다.
5. 시트·Docs 작성/연결·파일 기능을 확인된 AMA 동작과 맞춘다. 기존 내부 자료 호환성을 유지한다.
6. 대상 테스트·빌드·화면 비교 후 보고서를 작성한다. 이번 요구사항만으로 운영 배포나 실제 Google 공유 권한 변경은 수행하지 않는다.

사용자 제공 `/Users/gray/Desktop/Site/ambManagement`를 읽기 전용으로 확인했다. 아래는 로컬 소스 기준이며 운영 서버의 동일 커밋 여부는 검증하지 않았다. 앞 절의 파일 탭·시트 편집기 미확인 사항을 아래 내용으로 대체한다.

### 6.1 Route and Files (경로와 파일)
- `apps/web/src/router/index.tsx`: `/documents`는 `MeetingNotesPage`이고 `/drive`는 `DocumentsPage`다. 이름이 비슷하지만 별도 기능이다.
- `domain/meeting-notes/components/PersonalProjectDocuments.tsx`의 `MyFileList`: 프로젝트 파일 통합 목록. 파일명/프로젝트/단계/등록일/크기/다운로드 수 컬럼, 검색, 단계 필터, 등록일·이름·크기·다운로드 수 정렬. 행 클릭 시 해당 프로젝트 문서의 파일 탭으로 이동한다.
- `domain/project/components/ProjectFilesTab.tsx`: 프로젝트 내부는 설명/업로더도 표시하며 다운로드, 고객사 공개 토글, 삭제 확인, 업로드를 제공한다.
- `ProjectFileUploadModal.tsx`: 한 파일 선택 또는 드래그앤드롭, 제목/설명/단계(기획·디자인·개발·운영·기타), 업로드 상태와 오류 표시. 프로젝트 Drive 폴더 → 법인 공용 루트 순으로 저장 위치를 선택하며, Drive 미설정 시 일반 파일 업로드로 대체한다.
- ACM은 공용 계정 정책을 유지하며 일반 업로드 대체는 기존 ObjectStore 인프라로 구현한다. 원본 삭제와 연결 해제는 명확히 구분한다. AMA의 다운로드 오류를 조용히 무시하는 처리는 복제하지 않고 사용자에게 실패를 알린다.

### 6.2 Spreadsheet (시트)
- `domain/project/components/documents/SpreadsheetEditorPage.tsx`: `@fortune-sheet/react` Workbook 기반. 편집/보기 역할, 툴바, 제목 수정, 저장 상태·저장 버튼, XLSX 다운로드, Google Sheets 공유, 문서 권한 설정을 제공한다.
- `useDocumentEditSession`, `useDocumentSaveGuard`, `fortune-snapshot`, `fortune-xlsx`: 편집 세션·이탈 저장 보호·충돌 처리·편집 중 셀 반영·파일 내보내기가 함께 동작한다.
- `GsheetLinkViewer.tsx`: NATIVE는 편집기, GSHEET_LINK는 iframe 뷰어로 분기한다. 링크 문서에는 문서 ID 복사, 원본 새 탭 열기, 권한 설정이 있다.
- ACM의 현재 기본 셀 편집기로는 동등하지 않다. Fortune Sheet 도입의 React 버전 호환·라이선스·데이터 구조를 검증하고 같은 편집 흐름을 구성한다. 기존 ACM 시트 데이터는 버전별 변환과 원본 보존을 지원한다. 수식/서식/복수 시트/내보내기 호환을 별도 검증한다.

### 6.3 Google Docs (구글 문서)
- `GdocLinkViewer.tsx`: iframe 미리보기, 새 탭 열기, 문서 권한 설정. Google 공유 설정으로 임베드가 보이지 않을 수 있다는 안내를 항상 제공한다.
- 기존 Google 신규 생성/연결 흐름을 주 동작으로 하고 ACM 내부 문서는 호환 경로를 유지한다. 외부 링크를 공개로 바꾸지 않으며 허용된 Google URL만 임베드한다.

### 6.5 Implementation Additions (추가 구현 항목)
- 파일 메타데이터(설명·단계·업로더·다운로드 수·저장 유형), 안전한 업로드 확인/다운로드 API.
- 문서별 EDITOR/VIEWER 역할 및 공유 상태, 편집 세션·충돌 정책, 서버 측 권한 검사.
- 고객사 공개 버튼은 ACM 고객사 연결 모델과 권한을 함께 구현한 뒤 제공한다. 기존 학부모 전체 공개로 해석하지 않는다.
- Google 공유는 사용자가 선택한 대상과 역할을 명시한 작업으로 제공하며 자동으로 공개 권한을 부여하지 않는다.
- 소스의 UI·흐름을 참고하되 AMA의 인증·DB·API 경로를 ACM에 그대로 복사하지 않는다.


## 7. Implementation Status (구현 현황)
사용자가 보완안 구현을 승인했다. 구현·테스트 결과와 AMA 대비 남은 차이는 [RPT-261015](../report/RPT-261015-project-ama-parity.md)에 기록한다. 고객사 포털 권한, 실계정 Google·화면 비교는 완료 항목으로 간주하지 않는다.
