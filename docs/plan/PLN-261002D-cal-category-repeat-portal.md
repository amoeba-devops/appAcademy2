# Calendar Correction Plan (수업일정 수정 계획)

## 1. Outcome (목표)

[분석서](../analysis/REQ-261002D-cal-category-repeat-portal.md)의 네 가지 개선을 구현한다. 운영 데이터 정리는 대상 테넌트에 한정하며, 소스 변경은 최신 운영 main 기반 독립 브랜치에서 진행한다. 기존 작업 디렉터리의 다른 변경은 보존한다.

## 3. Implementation (구현)

### 3.1 Categories (카테고리)

- frontend-acm CAL/포털의 타입·선택지·표시·필터·색상 설정·다국어와 backend CAL DTO/엔티티/기본 생성 경로(즉시 수업, 수업 세션, ICS, 자체 반복)를 함께 점검한다.
- 운영 이관은 기존 evt_id 및 수업 연결을 유지하고 CLASS → REGULAR_CLASS로 바꾼다. 소프트 삭제된 이벤트, ICS source.category, 자체 반복 template 및 changes의 카테고리 패치까지 점검해 이후 복원/재전개 시 옛 분류가 남지 않게 한다.
- 기존 REGULAR_CLASS 색상이 있으면 유지, 없으면 CLASS 색상 승계. 담당 강사 색상은 유지한다. 폐기 카테고리 설정을 정리한다.
- 행사 9건은 사용자 확인에 따라 기존 일정을 보존하고 기타로 이동한다. 다른 테넌트에 폐기 카테고리가 남아 있으면 운영 데이터 변경을 확장하지 않고 별도 호환 방안을 검토한다. DB enum/check/default 변경 전 전체 사용 현황을 확인한다.

### 3.2 Repeat Cutoff (반복 종료와 데이터 정리)

- 대상: 기존 CLASS/REGULAR_CLASS의 반복 원본. 컷오프: 2026-11-01 00:00 Asia/Seoul. 실제 시작 시간이 이 시각 이상인 반복 회차를 제거한다.
- 실행 가능한 dry-run 도구로 원본 ID, 회차 ID, 이전 값, 삭제 예정 수, 변경 이력/연결 자료 및 이동 예외를 대사한다. 학생·출결·수납 연결 자료는 연쇄 삭제하지 않는다.
- ICS와 자체 반복을 각각 처리한다. 10월까지 필요한 회차를 확인한 뒤 원본 종료 시각을 설정한다. 미래 삭제 건이 없는 기존 수업 원본도 나중에 11월 이후를 생성할 수 있으면 종료 대상에 포함한다.
- 이미 더 이른 종료가 설정되어 있으면 연장하지 않는다. 원본 반복 규칙, occurrence 키, 예외를 보존한다. 사용자가 별도로 등록한 단일 일정은 제외한다.
- 자체 반복의 기준 회차와 시간 이동 후 실제 시각이 경계를 넘는 경우를 따로 검증하여 10월 보존/11월 제외를 모두 만족시킨다. 관리자·포털 조회, Cron, 재이관 경로에서 종료가 해제되지 않도록 검증한다.
- 생성 작업과 동일한 tenant/series lock 및 트랜잭션 사용. 백업 후 원본 종료와 미래 soft-delete를 한 작업으로 수행한다. 처리자·시각·배치 사유·ID별 이전 값을 남긴다. 개별 일정 알림을 828건 발송하는 부작용은 피한다.
- 재실행은 변경 0건이어야 한다. 복구는 배치가 변경한 원본/행만 이전 값으로 되돌리고 이후 사용자 변경은 덮어쓰지 않는다.

### 3.3 Optional Edit Reason (수정 사유 선택)

- 모달 필수 표시·빈값 차단 제거, API UpdateCalEventDto 선택 처리, 공백/미전송 정규화. 입력한 사유의 길이 제한은 유지한다.
- 반복 수정 ONE/FOLLOWING/ALL 및 ICS 개별 수정에도 적용한다. 수정/삭제 공유 DTO는 분리하거나 목적별 검증해 삭제 사유는 필수로 유지한다.
- 반복 내부 reason 불일치 검사는 정규화된 값으로 일치시킨다. 사유 없는 수정도 실제 변경 내용의 revision을 기록하고 이력에서는 ‘미입력’으로 표시한다.

### 3.4 Portal Overflow (포털 더보기)

- portal-calendar-page.tsx MonthGrid의 div를 접근 가능한 button으로 교체한다.
- 선택 날짜의 전체 dayEvents 목록 모달을 추가한다. 기존 선택 이벤트 상세 모달을 재사용하며 목록에서 더 이상의 slice 제한을 두지 않는다.
- 현재 사용자 권한·담당 강사 범위·조회 필터와 날짜 판정 기준을 그대로 사용한다. 불필요한 전체 학생 API 조회는 추가하지 않는다.

## 4. Verification (검증)

| 영역 | 통과 기준 |
|---|---|
| 이관 | 대상 CLASS 0, 기존 ID/담당자/시간/연결 보존, 정규수업 및 색상 정상 표시 |
| 경계 | 10월 31일 포함 보존, 11월 1일 00:00부터 제외, 한국 시간 기준 |
| 반복 | ICS 유한/무한·자체 반복·이동 예외 검증, 조회/Cron 후 재생성 0, 재실행 변경 0 |
| 보존 | 다른 테넌트·단일 미래 일정·레벨테스트/기타·출결/수납 자료 유지 |
| 수정 | 사유 없음/공백/정상값, ONE/FOLLOWING/ALL 저장 및 revision 기록 |
| 삭제 | 사유 없는 삭제는 거부, 정상 삭제는 기존 정책 유지 |
| 포털 | 0/3/4/다수 일정, 마지막 항목 상세 접근, 종일/여러 날 일정, 키보드·모바일·권한 |

타입 검사·관련 단위/API 테스트·빌드 및 스테이징 UI 검증을 수행한다. 운영 반영 직전 건수를 재집계하고 DB 백업 및 복구 자료를 준비한다. 배포 후 관리자/강사 화면에서 10월과 11월을 확인하고 재조회 후에도 종료 상태가 유지되는지 확인한다.

## 5. Approval (구현 확인)

사용자의 “진행”으로 전체 계획 구현 승인을 받았으며 구현과 로컬 검증을 완료했다. 프로젝트 [AGENTS.md §9.2](../../AGENTS.md)는 “요구사항 분석서 + 작업 계획서 작성 후 반드시 사용자 확인을 받은 후 구현으로 진행한다”고 정한다. 행사 9건의 기타 이동은 사용자 확인을 받았다. 확정한 화면 구성안·종료 범위에 따라 구현했다. 기존 기능의 과거 배포 요청을 이번 신규 변경의 배포 승인으로 간주하지 않는다.
