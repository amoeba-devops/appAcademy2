# Admin UI Consistency Plan (관리자 공통 UI 작업계획)

## 1. Objective (목표)

[요구사항](../analysis/REQ-260920E-admin-ui-consistency.md)에 따라 대시보드 외 관리자 업무 화면의 콘텐츠 폭과 배경을 통일하고 우측 팁/배너 패널을 제공한다. 기준은 운영 수업통계의 최대 896px 본문이다.

## 2. Screen Layouts (화면구성도)

### 2.1 Wide Desktop (넓은 화면)

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ ACM                                                               언어 ▾  │
├───────────────┬────────────────────────────────────────────────────────────┤
│ 좌측 메뉴     │ 콘텐츠 영역 배경: 회색                                    │
│               │ ┌──── 본문 최대 896px ───────────────┐ 24px ┌─ 256px ───┐ │
│ 대시보드      │ │ 페이지 제목              [주요버튼]│      │ 이용 팁   │ │
│ 신규 상담     │ │ [검색] [필터] [초기화]             │      │ 현재 화면 │ │
│ 학생관리      │ │ 결과 n개                           │      │ 사용 안내 │ │
│ …             │ │ ┌── 목록: 흰색 ──────────────────┐ │      │           │ │
│               │ │ │ 헤더: 연한 회색                │ │      └───────────┘ │
│               │ │ │ 데이터 행: 흰색                │ │      ┌───────────┐ │
│               │ │ │ 긴 표는 이 영역 안에서 스크롤  │ │      │ 배너      │ │
│               │ │ └───────────────────────────────┘ │      │ 제공 시   │ │
│               │ │ [페이지당 인원]       [이전][다음]│      │ 표시      │ │
│               │ └───────────────────────────────────┘      └───────────┘ │
└───────────────┴────────────────────────────────────────────────────────────┘
```

- 두 열 총 최대 폭: **1176px = 896 + 24 + 256**. 기존 사이드바 뒤 본문 시작점에 왼쪽 정렬한다.
- 콘텐츠 가용 폭이 1176px 이상일 때 두 열을 표시한다. 브라우저 폭만으로 판단하지 않고 사이드바/바깥 여백을 제외한 컨테이너 폭을 기준으로 한다.
- 보조 패널은 본문 제목의 상단 기준선에 맞춘다. 배너가 없으면 해당 카드 자체를 렌더링하지 않고 기본 팁만 표시한다.
- 배너 추가 시 이미지 비율 유지·대체 텍스트·접근 가능한 링크를 제공한다. 콘텐츠는 보조 패널의 선택 속성으로 관리하고 외부 광고 스크립트를 추가하지 않는다.

### 2.2 Detail / Settings (상세·설정)

```text
┌────────────── 본문 최대 896px ──────────────┐    ┌── 이용 팁 ──┐
│ [목록으로]  페이지 제목             [수정] │    │ 입력/조회   │
│ ┌ 기본정보: 흰색 ────────────────────────┐ │    │ 안내        │
│ │ 항목 : 값         항목 : 값            │ │    └─────────────┘
│ └───────────────────────────────────────┘ │
│ ┌ 관련정보: 흰색 ────────────────────────┐ │
│ │ 기존 기능과 입력 항목 유지             │ │
│ └───────────────────────────────────────┘ │
└───────────────────────────────────────────┘
```

학생 상세의 강사별 수업 카드, 제목 13px/Bold 및 회색 이탤릭 placeholder를 유지한다. 개별 입력창·짧은 설명글까지 강제로 896px로 늘리지 않고 페이지 외곽만 통일한다.

### 2.3 Narrow Desktop / Mobile (좁은 화면·모바일)

```text
┌─────────────────────────────────┐
│ ☰ ACM                      언어 │
│ 페이지 제목             [버튼]  │
│ [검색                         ] │
│ [필터] [필터] [초기화]           │
│ ┌ 목록: 흰색 ─────────────────┐ │
│ │ 필요한 경우 내부 가로 스크롤│ │
│ └─────────────────────────────┘ │
│ [이전] 1/n [다음]               │
│ ┌ 이용 팁: 흰색 ──────────────┐ │
│ │ 본문 아래로 배치            │ │
│ └─────────────────────────────┘ │
└─────────────────────────────────┘
```

본문은 가용 폭에 맞춰 줄어들고, 툴바/검색 조건은 줄바꿈한다. 보조 패널은 같은 본문 폭으로 하단 배치한다. 작은 화면에서 256px 패널을 옆에 유지하여 본문을 좁히지 않는다.

### 2.4 Dashboard Exception (대시보드 예외)

```text
대시보드 → 기존 가용 폭·4개 패널·그래프·배경 유지
           공통 896px 제한 및 우측 보조 패널 적용 안 함
```

## 3. Design Rules (공통 디자인 규칙)

| 항목 | 규칙 |
| --- | --- |
| 본문 폭 | width 100%, max-width 896px, min-width 0 |
| 보조 패널 | 넓은 화면 256px, 하단 배치 시 본문과 동일 폭 |
| 열 간격 | 24px |
| 페이지 배경 | bg-canvas / 현재 #fafafa |
| 목록·카드·패널 표면 | bg-surface / #ffffff |
| 목록 헤더 | 기존 연한 회색 토큰 |
| 테두리·모서리 | 공통 border-subtle·rounded-lg |
| 간격 | 정보 카드 16px, 주요 구역 24px, 기존 셸 바깥 여백 유지 |
| 상태 | 선택·hover·상태 배지의 의미 있는 색상 유지 |
| 텍스트 | 기존 크기 체계 유지, 미입력 안내만 회색 이탤릭 |

## 4. Route Inventory (점검 대상)

| 그룹 | 경로 | 주요 점검 |
| --- | --- | --- |
| 상담·접수 | csl, csl/:id, test, test/:id | 검색·상세·편집·넓은 열 |
| 학생·학부모 | std 및 사이트/퇴원/상세, std/parents | 전체 강사명·카드·페이지 이동 |
| 교사·직원 | tch, stf | 목록·상세 모달의 폭 구분 |
| 수업·일정·통계 | cls, cls/:id, cal, cal/:evtId, cal-stats, cal-stats/:tchId | 달력 이동·스크롤·통계 차트 |
| MAP·기준정보 | map, sch, ref | 표·탭·필터 |
| 게시·알림·등록 | posts 및 new/:id, notifications, enrollments | 편집기·목록·빈 상태 |
| Q&A·채팅 | qna, qna/categories, chat | 내부 분할·고정 높이·입력창 |
| 설정 | config 및 ama/boda/mail/general/kakao/ga4 | 기존 2xl/3xl 폭 제거, 개별 입력 크기 유지 |

모든 경로는 `/admin/` 기준이다. 구현 시 router.tsx와 대조하여 추가 경로가 있으면 인벤토리를 보완한다.

## 5. Implementation (구현 순서)

1. 사용자 계획 승인 후 공통 `AdminContentLayout` 및 `AdminSupportPanel`을 추가한다. AppShell Outlet을 감싸되 대시보드는 명시적으로 제외한다.
2. 공통 토큰에 본문/패널/간격 기준을 정의하고 컨테이너 폭에 따른 2열→1열 배치를 적용한다. ResizeObserver를 사용해 fixed 모달의 기준 좌표에 영향을 주는 CSS containment를 피한다. route 이동에 따른 페이지/폼 불필요한 재마운트를 피한다.
3. 페이지 최상위 `max-w-2xl/3xl/4xl` 등을 점검해 공통 프레임에 위임한다. 전역 `!important`나 모든 자손의 max-width 제거 방식은 사용하지 않는다.
4. 목록 표면 컴포넌트/스타일을 통일한다. 표의 실제 데이터 영역과 빈/로딩/오류 상태에 흰색 배경을 명시한다. 카드형 목록도 동일한 표면 토큰을 적용한다.
5. 달력·채팅·게시 편집기의 높이 계산과 내부 스크롤을 새 프레임에서 조정한다. 필터/버튼은 좁은 본문에서 줄바꿈되도록 한다.
6. 페이지 그룹별 팁을 연결한다. 기본 팁은 확인된 기능만 설명하며 ko/en/vi/zh-CN 번역을 제공한다. 배너는 자료가 제공되면 설정으로 연결할 수 있는 선택 영역으로 둔다.
7. 라우트별 레이아웃 확인, 빌드/타입 검사, 필요한 공통 레이아웃 회귀 검증, CI·스테이징·운영 배포 및 결과 보고서 작성.
8. `docs/standard/STYLE_GUIDE.md`의 관리자 레이아웃 기준을 승인된 공통 규칙으로 갱신한다.

## 6. Validation and Rollback (검증·복구)

- 1920/1536/1280/1024/768/390px, 사이드바 펼침·접힘을 점검한다. 컨테이너 1176px 경계 전후에서 두 열과 하단 패널 전환을 확인한다.
- 충분한 공간에서 대상 페이지의 본문 폭 896px, 보조 패널 256px를 실측한다. 좁은 화면에서 페이지 전체 가로 넘침이 없어야 한다.
- 데이터가 많은 표·긴 강사명·필터·페이지 이동·선택/일괄 작업·빈 결과·오류 화면을 확인한다.
- 달력 보기 전환, 채팅 입력/스크롤, 게시 편집기, 모달/드로어/팝오버가 가려지지 않는지 확인한다.
- 대시보드 4개 패널/그래프 및 별도 포털·로그인·시스템 화면은 비교하여 영향 없음을 확인한다.
- 접근성: aside에 이름 부여, 본문 우선 읽기/키보드 순서, 배너 대체 텍스트, 회색 안내 대비 유지.
- DB/API 변경 없음. 주요 화면 조작이 불가능하거나 대시보드가 변형되면 이전 프론트엔드 이미지로 복구한다.
