# Student Deletion Plan (학생 삭제 구현 계획)

## 1. Scope (범위)
[요구사항 v1.1](../analysis/REQ-261013C-std-ama-admin-delete.md)에 맞춰 기존 논리 삭제만 제공하는 안을 대체한다. 사용자가 AMA 관리자 범위를 MASTER·OWNER·MANAGER로 승인했다. 특정 운영 학생 삭제·배포는 실행하지 않는다.

## 2. UI Mockup (화면 구성안)
```text
학생관리   [학생 목록] [비활성화 목록] [삭제 이력]

학생 상세                    [수정] [퇴원 처리] [학생 삭제]
┌ 학생 삭제 확인 ──────────────────────────────────┐
│ 학생 이름 · 상담 N건 / 수업 N건 / 수납 N건        │
│ 비활성화하여 일반 목록에서 제외합니다.           │
│ 연결 기록은 비활성화 목록에서 확인할 수 있습니다.│
│                          [취소] [비활성화]        │
└─────────────────────────────────────────────────┘

비활성화 목록
이름 | 비활성화 날짜 | 담당자 | [상세 보기] [완전삭제]

┌ 완전삭제 — 복구 불가 ────────────────────────────┐
│ 테스트로 작성한 학생만 완전삭제하세요.           │
│ 실제 학생의 상담·수업·수납 기록이 있는 경우      │
```

권한 없는 사용자에게 삭제 동작을 노출하지 않는다. 모바일에서 버튼 줄바꿈·목록 스크롤·확인창 화면 맞춤을 제공한다. 처리 중 중복 클릭을 차단한다.

## 3. Implementation (구현 순서)
1. AMA 관리자 판정 기준 확정 후 서버 capability와 API guard를 공통 적용한다. 기존 DELETE 직접 호출로 완전삭제 제한을 우회할 수 없도록 한다.
2. 기존 INACTIVE 상태와 삭제 전용 비활성화의 의미를 구분해 설계한다. 현재 INACTIVE 데이터를 임의로 삭제 대상으로 전환하지 않는다. 일반 목록에서 제외하는 삭제 전용 표시와 관리자용 비활성화 조회 경로를 마련한다. 퇴원 이력과 혼동하지 않는다.
3. 학생 상세 삭제 확인창 및 비활성화 목록/상세를 추가한다. 비활성화 시 기록 유지, 일반 검색 제외 및 캐시 갱신을 검증한다.
4. 학생 FK/JSON 참조와 첨부파일을 조사해 완전삭제 대상 목록을 작성한다. 학생 전용 데이터만 처리하고 공유 기록은 보존하거나 삭제를 차단한다. 실거래 판별 근거가 있는 경우 서버에서 완전삭제를 거부한다.
5. 삭제 미리보기 API와 완전삭제 API를 분리한다. 최종 요청 시 테스트 확인·이름 일치·비활성화 상태·권한·테넌트·현재 연결 관계를 재검증하고 잠금/트랜잭션으로 동시 변경을 통제한다.
6. 독립 삭제 이력 테이블/조회 API를 추가한다. 학생/사용자 FK cascade에 이력이 제거되지 않게 하며 담당자 ID·당시 이름·날짜를 보존한다. 삭제 실패는 성공 이력으로 기록하지 않는다.
7. DB 밖의 학생 전용 첨부파일은 공유 여부 확인 후 재시도 가능한 정리 절차로 처리한다. DB 트랜잭션 성공 전 외부 파일을 지우지 않는다.
8. 4개 언어, 모바일 화면, 관련 테스트·빌드 및 보고서를 완료한다.

## 4. Validation (검증)
- 관리자/비관리자/비활성 계정/다른 테넌트/권한 철회별 접근 검사.
- 연결 기록 있는 학생은 비활성화 후 일반 목록 제외, 비활성화 목록 조회, 원본 업무 기록 유지.
- 테스트 확인·이름 확인 실패 및 활성 학생 직접 완전삭제 차단.
- 실거래가 확인되는 학생 및 분리 불가능한 공유 기록 완전삭제 차단.
- 합성 테스트 학생과 전용 상담/수업/수납 기록 삭제, 다른 학생/공유 계정 영향 없음.
- 삭제 이력에 날짜·담당자 보존, 중복 요청·동시 연관 기록 생성·실패 롤백 검증.
- 운영 학생을 삭제하는 테스트는 실행하지 않는다. 격리 DB 합성 데이터로 검증한다.

## 5. Decision (확인 사항)
사용자가 수정한 흐름은 반영 완료했다. 사용자 범위 승인에 따라 구현했다. 실제 데이터와 테스트 데이터를 내용만으로 완전히 자동 판별할 수 없으므로 테스트 여부 확인 및 실거래/공유 기록 차단을 함께 적용한다.


## Implementation Notes (구현 보충)
- 일반 INACTIVE와 별도로 std_archived_at/deleted_at으로 삭제 요청 비활성화를 구분한다. 삭제 날짜·담당자는 독립 이력에 보존한다.
- PG 결제 주문/정산, 공유 기록, 반복/ICS·외부 화상 수업, Q&A/MAP 배정/보강/수업 자료 등 별도 검토가 필요한 연결은 완전삭제를 차단하고 화면에 이유를 표시한다. 관련 기록을 임의로 제거하지 않는다.
- 학생 전용 상담/캘린더 첨부는 DB 커밋 후 정리 큐로 처리한다. 파일 소유 범위가 불명확하거나 공유 키이면 삭제를 차단한다.
- 최종 삭제는 미리보기 내용 해시 재검증 및 짧은 DB 쓰기 잠금으로 보호한다. 잠금 대기는 3초, 쿼리 제한은 15초이며 충돌 시 롤백한다.
