# Projects and Drive Revision (프로젝트·드라이브 개편 계획)

## 1. Baseline and Reference (현재 상태·AMA 참조)
기존 v1.2는 PR #320 / `6ce049c`로 운영 배포됐다. 프로젝트 생성·이슈·일반 텍스트 노트, 프로젝트 전용 Drive 탐색과 Google 문서 생성 기능이 있다. 운영 Google OAuth 설정은 미완료다. 이번 문서는 기존 화면 구성과 문서 편집기 제외 범위를 대체한다.

2026-10-14 실제 AMA 화면에서 확인한 내용:
- `/documents`: 노트·스프레드시트·구글Docs·마크다운·위키·파일 분류.
- 스프레드시트 작성창: **직접 작성 / 구글시트 연동**, 프로젝트·제목 입력, 연동 시 구글시트 URL 입력.
- 구글Docs 작성창: **새로 만들기 / 기존 문서 연동**. 새로 만들기는 법인 Google 계정으로 생성한다는 안내가 있다. AMA 자체 Docs 편집기를 확인한 것은 아니다.
- 노트: 검색, 카드/목록, 폴더, 새 노트 진입점.
- Drive는 프로젝트와 동등한 독립 좌측 메뉴다. 앞선 `/drive` 확인에서는 폴더 카드, 폴더 탐색, 목록/카드, 업로드, 원본 보존 연결 해제를 확인했다.
- 지정 프로젝트 상세 URL은 다시 확인했으나 본문 Loading 상태였다. 프로젝트 내부 편집기 세부 UI는 미확인이다. 기존 자료를 수정하거나 문서를 생성하지 않았다.

참조: [AMA 문서](https://ama.amoeba.site/documents), [AMA Drive](https://ama.amoeba.site/drive), [지정 프로젝트](https://ama.amoeba.site/project/projects/bb9c92db-5b6e-4a6e-b688-9e06d8046eba?tab=documents).

## 2. UI Mockups (화면 구성안)
### 2.1 Independent Drive (독립 드라이브)
```text
ACM 좌측 메뉴              드라이브                      [연결 관리]
  프로젝트                 [계정 연결 상태] [폴더 연결]
  드라이브 ← 독립 메뉴     [검색................] [정렬] [목록/카드]
                           ┌ 학원 공용 자료 ┐ ┌ 운영 문서 ┐
                           │ 열기 · ⋯      │ │ 열기 · ⋯ │
                           └───────────────┘ └───────────┘
폴더 열기 → 드라이브 > 공용 자료 > 하위 폴더
                           [새 폴더] [업로드] [새로고침]
                           파일명 / 종류 / 수정일 / 크기 / 작업
```
- 경로 `/admin/drive`, 독립 메뉴 키 `drive`와 메뉴 노출 설정. 프로젝트 생성/선택 없이 연결·탐색·업로드 가능.
- 기존 학원 공용 계정 1개 방식을 유지한다. 계정 연결/해제·루트 폴더 연결은 CONFIG_ADMIN만 수행한다.
- 공용 폴더별 열람/편집 대상(학원 운영자·선택 사용자)을 지정하는 설계로 한다. 기존 프로젝트 폴더를 공용으로 자동 공개하지 않는다. 프로젝트 연결 자료는 기존 참여 권한으로만 조회한다.
- 일반 사용자는 서버가 허용한 폴더만 탐색한다. 프로젝트 화면에서 Drive 연결 관리 UI를 제거하고 필요 시 독립 Drive 화면으로 안내한다.
- 기존 `/admin/config/drive`는 `/admin/drive` 연결 관리로 호환 이동한다. OAuth 복귀 경로도 함께 수정한다.
- Google 원본을 지우지 않는 연결 해제, 내 Drive/공유 Drive 구분, 연결 만료·미설정 안내를 유지한다.

### 2.2 Project Detail (프로젝트 상세)
```text
[← 프로젝트 목록]  겨울특강 준비                  [정보] [⋯]
[개요]  [문서]  [이슈]                            ← 고정 순서

개요: 설명 · 상태 · 담당자 · 참여자
      이슈 현황(할 일/진행/완료) · 최근 수정 문서
```
- 기본 진입 탭은 개요. 이슈 CRUD와 참여자 권한은 유지한다.
- 파일·노트 독립 탭은 문서 아래로 통합한다.
- 기존 `?tab=notes` → `?tab=documents&type=memo`, `?tab=files` → `?tab=documents&type=file`로 호환한다.

### 2.3 Documents (문서)
```text
[개요]  [문서 ●]  [이슈]
[메모] [시트(스프레드시트)] [문서(Docs)] [파일]     ← 고정 순서
[제목 검색................] [최근 수정순 ▾]       [+ 작성]
제목                 작성 방식       작성자       수정일    [열기][⋯]
특강 회의록          직접 작성       김담당       10.14
```

| 구분 | 작성·연결 | 저장·열기 |
|---|---|---|
| 메모 | 리치에디터 작성 | ACM 저장, 내부 편집 |
| 시트 | 직접 작성 / 구글시트 연동(링크) | 직접 작성은 ACM 표 편집·저장, Google 링크는 Google에서 열기 |
| 문서(Docs) | 직접 작성 / 구글독스 연동(링크) | 직접 작성은 ACM 문서 편집·저장, Google 링크는 Google에서 열기 |
| 파일 | 파일 업로드 / Drive 파일 연결 | 기존 Drive 저장·원본 열기 유지 |

```text
새 시트                                         [닫기]
[● 직접 작성] [○ 구글시트 연동]
제목 [......................................]
직접 작성 → [표 편집기 열기]
연동 선택 → Google Sheets URL [...............]
                                    [취소] [저장]
```
문서도 같은 선택 구조를 사용한다. 기존 Google 새 문서 생성 기능은 별도 [Google에서 새로 만들기] 보조 액션으로 보존하고 내부 작성과 구분한다.

### 2.4 Authoring (내부 작성)
- **메모**: 제목, 본문 리치에디터, 굵게/기울임/취소선, 제목 단계, 목록, 인용, 링크, 실행 취소/재실행.
- **문서**: 제목, 넓은 문서 편집 화면, 메모 공통 서식과 표 삽입/수정. ACM 내부 작성으로 해석한 제안이며 AMA의 Google 신규 생성과 구별한다.
- **시트**: 셀 입력, 행/열 추가·삭제·크기 조절, 범위 선택·복사/붙여넣기, 숫자/문자/기본 서식, 기본 수식(SUM/AVERAGE와 사칙연산), 실행 취소/재실행, 저장·재열기. 다중 워크시트·고급 Excel 호환·실시간 공동 편집은 별도 확장.
- 저장 상태/실패 표시, 수정 후 이탈 확인, 버전 충돌 시 덮어쓰기 방지. 기본 명시적 저장으로 시작한다.
- Google 링크는 URL 형식·서비스 종류를 검증한다. 링크 등록은 OAuth 없이 가능하며 접근 가능 여부를 보장하지 않는다. 비공개 자료의 공개 공유를 강제하지 않는다. Google 권한은 원본 정책대로 유지한다. 서버가 임의 URL을 가져오지 않는다.
- Google 링크와 ACM 본문은 자동 양방향 동기화하지 않는다.

### 2.5 Mobile (모바일)
- 메인 3개 탭은 한 줄, 문서 하위 분류는 탭 영역만 가로 스크롤.
- 작성 화면 전체 폭, 툴바 줄바꿈/내부 스크롤, 주요 저장 버튼 고정, 목록은 카드.
- 시트 가로 이동은 표 안으로 제한한다. 320/390/768/1280px에서 페이지 전체 넘침을 검사한다.

## 3. Implementation Plan (구현 방안)
1. 최신 main 별도 작업 디렉터리 사용. IDE의 기존 미커밋 변경 보존.
2. `frontend-acm/src/modules/prj/project-page.tsx`의 목록·개요·문서·이슈와 Drive 화면을 컴포넌트로 분리. 라우트·메뉴·4개 locale·노출 설정 추가.
3. 기존 Tiptap 의존성과 편집기 사용 패턴 재사용. 문서 구조 JSON을 검증하고 안전한 렌더러/에디터로 출력한다. 기존 HTML 주입 방식 복제 금지. 시트 라이브러리는 기능·라이선스·React18 호환 검증 후 선정한다.
4. 기존 `amb_acm_prj_item`을 유지하며 문서 하위 종류(MEMO/SHEET/DOC/FILE), 저장 방식(LOCAL/GOOGLE_LINK/DRIVE_FILE), 본문 JSON, 링크, revision 필드를 추가한다. `pit_kind` 호환과 기존 API 영향을 검토한다.
5. 기존 NOTE는 메모로 표시하고 평문을 안전한 문단 JSON으로 변환한다. Drive DOCUMENT는 MIME으로 시트/Docs 분류. FILE은 파일로 보존한다. 기존 ID·작성자·Drive 참조 유지.
6. 공용 Drive 연결 서비스를 프로젝트 수명주기에서 분리한다. 테넌트 공용 폴더 연결/권한 테이블을 `amb_acm_drv_*`로 추가하고 기존 공용 OAuth 토큰을 중복 복제하지 않는다. 기존 프로젝트 파일 권한과 범위 제한 유지.
7. 직접 작성 API, URL 연결 API, revision 충돌 검사, 서버 테넌트/참여자/폴더 권한 검증. 보관된 프로젝트는 읽기 전용.
8. 신규 SQL의 재실행 안전성·마이그레이션 전후 데이터 보존, API 권한, 편집 저장/재열기, 링크 검증, 모바일 UI와 빌드 검증 후 보고서/PR 작성.

## 4. Acceptance Criteria (완료 기준)
- Drive가 프로젝트 없이 ACM 기본 메뉴에서 사용 가능하고 기존 프로젝트 비공개 자료가 노출되지 않는다.
- 개요 | 문서 | 이슈 및 메모 | 시트(스프레드시트) | 문서(Docs) | 파일 순서가 일치한다.
- 메모 서식, 직접 작성 시트의 셀·수식, 문서 본문·표가 저장/재열기 후 보존된다.
- Google 미연결 상태에도 내부 작성 및 링크 등록이 가능하다. Google 생성·업로드만 OAuth 연결을 요구한다.
- 기존 노트/파일/Google 참조·이슈·권한·이전 URL 호환이 유지된다.
- 권한 없는 API 접근, XSS URL/본문, 타 테넌트 접근, 동시 저장 충돌, 파일/Drive 접근 실패를 검증한다.

## 5. Approval (확인)
v1.2 구현 승인은 기존 기능에 해당한다. 이번 독립 Drive/내부 편집기 확대는 신규 요구사항으로 분석·화면안을 작성했다. 2026-10-14 사용자가 “구현”으로 승인하여 구현했다. 운영 배포는 이후 별도 단계다.
