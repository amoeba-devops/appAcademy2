# Lightweight Projects Plan (간편 프로젝트 구현 계획)

## 1. UI Mockup (화면 구성안)

### 1.1 Reference Review (참조 확인)
[사용자 지정 AMA 문서 탭](https://ama.amoeba.site/project/projects/bb9c92db-5b6e-4a6e-b688-9e06d8046eba?tab=documents)을 실제 브라우저에서 열었다. 공통 헤더/좌측 메뉴/우측 로비 채팅은 표시되나 상세 본문은 `Loading...` 상태가 지속되었다. 프로젝트 목록을 경유한 재진입에서도 동일했다. 따라서 **아래 문서 상세안은 AMA 문서 탭을 확인하여 복제한 것이 아니라, 확인된 목록 구조와 사용자 요구사항을 결합한 ACM 구성안**이다. 상세 본문이 정상 표시되면 문서 탭 배치의 일치 여부를 추가 확인한다.

AMA 목록에서 확인한 요소:
- 상단 프로젝트 관리 제목, 프로젝트/제안서 구분과 새 제안서 버튼.
- 내 프로젝트/전체 프로젝트/고객사별 보기/업무 시나리오 탐색.
- 검색, 최근 등록·이슈 수·최근 이슈 기준 정렬, 상태 필터, 보관함 보기.
- 프로젝트 카드: 코드, 상태, 제목, PM, 참여자·이슈 수, 시작일, 이슈 상태별 수, 최근 이슈.

ACM 적용: 카드와 필터의 정보 구조를 따르고, 생성 버튼은 **프로젝트 생성**으로 둔다. 제안·고객사별 보기·업무 시나리오를 추가하지 않는다. ACM 공통 헤더와 기존 좌측 메뉴를 사용한다.

### 1.4 Documents Tab (문서 탭 — 핵심 구성)
```text
문서 (3)                     [+ 문서 만들기 ▾] [기존 문서 연결]
[문서명 검색................] [전체 / Google 문서 / Google 시트]
┌────┬─────────────────────┬─────────┬────────────┬─────────────┐
│종류│ 문서명              │ 등록자  │ 연결/등록일│ 작업        │
├────┼─────────────────────┼─────────┼────────────┼─────────────┤
│Docs│ 겨울특강 안내문      │ 김담당  │ 10.14      │ [열기] [⋯] │
│Sheet│ 반별 시간표         │ 이담당  │ 10.14      │ [열기] [⋯] │
└────┴─────────────────────┴─────────┴────────────┴─────────────┘
[+ 문서 만들기 ▾] → Google 문서 / Google 스프레드시트
```
- 신규 생성: 유형과 제목 입력 → 프로젝트 Drive 폴더에 생성 → 목록 추가 → [Google에서 열기]. 실패하면 재시도 표시, 중복 생성 방지.
- 기존 연결: Google Picker로 허용된 Docs/Sheets 선택 → 메타데이터 확인 → 프로젝트에 참조 등록. 원본 이동/복사 없음.
- 행 메뉴: 링크 복사, 연결 해제. 연결 해제 확인창에 Google 원본 보존 안내. 문서명 변경은 Google 편집기에서 수행하고 목록 새로고침 시 메타데이터 갱신.
- 편집은 새 창 Google Docs/Sheets에서 수행. 목록의 등록자는 ACM에서 연결한 사람이며 Google 원본 소유자와 구별한다.
- 빈 목록: ‘등록된 문서가 없습니다’와 생성/연결 버튼.
- Drive 미연결: 상단 ‘공용 Google Drive 연결이 필요합니다’ 표시. 설정 권한자는 [연결 설정], 일반 참여자는 관리자에게 연결 요청 안내.
- 접근 권한 없음/파일 삭제됨/연결 만료 상태는 해당 항목 또는 연결 영역에 표시. 임의 공개 공유는 하지 않는다.

### 1.6 Google Drive Connection and Browser (간편 연결·폴더 탐색)

#### Reference (AMA 참조 확인)
[AMA Drive](https://ama.amoeba.site/drive)를 브라우저에서 확인했다.
- 제목/설명 아래 검색 입력과 연결된 폴더 카드가 표시된다. 카드에는 폴더 이름, 공유 드라이브 구분, 연결 해제 액션이 있다.
- 연결 해제 안내에 ‘Drive에서 삭제되지 않음’을 명시한다.
- 폴더 내부: 전체 폴더로 돌아가기/현재 폴더명, 작성일·파일크기·종류·작성자 정렬, 정렬 방향, 리스트/카드 보기, 다중 선택, 새 폴더, 업로드.
- 빈 폴더는 ‘이 폴더에 파일이 없습니다’로 표시한다.
- 이번 세션은 이미 연결된 상태로 최초 OAuth 연결 화면은 확인하지 못했다. 제목 옆 아이콘은 ‘준비중’ 안내를 열어 연결 버튼으로 판단하지 않았다. 계정/공유/파일을 변경하지 않았다.

#### Entry Points (연결 진입점)
프로젝트의 문서/파일 탭과 설정 → Google Drive에서 동일한 연결 화면을 연다. 설정을 찾아 이동할 필요 없이 미연결 안내의 [Google Drive 연결]로 시작한다. 연결/해제 권한은 기존 설정 관리자에게만 부여하며 일반 참여자에게는 관리자 연결 필요 안내를 표시한다.

#### First Connection (최초 3단계)
```text
Google Drive 연결                                  [닫기]
학원 공용 계정을 연결하면 프로젝트 문서와 파일을 함께 관리합니다.

① 계정 연결        ② 저장 위치 선택        ③ 완료
[Google 계정으로 연결]

② 연결 계정: academy@example.com
[ACM Projects 폴더 자동 생성 (기본)]
[기존 폴더 선택] → 이름 검색 / 내 드라이브 / 공유 드라이브
선택 위치: 학원 운영 > 프로젝트
                                 [뒤로] [이 위치 사용]

③ 연결 완료
연결 계정 · 저장 위치 · [프로젝트로 돌아가기]
```
- 사용자 화면에서 Client ID/Secret, JSON 키, 폴더 ID를 직접 입력하지 않는다. OAuth 앱 설정은 운영 환경에서 사전 구성한다.
- OAuth 동의는 실제 공용 계정 소유자가 수행한다. 취소/권한 거절 시 원래 탭으로 돌아가 재시도 가능. 모바일은 리디렉션 방식으로 연결 가능하게 하고 팝업 차단 안내도 제공한다.
- 연결 성공 후 기존 프로젝트/선택 탭으로 복귀한다. 계정 연결과 저장 위치 확정 상태를 구분해 중단 후 이어서 설정 가능하게 한다.
- 기본 루트 폴더 `ACM Projects` 생성은 [이 위치 사용] 확정 시 수행한다. 프로젝트 폴더는 최초 문서/업로드 시 생성하며 폴더 실패가 프로젝트/이슈/노트 사용을 막지 않는다.
- 기존 위치 선택 시 서버에서 계정의 접근·생성 권한을 검사한다. 내 드라이브와 공유 드라이브는 표시를 구분하며 선택 가능한 위치만 허용한다.

```text
Google Drive                               [연결 관리]
[✓ 연결됨] academy@example.com
저장 위치: 학원 운영 / ACM Projects                 [폴더 열기]
[폴더·파일 검색...................] [새로고침]
┌ 겨울특강 준비 ────────┐ ┌ 교재 개편 ──────────┐
│ 프로젝트 폴더        │ │ 프로젝트 폴더        │
│ [열기]               │ │ [열기]               │
└─────────────────────┘ └─────────────────────┘

[전체 폴더] > 겨울특강 준비
[검색] [정렬 ▾] [↑↓] [목록/카드]       [새 폴더] [업로드]
파일명 / 유형 / 크기 / 등록자 / 등록일 / [열기] [⋯]
```
- 위 탐색기는 프로젝트 파일 탭과 폴더 선택창에서 재사용한다. 학원 공용 Drive 전체를 모든 참여자에게 노출하지 않고, 권한이 있는 ACM 프로젝트에 연결된 폴더·파일만 보여준다.
- [새 폴더]는 현재 프로젝트 폴더 안에서만 생성한다. 목록/카드 선택과 검색·정렬 제공. AMA 다중 선택은 참조 사실이며 초기 ACM 구현은 단건 작업 중심으로 유지한다.
- Google 메타데이터를 제공받지 못하면 작성자·크기를 추정하지 않는다. ACM 등록자/등록일과 Google 소유자/수정일을 혼동하지 않는다.
- [연결 관리]: 계정·상태·저장 위치, [재연결], [저장 위치 변경], [연결 해제]. 위치 변경은 새 프로젝트에만 적용하며 기존 프로젝트의 폴더 ID를 보존한다. 기존 자료를 자동 이동하지 않는다.
- 계정 교체는 기존 자료 접근 여부를 확인하고 접근 불가 항목을 명시한다. 연결 해제 시 생성/업로드 중단을 안내하되 Google 원본과 ACM 프로젝트/파일 참조를 보존한다.
- 연결 만료는 [다시 연결], 파일 권한 부족은 안내, 실패는 [재시도]로 복구한다. OAuth 앱이 미설정이면 계정 인증 버튼 대신 관리자용 설정 필요 상태를 보여준다.

#### Security and Acceptance (권한·완료 기준)
- 공용 OAuth access/refresh token을 참여자 브라우저에 전달하지 않는다. 공용 파일 탐색과 업로드는 서버의 테넌트/프로젝트 권한 검사를 거친다.
- Google Picker가 필요한 공용 계정 폴더/기존 파일 선택은 연결 관리자 전용으로 제한한다. 일반 참여자는 서버가 프로젝트 범위로 제한한 탐색기로 기존 연결 파일을 선택한다. 다른 계정의 임의 파일 연결은 지원하지 않는다.
- 최소 drive.file 범위로 접근할 수 있는 항목을 대상으로 한다. 공유 드라이브 전체 탐색을 위해 권한 범위를 자동 확대하지 않는다. 선택/쓰기 권한과 공유 드라이브 API 지원 여부를 구현 테스트한다.
- 첫 연결 완료/취소/거절/만료, 내 드라이브/공유 드라이브 쓰기 불가, 중복 폴더 방지, 계정 교체/연결 해제 시 원본 보존을 검증한다.
- Google 문서 자체 접근 권한은 ACM 참여 권한과 별개로 유지한다. 링크 열기만으로 Google 공유 권한을 추가하지 않는다.

## 2. Implementation (구현 순서)
1. 최신 main의 별도 작업 디렉터리에서 작업. 기존 IDE 변경 보존.
2. acm-prj 모듈과 프로젝트/참여자/이슈/노트/Drive 연결/파일 참조 테이블 설계. amb_acm_prj_* 명명, 모든 테넌트 데이터 ent_id 검증.
3. CRUD API와 서버 권한 검사, 프로젝트 메뉴/라우트 및 모바일 UI 구현. 프로젝트 생성 즉시 사용 가능.
4. 1.6의 간편 연결 화면과 관리자용 폴더 선택, 참여자용 프로젝트 범위 탐색기, 공용 Google OAuth, 프로젝트 폴더 생성을 구현한다. Drive 파일 생성 실패에도 로컬 프로젝트를 보존하고 재시도 상태 표시.
5. Docs/Sheets MIME type으로 Drive 파일 생성. 신규 폴더/파일 생성 요청의 중복 클릭·재시도 중복 방지. 기존 파일은 허용된 ID로 메타데이터를 서버 확인 후 연결.
6. 업로드 용량 제한/오류 처리, 만료·철회된 연결 복구 안내. 원본 삭제 없는 연결 해제/보관 구현.
7. CRUD·테넌트 격리·권한·OAuth state·외부 API 실패 및 중복 방지 테스트. 모바일/데스크톱 브라우저, 빌드 및 CI 검증.
8. 보고서/PR 작성. 운영 배포와 공용 계정 최초 인증은 별도 단계로 수행.

## 3. Boundaries (범위)
AMA 프로젝트의 제안/견적/계약/정산/자동 동기화, Google 외 저장소, 문서 자체 편집기, 실시간 문서 내용 동기화, Google 파일 자동 공유 및 원본 영구삭제는 이번 범위에 포함하지 않는다.

## 4. Approval (확인)
2026-10-14 사용자가 “구현”으로 v1.2 계획을 승인하여 구현하였다. 공용 계정 방식은 사용자 확인 완료. 프로젝트 참여자와 Google 공유 권한은 별개로 유지하는 기준으로 구현한다.

## 5. Implementation Notes (구현 반영 사항)
- 경로 `/admin/projects`, `/admin/projects/:id`, `/admin/config/drive`. 제안 단계 없이 즉시 생성. 목록은 참여/담당 프로젝트 구분, 상태·검색·최근 수정/이슈 수 정렬.
- 문서/파일은 반응형 행 카드로 구현. Drive 탐색 정렬은 이름·크기·유형이며 생성/수정일·Google 작성자 정렬은 초기 버전에 포함하지 않음.
- DB 목록 새로고침과 Google 파일 열기 시 메타데이터 갱신을 제공. Google 전체 파일 내용 자동 동기화는 없음.
- 공용 refresh token은 암호화된 서버 저장소에만 유지한다. Google Picker 요구사항상 설정 관리자에게만 단기 access token을 메모리로 전달한다(no-store, 브라우저 영구 저장 없음). 일반 참여자는 서버에서 프로젝트 범위를 검사하는 탐색기만 사용한다.
- OAuth 앱 미설정 시 안내가 표시된다. 실제 Google 인증/공유 드라이브 검증과 운영 배포는 미실행.
