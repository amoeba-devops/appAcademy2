# Student Search Selection Plan (학생 검색 선택 작업 계획)

## 1. UI Layout (화면 구성안)

```text
청구 등록 / 월별 생성
학생 검색 [이름 입력              ]
사이트 [전체]  수업 [전체]

검색 결과
예시 학생 A · TPI · 재원     [추가]
예시 학생 B · Trinity · 재원 [추가]

선택한 학생 (2명)
[예시 학생 A · TPI ×] [예시 학생 B · Trinity ×]

청구월 / 납기 / 수납명 / 청구액 / 할인액 ...
[미리보기] [확인 후 생성]
```

검색 전에는 결과 목록을 표시하지 않는다. 추가한 학생은 검색 결과에서 추가 비활성화 또는 선택됨 표시. 선택 목록은 검색어 변경 시에도 유지하며 개별 해제할 수 있다. 학생 없이 미리보기/생성 불가. “한 명씩 선택”은 여러 학생을 개별 추가하는 방식이며 청구당 1명만 허용하는 제한으로 변경하지 않는다.

## 2. Implementation (구현 계획)

1. 기존 CreateDialog를 검색 결과/선택 목록으로 분리하고 전체 선택 제거.
2. 검색어 공백 처리·입력 지연 처리 및 늦게 도착한 결과 혼동 방지. 검색 없이 학생 전체를 표시하지 않도록 조회/렌더링 조건 조정.
3. 선택 상태에 학생 표시 정보를 유지. 기존 사이트/수업 필터 변경 시 선택 초기화 정책과 안내를 일치시킨다.
4. 한국어/영어/베트남어/중국어 안내 반영. DB 구조 변경 없음. 수업 선택 옵션은 학생 검색 여부와 무관하게 사용 가능하도록 유지.
5. 브라우저에서 검색→개별 추가→다른 검색→추가→중복 방지→개별 삭제→청구 미리보기 검증, TypeScript/build 확인.
