# Payment Header Statistics Plan (수납 상단 통계 구현 계획)

## 1. UI Layout (화면 구성안)

선택 월이 2026년 10월일 때:

```text
수납관리                           [청구 등록] [월별 생성]
[◀] [2026년 10월 ▼] [▶]    사이트 [전체 ▼]
┌────────────────────────┬──────────────────┬──────────────────┐
│ 원생현황               │ 9월 수납현황     │ 10월 수납현황    │
│ 재원생: 파랑 막대      │                  │                  │
│ 신규원생: 검정 선      │   완납/미납      │   완납/미납      │
│ 휴원생: 초록 선        │   원형 그래프    │   원형 그래프    │
│ 퇴원생: 주황 선        │                  │                  │
│ 8월    9월    10월     │ 완납 xx% (n건)  │ 완납 xx% (n건)  │
│ 명(변동)   명(재원생)  │ 미납 xx% (n건)  │ 미납 xx% (n건)  │
│ [이력 확인 필요 n명]   │ 금액 미입력 n건 │ 금액 미입력 n건 │
└────────────────────────┴──────────────────┴──────────────────┘
청구월 기준 · 현재 납부상태 · 갱신 시각
[월별 보기] [기간 상세조회] [통계 대시보드]
기존 카드 / 검색 / 목록 / 대시보드 콘텐츠
```

- 이미지처럼 재원생 막대는 오른쪽 축, 신규/휴원/퇴원 선은 왼쪽 축으로 구분한다. 두 축은 0부터 시작하고 각각 명 단위 및 범례를 표시한다. 서로 다른 축임을 명확히 안내한다.
- 수납 완납은 파랑, 미납은 대비되는 주황으로 표시한다. 0%도 텍스트로 읽을 수 있게 하고 데이터가 없으면 중립색 빈 원과 ‘집계 대상 없음’을 표시한다.
- 모든 탭에서 상단 그래프를 유지한다. 공통 월·사이트 선택은 기존 월별 보기/대시보드 상태와 연동한다. 기간 상세조회 자체의 기간 필터와 상단 월별 그래프 기준은 각각 표시한다.
- 모바일은 원생현황 → 이전 월 → 선택 월 순으로 세로 배치한다. 툴팁과 별도로 범례/수치 또는 접근 가능한 표를 제공한다.
- 기준은 [요구사항 분석서](../analysis/REQ-261003-pay-top-statistics.md) §3을 따른다. 예시 그림의 7~9월과 수치는 하드코딩하지 않는다.

## 2. Implementation (구현 순서)

1. 최신 main 독립 브랜치에서 PAY 월·사이트 상태와 원생 이력 저장 경로를 점검한다. 운영 자료가 추가로 필요하면 읽기 전용으로 날짜 이력 보유 여부만 집계한다.
2. 휴원/복귀/퇴원 유효일을 기존 학생 정보/상태 변경 화면에서 기록하도록 보완한다. 상태 변경 이력은 ent_id 격리, 적용일·이전/새 상태·당시 사이트·작성자·감사 시각을 보존한다. 생성/수정/일괄 변경/가져오기 등 관련 상태 저장 경로가 이력을 누락하지 않게 한다. 취소·정정과 동일 날짜 변경 규칙을 명시한다.
3. 명시적인 날짜가 있는 기존 자료만 이관하고 불명확한 과거 상태는 확인 필요로 남긴다. 현재 상태로 과거 3개월을 역산하지 않는다. 기존 재원기간 판정 함수와 역할을 구분하고 불일치 검토 경로를 제공한다.
4. 공통 상단 그래프용 조회를 기존 PAY API에 추가하거나 전용 endpoint로 분리한다. 인자는 month/site만 받고 서버에서 3개월 원생 통계와 2개월 청구 건수, 제외 건수, 이력 품질 및 asOf를 함께 반환한다. 페이지/학생검색/납부상태 목록 필터와 분리한다.
5. 청구는 기존 순청구·잔액 계산을 재사용해 취소/환불/부분납부를 반영한다. 금액 비율인 기존 수납률을 건수 비율로 오용하지 않는다. 여러 사이트의 전체 인원은 학생 ID로 중복 제거한다.
6. 기존 월·사이트 상태를 상위 페이지에서 공유하고 재사용 가능한 상단 통계 컴포넌트를 작성한다. 화면이 요구하는 혼합/원형 그래프를 기존 그래프 방식과 SVG 등 가벼운 방식으로 구현하되 필요한 상호작용과 접근성을 검증한다. 로딩·오류·이력 부족·빈 데이터 상태를 분리하고 4개 언어를 반영한다.
7. 월 변경/연도 경계/사이트 이동/휴원·복귀/당월 중복 상태 변경/첫 입원과 복귀 구분/날짜 누락/여러 청구/0원/미입력/부분납부/환불/취소/테넌트 격리를 테스트한다. 차트 합계는 원장·월 명단과 대사하고 100% 완납/100% 미납/0건 및 모바일을 확인한다.
8. 빌드·관련 테스트·화면 검증 후 보고서를 작성한다. 실제 운영 배포·데이터 이관은 배포 요청 시 백업과 재검증을 거쳐 수행한다.

## 3. Approval and Completion (승인 및 완료)

2026-10-03 사용자의 “구현” 지시로 승인받아 구현했다. [구현 보고서](../report/RPT-261003-pay-top-statistics.md)에 검증·이력 한계·배포 상태를 기록했다. 2026-10-03 운영 배포를 완료했다(9851761).

## 4. Layout Revision Plan (배치 수정 계획, 구현 완료·운영 미배포)

```text
수납관리                                      [통계 닫기 ×]
[이전] [기준 월] [다음] [이번 달] [사이트] [새로고침]
┌───────────────────┬───────────────────┬───────────────────┐
│ 원생현황          │ 전월 수납현황     │ 선택 월 수납현황  │
│ 축소된 혼합그래프 │ 축소된 원형그래프 │ 축소된 원형그래프 │
└───────────────────┴───────────────────┴───────────────────┘
[월별 보기] [기간 상세조회] [통계 대시보드]

닫은 상태:
수납관리                                      [통계 보기]
[기준 월 / 사이트 필터 유지]
[월별 보기] [기간 상세조회] [통계 대시보드]
```

1. 기존 반응형 1열/3열 전환을 제거하고 3열 한 줄을 유지한다. 카드 여백·원형 크기를 줄이고 너비에 비례해 축소한다. 좁은 모바일은 그래프 행만 가로 스크롤하며 페이지 전체 가로 넘침을 막는다.
2. 그래프 우측 상단에 ‘통계 닫기 ×’, 닫은 상태에 ‘통계 보기’를 제공한다. 월·사이트 필터와 기존 수납 기능은 계속 사용할 수 있다. 접힘 상태는 페이지 내 월/사이트/탭 변경 시 유지하고 새로 진입하면 기본 펼침으로 제공한다.
3. 그래프가 닫혀 있을 때 전용 통계 조회를 비활성화한다. 다시 펼치면 조회한다. 버튼 접근성 이름과 4개 언어를 반영한다.
4. 1024/1280px 데스크톱에서 한 줄 배치, 390px에서 그래프 행 가로 스크롤, 닫기/다시 열기, 필터 유지, 빌드를 확인한다.

기존 §1의 모바일 세로 배치는 이번 요청으로 대체한다. 2026-10-03 사용자의 “구현” 승인 후 구현·빌드·화면 검증을 완료했다. 운영 배포는 별도 요청 시 수행한다.
