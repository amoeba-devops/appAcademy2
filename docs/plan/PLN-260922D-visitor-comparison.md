## 1. Plan (작업계획)
검토안 및 2026-09-22 구현 승인을 근거로 진행한다. 최신 main의 별도 작업트리에서 구현하며 기존 작업 파일을 보존한다.
1. 별도 원본·감사 이력 테이블 마이그레이션 추가. 기존 데이터 UPDATE 없음.
2. 비교 조회·아임웹 수정·이력 API 및 권한/동시 수정 검사 추가.
3. GA 동기화에 지표 정의별 원본 기록 추가. 기존 KPI 처리 유지.
4. 대시보드 모든 사이트 탭에 방문자 비교 패널, 아임웹 입력 폼, 이력 제공.
5. 단위·PostgreSQL 통합 테스트 및 양쪽 빌드. 배포는 마이그레이션 선행; 롤백은 앱 복귀, 원본 테이블 보존.

## 2. Screen Layout (화면 구성)
```text
[기존 KPI 카드 및 사이트 비교]
▼ 방문자 원본 비교   일별·사이트 합산 (중복 제거 아님)
[기간·사이트는 대시보드 필터 사용] [아임웹 입력: 관리자]
날짜 | 사이트 | 아임웹 | GA4 | GA 지표 | 차이 | 차이율 | 이력
합계 | 수집 건수/대상 건수 | 완전/부분/혼합 지표 표시

아임웹 입력
[날짜] [TPI / TA / SC] [방문자 수 (빈칸은 미입력)]
[자료 설명] [시간대: Asia/Seoul / 기타]
[저장] [취소]  변경 충돌 시 다시 조회 후 수정

이력
수집/수정 시각 | 출처 | 지표 | 방문자 수 | 자료 설명
```

## 3. Side Effects (영향 관리)
신규 패널은 조회 기간 365일 이하에서 표시한다. 기존 수기·GA KPI 계산, 방문자 분모를 쓰는 비율 및 비용을 변경하지 않는다. 비교 패널은 원본의 산술 차이이며 동일 정의가 확인된 보정 결과로 표현하지 않는다. 미입력과 장애를 0으로 채우지 않는다. 계수 적용 버튼은 제공하지 않는다.

## 4. Validation (검증 계획)
실제 PostgreSQL 임시 스키마에서 마이그레이션 멱등성·원본 및 이력·동시 수정·격리를 검증한다. GA 동기화 실패 및 재수집, 기존 KPI 테스트를 실행한다. frontend-acm 및 backend 빌드로 타입/번들 검증한다. 실제 아임웹 자료의 정확성은 자료 확보 후 검증한다.
