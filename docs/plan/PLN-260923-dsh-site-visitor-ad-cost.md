## 2. Screen Layout (화면 구성도)
아래 값은 예시이며 실제 운영 수치가 아니다.

```text
일별 수동 입력                                       [닫기]
일자 [2026-09-23]

사이트별 마케팅 현황                  GA 최근 수집: 09-23 09:00
사이트   방문자(GA) + 추가 수치 → 최종    사용광고비       효과
TPI        100     + [20   ] → 120        50,000원        3건
TA          50     + [     ] →  50        10,000원        2건

통합        GA 180 + 보정 25 → 205        60,000원        6건

[통합 보기] [TPI] [TA] [SC] [공통 비용]

                                      [취소] [저장]
```
- 상단에서 3사이트 수치와 합계를 함께 본다. 선택 사이트 탭은 광고매체 명세와 기존 추가 입력 범위를 바꾼다.
- 사이트 대시보드에서 모달을 열면 해당 사이트를 선택한다. 상단 3사이트 현황은 유지한다. 보정값은 상단/선택 사이트 표시가 같은 상태를 공유하고 중복 합산하지 않는다.
- 넓은 화면의 마케팅 항목은 `방문자 + [추가] | 사용광고비 | 효과` 한 줄. 모바일은 사이트별 카드/행으로 줄바꿈하며 입력이 경계를 넘지 않게 한다.
- GA 원본/최종 방문자/비용 합계/효과는 읽기 전용. 입력칸은 추가 수치·광고매체·광고비만 활성화한다.
- 미입력 안내는 회색 이탤릭 플레이스홀더. 조회 실패는 재시도 표시, 미수집은 실제 0과 구별한다. 폼 라벨/버튼/오류는 ko/en/vi/zh-CN 지원.

사이트별 대시보드 카드 및 일별 목록:
```text
마케팅 — TPI
방문자 120 (GA 100 + 보정 20) | 사용광고비 50,000원 | 효과 3건
날짜         방문자              사용광고비    효과
09-23        120 (100 + 20)        50,000원     3건
```
보정 없음은 불필요한 `+ 0`을 카드/목록에서 생략할 수 있으나 모달에서는 추가 입력칸을 항상 표시한다.

## 3. Implementation Design (구현 방안)
### 3.1 Storage and API (저장·API)
- 기존 GA와 manual_inputs를 그대로 두고 별도의 일자별 방문자 보정/정책 및 광고비 명세 저장소를 추가한다.
- 제안 테이블: `amb_acm_dsh_marketing_day`(일자 정책·revision), `amb_acm_dsh_visitor_adjustment`(ent/date/site, 추가 정수), `amb_acm_dsh_ad_cost`(UUID, ent/date/site, 매체명, 금액, 삭제 시각), 마케팅 변경 이력.
- 기존 비용의 명세 전환 여부는 일자·사이트별로 명시한다. “명세 0행”이 미전환인지 전부 삭제한 0원인지 구분한다.
- 신규 조회 제안 `GET /api/acm/dsh/marketing-inputs/:date`: 3사이트 GA·보정·최종값·효과·매체 명세·기존 수기값·정책·revision·수집 상태·공통 비용 반환.
- 변경 제안 `PATCH /api/acm/dsh/marketing-inputs/:date`: expectedRevision, 변경된 사이트 보정/비용 행 및 명시 삭제를 원자적으로 저장. 생략은 유지, null은 보정 해제. 클라이언트 전달 GA/합계/효과는 저장하지 않는다.
- 여러 사이트가 한 모달에서 편집되므로 하나의 마케팅 저장 요청으로 일괄 커밋한다. CS/수업 항목까지 같은 저장 버튼에서 변경했다면 부분 성공을 숨기지 않도록 기존 저장 경로와 트랜잭션 통합 또는 영역별 명확한 저장 상태를 구현한다. 기본안은 통합 트랜잭션이다.
- 기존 PUT API의 생략값 null 덮어쓰기 문제를 신규 부분 수정 경로에 복제하지 않는다. 구버전 클라이언트가 명세 전환된 비용/보정을 덮어쓰지 못하도록 관련 필드 변경만 충돌 응답으로 차단한다.

### 3.2 Calculation (집계)
- 공통 산출 함수를 도입해 일별 통합/사이트, 기간 요약, 월별 표, 사이트 비교, CSV가 같은 보정·비용 값을 사용하게 한다.
- 방문자 정책 전환은 사용자가 방문자 보정을 처음 저장한 해당 날짜만 수행한다. 효과는 기존 서버 산식을 재사용한다.
- 기존 비용 명세 전환은 최초 편집 시 가상 “기존 입력(매체 미지정)” 행을 동일 금액으로 한 번만 실체화한다.
- GA 동기화와 수정 요청이 동시에 실행돼도 오래된 집계가 마지막에 남지 않도록 날짜별 재집계 잠금 또는 버전 확인을 공유한다. 저장 성공 후 해당 날짜 집계 완료와 쿼리 캐시 무효화를 보장한다. 재집계 실패를 성공으로 숨기지 않는다.
- 방문자/비용 마케팅 변경이 학생 입학일 누적·교사 통계·기존 수기 병기/CS 원장에 영향을 주지 않도록 범위를 제한한다.

## 4. Work Order (작업 순서)
1. 최신 운영 버전·권한·관련 미병합 PR을 확인하고 기존 GA/수기/비용 저장 분포와 충돌 사례를 읽기 전용으로 조사한다.
2. nullable/추가 테이블 방식의 멱등 마이그레이션과 조회·부분 수정 DTO, 트랜잭션, 감사 이력, revision을 구현한다.
3. 보정/비용 합산 공통 함수 및 일별·기간·비교·CSV 연결을 구현한다. 미편집 과거 날짜 회귀 비교를 수행한다.
4. 화면 구성도에 따라 모달, 사이트 효과, 사용광고비 라벨, 광고매체 행 추가/수정/삭제를 구현한다.
5. 단위·실제 PG·API 및 화면 검증 후 스테이징 배포. 테스트 데이터로 저장→재조회→GA 재수집→수정·삭제 흐름을 검증한다.
6. 운영 배포 시 스키마 선적용→앱 배포→읽기 전용 스모크 확인. 운영 과거 방문자/비용을 임의 일괄 변환하거나 QA 데이터를 입력하지 않는다.
7. 변경 보고서에 배포 버전, 검증 범위, 기존 데이터 유지와 실제 전환 건수를 기록한다.

## 5. Acceptance Tests (검증 기준)
- 3사이트 GA 및 보정 합, 0/빈칸/미수집, 사이트 전환, 기간 경계, GA 재수집 후 보정 보존.
- 동일 보정 재저장 시 중복 가산 없음. 기존 수기 날짜 전환 미리보기와 적용 후 합계 일치. 비용만 수정 시 방문자 산식 유지.
- 매체 1개/여러 개/모두 삭제, 기존 비용 최초 전환과 재저장, 공통 비용 분리, 숫자 범위·이름/금액 누락 검증.
- 한 저장 요청 중간 실패 시 전체 롤백, revision 충돌 409, 멀티테넌트·권한 차단, 다른 사이트/CS·수업 값 보존.
- 효과는 서버 상담+지원과 일치. 방문자/광고비 수정으로 효과가 바뀌지 않음.
- 통합·사이트 카드/일별/기간/비교/CSV 값 일치 및 학생·교사 운영 통계 회귀.
- 기존 CI의 통합 테스트 이미지/구형 fixture 문제는 이번 검증 결과와 구분한다. 신규 테스트는 CI에서 획득 가능한 PostgreSQL 이미지와 최신 스키마로 실행한다.

## 6. Approval (확인)
현재는 요구사항 및 화면 구성 포함 계획 작성 단계이며 앱/운영 데이터 변경은 없다.
프로젝트 [AGENTS.md](../../AGENTS.md) 9.2의 “요구사항 분석서 + 작업 계획서 작성 후 반드시 사용자 확인을 받은 후 구현으로 진행한다”에 따라 확인 후 구현한다.
확인할 기본안: 일별·사이트별 추가 보정(0 이상 정수), 효과는 상담+지원 유지, 기존 비용은 매체 미지정 행으로 금액 보존, 과거 방문자는 편집한 날짜만 새 산식으로 전환.

## Implementation Decisions (구현 확정 사항)
- 2026-09-23 사용자 “진행” 승인 후 구현.
- 방문자 보정과 광고비 전환 상태는 `amb_acm_dsh_marketing_site`에 함께 저장한다.
- `마케팅 저장`과 `CS·수업 저장` 버튼을 분리한다. 마케팅 미저장 변경이 있으면 CS·수업 저장을 비활성화하며 날짜 변경/닫기 시 미저장 내용을 보호한다.
- 캐시 재집계 대신 조회 공통 resolver로 최신 GA4 원본과 보정/명세 비용을 합산한다. GA 동기화와 기존 배치가 원본 캐시를 갱신해도 신규 값을 덮어쓰지 않는다.
- 공통 비용은 최초 비용 전환 시 기존 통합 비용과 사이트 비용의 차이를 보존한다. 음수 차이는 자동 추정하지 않고 충돌로 알린다.
