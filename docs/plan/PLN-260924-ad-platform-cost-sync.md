## 3. Data and API Design (데이터·API 설계)
테이블명은 제안이며 migration 번호는 구현 시 최신 main 기준 할당한다. 모든 테이블은 `ent_id`, UUID PK/명시적 유니크키, 타임스탬프와 표준 인덱스, 필요한 soft-delete를 따른다.

| 저장소 | 내용 |
|---|---|
| `amb_acm_ads_connection` | provider/account, 연결명, 암호화 자격증명, 통화/시간대, 활성 상태, revision, 테스트 결과, 수집 시작일 |
| `amb_acm_ads_site_mapping` | 계정/캠페인 ID→site, 적용 시작/종료일, mapping revision; 기간 겹침·중복 배정 방지 |
| `amb_acm_ads_daily_spend` | 원천 계정/캠페인/보고일 비용, 원본 단위·통화·정밀도·세금 기준·조회시각·run ID. 수기 수정 불가 |
| `amb_acm_ads_cost_adjustment` | 날짜/site/매체별 DELTA 또는 FIXED, 금액, 사유, revision 및 변경 이력 |
| `amb_acm_ads_sync_run` | 실행 트리거, 요청 기간, 계정별/날짜별 완결성, lease/fencing token, 재시도·오류·성공 시각 |
| 비용 적용 정책 | 날짜/site/매체의 수기→자동 적용 상태와 시작일, 기존 행 대체 연결, 감사 이력 |

기존 `amb_acm_dsh_ad_cost`는 수기 행으로 보존한다. 자동 API 데이터를 같은 행에 덮어써서 수기 수정과 혼합하지 않는다. 수기 행의 ‘매체명’은 자유문자이므로 자동 제공자 코드로 추정하지 않는다.

제안 API:
- `GET/POST /api/acm/admin/ad-connections`, `GET/PATCH /:id`: 설정 조회/등록/변경.
- `POST /:id/test`: 제한된 읽기 검증. 아직 저장하지 않은 신규 인증정보 테스트도 별도 DTO로 검증하며 로그에 키를 남기지 않는다.
- `GET/PUT /:id/mappings`, `POST /:id/enable`, `POST /:id/pause`, `POST /:id/disconnect`.
- `POST /:id/sync`, `GET /:id/runs`, `GET /runs/:runId`: 비동기 실행 ID·진행 상태 반환. 수동 재수집은 설정된 최대 기간 내에서만 수행.
- Google OAuth start/callback: 서버 관리 state·사용자·tenant 결합, 짧은 유효기간, 콜백 URI 제한. 토큰은 서버 암호화 저장.
- 기존 `/api/acm/dsh/marketing-inputs/:date`에 자동 비용·보정·완결성 정보를 확장하고 가감/고정 수정은 expectedRevision을 검증한다. 서버 산출 합계는 클라이언트 입력을 신뢰하지 않는다.

## 4. Collection Pipeline (자동 수집 처리)
1. 매일 08:00 KST의 단일 스케줄이 활성 연결을 큐에 등록한다. 재시작 후 놓친 실행은 run 기록을 기준으로 보충하며 다중 서버에서 중복 실행하지 않는다.
2. 계정별 lease/fencing과 고유 실행 키를 확보한다. 외부 HTTP 요청 동안 DB 트랜잭션을 열어두지 않는다.
3. 최근 7개 완료 일자를 일별 캠페인 단위로 조회한다. 페이징·비동기 보고서 폴링·429/5xx 제한 재시도·타임아웃을 어댑터별 구현한다. 인증 실패는 재인증 필요 상태로 종료한다.
4. 통화/시간대/계정/캠페인/기간, 전체 응답 완결성을 검증한다. 당일 미확정값은 수집 범위에서 제외한다. 완료된 무집행 응답과 실패/응답 누락을 분리한다.
5. staging 결과를 계정/날짜 단위 원자적으로 교체한다. 재조회 때 사라진 이전 캠페인 비용도 완결된 결과에서만 제거/0 처리한다. 일부 페이지 실패는 기존 성공 원본을 유지한다.
6. 현재 연결·매핑 revision과 fencing을 재검사한다. 중간에 중지/재설정된 오래된 worker의 커밋을 거절한다.
7. 기존 날짜 잠금 규칙과 순서를 통일해 비용 원본·적용 정책·감사·대시보드 날짜 revision을 갱신한다. 운영자 보정 행은 수정하지 않는다. 동시 보정은 409 충돌로 최신 원본 재확인을 유도한다.
8. `marketing-resolver`에서 자동 원본+보정+별도 수기 비용을 계산한다. 방문자 보정 모드·효과·CS·수업·학생/교사 통계는 바꾸지 않는다.
9. 모든 조회 경로/캐시를 무효화한다. 수집 run 상태는 계정별 성공/실패 및 반영 일자를 보여준다. 자동 수집 실패가 서버 전체 작업을 중단시키지 않는다.

## 5. Access and Reliability (권한·신뢰성)
- 설정·비밀값 교체·테스트·연동 활성화는 기존 설정 메뉴와 같은 ADMIN 가드를 서버에서도 적용한다.
- 광고비 보정은 기존 마케팅 수정 권한을 따르며, 구현 착수 시 현재 역할 정책을 확인한다. 일반 조회 사용자에게 설정 비밀이나 쓰기 권한을 추가하지 않는다.
- 기존 AES-GCM 유틸리티를 재사용하고 응답/로그/감사에는 토큰·시크릿을 제외한다. API 대상 호스트는 매체별 고정 허용목록, URL 임의 입력 기능 없음.
- 광고 읽기만 수행한다. 캠페인 생성·입찰·예산·광고 활성화 변경 API는 구현하지 않는다.
- 연결 해제 시 자격증명을 제거하고 과거 비용·보정은 보존한다. API 버전/토큰 만료/권한 오류는 운영 화면에서 식별 가능해야 한다.

## 6. Migration and Side Effects (전환·사이드이펙트)
- 자동 수집 활성화 전 적용 시작일과 기존 수기 비용 중복을 미리보기로 확인한다. 일괄 과거 덮어쓰기 금지.
- 같은 매체의 기존 수기 비용은 운영자가 ‘자동 비용으로 대체’ 또는 ‘별도 추가 비용으로 유지’를 명시해야 한다. 구분되지 않은 기존 통합 비용은 해결 전 해당 날짜의 자동 적용을 보류한다.
- 매핑이 없는 새 캠페인 비용을 버리거나 사이트들에 임의 배분하지 않는다. 미분류 비용/부분 집계 표시로 후속 매핑을 유도한다.
- 계정 전체 매핑과 캠페인별 매핑을 동시에 합산하지 않는다. 매핑 변경의 과거 영향 범위를 미리보기하고 수기 보정이 다른 사이트로 이동하지 않게 한다.
- 기능 플래그 기본 OFF, additive migration → 서버 → UI → 읽기 테스트 → 계정별 활성화 순서. 기존 GA 자격증명·수집 스케줄·방문자 보정은 변경하지 않는다.
- 롤백 시 수집을 중지하고 원본/보정/이력을 보존한다. 구버전 resolver는 자동 비용을 읽지 못하므로 구버전으로 단순 복귀하면 비용이 사라질 수 있다. 배포 전 활성 날짜별 금액을 export하고, 스키마 호환하는 수정 버전으로 복구를 우선한다.

## 7. Work Packages (작업 순서)
1. 분석서·화면 계획 확인. **네이버 검색광고+GFA 모두 사용 확인 완료.** 실제 계정/통화/시간대·사이트 관계와 GFA API 권한·문서 확인.
2. Meta 최신 권한/운영 토큰 방식, Google Cloud 접근 전환 및 OAuth, Naver 상품별 API를 읽기 PoC로 검증. 성공 전 해당 매체를 ‘연동 완료’로 표시하지 않는다.
3. 추가 스키마·암호화 설정 API·매핑·revision·run 관리 구현.
4. 설정 카드/목록/등록/연결 테스트/OAuth/수집 이력 화면 구현. 네이버 검색광고와 GFA를 구분 등록하며 비용은 동일 네이버 매체 하위 유형으로도 조회 가능하게 한다.
5. Meta/Google/Naver Search/Naver GFA 4개 보고서 어댑터와 일일 스케줄, 중복방지·재시도·재수집 구현. GFA 권한 미확보 시 명시적으로 미연결 상태를 유지하고 나머지 구현·테스트는 계속한다.
6. 비용 resolver·운영자 보정 UI·기존 수기 전환 미리보기·일별/요약/비교/CSV 연결.
7. 단위·PostgreSQL·API 권한·화면 테스트 후 스테이징 배포 및 계정별 보고서 대사.
8. 운영 배포: 기능 OFF 상태로 배포, 운영자가 자격증명을 등록하고 테스트·매핑·시작일 확인 후 활성화. 실제 일일 자동 실행 결과를 별도로 확인·보고.

## 8. Acceptance Tests (인수 검증)
- 매체별 인증 정상/만료/권한 없음/잘못된 계정; 오류 분류와 비밀값 마스킹.
- 테스트 호출이 광고비·캠페인·집행 상태를 변경하지 않음. 설정 변경 시 이전 테스트 성공 무효화.
- 1매체 다계정·1계정 다사이트, 계정 재등록, 중복 캠페인·기간 중첩 방지, 미분류 비용 표시.
- 동일 작업 재실행·다중 worker·수집 중 연결 해제·worker lease 만료에도 비용 중복/구 설정 커밋 없음.
- 원본 30,000 + 보정 -2,000 = 28,000; 재수집 31,000 → 29,000. 고정 28,000 모드는 원본 갱신 후에도 28,000. 원본 복귀·0원·음수 최종액 금지.
- 응답 실패/빈 응답/실제 0/페이징 중단 구분, 부분 실패 시 이전 원본 유지, 완료된 재수집의 감소액/사라진 행 반영.
- 통화/시간대 불일치 자동 반영 보류, micros/decimal 정확성, 사이트 표시액 합=통합 표시액.

- 광고비 수정/수집 동시 요청 revision 충돌, 타 tenant 계정/원본/보정/이력 접근 차단.
