# Admin Mobile Follow-up Plan (모바일 추가 개선 계획)

## 1. Scope (범위)
[분석서](../analysis/REQ-261013D-admin-mobile-detail.md)에 따라 상담 상세를 우선 수정하고 관리자 메뉴 전반을 점검한다. 기존 미커밋 작업은 보존한다. frontend-acm만 변경하며 운영 상담 정보를 수정하지 않는다.

## 3. Audit Matrix (조사 범위)
| 영역 | 점검 동선 |
|---|---|
| 상담 | 목록/검색/칸반, 상세 1~7단계, 점수/일정/첨부/결제 및 확인창 |
| 학생·학부모·강사·직원 | 목록/검색, 긴 이름의 상세, 등록·수정, 비활성화·삭제 이력 |
| 수업·수강·캘린더 | 목록/상세, 반복 일정 모달, 월/주/일 보기, 날짜·사이트 필터 |
| 수납·대시보드·수업통계 | 필터/버튼, 표 영역 스크롤, 그래프 3개 한 줄, 우측 패널 |
| 채팅·알림 | 이전 개선 회귀: 방 선택/복귀, 참여자, 알림함 및 바로가기 |
| 학교·자료·문항·게시글·Q&A·고객불만·설정 | 목록/상세/입력 폼/팝업의 고정 폭과 작업 버튼 |
각 영역은 실제 라우트 및 공유 컴포넌트로 조사한다. 단순 CSS 검색 결과만으로 ‘오류’ 또는 ‘검증 완료’라고 기록하지 않는다.

## 4. Implementation (구현 순서)
1. 상담 안내 블록에 모바일 숨김을 적용한다. 데스크톱 설명과 실제 오류 표시는 유지한다.
2. 상담 상단 버튼/선택 입력을 모바일에서 줄바꿈 또는 세로 배치하고 단계별 패널의 넘침을 수정한다.
3. 라우트별 반응형 체크리스트를 작성해 위 매트릭스의 공통 요소와 개별 화면을 조사한다. 이미 정상인 레이아웃은 유지하며 재현된 문제를 수정한다.
4. 모바일 공통 터치·입력·스크롤 문제는 공용 컴포넌트에서, 페이지 고유 문제는 해당 페이지에서 해결한다. 광범위한 overflow hidden으로 내용을 잘라내지 않는다.
5. 합성 데이터를 사용하는 로컬 브라우저 fixture로 검증한다. 운영 상담·수업·결제·메시지는 테스트로 생성/수정하지 않는다.
6. 화면별 결과와 수정 전후 모바일 증빙, 미검증 범위를 보고서에 작성한다. 구현 완료 후 배포는 별도 요청에 따라 진행한다.

## 5. Verification (검증)
- 폭 320/360/390/430/767/768/1024/1280px. 경계 767px 숨김 / 768px 표시 확인.
- 긴 학생 이름, 영문·베트남어·중국어 번역, 다수 버튼, 긴 파일명·URL·오류 문구로 점검.
- 페이지 전체 scrollWidth 초과 여부와 의도적 스크롤 영역을 구분한다.
- 단계 이동 버튼/저장/취소 접근, 필수 오류 노출, 모달 닫기 및 포커스 복귀 확인.
- TypeScript/Vite build와 변경 동작 중심의 브라우저 확인. 실제 모바일 기기 검증을 수행하지 못한 경우 명시한다.
