# Chat Notification Improvement Plan (채팅 알림 개선 계획)

## 1. Layout (화면 구성안)
```text
모바일 헤더  [메뉴] ACM         [채팅 3] [종 5] [언어]
메뉴        로비채팅                           [3]
방 목록     운영방 [2] / 강사방 [1]

종 알림
[전체 / 안 읽음]                 [알림 설정]
● 운영방 · 새 메시지 2개           [대화 보기]
● 상담 #109 상태 변경             [상담 보기]

알림 설정
기기 알림: 미설정 / 허용 / 차단 / 미지원
구독 연결: 연결됨 / 재연결 필요
[이 기기 알림 켜기] [끄기]
iPhone 일반 탭: 홈 화면에 추가 후 실행 안내
```
종 숫자는 미확인 알림 항목 수, 채팅 숫자는 미확인 메시지 수로 구분하고 중복 합산하지 않는다. 방 단위로 묶어 표시하더라도 메시지별 읽음 경계는 보존한다.

## 2. Implementation (구현 순서)
1. 읽음 처리: 현재 활성 방이 화면에 보이고 탭이 visible/focused이며 메시지를 실제 확인한 경우만 호출. 모바일 방 목록, 숨겨진 탭, 이전 메시지를 읽는 중에는 새 메시지 자동 읽음 금지. 서버는 표시된 마지막 메시지 ID로 읽음 경계를 검증하고 단조 증가 처리; 동시 도착 메시지 보존.
2. 미확인 배지: 관리자/강사 방 목록·메뉴·모바일 헤더에 공통 서버 기준 수 표시. SSE, 앱 복귀, 재연결, 폴링에서 재조회. 99+ 표시 및 오류/재시도 처리. 방을 읽으면 관련 채팅 알림도 같은 경계까지 읽음 처리.
3. 일반 텍스트/파일 채팅의 알림함 적재: 참여자별 전달, 본인 제외, 멘션과 중복 방지, outbox 멱등성 보장. 보관 방은 목록 숨김 상태를 유지하되 별도 알림 끄기와 혼동하지 않도록 정의. 기존 과거 메시지로 푸시를 대량 소급 발송하지 않음.
4. 바로가기: 토스트·종·푸시에 channelId/messageId 포함. 다른 방을 보고 있으면 알림 표시. 상담·일정 상세 경로 유지. 로그인 만료 시 안전한 내부 returnTo 보존; 삭제/접근 불가 대상은 안내 후 목록 이동.
5. Web Push: manifest/Service Worker, 사용자 동작 기반 권한 요청, 인증된 기기 구독 API/해지, PostgreSQL amb_acm_* 테넌트·사용자·기기 관리, VAPID 운영 키 구성. 기존 권한 허용 상태와 실제 구독 성공을 구분. 로그아웃/계정 전환 시 구독 소유자 정리. Push endpoint 검증·비밀값 로그 제외, 만료 404/410 정리, 일시 실패 재시도. 앱 업무/API 데이터의 오프라인 캐싱은 추가하지 않음.
6. 푸시 클릭: 기존 ACM 창 활성화 또는 새 창 열기 후 대상 위치로 이동. 포그라운드 토스트와 중복 억제. 잠금화면 내용은 기본적으로 방/알림 유형 위주로 최소화. 기존 AMA 알림과 별도 설정·중복 정책 유지.
7. 번역 ko/en/vi/zh-CN, 구현 보고서, DB 마이그레이션/설정 포함 배포 절차 준비.

## 5. Overdue Review Alerts (숙제·피드백 지연 알림)
- 대상: 실제 수업 유형 CAL 이벤트/반복 회차, 취소·삭제 제외, 담당 강사와 종료 시각 기준. 일반 개인/행사 일정은 제외. review 행이 없어도 검사한다.
- 제안 완료 기준: 피드백은 빈 HTML을 제외한 실제 내용 저장; 숙제는 ASSIGNED 상태에서 내용 또는 유효한 HOMEWORK 첨부 존재, 또는 NONE 명시. 둘 중 하나라도 미완료이면 알림. 사용자가 이 기준으로 진행 승인.
- 1분 주기 작업이 종료+5h/+10h 경과를 검사하여 단계별 1회만 outbox에 기록한다. 수업·단계별 유니크 키로 다중 워커/재시도 중복 방지. 수신자는 현 담당 강사와 같은 학원의 활성 ADMIN/APP_ADMIN이며 동일 사용자는 중복 제거. 발송 직전 완료·취소·담당자 변경을 재확인한다.
- 알림 내용: 수업명/종료 시각/5시간 또는 10시간 경과/미완료 항목. 클릭 시 관리자 또는 강사 포털의 해당 수업 피드백 영역으로 이동.
- 앞선 계획의 종 알림 및 구독된 기기 Web Push 전달 경로를 사용한다. 자동 학부모 메일 발송은 하지 않는다.
- 서비스 복구 시 두 단계가 모두 지난 수업에는 최신 단계 알림만 보내어 연속 두 건 발송 방지. 5시간 알림 후 완료하면 10시간 알림은 미발송.
- 도입 전 과거 전체 수업에 대량 소급 알림을 보내지 않도록 활성화 기준시각을 기록한다. 종료일 변경/반복 예외/시간대/중복 스케줄러를 테스트한다.
- 기존 CLS 24h SLA와 CAL 적용 대상 중복 여부를 확인하고 같은 수업에 중복 알림이 발생하지 않도록 분리한다.

## 6. Teacher Feedback Email (강사 학부모 메일 발송)
```text
강사 포털 > 수업 상세 > 피드백
[피드백 편집 영역]
[저장]                         [학부모 메일 발송]

학부모 메일 발송
학생 / 연결 학부모 / 등록 메일 / 선택
[저장된 피드백 미리보기]
[닫기]                         [메일 발송]
발송 결과: 성공 / 메일 없음 / 실패
```
- 담당 강사만 버튼/수신자 조회/발송 API 사용. 서버에서 테넌트·수업 접근·담당강사 및 학생-학부모 연결을 매 요청 검증한다. 임의 외부 주소 입력은 제공하지 않는다.
- 저장된 피드백으로 발송. 저장되지 않은 변경이 있으면 저장 안내 후 진행하며 오래된 피드백을 조용히 발송하지 않는다. 저장만 했을 때 자동 발송하지 않는다.
- 기존 FeedbackMailerService 및 이메일 전용 수신자 선택 UI 재사용/확장. 알림톡 발송 권한까지 확대하지 않는다. 메일 본문은 기존처럼 피드백만 포함한다.
- 이메일 없음/SMTP 미설정/피드백 없음은 사유 안내. 부분 성공/실패를 표시하고 실패 대상 재시도 제공. 중복 클릭과 요청 재시도는 멱등 처리하며 사용자가 의도한 재발송은 구분한다.
- 발송 기록에 담당 강사·수업·수신 대상·시각·결과 및 전송 피드백 버전/스냅샷 식별 정보를 기록한다. 학부모 간 주소 노출 없이 개별 발송한다.
