# Admission-based Student Count (입학일 기준 학생수)

## 1. Approved Requirement (확정 요구사항)

사용자 승인: “학생수도 입학일 기준으로 처리”. 신규학생뿐 아니라 운영 학생수·기초잔액·기간 말 학생수를 입학일 기준으로 계산한다. 통합은 TPI + TA + SC 합계다. 원본 수업일자·수기값·교사 집계는 유지한다.

## 2. Calculation (계산 기준)

- 최초 등록 기간의 시작 경계를 학생 입학일로 대체하여 읽기 시 계산한다. DB 날짜를 변경하거나 일별 숫자를 수기로 보정하지 않는다.
- 퇴원일 당일부터 제외한다. 이후 확인된 재입학 기간은 그 기간 시작일에 복귀하며 퇴원과 재입학 사이 공백을 재원으로 세지 않는다.
- 동일 사이트·학생의 겹치는 유효 기간은 한 명으로 계산한다. 입학일보다 이른 수업기간을 학생수 근거로 쓰지 않는다.
- 입학일 누락은 수업시작일로 대체하지 않고 집계에서 제외, PARTIAL 표시한다. 날짜가 없는 수업 정보라도 입학일이 있으면 집계할 수 있다. 취소/미확정 기간을 복원하지 않는다.
- 미래일은 기존처럼 계산값 미제공. 수기 0은 `0`으로 보존하며 미입력만 괄호를 숨긴다.
- 신규학생 지표는 기존대로 학생별 최초 입학일 1회, 퇴원학생은 기존 확인된 종료 이벤트를 유지한다. 재입학/중복 기간이 있는 경우 단순히 ‘최초 입학 인원 - 모든 종료 이벤트’로 계산하면 왜곡되므로 학생수는 입학일을 적용한 유효 재원 기간의 학생 수로 산출한다.
- 사이트 이동 이력이 있는 경우 최초 기간 판정은 사이트 필터 전에 수행한다. 사이트별 기간 귀속과 통합 합산 규칙을 유지한다.

## 3. Screen Layout (화면 구성도)

```text
대시보드 [통합] [TPI] [TA] [SC]
운영 · 계산값 (수기값)
날짜          신규학생 (입학일)    퇴원학생    학생수 (입학일 기준)
2026-09-21    0                   0           48
2026-09-22    3                   0           51
2026-09-23    0                   0           51
```

수기값이 있으면 `51 (50)` 형식. 표·요약·차트·CSV가 공용 운영 API 산출값을 사용한다. 학생수 제목은 4개 언어에서 변경한다.

## 4. Validation & Release (검증·배포)

- 입학22일/수업23일, 기초잔액, 퇴원 당일, 재입학 공백, 중복 기간, 누락 입학일, 수기0, 미래일, 교사 비영향을 회귀 검증.
- PostgreSQL 통합 테스트로 테넌트 격리와 날짜 원본 보존 확인.
- 운영 읽기 전용 스냅샷으로 2024-12-02~2026-09-23 전체 사이트 합계 및 22·23일 각 51명 검증.
- DB 마이그레이션 불필요. 애플리케이션 배포 후 반영된다. 롤백은 이전 앱 이미지 복원.
