# Level Test Schedule Reset Plan (레벨테스트 일정 초기화 계획)

## 1. Scope (범위)
[요구사항 분석](../analysis/REQ-260923-csl-level-test-schedule-reset.md)을 기준으로 날짜·시간 초기화와 해당 CAL 일정 정리를 함께 구현한다. 시험 결과·강사·상담 단계는 유지한다.

## 2. Screen Layout (화면 구성도)
```text
상담 상세 > 레벨테스트
시험       응시예정일          담당강사      상태
MAP        [📅 2026-09-25]     강사명        대기

┌ MAP 일정 설정 ─────────────────────────┐
│ 응시예정일 [2026-09-25]                 │
│ 시간       [14:00]                     │
│ 담당강사   [강사명 / 미지정]            │
│                                       │
│ [일정 초기화]     [취소] [저장 + 일정등록]│
└───────────────────────────────────────┘

┌ 일정을 초기화할까요? ──────────────────┐
│ 응시예정일과 시간을 지웁니다.          │
│ 연결된 수업일정도 삭제됩니다.          │
│ 담당강사와 시험 결과는 유지됩니다.     │
│                     [취소] [초기화]    │
└───────────────────────────────────────┘
```
초기화 버튼은 텍스트+아이콘의 테두리 버튼, 최종 확인은 주의색으로 구분. 처리 중 중복 클릭·저장 방지, 성공 시 팝업 닫기·목록 갱신·완료 알림. 실패 시 창을 유지하고 원인을 표시. 4개 언어 번역 적용.

## 3. Tasks (작업 순서)
1. 시험별 일정 초기화 전용 API와 요청 검증·권한을 추가한다. 기존 시험이 없으면 새 시험을 만들지 않는다.
2. 상담·시험·연동 CAL의 테넌트와 연결 소유를 검증하고, 날짜·시간·CAL 소프트 삭제·연결 해제를 트랜잭션으로 묶는다. 기존 단독 CAL remove 호출만으로 부분 성공시키지 않는다.
3. 반복 요청/동시 예약 변경을 제어한다. CAL 미존재·이미 삭제는 초기화 성공으로 처리하되 잘못된 연결은 다른 일정 삭제 없이 거부한다.
4. 현재 CAL에는 복구 API가 없음을 확인했다. 삭제 이력을 보존하고 상담에서 재예약한다. 삭제 사유·작업자 이력을 남긴다. 외부 미팅이 붙은 예외는 자동 삭제하지 않는다.
5. 팝업 초기화·확인 동작과 React Query 상담/시험/CAL 캐시 갱신을 연결한다. 취소 후 다시 열 때 서버 저장값으로 입력 상태를 복원한다.
6. 단위·PostgreSQL 통합 테스트, 프론트·백 빌드, 스테이징에서 초기화→재예약 검증 후 운영 배포한다. 운영 데이터에 테스트 예약을 만들지 않는다.

## 4. Approval (구현 확인)
2026-09-23 사용자 “진행”으로 구현 승인. 날짜·시간·연동 일정 초기화를 구현했으며 운영 데이터는 검증 목적으로 변경하지 않는다.
