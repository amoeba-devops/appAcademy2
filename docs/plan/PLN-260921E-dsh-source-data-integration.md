# Dashboard Integration Plan (대시보드 원장 연계 작업계획)

## 1. Approach (구현 방안)

[요구사항 정의서](../analysis/REQ-260921E-dsh-source-data-integration.md)를 따른다. 기존 일별 KPI 저장소를 폐기하지 않고 원천 집계 서비스와 지표 메타데이터를 공통화한다. **현재 관리 현황은 원장 조회**, **기간 사건 실적은 일별 집계**, **과거 인원은 이력/확정 스냅샷**으로 분리한다. 프론트엔드가 목록 페이지를 순회하며 인원을 계산하지 않는다.

| 방안 | 장점 | 문제 | 선택 |
|---|---|---|---|
| 기존 KPI 쿼리만 STD/TCH로 교체 | 수정량 적음 | 현재 상태를 과거에 복제, 수동 잠금/배정 의미 문제 잔존 | 제외 |
| 매 조회마다 모든 과거 원장 재계산 | 최신 반영 | 과거 이력 없으면 오답, 대량 기간 성능 부담 | 현재 현황에 한정 |
| 현재 원장 조회 + 사건 캐시 + 검증된 이력 | 모집단·시간 의미 유지, 점진 전환 | 품질 메타데이터와 이력 필요 | 권장 |

## 2. Screen Layout (화면구성도)

기존 대시보드 4개 패널과 사이트/기간 선택은 유지한다. 수치는 예시 대입 없이 동적 값 위치로 표시한다.

```text
대시보드        [통합][TPI][TA][SC]   [시작일] ~ [종료일]
기간 실적 기준: {기간 종료 또는 오늘}   최종 갱신: {시각}
┌ Marketing ┐ ┌ CS ──────────────┐ ┌ Operating ─────────┐ ┌ Class ─────────────┐
│ 기존 지표 │ │ 상담 접수  {건}  │ │ 재원 학생 {명}     │ │ 배정 학생 {명}     │
│ 유지      │ │ 등록 신청  {건}  │ │ 재직 강사 {명}     │ │ 배정 강사 {명}     │
│           │ │ 완료 체험  {회}  │ │ 기간 입학 {명}     │ │ 완료 수업 {시간}   │
│           │ │ 출처: 상담관리   │ │ 출처: 학생·교사관리│ │ 출처: 배정 / CLS   │
└───────────┘ └─────────────────┘ └────────────────────┘ └────────────────────┘
현재 현황: {조회 시점} / 과거 현황: {선택 기준일·지원 여부}
지표 상태: 자동 / 부분 집계 / 과거 이력 없음 (관련 항목 옆에만 표시)

[사이트 비교: 기존 범위]   [일별 상세 표] [CSV]
지표 클릭 → 집계 근거 패널
  정의·기준일·필터·원천 메뉴 / 포함 건수 / 누락·제외 사유
  [같은 조건으로 원장 보기]
```

과거 기간 선택 시 Operating/배정 현황은 해당 시점 이력이 있으면 과거값, 없으면 ‘과거 이력 없음’을 표시한다. 현재값을 함께 보여줄 경우 별도 현재 현황 행으로 구분한다. 인원 열 제목은 ‘기준일 인원’, 사건 지표는 ‘기간 합계’로 구분한다. 제거 요청했던 사이트 합계 차이 안내 박스는 다시 추가하지 않는다.

### 2.1 Minimal Form Additions (필요한 입력 항목)

```text
상담 > 등록상담   [등록 신청 여부] [신청일 YYYY-MM-DD]
교사 > 기본정보   [입사일] [상태] [퇴직일: 퇴직 선택 시]
상담 > 레벨테스트 [시험 종류] [실시 상태] [실제 실시일]
```

학생 입학일/퇴원일은 기존 필드를 재사용한다. 상태 변경은 유효일을 받아 이력을 남긴다. 기존 미입력 자료에 생성일/오늘을 일괄 대입하지 않는다. 실제 시험일은 일정일과 동일함이 확인된 경우에만 승인된 이관 규칙으로 채운다.

## 3. Work Packages (작업 단위)

### P0 — Source Audit and Definition Lock (원천 대사·정의 확정)

- 운영 읽기 전용 집계: 학생 ACTIVE/INACTIVE/WITHDRAWN·삭제·사이트별 ID 수, 입학/퇴원일 누락·모순, 강사 상태/isInstructor/입사일 누락, 배정 고아 참조/중복, CSL 날짜·완료 상태·시험 종류 분포.
- 일별 KPI의 수동 잠금/기존 수동 입력과 원장 결과 차이를 지표별·일자별로 산출한다. 09-11/12, 09-21/22 인원 변화 원인도 확인한다.
- CLS 세션과 CAL 수업통계의 원천/ID 매핑·실시 상태·시간 정의를 비교한다. 이번 조사에서 CAL 통계와의 정합성은 확정하지 않았으므로 P0 완료 조건에 포함한다.
- 사용된 데이터가 계정 UUID인지 학생/교사 마스터 UUID인지 확인한다. 이름 매칭으로 우회하지 않는다.
- 결과물: 개인정보 없는 집계 대사표, 누락 건수, 지표별 적용 시작일·정의 버전·기존 수동 값 보존 방안. 이 결과 전에는 과거 값 일괄 재계산 금지.

### P1 — Directly Available Metrics (현재 입력값 연계·비노출 병행 계산)

- 공통 원천 집계 서비스에 CSL 접수/완료 체험/시작/종료, STD 현재 재원/날짜 있는 입학·퇴원, TCH 현재 재직/날짜 있는 입사, STD↔TCH 현재 배정 현황 구현.
- 현재 현황은 실시간 조회 또는 저장 후 무효화되는 짧은 캐시를 사용한다. 배정 현황은 새 지표 코드로 기존 Class 실적과 분리한다.
- 총수업 기존 산식은 시간 단위로 정정한다. 완료 실적 원장이 준비되지 않은 부분은 산출 불가/부분 상태로 표시한다.
- 일별 DTO/요약/CSV에 지표별 품질·출처·정의 버전을 전달한다. 고정 0과 지표별 null을 구분하도록 스키마/타입을 보강한다.
- 자동 지표는 기존 일별 행을 수정하지 않는 버전별 별도 집계에 먼저 기록한다. 수동 전체행 잠금 해제나 기존 행 재계산은 P1에서 수행하지 않는다. 지표별 우선순위·전환일·호환 API·롤백 검증이 완료된 P4에서 신규 화면 읽기 경로만 전환한다.

### P2 — Event Dates and History (정확한 사건일·이력)

- 등록 신청일, 강사 퇴직일, 시험 실제 실시일을 PG 마이그레이션/DTO/입력 UI에 추가한다. nullable로 시작하고 신규 유효 입력에 조건부 검증을 적용한다.
- STD/TCH 상태 유효기간, 학생 사이트 변경, 학생↔교사 배정 이력을 보존한다. 재입학/재입사·휴원/복직 같은 여러 기간을 기록할 수 있어야 한다.
- 모든 새 테이블은 `amb_acm_*`, `ent_id`, UUID, TIMESTAMPTZ 및 표준 감사 필드를 사용한다. 구체적 테이블명은 설계에서 확정한다.
- 기존 자료는 근거 있는 날짜만 마이그레이션한다. 이력 시작 이전은 알 수 없음으로 유지하며 운영 확인 후 선택 구간만 재구축한다.
- 등록 신청/퇴직/MAP 실시 지표를 확정 원천으로 전환한다. 완료 상태 쓰기 경로가 일관되지 않은 시험은 legacy 상태 문자열만 믿지 않는다.

### P3 — Reliable Refresh and Reconciliation (갱신·정합성)

- 원장 저장 트랜잭션과 재계산 요청을 원자적으로 기록하는 outbox 또는 기존 신뢰 가능한 큐를 사용한다. 같은 날짜·지표 재계산을 병합하고 멱등 처리한다.
- 변경 전/후 사건일, 상태 유효기간, 이전/신규 사이트를 모두 invalidation 대상으로 계산한다. 테넌트 목록은 상담 존재 여부에 의존하지 않는다.
- 일별 전체/사이트 값을 같은 집계 실행 버전으로 게시한다. 현재 구현의 별도 트랜잭션으로 인한 부분 완료를 방지한다.
- 실패는 원장 저장을 취소하지 않고 pending/failed로 표시하며 재시도·운영 재실행을 제공한다. 야간 배치는 안전망으로 유지한다.
- 드릴다운과 원장 목록에 동일한 조건/식별자 집합을 적용한다. 기간 고유 인원을 일별 distinct 합으로 계산하지 않는다.

### P4 — Release (전환·배포)

1. 소스/집계 백업 및 배포 전 결과 보존. 원천 데이터 원본은 수정하지 않음.
2. 새 산식 shadow 계산 및 구버전과 차이 보고. 단위·의미 변경은 정상 차이로 별도 설명.
3. 기능 플래그로 통합 화면부터 적용. 이미 승인된 UI 배치 유지, 네 언어 문구 추가.
4. 현재 현황·사건 지표 검증 후, 근거 있는 과거 기간만 재계산. 이력 불완전 기간은 제외.
5. 스테이징/운영 스모크와 원장 대사, 작업 결과 보고서 작성.
6. 롤백은 기능 플래그/정의 버전을 이전으로 복구한다. 새 입력 날짜·감사 이력은 삭제하지 않는다.

## 4. Tests (검증 계획)

| 사례 | 기대 결과 |
|---|---|
| 학생 한 명에 강사 두 명 | 재원 1, 배정 학생 1, 배정 강사 2 |
| 강사 한 명에 학생 여러 명 | 강사는 1명으로 집계 |
| 휴원/퇴원·휴직/퇴직·비강사 | 권장 모집단에 따라 제외, 별도 사유 확인 |
| 메모만 수정 | 등록 신청일/입학일 실적 이동 없음 |
| 입학일/퇴원일/신청일 소급 수정 | 이전·새 날짜 모두 수정, 31일 이전도 반영 |
| 재입학/재직 복귀 | 과거 입퇴 사건 보존, 시점별 인원 정확 |
| 시험 예정/취소/완료, non-MAP | 완료 MAP만 실적, 예정 별도 |
| 동일 시험 점수 과목 세 개 | 1회로 집계 |
| 60분·90분 완료 수업 | 2.5시간, 신청 수업시간과 분리 |
| 원천 없음/누락/조회 실패 | 0과 null/부분/오류 상태 구분 |
| 수동 방문자·비용 입력일의 학생 수정 | 방문자/비용 보존, 자동 학생 지표 갱신 |
| 교사 계정 미발급 | 유효한 교사 마스터라면 인원 포함 |
| 사이트 미지정/복수 사이트 배정 | 누락 또는 이중 합산 없는 정의별 집계 |
| 타 테넌트·삭제/복구·중복 링크 | 테넌트 격리, 원장과 동일한 포함 집합 |
| 미래일·월말·KST 경계·부분 과거 | 미래 제외, 기준일 명시, 잘못된 증감률 없음 |
| 카드/표/CSV/원장 | 동일 정의·버전·필터에서 값 일치 |
| 배치 실패·동시 수정·재실행 | 중복 없는 멱등 갱신, 부분 게시 방지 |

백엔드 집계 단위 테스트와 실제 PostgreSQL 통합 테스트, 프론트 빌드·운영 브라우저 대사를 수행한다. CI의 continue-on-error 작업은 실제 로그를 확인하고 녹색 상태만으로 통합 테스트 통과를 보고하지 않는다.

## 5. Deliverables and Approval (산출물·확인)

산출물: 원천 대사표, 확정 지표 사전, DB/API 설계·마이그레이션, 원장 집계 서비스, 카드/표/CSV 개선, 재계산 운영 절차, 배포 결과 보고서. P0로 정의를 확정하고 P1은 비노출 계산으로 검증한다. 이력 기록 기반과 P3 갱신 보장은 첫 운영 전환 전에 완료하고, P2의 개별 날짜 지표는 준비된 항목부터 P4로 전환한다. 날짜 미입력·이력 부재를 발견하면 해당 지표만 보류한다. 가능한 현재 지표를 우선 제공하되 이력·갱신·호환성 게이트는 생략하지 않는다.

이번 요청에 따라 요구사항·검토·작업계획 작성까지만 완료한다. AGENTS.md §9.2의 “요구사항 분석서 + 작업 계획서 작성 후 반드시 사용자 확인을 받은 후 구현” 규칙에 따라 계획 확인 후 구현에 착수한다.

## 6. Side-effect Review (최종 영향도 점검)

### 6.1 Findings and Controls (위험·통제)

| 위험/영향 범위 | 코드 근거·발생 조건 | 최종 통제 및 검증 |
|---|---|---|
| 과거 수동 통계·방문자·비용 손실 | `recomputeDay` 전체행 잠금, `daily-kpi-manual`과 `manual-inputs` 두 입력 경로 | 기존 KPI/수동 원본은 수정 없이 보존. v2 별도 저장/조회 후 지표별 전환. 방문자·비용은 기존 값과 정확히 일치하는지 회귀 대사 |
| 기능 플래그만으로 롤백 불가 | 동일 테이블 값을 덮어쓴 뒤 읽기 플래그만 복구하는 경우 | 정의 버전별 스냅샷/집계 저장 및 구버전 읽기 경로 유지. 전환 후에도 기존 writer가 기존 통계를 유지하는지 확인. 복구 시 데이터 재작성 불필요한 구조로 설계 |
| 요약·일별 표·CSV 다른 값 | `KPI_FIELDS`, `isSnapshot`, `CATEGORY_METRICS`, `METRIC_TO_FIELD`, DB metric definition이 각각 존재 | 지표 사전을 공통 계약으로 정의하고 모든 매핑·단위·표시 코드를 동시 갱신. 새 배정 코드는 스냅샷으로 분류. 코드 누락 시 0 반환 대신 검증 실패 |
| 기존 클라이언트 null 처리 오류 | 기존 DTO/entity에는 number 및 non-null/default 0 필드 존재 | 기존 응답 의미는 유지하고 v2 엔드포인트 또는 명시적 버전 협상으로 전환. 선택된 v2 값·품질을 별도 구조로 제공; 숫자 필드만 무조건 nullable로 바꾸지 않음 |
| Marketing 효과·사이트 비교 변경 | 효과=상담+지원, 통합/사이트 원천 및 수동 값 혼재 | 효과는 의존 지표와 동일 정의 버전으로 계산. 하나가 미확정이면 효과도 부분/미확정. CS만 전환하고 효과/사이트 비교는 구원천을 쓰는 조합 금지. 영향값을 전환 대사표에 포함 |
| 현재 인원이 과거 실적으로 섞임 | 기간 카드가 현재값을 대체 사용하거나 여러 날짜 현재 인원을 복제 | 현재 현황은 별도 `currentSnapshot`과 시각, 기간 결과는 `rangeMetrics`로 구분. 과거값 없는 일별 행에 현재값 복제 금지. 인원 그래프는 이력 시작 이전 공란 |
| 관리 메뉴 기본 건수와 불일치 | STD CURRENT는 ACTIVE+INACTIVE, 대시보드 권장 재원은 ACTIVE. 교사 기본 목록은 비강사 포함 가능 | ‘재원(ACTIVE)’, ‘재직 강사(ACTIVE·강사)’ 조건 명시. 드릴다운은 동일 필터를 적용하며 필터 없는 목록 total과 비교하지 않음 |
| 사이트 합계 오해 | 교사 소속 없음, 사이트 간 배정 중복, 과거 사이트 이동 이력 없음 | 1차 통합만 전환. 사이트 CS는 통합과 같은 버전 보장. 배정 강사 통합은 distinct, 사이트 합산 금지. 과거 사이트는 근거 없으면 산출 불가 |
| 학생·교사 기존 저장이 막힘 | 미입력 legacy 자료에 새 날짜 필수 검증 적용 | 신규 상태 전환/사건 입력 시에만 날짜 검증. unrelated 필드 수정은 허용. 기존 클라이언트·이관 API 호환 정책과 오류코드 명시. 계정·로그인·AMA 연동을 통계 때문에 변경하지 않음 |
| 가져오기·동기화 누락 | `site-import.service`, `withdrawn-import.service`, `scripts/import-tch-profiles.cjs` 등 일반 service를 우회 | P0에 UI CRUD·삭제/복구·사이트 일괄 변경·엑셀/API 이관·AMA 동기화·운영 SQL 전체 writer 목록 작성. 각 경로에 이력/outbox를 연결하거나 운영 재계산 절차를 필수화. 과거 이미 실행된 경로는 이력 있다고 추정하지 않음 |
| 늦게 시작한 이력으로 초기 변경 유실 | P1부터 노출하고 P2에서 이력을 뒤늦게 기록 | 최초 신규 지표 공개 전에 상태·배정 이력 기록을 시작. 기준선에는 ‘해당 시각에 관찰한 상태’만 기록하며 입학/입사 시점으로 소급 생성하지 않음 |
| 신청 취소·재신청/재입학 중복 | 단일 날짜 필드 덮어쓰기, 같은 날 여러 전환 | 이벤트 ID·종류·유효일·정정/취소 관계를 보존. ‘신규학생’은 최초 확인 입학 ID 기준, 재입학 별도 사건. 이탈은 일별 고유 상담 기준으로 문서화하고 기간 고유 인원과 구분 |
| 시험 완료·데모 상태와 업무 흐름 충돌 | 시험 상태 필드의 legacy 주석과 현재 쓰기 경로가 혼재 | 실제 DTO/service 및 전환 guard를 확인해 기존 상태 입력을 재사용. 대시보드 집계가 상담 단계·CAL 일정·결제 상태를 변경하지 않음. 시험 점수 입력시각을 실제 시험일로 간주하지 않음 |
| 순서 역전·재시도로 과거 결과 덮임 | 동시에 원장 수정/수동 입력/야간 작업, 오래된 큐 작업 후 완료 | 원장 revision 또는 계산 watermark로 최신성 비교, 멱등 키에 테넌트/날짜/지표/정의 버전 사용. 오래된 결과 게시 거부; 이벤트 before/after ID·날짜 보존 |
| 장기간 재계산 DB 부하 | 최대 365일 조회, N일×N지표 반복 SQL, 이관 직후 대량 요청 | set-based 기간 집계, tenant/date 인덱스, EXPLAIN 확인, 작은 청크와 동시성 제한. HTTP 조회에서 장기 backfill 실행 금지. 실패 지표만 재시도 |
| 인원·연락처 노출/권한 우회 | 대시보드 사용자가 상세 원장 권한 없이 드릴다운·CSV 호출 | API에서 기존 역할·테넌트 권한 검사. 집계 응답은 개인정보 제외, 원장 상세는 원천 권한 필요. 캐시 키에 tenant/site/version/asOf 및 필요한 권한 범위 포함 |
| 반응형·다운로드 회귀 | 패널에 지표·출처 추가, CSV 헤더/단위 변경 | 기존 4개 패널 배치 유지, 한국어/영어/베트남어/중국어·모바일 검증. v2 CSV는 버전/기준일/단위 명시, legacy CSV는 기존 계약 유지 |

### 6.2 Fixed Decisions (계획상 확정할 기본 동작)

1. 자동 원장 값으로의 전환은 **기존 값 삭제가 아니라 새 버전 선택**이다. 방문자·비용 수동 입력은 기존 원천을 유지한다. 미전환 과거는 legacy 표시 또는 비교 제외한다.
2. 기존 Class 학생/교사 지표는 보존하고 새 배정 현황 코드를 추가한다. 신구 의미가 다른 시계열을 이어 붙이지 않는다. UI 적용 시 카드·표·내보내기의 선택 버전을 통일한다.
3. 재원/재직 현재값은 현황 기준, 입학/입사/퇴원/퇴직은 사건 기준이다. 현재 RESIGNED라는 이유로 과거 입사 사건을 제외하지 않는다. 삭제 오류 정정과 정상 퇴직을 구분한다.
4. 배정 강사는 `ACTIVE && isInstructor=true`만 포함한다. 재원 학생에 유효한 해당 강사가 한 명 이상 있을 때 배정 학생으로 센다. 계정이 없는 마스터도 포함하고 텍스트 강사명만 있는 자료는 ‘미연결’로 별도 집계한다.
5. 입력률이 낮아도 현재 현황을 구현할 수 있지만 미확정 사건의 기간 합계는 부분 집계로 표시한다. ‘알려진 값 0’과 ‘정확히 0’을 분리한다.
6. snapshot 기준시각과 기간 실적 종료일을 구분한다. 캐시 만료/자정 갱신도 KST 기준이며 현재일 변경 시 재조회한다.

### 6.3 Release Dependencies and Gates (의존성·출시 게이트)

```text
P0 원천·writer·정의 대사
  → 확장 스키마/API 계약 + 기준선·이력 기록 + P3 갱신 기반
  → P1 비노출 병행 집계 / 준비된 P2 사건 지표
  → 신구 차이 대사·권한·회귀·롤백 리허설
  → P4 테넌트/지표별 전환 → 모니터링 → 범위 확대
```

| 게이트 | 공개 전 필수 증거 |
|---|---|
| G0 정의 확정 | 지표별 원천/단위/모집단/유효일/누락/전환일/삭제정책 표; CAL/CLS 연계 미확정 지표는 공개 제외 |
| G1 입력 경로 | 전체 writer별 저장·이력·갱신 경로 표, 실패 시 재처리 방법, 기존 편집/이관/AMA 동기화 회귀 통과 |
| G2 데이터 대사 | 샘플 기대값 대신 동일 테넌트·필터에서 원장 ID 집합과 건수 정확히 일치. 수동 방문자/비용 원본 차이 0, 정의 변경 차이는 전부 설명 가능 |
| G3 성능·신뢰성 | 일반 저장 후 재조회 5초 내 또는 명시적 pending; 31일/365일 대표 조회의 p95가 기존 대비 20% 넘게 악화하면 원인 개선 후 재검증. 이는 제안된 승인 기준이며 현재 측정 결과 아님 |
| G4 배포 호환 | 구 프론트+새 백엔드, 새 프론트+새 백엔드, 플래그 OFF, 큐 backlog, 캐시 전환 및 v1/v2 CSV 검증. 구 백엔드에서는 새 기능 비활성화 |
| G5 롤백 | 신버전 OFF 즉시 구 조회 복구, 신버전 worker 게시 중지, 큐 이벤트 보존·재처리 가능, 신규 이력/입력값 유실 없음. 운영 DB 전체 복원 방식은 사용하지 않음 |

지표별 게이트를 통과한 범위만 출시한다. 아직 없는 날짜·이력을 통과한 것으로 간주하지 않는다. 새 DB 구조는 확장형으로 먼저 배포하고 기존 컬럼 삭제/축소는 별도 작업으로 미룬다. 첫 공개부터 전체 과거를 backfill하지 않고 짧은 검증 구간 후 범위를 넓힌다.

### 6.4 Monitoring and Stop Conditions (관찰·중단 기준)

- 원장↔지표 불일치, 테넌트 간 데이터 혼입, 수동 방문자·비용 변형, 정의 버전 혼합이 발견되면 해당 기능 플래그를 끄고 신규 게시를 중단한다.
- 집계 오류율·원천 지연·outbox 적체·API 응답시간·기준일별 누락을 지표/테넌트별 관찰한다. 기존 조회는 계속 제공한다.
- 기존 입력 저장 실패가 새 검증/통계 경로 때문에 발생하면 즉시 입력 경로를 복구한다. outbox 장애 시 데이터 자체가 부분 저장되지 않도록 트랜잭션/재처리 설계를 G1에서 검증한다.
- 운영 변경 승인 없이 백필로 기존 확정 과거값을 교체하지 않는다. 자동 전환 대상과 별도 과거 정정 대상을 분리한다.

## 7. Final Review Result (최종 점검 결론)

**기존 계획 그대로 일괄 전환은 부적합하며, 위 통제와 출시 순서 보완 후 단계 구현이 타당하다.** 주요 보완은 원본 보존형 v2 집계, 사전 이력 기록, 우회 입력 경로 포함, 파생 Marketing 지표 정합성, 구 API/CSV 호환, 데이터 복원 없는 롤백이다.

현재 문서 검토만 완료했다. 운영 데이터 입력률·신구 산식 대사·성능·배포 호환성은 아직 검증 전이며 P0 및 출시 게이트에서 확인한다. 이 상태를 구현/배포 승인 또는 운영 검증 완료로 해석하지 않는다.

## Execution Update (진행 기록)

사용자 “진행” 승인 후 P0 운영 대사를 수행했다. 날짜 미입력과 과거 원장 부재로 기간 지표의 공개 전환은 G0/G2 미충족이다. 기존 기간 통계를 보존하면서 **현재 원장 현황만 별도 읽기 전용 패널**로 우선 제공한다. 이는 과거 집계 전환이 아니며 원래 계획의 이력/갱신/버전 게이트는 후속 기간 전환에 적용한다. [1차 결과](../report/RPT-260921E-dsh-source-data-integration.md) 참조.
