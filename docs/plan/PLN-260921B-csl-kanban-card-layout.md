# Consultation Kanban Plan (상담 칸반 개선 계획)

## 1. Scope (범위)

[요구사항](../analysis/REQ-260921B-csl-kanban-card-layout.md)을 기준으로 칸반 카드 표시를 개선한다.

## 2. Screen Layout (화면구성도)

```text
┌ 1. 접수 ───── 63 ┐  ┌ 2. 레벨테스트 ─ 3 ┐
│ ┌─────────────┐ │  │ ┌───────────────┐ │
│ │ 학생명  #번호│ │  │ │ 학생명  #번호 │ │
│ │ TA · 중2    │ │  │ │ TPI · 초1     │ │
│ │ 실제 학교명 │ │  │ │ [상담만]      │ │
│ │ [시험만]    │ │  │ │ 2026. 9. 16. │ │
│ │ 2026. 9. 9. │ │  │ │ 12:42         │ │
│ └─────────────┘ │  │ └───────────────┘ │
└─────────────────┘  └───────────────────┘
```

실제 학교명은 있을 때만 표시하며 접수용 대체 문구는 숨긴다. 날짜는 폭에 따라 자연스럽게 줄바꿈한다. 카드 간 간격과 단계 안쪽 여백을 유지한다. 좁은 화면에서는 열 수를 줄여 가독성을 확보하고 탈락 영역 카드에도 동일 규칙을 적용한다.

## 3. Implementation (구현)

1. 단계·카드 그리드·버튼에 `min-w-0`, `w-full`, `max-w-full` 등 폭 제약을 적용하고 자식 텍스트와 배지의 줄바꿈을 처리한다. 단순히 바깥을 잘라 콘텐츠를 가리는 방식은 사용하지 않는다.
2. 실제 콘텐츠 가용 폭을 고려해 반응형 열 수를 조정한다. 공통 관리자 페이지 폭과 우측 패널 환경을 포함해 검증한다.
3. 칸반 사이트 타입에 기존 `siteOverride`를 반영하고 TPI/TA/SC 매핑 및 미지정 처리를 추가한다.
4. 학교 대체 문구 판별을 제한된 접수 문구에만 적용해 실제 학교명이 사라지지 않도록 한다.
5. 공용 날짜 컴포넌트에 카드용 옵션을 추가하거나 기존 포맷 결과를 재사용하여 별도 접수 일시만 생략한다. 표 목록의 기본 동작은 유지한다.
6. 카드의 📥 표시 및 중복 홈페이지/외부 웹 배지를 제거한다.

## 4. Validation and Release (검증·배포)

- 프론트엔드 타입 검사/빌드 및 diff 검사.
- 사이트 지정 우선순위·미지정 처리, 실제 학교명/접수 대체 문구, 이관 날짜 표시 확인.
- 넓은 화면/우측 패널 포함 화면/모바일에서 카드 경계와 텍스트 겹침 확인.
- 단계별 개수·필터·상세 모달·탈락 카드 확인, 표 목록 날짜 표시 유지 확인.
- CI 및 스테이징 검증 후 운영 배포, `/admin/csl` 칸반 확인.
