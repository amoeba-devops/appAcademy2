# Operating Dual Values (운영 계산값·수기값 병기 결과)

## 1. Implementation (구현)

- 통합 학생 계산값은 날짜별 TPI+TRINITY+SANTACROCE의 합. 미분류는 통합에서 제외하고 건수 표시.
- 수업 기간별 시작/종료 사건, 조회 시작 이전 기초 인원, 종료일 당일 차감, 재등록 기간 보존. 선택 기간의 신규/종료 합계와 마지막 실제일 인원을 표시.
- 통합·사이트 운영 카드/그래프/일별 셀에 계산값 (수기값), 미입력 괄호 생략. 운영 수기 전용 편집은 0/빈칸 구분. 통합 수기를 사이트에 배분하지 않음.
- CSV는 계산·수기·존재 여부·품질 열 분리. 운영은 최대1096일; 기존 다른 지표365일 제한 유지. 기존 KPI가 없는 날짜에도 운영 행 표시.
- 학생 상세/교사 편집 화면에 기간 이력 편집. 기존 단일 날짜 경로 수정은 시작일이 일치하는 단일 이력에만 연결. 여러 기간 중 대상이 불명확하면 기간 편집 이용. 현재 사이트 수정으로 과거 기간 사이트를 변경하지 않음.
- 교사 날짜 누락은 미확정이며 기존 수기만 출처 확인 시 표시. 계정 생성일을 입사일로 추정하지 않음.
- 별도 기간·수기·감사 테이블: `999v-acm-dsh-operating-period.sql`. 계획의 학생/교사 기간 테이블은 동일 검증·감사를 공유하는 kind 구분 테이블로 구현했다. subject/tenant 일치 DB 트리거 및 서비스 검증, optimistic revision, 취소/복구 제공.

## 2. Import and Reconciliation (이관·대사)

- 사용자 제공90기간: 89행 이름 유일 일치로 연결, 1행 미연결로 confirmed=false 보존. 개인 명부와 실행 SQL은 Git에 포함하지 않음.
- 사이트별 제공 명부 기대: TPI63/30/33, TA7/4/3, SC20/6/14.
- 운영 전체 원장: TPI64/30/34, TA7/4/3, SC19/5/14, 통합90/39/51(2024-12-02~2026-09-22).
- 차이: 원장에 제공 명부 외 TPI 시작1건이 추가 존재. SC 이름 미일치1건의 시작/종료는 미확정 제외. 해당 사이트·통합은 부분 집계 표시. 통합값을 제공표50으로 강제 보정하지 않았다.
- 모든 조회 날짜의 통합 신규/종료/인원이 세 사이트 합과 일치함을 운영 읽기 자료로 검증.
- 기존 원본 엑셀 셀과 현재 저장값이 일치하는472항목의 수기 출처 복원. 원본 빈칸/값 불일치 등518항목은 수기 출처 미확정이며 기존 KPI를 보존하고 자동 괄호 표시하지 않음. 건수는 최초 대사 시점 기준.
- 운영 원장·수기 백업: 서버 비공개 `~/app-academy-backups/ops-dual-260922/before.dump`. 기간 이관은 source_key로 멱등, 기존 기록을 재실행 덮어쓰기하지 않음.
- 학생 상태·사이트·입학일·퇴원일, 기존 일별 KPI/방문자/비용 값은 이관 SQL에서 변경하지 않음. 학생 기간은 사용자 제공 날짜를 독립 이력으로 보존하므로 대표 단일 날짜 선택과 분리.

## 3. Validation (검증)

- 프론트엔드/백엔드 빌드 통과.
- 대시보드 단위7 suites/24 tests 통과.
- 실제 PostgreSQL 통합4개 통과: 실시간 기존 날짜 반영·tenant 격리, 기간 revision/감사, 재등록 및 단일 이력 수정, 수기0/해제/사이트 분리.
- frontend lint script는 현재 프로젝트에서 skipped 처리다. 이를 lint 통과로 간주하지 않음. 타입검사·빌드는 별도 통과.
- 배포 및 운영 화면 검증 진행 중.

## 4. Remaining Data and Recovery (남은 데이터·복구)

이름 미일치 학생1명의 원장 연결과 교사 날짜14명 입력, 과거 수기 출처 미확정 자료 확인은 남아 있다. API의 PARTIAL/UNAVAILABLE 및 확인 건수로 표시한다. 기간/수기 데이터는 보존하고 이전 앱 이미지로 되돌리면 기존 통계 읽기 경로로 복구된다. 확장 테이블은 삭제하지 않는다. 기존 master 날짜 트리거는 이력 보호를 위해 유지하며, 날짜 수정 오류 발생 시 해당 기간 편집으로 정정한다. DB 전체 복원은 하지 않는다.
