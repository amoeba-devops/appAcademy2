# Dashboard Lifecycle Implementation (대시보드 개선 구현 결과)

## 1. Result (결과)

사용자 “진행” 승인에 따라 구현했다. CS 표시명은 Scheduled, Scheduling은 수업 스케줄 조율 중, Scheduled는 조율 완료, New Class는 학생정보의 수업시작일이 해당일인 학생이다. Returning St./Referral St.와 최초 납부 후 첫 수업 대기 New St.를 함께 반영했다.

기존 원장 현재 현황을 오늘 실시간 현황으로 변경했다. 기존 재원학생·재직강사·수업배정학생·수업배정교사를 유지하고, 같은 지표 레지스트리를 사용하여 마케팅·스케줄·운영·수업 전체 항목을 표시한다. 기간 필터와 무관하게 서버 한국 날짜 기준 오늘을 조회한다. 활성 화면 5초 갱신, 수동 갱신, 창 복귀 갱신을 유지하며 외부 광고/GA 자료는 원천 동기화 시각과 자료 기준일을 표시한다.

## 2. Source Input and Counting (입력·집계)

- 상담 상세(접수/중단 등 모든 단계)와 학생 상세에 공용 이력 패널을 추가했다. 학생/과거 상담 및 소개 학생/학부모는 이름 검색으로 선택한다. 동명이인은 소속·학교·학년·생년월일 또는 상담 등록일로 구분한다.
- 스케줄 상태는 수강건별 날짜 이력이며 수업 시작과 독립적이다. 여러 수강건 중 조율 중이 있으면 Scheduling, 모두 완료이면 Scheduled에 학생당 1명으로 집계한다. 종료/취소 건은 제외한다.
- 복귀는 기존 중단 근거와 날짜를 검증한다. 소개는 실제 존재하는 동일 테넌트의 학생/학부모를 연결해야 집계한다. 학생 생애 최초 납부는 관리자 확인과 기존 수강료 납부일·금액·완료 기록이 필요하다. 첫 수업 진행이나 환불·등록 취소도 확인 기록을 남긴다.
- 신규 지표의 기록·취소는 ADMIN/STAFF, 납부·첫 수업·환불 확인/취소는 ADMIN으로 제한했다. 과거 학생과 상담을 이름만으로 자동 병합하지 않는다.
- New Class의 시작일 정정은 이전/새 날짜 집계에 즉시 반영한다. 숫자를 누르면 학생 상세/상담 링크를 볼 수 있다. 일별 표·기간 요약·차트·CSV를 연결하고, 기존 운영 학생수·강사수 산식 및 과거 수기 원본은 보존했다.
- 증빙이 부족한 과거 자료는 일부 집계 표시를 사용한다. 이름을 메모에서 추출하거나 최초 납부일·중단일을 임의 생성하지 않는다. 확인 기록의 오류는 취소 후 재등록하며, 수강료 전액 환불/등록 취소는 발생일이 있는 별도 기록으로 입력한다.

## 3. Validation (검증)

- 백엔드 전체 단위 테스트: 86 suites / 668 tests 통과 (신규 15 tests 포함).
- 백엔드 Nest build 및 프론트엔드 TypeScript/Vite production build 통과. Vite의 기존 대형 번들 경고는 남아 있다.
- 기존 로컬 DB에서 구조만 복제한 `acm_lifecycle_test_260929`에 가상 학생/상담을 생성하여 실제 서비스 통합 검증을 수행했다. 원래 로컬 DB 데이터와 운영 데이터는 변경하지 않았다.
- 검증 항목: 전체 지표 응답, New Class 시작일 수정, 첫 납부·첫 수업 대기 전환, 복귀/소개 등록, 취소, 동일 요청 멱등성, 학생 상세 조회, 테넌트 격리, 날짜별/기간별 중복 제거.
- 재현 스크립트: `backend/test/lifecycle-pg-check.ts`. `ACM_TEST_ENV_FILE`로 로컬 접속 설정을 전달하고 `ACM_LIFECYCLE_TEST_DB`는 `acm_lifecycle_test_` 접두사가 있는 격리 DB만 허용한다. 테스트 후 해당 가상 테넌트 데이터를 정리한다.
- 실제 로그인 브라우저 E2E 및 운영 원장 대사는 아직 수행하지 않았다. 운영 적용 시 대표 학생/상담으로 최종 화면 대사가 필요하다.
