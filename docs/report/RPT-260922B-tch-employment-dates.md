# Teacher Employment Dates Report (교사 입사일·퇴사일 구현 보고서)

## 1. Result (결과)

사용자의 “구현” 승인에 따라 작업을 완료했다. 기존 사용자 작업트리의 변경을 보존하기 위해 `/private/tmp/acm-tch-employment-dates`, 브랜치 `feat/tch-employment-dates`에서 작업했다. 운영 배포는 아직 수행하지 않았다.

- 교사 목록의 기존 입사일 열을 이름 다음으로 이동했다. 미입력은 빈칸이다.
- 교사 등록·수정 모달에 입사일·퇴사일을 2열로 배치했다. 모바일은 1열이며 미입력 안내는 회색 이탤릭이다.
- 기존 `tch_ended_at DATE`를 엔티티·DTO·서비스·프론트 타입에 연결했다. 미전송은 유지, null은 지우기로 처리한다.
- 실제 날짜와 시작·종료 순서를 검증한다. 날짜를 변경하지 않는 일반 정보 수정은 누락된 날짜 때문에 차단하지 않는다.
- 교사 수정은 행 잠금과 트랜잭션을 사용한다. 화면의 날짜 변경에는 `expectedUpdatedAt`을 전송하여 다른 화면의 변경을 덮어쓰지 않는다.
- 대표 날짜에 대응하는 재직 기간 한 건만 갱신하며 재입사 이력을 보존한다. 기간 편집에서 대표 기간을 수정해도 교사 원장 날짜가 함께 갱신된다. revision과 감사 기록은 한 번씩 증가한다.
- 기간 편집 후 상세 날짜·비교 기준을 새로 불러오고, 교사 목록·대시보드 캐시를 무효화한다.
- 한국어·영어·베트남어·중국어 날짜 라벨과 오류 안내를 추가했다.

## 2. Data Rules (데이터 규칙)

명시적 이력이 없는 교사는 입사일·퇴사일을 비울 수 있다. 명시적 이력이 있는 경우 입사일 삭제나 매칭 불가 상태는 기간 편집으로 안내한다. 퇴사일 삭제로 다른 재입사 기간과 겹치면 거절한다. 취소된 기간은 자동으로 다시 활성화하거나 최신 기간으로 대체하지 않는다.

날짜 저장만으로 재직 상태·계정 권한·AMA 프로필을 변경하지 않는다. 기존 수기 대시보드 값도 변경하지 않는다. 과거에 이미 불일치한 원장 날짜를 일괄 보정하지 않는다.

실제 브라우저의 데스크톱·모바일 시각 검증과 운영 배포 후 조회 검증은 미실시다. 운영 교사 데이터는 수정하지 않았다.

## 4. Deployment Notes (배포 참고)

새 마이그레이션 `sql/acm/999w-acm-tch-employment-dates.sql`을 기존 `999v` 이후 적용해야 한다. 새 컬럼 추가 대신 기존 컬럼을 사용하고 트리거를 보강한다. 배포 스크립트의 SQL 정렬 실행 대상에 포함된다. 애플리케이션만 먼저 배포하면 기간 동기화 보호가 누락되므로 스키마와 함께 배포한다.

신규 트리거는 교사 날짜의 순서·기간 겹침을 확인하고 기간 편집을 교사 대표 날짜로 반영한다. 기존 공통 트리거에는 중첩 실행 방지를 추가했다. 학생 기간 동기화 회귀 테스트도 통과했다.

운영 반영 전 staging에서 목록 열과 날짜 입력 배치, 저장 후 재조회, 권한별 동작을 확인한다. 운영 데이터로 시험 입력하지 않는다.
