# Student Site Management (사이트별 학생관리 구현 결과)

## 1. Outcome (구현 결과)

사용자의 계획 진행 승인에 따라 학생당 현재 주 소속 사이트 1개를 적용했다. TPI / Trinity Academy / Santa Croce / 미분류를 구분하며, 기존 학생에 사이트를 임의 지정하지 않는다. **소스 구현과 로컬 검증을 완료했으며 운영 배포·운영 학생 입력은 수행하지 않았다.**

- 통합/사이트별 탭과 인원 집계. 상태·검색·학교·학년·담당강사 ID·수업 시작일 필터 적용.
- 사이트·이름·수업 시작일·시스템 등록일 정렬, ID 보조 정렬, 25/50/100명 페이지 이동.
- URL에 필터·정렬·페이지 유지, 상세 화면에서 목록으로 돌아올 때 복원.
- 학생 등록·수정·상세에 소속 사이트 표시. 신규 수동 등록에는 사이트 필수.
- 상담에서 수업 시작 단계로 전환할 때 신규 학생 사이트 선택. 기존 학생 연결 시 소속 유지. 자동 호출에서 사이트 선택값이 없으면 미분류 유지.
- ADMIN/APP_ADMIN의 현재 페이지 선택 학생 일괄 사이트 변경. 변경 사유와 변경 전후 확인, 테넌트·삭제 상태·수정 시각 재검증, DB 감사 기록.
- 3사이트 엑셀 미리보기/적용 API 및 화면. 확인 전 학생 DB 쓰기 없음. 행별 적용 대상을 선택하고 학생·강사 매칭과 변경 전후를 검토한 후 적용.
- 영어·한국어·베트남어·중국어 간체 표시 문구 추가.

## 2. Workbook Handling (엑셀 처리)

실제 원본 `TPI 학생 정보.xlsx`를 읽기 전용으로 실행한 결과 이름 앵커는 **TPI 33 / Trinity Academy 3 / Santa Croce 14**로 확인됐다. 파서의 날짜 오류는 0개, 공유 셀·연락처 등 검토 표시가 있는 행은 45개였다. 운영 학생과의 실제 매칭은 실행하지 않았다.

이름 병합 범위 안의 강사·수업 연속행을 수집한다. 학생 경계를 넘는 병합 셀은 원본 값과 위치를 표시하되 자동 입력에서 제외한다. 학년과 괄호가 포함된 이름은 원문을 보존한다. MAP는 시험일을 추측하지 않고 메모로 보존하며 스케줄 원문은 기존 JSON의 `importedText`에 저장한다.

연락처·이메일은 행별 원문을 검토한 뒤 학생 본인의 값으로 확인한 항목만 직접 입력한다. 공유 연락처를 학생 로그인 이메일로 자동 저장하거나 학부모/포털 계정을 생성하지 않는다. 빈 값은 기존 값을 유지한다. 파일에 없는 학생도 삭제하지 않는다.

미리보기에는 신규/수정 후보, 동일·기적용, 모호한 매칭, 오류, 삭제 이력 충돌 건수를 표시한다. 이름의 괄호 표기 차이와 같은 생년월일은 후보 검토에 활용하며 자동 병합하지 않는다. 삭제 이력 충돌은 적용을 차단한다. 담당강사는 같은 tenant의 삭제되지 않은 강사만 선택할 수 있다.

적용은 트랜잭션으로 수행하며 학생·강사 관계·원본 행 식별자를 함께 저장한다. 같은 파일의 동일 행은 재생성하지 않는다. 미리보기 뒤 학생이 바뀌었으면 다시 검토한다. 개인정보가 포함된 미리보기는 1시간 후 사용할 수 없고, 매시간 및 새 미리보기 생성 시 만료 자료를 삭제한다. 적용된 미리보기의 원문 payload는 즉시 비운다. 재업로드 판별용 파일 해시·시트/행·학생 ID는 별도 유지한다.

## 3. Verification (검증)

| 검증 | 결과 |
|---|---|
| Backend `npm run build` | 통과 |
| Frontend `npm run build` | 통과 |
| 파서·상담 자동등록·API 요청 계약 단위 테스트 | 15개 통과 |
| 격리 PostgreSQL 통합 테스트 | 7개 통과 |
| 원본 파서 실행 | 33/3/14, 날짜 오류 0 |
| 합성 API를 사용한 브라우저 검증 | 페이지 이동, 사이트 전환, 상세 복귀, 미리보기 무저장, 명시적 적용 확인 |
| `git diff --check` | 통과 |

통합 테스트는 운영/기존 로컬 DB 대신 폐기 가능한 `std_test` DB에서 수행했다. 마이그레이션 재실행, 51명 페이지 경계, 사이트 집계, 테넌트 격리, 변경 감사, 만료/타인 미리보기 차단, 삭제 기록 충돌, 재실행 중복 방지, 다른 tenant 강사 지정 시 전체 롤백을 검증했다. 상담 등록 테스트는 신규 사이트 반영과 기존 학생 소속 보존을 포함한다.

브라우저는 빌드 결과를 직접 제공하고 모든 API를 합성 응답으로 대체했다. 운영 화면에 테스트 학생을 생성하지 않았다. 기존 개발 포트의 다른 프로젝트 프로세스도 변경하지 않았다.

재실행할 때는 먼저 테스트 전용 PostgreSQL을 준비한다. 통합 테스트는 `STD_TEST_DB_PORT`가 없으면 skip하며, 고정된 테스트 DB 이름/계정만 사용한다.

```sh
npm test --prefix backend -- --runInBand site-import.parser.spec.ts student.dto.spec.ts csl-enrollment-registration.service.spec.ts
# backend/ 디렉터리에서, 폐기 가능한 테스트 DB 포트 지정 후:
STD_TEST_DB_PORT=<test-db-port> npm run test:int -- --runTestsByPath test/integration/acm/it-std-site.int-spec.ts
```

## 4. Deployment and Data Application (배포·데이터 반영)

1. 변경 대상 환경을 확인하고 DB 백업을 확보한다.
2. [999o 마이그레이션](../../sql/acm/999o-acm-std-site-import.sql)을 적용한다. 기존 학생 소속 backfill은 없다.
3. 백엔드와 프론트엔드를 같은 릴리스로 배포한다. 신규 수동 등록의 사이트 필수 계약과 업로드 경로가 함께 바뀌므로 서로 다른 버전이 오래 공존하지 않게 한다.
4. 미분류 및 기존 학생 목록/집계를 확인한다. 사이트 일괄 지정은 선택된 학생 ID에만 적용한다.
5. 원본 업로드 미리보기에서 기준일·학생·강사·연락처·변경 전후를 검토한다. 검토 완료 행만 적용한다. 실제 적용 결과는 별도 운영 기록으로 남긴다.

추가 컬럼과 테이블을 즉시 삭제하는 롤백은 하지 않는다. 데이터 적용 후 복구가 필요하면 실행별 원본 매핑과 사전 백업을 기준으로 검토하며, 이후 사용자가 수정한 값을 자동 역변경하지 않는다.

## 5. Scope and Follow-up (범위와 후속 작업)

- 이번 릴리스는 계획의 사이트 목록·관리 기능과 3사이트 원본의 검토형 업로드를 구현한다. 실제 운영 대사/입력(단계 4)은 미실행이다.
- 기존 두 번째 시트/C열 고정 방식의 즉시 저장 업로드는 `IMPORT_PREVIEW_REQUIRED`로 차단했다. 새 템플릿은 3사이트 시트를 제공한다. **구 상담형 템플릿 변환은 지원하지 않으며** 명시적인 매핑을 추가하는 후속 작업으로 남긴다.
- 공유 병합 필드의 자동 분배, 학부모 연락처 자동 분리, 오류 셀 인라인 수정은 제공하지 않는다. 원본 정정 후 재업로드하거나 검토 대상 행을 제외한다.
- 동명이인 후보가 있으면 이번 입력에서 임의로 새 학생을 생성할 수 없다. 별도 학생 등록/정리 후 다시 검토한다.
- 기존 이메일 필수/중복 제한 정책은 유지한다. 학생 수정 화면에서 이메일이 없는 기존 학생은 이메일 보완이 필요하며, 사이트만 지정할 때는 관리자 일괄 변경을 사용할 수 있다.
- 계획의 P1 선택 열·확장 상세·전체 검색 결과 내보내기·종료/상담 이력 보강은 후속 범위다.
