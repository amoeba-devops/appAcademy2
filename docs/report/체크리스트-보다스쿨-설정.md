# 보다스쿨(BODA) 연동 설정 체크리스트

> 포털 학생/강사의 화상강의(BODA) 입장 이슈에 대한 **현재 문제점 · 적용한 우회조치 · BODA(벤더)에 요청할 사항 · 우리가 설정할 내용**을 정리한다.

---

## 1. 현재 문제점 (Root Cause)

**한 줄 요약:** 강사는 자기 클라이언트에서 방을 열고 바로 입장하지만, **벤더 webhook 미연동**으로 우리 서버가 "방이 열림 / meetIdx"를 알지 못해 **학생이 입장할 수 없다.**

프로덕션 실측(2026-07-16, read-only 조회):

| 항목 | 값 | 의미 |
|------|-----|------|
| `amb_acm_cal_boda_event_log` | **0 건** | 벤더 webhook 이 **한 번도 수신된 적 없음** |
| `amb_acm_cal_boda_room` 상태 | **전건 PENDING** (23~25개) | ROOM_OPENED 이벤트로 OPEN 전환된 방이 0개 |
| `bdc_event_secret_enc` | **미설정(null)** | webhook 서명검증 시크릿 없음 |
| `bdc_webhook_allow_cidrs` | **미설정(null)** | webhook 허용 IP(CIDR) 없음 |
| `bdc_company_code` / `bdc_company_id` | **245 / tpi** (설정됨) | 회사 식별자 OK |
| `bdc_webrtc_url` / `bdc_boda_web_url` / `bdc_auth_key_enc` | 설정됨 | 기본 연동값 OK |

### 연쇄 영향
1. 벤더가 `ROOM_OPENED(code 1)` webhook 을 우리 `/api/webhooks/boda` 로 보내지 않음(또는 인증설정이 없어 거부됨).
2. → `amb_acm_cal_boda_room.bdr_status` 가 계속 `PENDING`, `bdr_meet_idx` 가 계속 `NULL`.
3. → **학생 입장 게이트**가 "강사가 강의실을 열면 입장" 으로 막음(설계상 정상 동작이나, 실제로는 열려 있어도 우리가 모름).
4. → 학생 `meetIdx` 기반 조인(JOIN_IDX) 불가. 벤더가 `WB-400-221 InvalidMeetIdx` 반환.

### 부가 문제
- **공유된 webrtc 링크가 학생에게 무효**: `https://bodaedu.kr/webrtc?...&UTy=11&UId=<강사>` 형태는 **사용자별(UTy/UId 고정)** 이라 타인에게 공유 불가.
- **webrtc(브라우저) 조인 URL 계약 미확인**: 우리가 만든 GET 쿼리 형식은 벤더 확인 전(질문 B3 미회신). 벤더 실제 조인은 `BodaAppApi.js` 의 form POST(`/api/page/joinRoom`, `joinParam` JSON).

### 우회의 한계
- 학생 `bodaJoin({ meetKey })`(JOIN_KEY) 가 **실제 입장까지 되려면 벤더가 meetKey 조인을 허용**해야 함(미확인). webhook 이 연동되면 meetIdx 가 채워져 정석 경로(JOIN_IDX)로 안정화된다.

## 3. BODA(벤더)에 요청할 사항  ☑ 요청 체크리스트

- [ ] **① Webhook 전송 설정**: 방 생명주기 이벤트를 아래 URL 로 POST 하도록 등록
  - URL: **`https://acm.amoeba.site/api/webhooks/boda`**
  - 최소 이벤트: `ROOM_OPENED(code 1)` (필수), `STARTED / ENDED / CLOSED`, 참가자 join/leave
  - 페이로드에 **`meetIdx`, `meetKey`, `eventCode`, `eventAt`, `userId`** 포함(우리 dedup 키: meetIdx+eventCode+eventAt+userId)
- [ ] **② Webhook 인증 방식 회신**
  - 공유 시크릿(서명) 값 + **어느 HTTP 헤더**로 오는지
  - 서명 알고리즘(HMAC 등) 규격
- [ ] **③ 벤더 발신 IP 대역(CIDR)** 목록 — allowlist 등록용
- [ ] **④ `/api/page/joinRoom` 조인 계약 확정 (질문 B3)**
  - 웹/브라우저 조인이 **GET 쿼리** 인가 **POST JSON(`joinParam`)** 인가
  - **학생(UTy=12)** 조인에 필요한 최소 파라미터 (meetKey vs meetIdx)
  - 강사 개설 **전/미개설 방**에 학생이 **meetKey 로 조인 가능**한지
- [ ] **⑤ 설치 불필요(WebRTC/브라우저) 학생 입장 지원 여부** — 학생 모드에서 브라우저만으로 입장 가능한지, 아니면 데스크톱 앱 필수인지
- [ ] **⑥ meetIdx 생성 시점 확인** — ROOM_OPENED 이후에만 생성되는지 / 서버 API 를 meetKey 로 조회 가능한지
- [ ] **⑦ iframe 임베드 허용 여부 (질문 Q-LX-1)** — 포털 내 iframe 강의실 임베드 가능 여부(현재 `BODA_EMBED_ENABLED=false`)

## 4. 우리(운영)가 설정할 내용  ☑ 설정 체크리스트

### 4.1 테넌트 BODA 설정 (`amb_acm_cal_boda_config`, ent_id=…0001)
- [ ] **`bdc_event_secret_enc`** — ②에서 받은 webhook 시크릿을 **암호화 저장** (관리자 콘솔 `/admin/config/boda` 또는 운영 절차)
- [ ] **`bdc_webhook_allow_cidrs`** — ③에서 받은 벤더 IP 대역(CSV CIDR) 등록
- [ ] (확인) `bdc_company_code=245`, `bdc_company_id=tpi`, `bdc_webrtc_url`, `bdc_boda_web_url`, `bdc_auth_key_enc`, `bdc_is_active=true` — **이미 설정됨**

### 4.2 인프라
- [ ] **`https://acm.amoeba.site/api/webhooks/boda`** 가 벤더 IP 에서 도달 가능한지(방화벽/프록시/nginx) 확인
- [ ] 리버스 프록시가 **원 IP(X-Forwarded-For)** 를 전달하는지 확인(allowlist 판정용)

### 4.3 연동 후 검증
- [ ] 강사 계정으로 강의실 **개설** → 수 초 내 `amb_acm_cal_boda_event_log` 에 행 생성 확인
- [ ] 해당 room `bdr_status = OPEN`, `bdr_meet_idx` **NOT NULL** 로 전환 확인
- [ ] **학생 계정** `/portal/calendar/:evtId` → 앱 입장 성공 확인
- [ ] 방 종료 시 `ENDED/CLOSED` 반영 확인
