# 상담관리 사용자 매뉴얼 (CSL Consultation User Manual)

> 본 매뉴얼은 운영 콘솔의 **상담 관리** 메뉴(좌측 사이드바 → "상담 관리", 경로 `/admin/csl`)에서
> 신규 상담 접수부터 수강 시작까지의 **6단계 파이프라인**을 운영하는 방법을 설명합니다.
> 화면 라벨/옵션 표기는 실제 UI(한국어)와 동일하게 기재했습니다.

---

## 0. 한눈에 보기 (Pipeline at a glance)

```
1. 접수            2. MAP 테스트       3. 청강            4. 등록 상담        5. 결제          6. 수강 시작
 INTAKE     ──▶     MAP_TEST    ──▶    TRIAL_CLASS  ──▶  ENROLLMENT_   ──▶   PAYMENT   ──▶   CLASS_STARTED
                                                          COUNSELING
   │                                                                                              
   └────────────────────────── 어느 단계에서든 ▶  이탈(DROPPED)  ◀── 재활성화 ──────────────────────┘
```

**단계별 "다음 단계로 넘어가기 위한 조건" 요약**

| 전환 | 필요 조건 (이 조건을 만족해야 진행 버튼이 성공) |
|------|--------------------------------------------------|
| 접수 → MAP 테스트 | (조건 없음) — 단, **익명 문의는 접수에서 더 진행 불가**(이탈 제외) |
| 접수 → 청강 (건너뛰기) | MAP "이전 점수 보유" ✔, 또는 응시료 **납부/면제**, 또는 **점수(읽기·수학·언어) 중 1개 이상 입력** (Q-CSL-003) |
| MAP 테스트 → 청강 | 위와 동일(이전 점수 보유 / 응시료 납부·면제 / 점수 입력 중 하나) |
| 청강 → 등록 상담 | **청강 일정이 1건 이상** 등록됨 |
| 등록 상담 → 결제 | 등록 정보의 **"등록 상담 완료" = 완료(YES)** |
| 결제 → 수강 시작 | 등록 정보의 **"수강료 납부 완료" = 체크**(※ **책임자(ADMIN)만** 설정 가능) |
| 어느 단계 → 이탈 | **이탈 사유 코드** 선택(기타 선택 시 상세 사유 필수) |
| 이탈 → 재활성화 | 직전 단계로 복귀(직전 단계 정보가 없으면 접수로) |

> 진행 버튼은 **현재 단계에서 허용된 다음 단계만** 표시됩니다. 조건 미충족 시 버튼을 눌러도
> 오류 메시지가 뜨고 단계가 바뀌지 않습니다(아래 각 단계 설명 참조).

## 1. 화면 구성 (Screen layout)

### 1.1 상담 목록 (`/admin/csl`)
- 컬럼: **No. / 학생 / 학교·학년 / 단계 / 유입 / 신청 / 등록일 / 후속 일정**
- 단계는 색상 배지로 표시되며, 행을 클릭하면 **상담 상세**로 이동합니다.
- 우측 상단 **"+ 신규 상담"** 버튼으로 접수 등록 다이얼로그를 엽니다.

### 1.2 상담 상세 (`/admin/csl/:id`)
세 영역으로 구성됩니다.
1. **상단 헤더** — 학생 정보 + **단계 진행 버튼**(허용된 다음 단계만 노출) + **이탈 처리 / 재활성화** 버튼
2. **단계 스테퍼** — 6단계 진행 상태를 시각적으로 표시
3. **본문 2단**
   - **왼쪽**: 현재 단계에 해당하는 입력 패널(MAP 테스트 / 청강 / 등록·결제 등)
   - **오른쪽**: **기록 / 타임라인**(단계 변경 이력 + 메모). 메모는 추가만 가능하고 이력은 삭제되지 않습니다.

---

## 2. 단계별 상세 (Stage-by-stage)

### 단계 1 — 접수 (INTAKE)

**목적**: 신규 상담을 시스템에 등록합니다. 모든 상담은 접수에서 시작합니다.

**입력 항목** (신규 상담 등록 다이얼로그)

| 항목 | 필수 | 설명 / 옵션 |
|------|:---:|-------------|
| 학생 이름 | ✔* | 익명이 아니면 필수(암호화 저장). *익명 문의 체크 시 생략 |
| 익명 문의 | | 체크 시 학생 이름 없이 접수 가능. **단, 접수 단계 이후로 진행 불가** |
| 보호자 전화번호 | | "전화번호 상태 = 제공됨"이면 필수. 형식: 숫자/`+ - ( )`, 7~20자(암호화 저장) |
| 보호자 이름 | | 선택(암호화 저장) |
| 전화번호 상태 | | 제공됨 / 거부 / 미확인 |
| 학교 | ✔ | 학교 선택 또는 **자유 입력**(둘 중 하나 필수) |
| 학년 | | 초5·초6·중1~중3·고1~고3·기타 |
| 유입 경로 | ✔ | 홈페이지 / 카카오 채널 / 전화 |
| 신청 유형 | ✔ | 상담만 / 시험만 / 상담+시험 |
| 신청 목적 | | (다중 선택) MAP TEST 튜터링 / ISEE 튜터링 / 국제학교·외국인학교 입학 준비 / 맞춤형 GPA 관리 / 심화 수업 |
| 상담 완료 여부 | | 완료 / 미완료 |
| 등록일 | | 미입력 시 당일로 저장 |
| 후속 일정 · 후속 메모 | | 후속 관리용 날짜/메모 |

**입력 검증**
- 익명이 아니면 학생 이름 필수 · 학교명 필수 · 전화번호 상태가 "제공됨"이면 번호 필수 · 신청 목적 "기타" 선택 시 사유 필수.

**다음 단계 진행 조건**
- **→ MAP 테스트**: 조건 없음.
- **→ 청강(건너뛰기)**: MAP 정보에 *이전 점수 보유* 또는 *응시료 납부/면제* 또는 *점수 1개 이상*이 있어야 함(Q-CSL-003).
- ⚠️ **익명 문의는 이탈 외에는 진행 불가** — 진행하려면 먼저 학생 정보를 입력해 익명을 해제하세요.

---

### 단계 2 — MAP 테스트 (MAP_TEST)

**목적**: MAP(NWEA) 응시료 상태·일정·점수를 기록합니다. 왼쪽 **MAP 테스트** 패널에서 입력합니다.

**입력 항목**

| 항목 | 설명 / 옵션 |
|------|-------------|
| 이전 점수 보유 | 체크 시 청강 진행 게이트 충족 |
| 응시료 상태 | 납부 / 미납 / 면제 |
| 면제 사유 | 응시료 상태가 **면제**일 때 필수 — 90일 내 재응시 / 체험 프로모션 / 자매학원 이동 / 기타 |
| 면제 비고 | 보충 설명(선택) |
| 응시 예정일 | 날짜 |
| 응시 상태 | 예정 / 응시 완료 / 미응시 / 재예약 |
| 점수 (100~300) | 읽기 · 수학 · 언어 (각 100~300, NWEA 척도) |

**다음 단계 진행 조건**
- **→ 청강**: 아래 중 **하나 이상** 충족해야 함.
  1. *이전 점수 보유* 체크, 또는
  2. *응시료 상태* = **납부** 또는 **면제**, 또는
  3. *점수(읽기/수학/언어)* 중 **1개 이상 입력**.
- 미충족 시: "청강 진입에는 MAP 점수 기록 또는 응시료 납부/면제가 필요합니다" 오류.

---

### 단계 3 — 청강 (TRIAL_CLASS)

**목적**: 체험 수업(청강) 일정을 기록합니다(여러 건 등록 가능). 왼쪽 **청강 일정** 패널에서 관리합니다.

**입력 항목** (청강 1건 추가 시)

| 항목 | 필수 | 설명 / 옵션 |
|------|:---:|-------------|
| 청강일 | ✔ | 날짜(미선택 시 "추가" 버튼 비활성화) |
| 피드백 상태 | | 전송 완료 / 대기 / 해당 없음 (기본: 대기) |
| 메모 | | 세션 메모 |

**다음 단계 진행 조건**
- **→ 등록 상담**: **청강 일정이 최소 1건** 등록되어 있어야 함. 미충족 시 "등록 상담 진입에는 청강 1건 이상이 필요합니다" 오류.

---

### 단계 4 — 등록 상담 (ENROLLMENT_COUNSELING)

**목적**: 등록 상담 진행 상황과 수강료·수업 정보를 기록합니다. 왼쪽 **등록 / 결제** 패널에서 입력합니다(이 패널은 등록 상담·결제·수강 시작 단계에서 공통 사용).

**입력 항목**

| 항목 | 설명 / 옵션 |
|------|-------------|
| 등록 상담 완료 | 완료 / 미완료 — **결제 단계 진입 게이트** |
| 수강료 안내 상태 | 발송 / 대기 / 해당 없음 |
| 수강 신청 | 신청 완료 여부(체크) |
| 수강료 안내 발송 | 완료 / 미완료 |
| 수업 시간(분) | 1 이상 정수 |
| 수강료 | 0 ~ 50,000,000원 (Q-CSL-008) |
| 수강료 납부 완료 | 체크 — **수강 시작 게이트**. ※ **책임자(ADMIN)만** 설정 가능(아래 5단계 참조) |
| 수강 시작일 / 수강 시작 여부 | 수강 시작 단계 정보 |

**다음 단계 진행 조건**
- **→ 결제**: **"등록 상담 완료" = 완료(YES)** 여야 함. 미충족 시 "결제 진입에는 등록 상담 완료가 필요합니다" 오류.

---

### 단계 5 — 결제 (PAYMENT)

**목적**: 수강료 수납을 확정합니다. 별도 입력 화면 없이 **등록 / 결제** 패널의 **"수강료 납부 완료"** 체크로 처리합니다.

**핵심 규칙 (BR-CSL-012)**
- **"수강료 납부 완료" 체크는 책임자만 표시할 수 있습니다.** (UI 안내: "※ 결제 확정은 책임자만 표시할 수 있습니다.")
- 허용 권한: **ADMIN, APP_ADMIN**. 그 외(TEACHER/STAFF)가 시도하면 **403** 오류가 발생하며 저장되지 않습니다.
- 납부 완료로 표시되면 처리자·처리시각이 자동 기록됩니다.

**다음 단계 진행 조건**
- **→ 수강 시작**: 등록 정보의 **"수강료 납부 완료"가 체크**되어 있어야 함. 미충족 시 "수강 시작 진입에는 수강료 납부가 필요합니다" 오류.

---

### 단계 6 — 수강 시작 (CLASS_STARTED)

**목적**: 정식 등록 완료 상태. 이 단계로 전환되면 상담의 **등록일(enrolledAt)** 이 자동 기록되고, 이후 수업 운영은 **반/수업(CLS) 모듈**이 담당합니다.

**관련 정보** (등록 / 결제 패널)
- 수강 시작일, 수강 시작 여부.

**진행**
- 수강 시작은 파이프라인의 **마지막 정방향 단계**입니다(이후 정방향 진행 없음, 이탈만 가능).

---

## 3. 공통 작업 (Common operations)

### 3.1 단계 진행 (정방향)
- 상단 헤더의 **단계 진행 버튼**(허용된 다음 단계만 노출)을 클릭합니다.
- 진행 조건 미충족 시 오류 메시지가 표시되고 단계는 변경되지 않습니다 → 해당 단계 패널에서 필요한 정보를 먼저 입력하세요.

### 3.2 단계 되돌리기 (역방향) — 관리자 전용
- **ADMIN / APP_ADMIN** 권한만 가능하며, **사유(2~500자) 입력이 필수**입니다(C-12).
- 잘못 진행한 단계를 이전 단계로 되돌릴 때 사용합니다. 모든 역방향 이력은 타임라인에 남습니다.

### 3.3 이탈 처리 (DROPPED)
- 헤더의 **"이탈 처리"** 버튼 → 사유 코드 선택:
  - 학원 사정으로 취소 / 학생 건강 / 학생 일정 변경 / 결제 거절 / 타 학원 등록 / 기타
  - **"기타" 선택 시 상세 사유 필수.**
- 이탈 시 종료시각(closedAt)이 기록되며, 이탈 이력은 **삭제 불가**(append-only, Q-CSL-006).

### 3.4 재활성화 (REACTIVATE)
- **이탈 상태**에서만 가능. **직전 단계로 복귀**합니다(직전 단계 정보가 없으면 접수로). 종료시각은 초기화됩니다.

### 3.5 메모 / 타임라인
- 오른쪽 **기록 / 타임라인** 패널에서 메모(최대 2000자)를 추가합니다. 단계 변경 이력과 함께 시간순으로 표시되며 **삭제되지 않습니다**.

### 3.6 전화번호 보기 (PII)
- 보호자 전화번호는 암호화 저장됩니다. **보기 동작은 감사 로그**(처리자·IP·브라우저)로 기록됩니다(C-07). 업무상 필요한 경우에만 조회하세요.

### 3.7 상담 삭제 / 복원
- 상담 삭제는 **소프트 삭제**이며 **90일 이내 복원** 가능합니다(C-06).

## 4. 권한 요약 (Permissions)

| 작업 | 허용 권한 |
|------|-----------|
| 상담 조회·생성·수정, 단계 정방향 진행, MAP/청강/등록 입력, 메모 | 로그인한 운영자(해당 테넌트) |
| **수강료 납부 완료 표시**(BR-CSL-012) | **ADMIN, APP_ADMIN** |
| **단계 역방향 전환**(사유 필수) | **ADMIN, APP_ADMIN** |

> 모든 데이터는 **소속 학원(테넌트) 단위로 격리**됩니다. 다른 학원의 상담은 보이지 않습니다.

## 5. 자주 묻는 문제 (Troubleshooting)

| 증상 | 원인 / 해결 |
|------|-------------|
| 진행 버튼을 눌렀는데 단계가 안 바뀜 | 해당 단계의 **진행 조건 미충족**. 0장·각 단계의 "다음 단계 진행 조건" 확인 후 필요한 정보 입력. |
| "수강료 납부 완료" 저장 시 **403** | 권한 부족. **ADMIN/APP_ADMIN** 계정으로 처리해야 함(BR-CSL-012). |
| 익명 문의가 접수에서 안 넘어감 | 익명은 접수 이후 진행 불가. 학생 정보를 입력해 익명을 해제하세요. |
| 청강 "추가" 버튼이 비활성화 | **청강일(날짜)** 을 먼저 선택해야 활성화됩니다. |
| 면제 저장이 안 됨 | 응시료 상태가 "면제"면 **면제 사유**가 필수입니다. |
| 이탈 저장이 안 됨 | 사유 코드가 "기타"면 **상세 사유**가 필수입니다. |
