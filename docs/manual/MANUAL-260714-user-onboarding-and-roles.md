# 사용자 등록·역할 운영 매뉴얼 (User Onboarding & Roles Manual)

> 웹페이지 상담신청으로 들어온 학생·학부모가 **상담 → 수강등록 → 수강중**을 거쳐
> **학생·학부모·강사 각각의 계정**을 갖게 되기까지의 전 과정을 설명합니다.
> 상담 6단계의 세부 입력 항목은 [상담관리 사용자 매뉴얼](MANUAL-260624-csl-consultation-userguide.md)을,
> 본 매뉴얼은 **계정 생성과 역할**에 초점을 둡니다. 화면 라벨은 실제 UI(한국어) 기준입니다.

---

## 0. 두 가지 계정 체계 (Two account systems) — 먼저 이해할 것

TAC에는 **성격이 다른 두 종류의 로그인**이 있습니다. 헷갈리지 않도록 먼저 구분합니다.

| 구분 | 운영 콘솔 계정 (Admin/Console) | 포털 계정 (Portal) |
|------|-------------------------------|--------------------|
| 로그인 위치 | `/admin/*` 운영 콘솔 | `/portal/login` 포털 |
| 테이블 | `amb_acm_user` | `amb_acm_portal_account` |
| 대상 | **관리자 · 강사 · 직원** | **학생 · 학부모 · 강사** |
| 역할값 | `ADMIN` / `TEACHER` / `STAFF` / `APP_ADMIN` | `STUDENT` / `PARENT` / `TEACHER` |
| 용도 | 학원 운영·상담·수업 관리 | 공지·수업일정·자료실 열람 |

- **강사는 두 계정을 모두 가질 수 있습니다.** 콘솔 로그인(수업/출석 관리)과 포털 로그인(포털 열람)은 별개입니다.
- **학생·학부모는 포털 계정만** 갖습니다(운영 콘솔에 로그인하지 않습니다).
- 모든 계정·데이터는 **소속 학원(테넌트) 단위로 격리**됩니다. 다른 학원의 계정은 보이지 않습니다.

## 1. 전체 흐름 한눈에 (End-to-end flow)

```
[웹 상담신청]          [운영 콘솔 — 상담관리 /admin/csl]                    [계정 발급]
홈페이지 폼      ─▶   1.접수 → 2.레벨테스트 → 3.데모수업 → 4.등록상담 → 5.결제
(학생/학부모 입력)                                                    │
                                                                     ▼ 6.수강등록 진입 시
                                                        ┌─────────────────────────────┐
                                                        │ 학생 자동 생성 (학생관리 /admin/std)│
                                                        │ 학부모 자동 생성 + 학생에 연결      │
                                                        │ 학생·학부모 포털 계정 자동 준비     │
                                                        │ 레벨테스트 점수 학생에게 상속       │
                                                        └─────────────────────────────┘
                                                                     │ [수강등록완료] 버튼
                                                                     ▼
                                                                7.수강중

[강사] 관리자가 직접 등록 (/admin/tch) ─▶ [수업일정 등록 /admin/cls: 강사·과목·요일·시간 + 학생 추가]
                                       ─▶ [강의 진행: 세션 출석·피드백 기록]
```

**핵심 규칙 한 줄 요약**
- 학생·학부모 계정은 상담이 **6. 수강등록**에 도달할 때 **자동으로** 만들어집니다(관리자가 수기로 만들 필요 없음).
- 강사는 **관리자가 직접** 등록합니다(자동 생성 아님).
- 포털 로그인은 항상 **(학원 코드 + 아이디 + 비밀번호)** 3가지가 필요합니다.

## 2. 사용자 유형과 역할 (User types & roles)

### 2.1 역할 요약표

| 사용자 | 계정 체계 | 역할/종류 | 계정 생성 주체 | 주요 권한 |
|--------|-----------|-----------|----------------|-----------|
| **관리자(원장/책임자)** | 콘솔 | `ADMIN` | AMA 연동 / 최초 시드 | 전 기능. 강사 등록·수정·삭제, 수강료 납부 확정, 단계 역방향, 포털계정 발급 |
| **직원(비담임 스태프)** | 콘솔 | `STAFF` | 관리자 | 상담·수업 화면 사용, AMA 강사 가져오기. **강사 마스터 등록/수정 불가** |
| **강사** | 콘솔(선택) + 포털(선택) | 콘솔 `TEACHER` / 포털 `TEACHER` | 관리자(강사 등록 시) | 담당 수업 진행, 출석·피드백 기록, 데모수업 피드백 작성. 강사 마스터 관리 불가 |
| **학생** | 포털 | `STUDENT` | **자동**(6.수강등록) 또는 학생관리에서 수기 | 포털에서 공지·수업일정·자료실 열람 |
| **학부모** | 포털 | `PARENT` | **자동**(6.수강등록) 또는 학생관리에서 수기 | 포털에서 자녀 관련 공지·일정 열람, 수업 신청 |
| (플랫폼 운영자) | 콘솔 | `APP_ADMIN` | AMA 플랫폼 | 시스템/테넌트 관리(학원 코드 설정 등) |

> 콘솔 역할은 AMA 플랫폼 등급에서 파생됩니다: MASTER/OWNER/MANAGER → **ADMIN**, jobRole=TEACHER → **TEACHER**, 그 외 → **STAFF**.

### 2.2 각 사용자의 역할 상세

- **학생 (STUDENT)** — 수강 중인 본인 학생. 포털에서 **자신과 관련된** 공지·수업일정(캘린더)·자료실을 열람합니다. 로그인 아이디는 **본인 이메일**입니다.
- **학부모 (PARENT)** — 학생의 보호자. 한 학생에 여러 보호자, 한 보호자가 여러 자녀를 가질 수 있으며 **대표 보호자(primary)** 1명이 지정됩니다. 포털에서 자녀 관련 정보를 열람하고 수업 신청을 할 수 있습니다.
- **강사 (TEACHER)** — 관리자가 직접 등록. 담당 수업의 일정·출석·피드백(진도)을 기록하고, 상담 파이프라인의 데모수업 피드백을 작성합니다. **강사 명단(마스터)은 관리자만** 관리합니다.

## 3. 웹페이지 상담신청 (Public intake) — 계정의 출발점

학생·학부모는 **홈페이지 공개 폼**에서 시작합니다. 두 종류가 있으며, 접수되면 운영 콘솔의
**상담관리(`/admin/csl`)에 1. 접수 상태의 신규 상담으로** 쌓입니다.

| 폼 | 화면 | 주요 입력 | 접수 결과 |
|----|------|-----------|-----------|
| **상담 신청** | `/web/contact` | 학생 이름·학년 / **보호자 이름·전화(필수)** / 상담 목적(다중) | 유입=홈페이지, 신청유형=상담만 |
| **레벨테스트(MAP) 신청** | `/web/test` | 학생 국·영문 이름·생년월일·성별 / 보호자 이름·전화·이메일 / 응시 국가·도시 | 유입=홈페이지, 신청유형=시험만 |

> 이 단계에서는 아직 **학생/학부모 계정이 생성되지 않습니다.** 접수는 "상담 건"으로만 존재하며,
> 실제 학생·학부모 레코드와 포털 계정은 **6. 수강등록** 단계에서 만들어집니다(4장).

## 4. 신규 상담 단계별 입력 (Consultation stages)

상담은 **7단계 + 상담종료**로 진행됩니다. 각 단계 진행 버튼은 **허용된 다음 단계만** 노출되며,
진행 조건 미충족 시 오류가 뜨고 단계가 바뀌지 않습니다.

| # | 단계(라벨) | 내부 코드 | 이 단계에서 입력하는 것(요약) | 다음 단계 진행 조건 |
|---|-----------|-----------|------------------------------|---------------------|
| 1 | **접수** | `INTAKE` | 학생/보호자 정보, 학교·학년, 유입경로, 신청유형·목적 | (조건 없음) · 익명은 진행 불가 |
| 2 | **레벨테스트** | `MAP_TEST` | 응시료 상태(납부/면제), 응시 예정일·담당강사, 점수(읽기·수학·언어 등) | 이전 점수 보유 / 응시료 납부·면제 / 점수 1개 이상 |
| 3 | **데모수업** | `TRIAL_CLASS` | 데모수업 예정일·담당강사, 강사 피드백 | 데모수업 1건 이상 등록 |
| 4 | **등록 상담** | `ENROLLMENT_COUNSELING` | 코스, 수강 회수, 수강료, 수업시간, **담당강사 배정**, 등록상담 완료 | "등록 상담 완료 = YES" |
| 5 | **결제** | `PAYMENT` | 결제일·방법·금액, **수강료 납부 완료(책임자만)** | "수강료 납부 완료" 체크 |
| 6 | **수강등록** | `CLASS_STARTED` | (별도 입력 없음 — 요약 확인) | ⇒ 진입 시 **학생·학부모·계정 자동 생성** |
| 7 | **수강중** | `ATTENDING` | (별도 입력 없음) | 마지막 정방향 단계 |
| — | **상담종료** | `DROPPED` | 종료 사유(기본값: **단순문의종료**) | 어느 단계에서든 종료 가능 |

> 각 단계의 상세 입력 항목·검증 규칙은 [상담관리 사용자 매뉴얼 §2](MANUAL-260624-csl-consultation-userguide.md)를 참고하세요.
> **주의(라벨 vs 동작):** 단계 6의 라벨은 "6. 수강등록"이며, 6단계 패널의 **[수강등록완료]** 버튼을 누르면
> 상담이 **7. 수강중**으로 넘어갑니다. 학생·학부모 레코드는 그보다 앞선 **6단계 "진입 시점"에 이미 생성**됩니다(아래 §5).

## 5. 6단계 "수강등록" 진입 시 — 자동 등록 (What happens at CLASS_STARTED)

상담이 **5. 결제 → 6. 수강등록**으로 넘어가는 순간, 시스템이 **자동으로** 다음을 수행합니다
(관리자 조작 불필요, 실패해도 상담 전환은 막지 않는 best-effort 처리).

1. **학생 자동 생성/매칭** — 상담의 학생 이름+전화로 기존 학생을 찾고, 없으면 학생관리(`/admin/std`)에 신규 생성(상태 `ACTIVE`, 시작일=오늘, 학교·학년 이관).
2. **학부모 자동 생성/매칭 + 연결** — 보호자 이름이 있으면 학부모를 찾거나 생성하고, **학생에 연결**(첫 보호자는 대표 보호자로 지정).
3. **포털 계정 자동 준비** — 학생·학부모 포털 계정을 준비합니다.
   - **학부모**: 임의 아이디로 즉시 발급.
   - **학생**: **이메일이 있어야** 발급됩니다. 자동 생성된 학생은 이메일이 없으므로 이 단계에서는 **조용히 건너뜁니다** → 관리자가 학생 이메일을 입력한 뒤 발급(§6).
4. **레벨테스트 점수 상속** — 상담에서 기록한 MAP 점수를 학생 레코드로 복사합니다.
5. **[수강등록완료] 버튼** — 위 자동 등록으로 학생이 연결(`stdId`)되면 버튼이 활성화되며, 클릭 시 상담을 **7. 수강중**으로 전환합니다. (학생 연결 전에는 "학생 자동등록 대기 중"으로 비활성)

> **멱등성**: 이미 학생이 연결된 상담은 다시 등록하지 않습니다. 중복 생성 걱정 없이 재진입해도 안전합니다.

## 6. 학생 등록 · 이메일 · 포털 로그인 발급 (Student account)

### 6.1 학생 등록 (`/admin/std`)

학생은 **자동 생성**(§5) 또는 학생관리에서 **직접 추가**할 수 있습니다. 저장 시 규칙:

| 항목 | 규칙 |
|------|------|
| **이메일** | **필수** — 없으면 저장 불가(`EMAIL_REQUIRED`). 학생 포털 로그인 아이디로 사용됩니다. |
| **이메일 중복** | 같은 학원 내 **중복 불가**(`EMAIL_DUPLICATE`, 409). 대소문자 무시. |
| **담당강사** | 자유 입력이 아니라 **등록된 강사 목록(`/admin/tch`)에서 선택**(FK 연결). |
| 기타 | 이름·영문이름·성별·생년월일·전화·학교·학년·과목·상태 등 |

> 목록 기본 정렬은 **최신 등록일순**입니다.
> 자동 생성된 학생은 이메일이 비어 있으므로, **포털을 열어주려면 관리자가 학생 상세에서 이메일을 입력**해야 합니다.

### 6.2 학생 포털 계정 발급

학생 상세 화면의 **"포털 계정" 패널**에서 발급합니다.

- 이메일이 **없으면**: "이메일 입력 후 발급 가능" 안내가 뜹니다(발급 시도 시 `422 STUDENT_EMAIL_REQUIRED`).
- 이메일이 **있으면**: **로그인 아이디 = 학생 이메일**(소문자)로 계정을 발급합니다.
- 발급/재발급 시 **임시 비밀번호(10자, 영문+숫자)가 1회 표시**됩니다 → 복사해서 학생/학부모에게 전달하세요.
- 최초 로그인 시 **비밀번호 변경이 강제**됩니다(`mustChangePassword`).
- 비밀번호를 잊었으면 **[비밀번호 재발급]**으로 새 임시 비밀번호를 발급합니다(잠금도 해제).

## 7. 학부모 등록 · 학생 연결 (Parent account & linkage)

### 7.1 학부모 생성과 연결 방식

학부모는 **독립된 레코드**이며, 학생과는 **연결 테이블**로 이어집니다(학생에 직접 붙는 필드가 아님).

- **자동**(§5): 상담의 보호자 정보로 생성·연결(첫 보호자 = 대표).
- **학생 폼 내 입력**: 학생 등록/수정 시 보호자 목록에서 기존 학부모 연결 또는 신규 입력(이름·관계·전화·이메일 + 대표 여부).
- **개별 관리**: 학부모 단독 등록 후 학생에 연결/해제, 대표 보호자 지정도 가능합니다.

관계 특성:
- 한 학생 ↔ 여러 보호자, 한 보호자 ↔ 여러 자녀(형제·자매) 가능.
- **대표 보호자(primary)는 학생당 1명** — 새로 대표를 지정하면 기존 대표는 자동 해제됩니다.

### 7.2 학부모 포털 계정

- 학부모 계정 아이디는 **임의 생성 아이디**(예: `p8k3m9`)입니다. (학생과 달리 이메일 로그인 아님)
- 발급/재발급·임시 비밀번호·최초 변경 강제는 학생과 동일합니다(§6.2).

## 8. 강사 등록 (Teacher registration) — 관리자 직접

강사는 **관리자(ADMIN)가 직접** 강사관리(`/admin/tch`)에서 등록합니다. (직원 STAFF는 등록 불가, 조회만)

### 8.1 입력 항목

| 항목 | 필수 | 설명 |
|------|:---:|------|
| 강사 이름 / 영문 이름 | ✔ / | 학원 내 이름·영문이름 중복 불가 |
| 이메일 | ✔ | 학원 내 중복 불가 |
| 전화 · 생년월일 | | |
| 담당 과목 | | MAP / 수학 / Writing / Language Arts / SSAT / ISEE / 국제입시 / 기타(다중) |
| 강사 여부 · 고용형태 | | 강사/비강사 구분, 정규직/파트타임 |
| 입사일자 · 출결번호 · 메모 | | |
| 상태 | | 재직(ACTIVE) / 휴직(LEAVE) / 퇴사(RESIGNED) |

### 8.2 강사 로그인(콘솔 계정) 발급

- 강사 등록 시 **"계정 생성" 옵션**을 켜고 비밀번호(8자 이상, 영문+숫자)를 지정하면 **콘솔 로그인(`usr_role=TEACHER`)**이 함께 만들어집니다.
- 이후 강사 상세에서 **비밀번호 재설정 / 계정 잠금·해제**가 가능합니다.
- **강사 포털 계정**(포털 열람용)은 별도로 "포털 계정" 패널에서 발급합니다(임의 아이디).

### 8.3 AMA 연동

- 강사 생성 시 **AMA 사용자 선택기**로 플랫폼 교사를 고르면 이름·이메일이 자동 채워집니다(연결 `tch_ama_user_id`).
- AMA가 불가할 때를 위한 **수동 입력 모드**도 있습니다.
- 상담 2·3단계(레벨테스트/데모수업)에서 담당강사 일정 저장 시에도 AMA 강사가 자동 upsert됩니다.

## 9. 강사 수업일정 등록 · 학생 추가 (Class scheduling & roster)

수업(`/admin/cls`)은 **강사 + 과목 + 학생 명단 + 주간 반복 일정**을 묶은 단위입니다.

### 9.1 수업 생성

수업 생성 다이얼로그에서 입력:
- **과목 / 코스**
- **담당 강사** — `ACTIVE` 강사 중 **콘솔 계정이 있는 강사**만 선택 가능(수업은 강사의 콘솔 사용자에 연결됩니다).
- **개강일 / 종강일 / 교재·메모 / 시급**
- **학생 추가** — 수업에 넣을 학생을 **여러 명 선택**하고 그중 **대표 학생 1명**을 지정(1명 초과 시 그룹 수업으로 자동 표시).
- **주간 반복 일정(1개 이상)** — 요일 / 시작 시각 / 수업시간(분) / 수업방식(대면·온라인·2인 대면).

저장하면 수업이 만들어지고, 이어서 **세션(개별 수업 회차)이 반복 규칙으로 자동 생성**됩니다(기본 35일치). 이때 **같은 강사/학생의 시간 겹침**은 자동 검출되어 차단됩니다.

### 9.2 학생 추가에 대한 중요한 구분

학생↔수업 연결은 **두 가지**가 있으니 혼동하지 마세요.

| 구분 | 무엇 | 어떻게 |
|------|------|--------|
| **수업 명단(roster)** | 실제 수업을 듣는 학생 목록. 출석·정산의 기준 | 수업 **생성 시** 학생을 추가(대표/그룹). *기존 수업에 나중에 추가하는 별도 버튼은 현재 없음 — 명단은 생성 시 확정* |
| **수강 신청(enrollment)** | 학부모가 수업에 **신청** → 관리자가 **승인** | 신청 상태 `대기 → 확정/취소` 관리 |

> 요구사항의 "강사 수업일정 등록 → 학생 추가"는 **수업 명단(roster)** 경로입니다.

## 10. 강의 진행 (Conducting the class)

각 수업 세션에서 강사/관리자가 기록하는 항목:

- **출석(출석부)** — 세션별로 학생 상태(출석 / 결석(사유)/ 지각 / 조퇴)와 인정 시수를 기록합니다.
  출석을 기록하면 **세션이 자동으로 "진행완료(HELD)"** 로 바뀌고 실제 진행 시각·분이 채워집니다.
- **수업 피드백(진도)** — 진도, 피드백, 과제, 취약점·발전, 학습계획을 작성(초안 → 제출 → 학부모 전달).
- **보강** — 결석/휴강에 대한 보강 세션 계획·결정.
- **정산** — 출석 × 시급으로 강사 정산 라인이 집계됩니다.
- **세션 관리** — 일정 변경(reschedule) / 취소(cancel) / 진행(hold), 화상 링크(Google Meet 등) 연동.

학생·학부모는 **포털 수업일정(캘린더)** 에서 자신과 관련된 세션만 열람하고, 전달된 피드백을 확인할 수 있습니다.

## 11. 포털 로그인 방법 (Portal login) — 학생·학부모·강사 공통

포털 로그인(`/portal/login`)은 **학원 코드 + 아이디 + 비밀번호** 3가지가 필요합니다(멀티테넌트 격리, PLN-260708).

```
┌───────────────────────────────────┐
│         (학원 로고) TAC 포털        │
│  학원 코드  [ tpi              ]    │ ← 로그인 링크 ?t=tpi 있으면 자동채움(고정)
│  아이디    [ student@example.com]   │ ← 학생=이메일, 학부모·강사=발급 아이디
│  비밀번호  [ ••••••••          ]    │
│          [        로그인        ]   │
│  · 최초 로그인 시 비밀번호를 변경합니다 │
└───────────────────────────────────┘
```

- **학원 코드**: 학원별 짧은 코드(예: 트리니티/TPI = `tpi`). 관리자가 배포하는 로그인 링크 `…/portal/login?t=<코드>`를 쓰면 자동으로 채워집니다.
- **아이디**: 학생 = **본인 이메일**, 학부모·강사 = **발급된 임의 아이디**.
- **비밀번호**: 관리자가 발급한 **임시 비밀번호** → **최초 로그인 시 변경**.
- 로그인 후에는 학원 코드를 다시 넣을 필요가 없습니다(토큰에 학원 정보 포함).
- **보안**: 잘못된 학원 코드·아이디·비밀번호는 **모두 동일한 오류 메시지**로 처리되어 계정 존재 여부가 노출되지 않습니다. 계정 잠금 시 "학원에 문의하세요" 안내가 표시됩니다.

## 13. 자주 묻는 문제 (Troubleshooting)

| 증상 | 원인 / 해결 |
|------|-------------|
| [수강등록완료] 버튼이 비활성 | 학생 자동등록이 아직 안 됨. 상담 학생 정보(이름/전화)가 유효한지, 익명이 아닌지 확인. |
| 학생 저장 시 "이미 사용 중인 이메일" | 같은 학원에 동일 이메일 학생 존재(중복 불가). 다른 이메일 사용. |
| 학생 포털 계정 발급이 안 됨 | 학생 **이메일이 비어 있음**. 학생 상세에서 이메일 입력 후 발급. |
| 자동 생성된 학생에 포털이 안 열림 | 자동 학생은 이메일이 없음 → 관리자가 이메일 입력 후 [발급]. |
| 수업 생성 시 강사가 목록에 없음 | 해당 강사에 **콘솔 계정(TEACHER)이 없음**. 강사 등록 시 계정을 생성했는지 확인. |
| 기존 수업에 학생을 못 추가 | 명단은 **수업 생성 시** 확정됩니다(현재 추가 버튼 없음). 신규 수업으로 구성하거나 수강신청 승인 경로 사용. |
| 포털 로그인 실패(원인 불명) | 보안상 코드/아이디/비번 오류가 동일 메시지입니다. **학원 코드**와 아이디(학생=이메일)를 재확인. |
| 강사를 STAFF가 등록하려는데 막힘 | 강사 마스터 등록은 **ADMIN만** 가능. |
