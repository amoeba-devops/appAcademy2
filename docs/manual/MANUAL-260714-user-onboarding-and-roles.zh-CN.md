# 用户注册与角色运营手册 (User Onboarding & Roles Manual)

> 本手册说明通过网页咨询申请进入的学生与家长，如何经过 **咨询 → 报名注册 → 在读**，
> 最终获得 **学生、家长、讲师各自的账户** 的完整流程。
> 咨询 6 阶段的具体录入项请参阅[咨询管理用户手册](MANUAL-260624-csl-consultation-userguide.md)，
> 本手册聚焦于 **账户创建与角色**。界面标签均以实际 UI（韩语）为准。

---

## 0. 两套账户体系 (Two account systems) — 请先理解

TAC 中存在 **性质不同的两类登录**。为避免混淆，先做区分。

| 分类 | 运营控制台账户 (Admin/Console) | 门户账户 (Portal) |
|------|-------------------------------|--------------------|
| 登录位置 | `/admin/*` 运营控制台 | `/portal/login` 门户 |
| 数据表 | `amb_acm_user` | `amb_acm_portal_account` |
| 对象 | **管理员 · 讲师 · 职员** | **学生 · 家长 · 讲师** |
| 角色值 | `ADMIN` / `TEACHER` / `STAFF` / `APP_ADMIN` | `STUDENT` / `PARENT` / `TEACHER` |
| 用途 | 学院运营、咨询、课程管理 | 查看公告、课程日程、资料室 |

- **讲师可以同时拥有两种账户。** 控制台登录（课程/考勤管理）与门户登录（门户查看）是相互独立的。
- **学生与家长只拥有门户账户**（不会登录运营控制台）。
- 所有账户与数据都 **按所属学院（租户）单位隔离**。看不到其他学院的账户。

## 1. 整体流程一览 (End-to-end flow)

```
[网页咨询申请]        [运营控制台 — 咨询管理 /admin/csl]                    [账户发放]
主页表单        ─▶   1.接受 → 2.分级测试 → 3.演示课 → 4.报名咨询 → 5.支付
(学生/家长填写)                                                       │
                                                                     ▼ 进入 6.报名注册 时
                                                        ┌─────────────────────────────┐
                                                        │ 自动创建学生 (学生管理 /admin/std)│
                                                        │ 自动创建家长 + 关联到学生         │
                                                        │ 自动准备学生·家长门户账户         │
                                                        │ 分级测试成绩继承到学生            │
                                                        └─────────────────────────────┘
                                                                     │ [수강등록완료] 按钮
                                                                     ▼
                                                                7.在读
                                                                
[讲师] 管理员直接注册 (/admin/tch) ─▶ [注册课程日程 /admin/cls: 讲师·科目·星期·时间 + 添加学生]
                                   ─▶ [授课进行: 课时考勤·反馈记录]
```

**核心规则一句话总结**
- 学生与家长账户在咨询到达 **6. 报名注册** 时会 **自动** 创建（无需管理员手动创建）。
- 讲师由 **管理员直接** 注册（非自动创建）。
- 门户登录始终需要 **（学院代码 + 账号 + 密码）** 这 3 项。

## 2. 用户类型与角色 (User types & roles)

### 2.1 角色一览表

| 用户 | 账户体系 | 角色/种类 | 账户创建方 | 主要权限 |
|--------|-----------|-----------|----------------|-----------|
| **管理员(院长/负责人)** | 控制台 | `ADMIN` | AMA 联动 / 初始种子 | 全部功能。讲师注册·修改·删除、学费缴纳确认、阶段回退、门户账户发放 |
| **职员(非带班职员)** | 控制台 | `STAFF` | 管理员 | 使用咨询·课程界面、从 AMA 导入讲师。**不可注册/修改讲师主档** |
| **讲师** | 控制台(可选) + 门户(可选) | 控制台 `TEACHER` / 门户 `TEACHER` | 管理员(注册讲师时) | 进行所负责课程、记录考勤·反馈、撰写演示课反馈。不可管理讲师主档 |
| **学生** | 门户 | `STUDENT` | **自动**(6.报名注册) 或在学生管理中手动 | 在门户查看公告、课程日程、资料室 |
| **家长** | 门户 | `PARENT` | **自动**(6.报名注册) 或在学生管理中手动 | 在门户查看子女相关公告·日程、申请课程 |
| (平台运营者) | 控制台 | `APP_ADMIN` | AMA 平台 | 系统/租户管理(学院代码设置等) |

> 控制台角色由 AMA 平台等级派生：MASTER/OWNER/MANAGER → **ADMIN**，jobRole=TEACHER → **TEACHER**，其余 → **STAFF**。

### 2.2 各用户角色详解

- **学生 (STUDENT)** — 在读的学生本人。在门户查看 **与自己相关的** 公告、课程日程（日历）、资料室。登录账号为 **本人邮箱**。
- **家长 (PARENT)** — 学生的监护人。一名学生可有多名监护人，一名监护人可有多名子女，并指定 1 名 **主监护人(primary)**。可在门户查看子女相关信息并申请课程。
- **讲师 (TEACHER)** — 由管理员直接注册。记录所负责课程的日程、考勤、反馈（进度），并撰写咨询流程中的演示课反馈。**讲师名单（主档）仅管理员** 可管理。

## 3. 网页咨询申请 (Public intake) — 账户的起点

学生与家长从 **主页公开表单** 开始。共有两种表单，受理后会在运营控制台的
**咨询管理(`/admin/csl`)中，以 1. 接受状态的新增咨询** 累积。

| 表单 | 界面 | 主要录入 | 受理结果 |
|----|------|-----------|-----------|
| **咨询申请** | `/web/contact` | 学生姓名·年级 / **监护人姓名·电话(必填)** / 咨询目的(多选) | 来源=主页，申请类型=仅咨询 |
| **分级测试(MAP)申请** | `/web/test` | 学生中·英文姓名·出生日期·性别 / 监护人姓名·电话·邮箱 / 应试国家·城市 | 来源=主页，申请类型=仅考试 |

> 此阶段 **尚不会创建学生/家长账户**。受理仅以"咨询记录"形式存在，
> 实际的学生·家长记录与门户账户在 **6. 报名注册** 阶段才创建（见第 4 章）。

## 4. 新增咨询各阶段录入 (Consultation stages)

咨询按 **7 个阶段 + 咨询结束** 进行。各阶段的推进按钮 **只显示允许的下一阶段**，
不满足推进条件时会报错，阶段不会变更。

| # | 阶段(标签) | 内部代码 | 本阶段录入内容(摘要) | 进入下一阶段的条件 |
|---|-----------|-----------|------------------------------|---------------------|
| 1 | **접수**(接受) | `INTAKE` | 学生/监护人信息、学校·年级、来源渠道、申请类型·目的 | (无条件) · 匿名无法推进 |
| 2 | **레벨테스트**(分级测试) | `MAP_TEST` | 应试费状态(缴纳/免除)、应试预定日·负责讲师、成绩(阅读·数学·语言等) | 已有既往成绩 / 应试费缴纳·免除 / 至少 1 项成绩 |
| 3 | **데모수업**(演示课) | `TRIAL_CLASS` | 演示课预定日·负责讲师、讲师反馈 | 至少登记 1 次演示课 |
| 4 | **등록 상담**(报名咨询) | `ENROLLMENT_COUNSELING` | 课程、上课次数、学费、上课时间、**分配负责讲师**、报名咨询完成 | "报名咨询完成 = YES" |
| 5 | **결제**(支付) | `PAYMENT` | 支付日·方式·金额、**学费缴纳完成(仅负责人)** | 勾选"学费缴纳完成" |
| 6 | **수강등록**(报名注册) | `CLASS_STARTED` | (无单独录入 — 确认摘要) | ⇒ 进入时 **自动创建学生·家长·账户** |
| 7 | **수강중**(在读) | `ATTENDING` | (无单独录入) | 最后一个正向阶段 |
| — | **상담종료**(咨询结束) | `DROPPED` | 结束原因(默认值：**단순문의종료**/单纯咨询结束) | 在任意阶段均可结束 |

> 各阶段的详细录入项与校验规则请参阅[咨询管理用户手册 §2](MANUAL-260624-csl-consultation-userguide.md)。
> **注意(标签 vs 动作):** 阶段 6 的标签为"6. 수강등록"（报名注册），在第 6 阶段面板点击 **[수강등록완료]**（报名注册完成）按钮后，
> 咨询会推进到 **7. 수강중**（在读）。而学生·家长记录则在更早的 **进入第 6 阶段"进入时点"就已创建**（见下文 §5）。

## 5. 进入第 6 阶段"报名注册"时 — 自动注册 (What happens at CLASS_STARTED)

咨询从 **5. 支付 → 6. 报名注册** 推进的那一刻，系统会 **自动** 执行以下操作
（无需管理员操作，即使失败也不会阻止咨询转换，采用 best-effort 处理）。

1. **自动创建/匹配学生** — 用咨询的学生姓名+电话查找既有学生，若无则在学生管理(`/admin/std`)新建（状态 `ACTIVE`，开始日=今天，转移学校·年级）。
2. **自动创建/匹配家长 + 关联** — 若有监护人姓名则查找或创建家长，并 **关联到学生**（首位监护人指定为主监护人）。
3. **自动准备门户账户** — 准备学生·家长的门户账户。
   - **家长**：以随机账号立即发放。
   - **学生**：**必须有邮箱** 才能发放。自动创建的学生没有邮箱，因此此步骤会 **静默跳过** → 由管理员录入学生邮箱后再发放（§6）。
4. **分级测试成绩继承** — 将咨询中记录的 MAP 成绩复制到学生记录。
5. **[수강등록완료] 按钮** — 经上述自动注册使学生被关联（`stdId`）后，按钮即被激活，点击后将咨询转换为 **7. 수강중**（在读）。（学生关联前，按钮显示为"学生自动注册等待中"的禁用状态）

> **幂等性**：已关联学生的咨询不会重复注册。无需担心重复创建，重新进入也是安全的。

## 6. 学生注册 · 邮箱 · 门户登录发放 (Student account)

### 6.1 学生注册 (`/admin/std`)

学生可以 **自动创建**（§5），也可以在学生管理中 **直接添加**。保存时的规则：

| 项目 | 规则 |
|------|------|
| **邮箱** | **必填** — 无则无法保存(`EMAIL_REQUIRED`)。将作为学生门户登录账号使用。 |
| **邮箱去重** | 同一学院内 **不可重复**(`EMAIL_DUPLICATE`, 409)。忽略大小写。 |
| **负责讲师** | 非自由输入，而是 **从已注册讲师列表(`/admin/tch`)中选择**（FK 关联）。 |
| 其他 | 姓名·英文名·性别·出生日期·电话·学校·年级·科目·状态等 |

> 列表默认排序为 **最新注册日顺序**。
> 自动创建的学生邮箱为空，因此 **若要开通门户，管理员需在学生详情中录入邮箱**。

### 6.2 学生门户账户发放

在学生详情界面的 **"门户账户"面板** 中发放。

- **无邮箱** 时：显示"录入邮箱后方可发放"提示（尝试发放时返回 `422 STUDENT_EMAIL_REQUIRED`）。
- **有邮箱** 时：以 **登录账号 = 学生邮箱**（小写）发放账户。
- 发放/重新发放时，**临时密码（10 位，字母+数字）会一次性显示** → 请复制后转交给学生/家长。
- 首次登录时 **强制修改密码**（`mustChangePassword`）。
- 若忘记密码，可通过 **[비밀번호 재발급]**（密码重新发放）发放新的临时密码（同时解除锁定）。

## 7. 家长注册 · 学生关联 (Parent account & linkage)

### 7.1 家长创建与关联方式

家长是 **独立的记录**，与学生之间通过 **关联表** 连接（并非直接挂在学生上的字段）。

- **自动**（§5）：用咨询的监护人信息创建·关联（首位监护人 = 主监护人）。
- **在学生表单内录入**：注册/修改学生时，从监护人列表关联既有家长或新增录入（姓名·关系·电话·邮箱 + 是否主监护人）。
- **单独管理**：家长可单独注册后再关联/解除学生，也可指定主监护人。

关系特性：
- 一名学生 ↔ 多名监护人，一名监护人 ↔ 多名子女（兄弟姐妹）均可。
- **主监护人(primary)每名学生仅 1 人** — 新指定主监护人时，原主监护人会自动解除。

### 7.2 家长门户账户

- 家长账户的账号为 **随机生成账号**（例：`p8k3m9`）。（与学生不同，不是邮箱登录）
- 发放/重新发放、临时密码、首次强制修改均与学生相同（§6.2）。

## 8. 讲师注册 (Teacher registration) — 管理员直接操作

讲师由 **管理员(ADMIN)直接** 在讲师管理(`/admin/tch`)中注册。（职员 STAFF 不可注册，仅可查看）

### 8.1 录入项

| 项目 | 必填 | 说明 |
|------|:---:|------|
| 讲师姓名 / 英文名 | ✔ / | 学院内姓名·英文名不可重复 |
| 邮箱 | ✔ | 学院内不可重复 |
| 电话 · 出生日期 | | |
| 负责科目 | | MAP / 数学 / Writing / Language Arts / SSAT / ISEE / 国际升学 / 其他(多选) |
| 是否讲师 · 雇佣形态 | | 讲师/非讲师区分，正式/兼职 |
| 入职日期 · 考勤号 · 备注 | | |
| 状态 | | 在职(ACTIVE) / 休职(LEAVE) / 离职(RESIGNED) |

### 8.2 讲师登录(控制台账户)发放

- 注册讲师时开启 **"创建账户"选项** 并指定密码（8 位以上，字母+数字），即会一并创建 **控制台登录(`usr_role=TEACHER`)**。
- 之后可在讲师详情中进行 **密码重置 / 账户锁定·解锁**。
- **讲师门户账户**（供门户查看）需另在"门户账户"面板发放（随机账号）。

### 8.3 AMA 联动

- 创建讲师时通过 **AMA 用户选择器** 选取平台教师，姓名·邮箱会自动填充（关联 `tch_ama_user_id`）。
- 也提供在 AMA 不可用时使用的 **手动录入模式**。
- 在咨询第 2·3 阶段（分级测试/演示课）保存负责讲师日程时，AMA 讲师也会自动 upsert。

## 9. 讲师课程日程注册 · 添加学生 (Class scheduling & roster)

课程(`/admin/cls`)是将 **讲师 + 科目 + 学生名单 + 每周重复日程** 打包成的单元。

### 9.1 创建课程

在创建课程对话框中录入：
- **科目 / 课程**
- **负责讲师** — 仅可从 `ACTIVE` 讲师中 **拥有控制台账户的讲师** 中选择（课程会关联到讲师的控制台用户）。
- **开课日 / 结课日 / 教材·备注 / 时薪**
- **添加学生** — 选择要加入课程的 **多名学生**，并从中指定 **1 名代表学生**（超过 1 名时自动标记为团体课程）。
- **每周重复日程(1 个以上)** — 星期 / 开始时刻 / 上课时长(分钟) / 上课方式(面授·线上·2 人面授)。

保存后课程即创建，随后会按重复规则 **自动生成课时（单次课程会次）**（默认 35 天量）。此时 **同一讲师/学生的时间重叠** 会被自动检测并阻止。

### 9.2 关于"添加学生"的重要区分

学生↔课程的关联有 **两种**，请勿混淆。

| 分类 | 是什么 | 如何操作 |
|------|------|--------|
| **课程名单(roster)** | 实际上课的学生列表。考勤·结算的依据 | 在 **创建课程时** 添加学生(代表/团体)。*目前没有向既有课程后续添加的独立按钮 — 名单在创建时确定* |
| **课程申请(enrollment)** | 家长向课程 **申请** → 管理员 **审批** | 管理申请状态 `等待 → 确定/取消` |

> 需求中的"讲师课程日程注册 → 添加学生"走的是 **课程名单(roster)** 路径。

## 10. 授课进行 (Conducting the class)

各课时中由讲师/管理员记录的项目：

- **考勤(考勤簿)** — 按课时记录学生状态（出席 / 缺席(原因) / 迟到 / 早退）与认定课时数。
  记录考勤后，**课时会自动变为"진행완료(HELD)"（进行完成）**，并填入实际进行的时刻·分钟。
- **课程反馈(进度)** — 撰写进度、反馈、作业、薄弱点·进步、学习计划（草稿 → 提交 → 转达给家长）。
- **补课** — 针对缺席/停课的补课课时计划·决定。
- **结算** — 按 出席 × 时薪 汇总讲师结算明细。
- **课时管理** — 日程变更(reschedule) / 取消(cancel) / 进行(hold)、视频链接(Google Meet 等)联动。

学生与家长可在 **门户课程日程（日历）** 中仅查看与自己相关的课时，并确认已转达的反馈。

## 11. 门户登录方式 (Portal login) — 学生·家长·讲师通用

门户登录(`/portal/login`)需要 **学院代码 + 账号 + 密码** 这 3 项（多租户隔离，PLN-260708）。

```
┌───────────────────────────────────┐
│         (学院 Logo) TAC 门户        │
│  学院代码  [ tpi              ]    │ ← 登录链接带 ?t=tpi 时自动填充(固定)
│  账号     [ student@example.com]   │ ← 学生=邮箱，家长·讲师=发放的账号
│  密码     [ ••••••••          ]    │
│          [        登录          ]   │
│  · 首次登录时需修改密码              │
└───────────────────────────────────┘
```

- **学院代码**：各学院的简短代码（例：Trinity/TPI = `tpi`）。使用管理员分发的登录链接 `…/portal/login?t=<代码>` 时会自动填充。
- **账号**：学生 = **本人邮箱**，家长·讲师 = **发放的随机账号**。
- **密码**：管理员发放的 **临时密码** → **首次登录时修改**。
- 登录后无需再次输入学院代码（令牌中已含学院信息）。
- **安全**：错误的学院代码·账号·密码 **均以相同的错误消息** 处理，不会暴露账户是否存在。账户被锁定时会显示"请联系学院"的提示。

## 13. 常见问题排查 (Troubleshooting)

| 症状 | 原因 / 解决 |
|------|-------------|
| [수강등록완료] 按钮为禁用 | 学生自动注册尚未完成。检查咨询学生信息(姓名/电话)是否有效、是否非匿名。 |
| 保存学生时提示"该邮箱已被使用" | 同一学院内存在相同邮箱的学生(不可重复)。请使用其他邮箱。 |
| 学生门户账户无法发放 | 学生 **邮箱为空**。在学生详情录入邮箱后再发放。 |
| 自动创建的学生无法开通门户 | 自动学生没有邮箱 → 管理员录入邮箱后点击[发放]。 |
| 创建课程时讲师不在列表中 | 该讲师 **没有控制台账户(TEACHER)**。检查注册讲师时是否创建了账户。 |
| 无法向既有课程添加学生 | 名单在 **创建课程时** 确定(目前无添加按钮)。请重新组建新课程，或使用课程申请审批路径。 |
| 门户登录失败(原因不明) | 出于安全，代码/账号/密码错误均为相同消息。请重新确认 **学院代码** 与账号(学生=邮箱)。 |
| STAFF 尝试注册讲师但被阻止 | 讲师主档注册 **仅 ADMIN** 可操作。 |
