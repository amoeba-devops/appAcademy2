# 가이드 1 — 상담 진행 관리 과정 (Consultation Process)

> **상담신청자**(홈페이지에서 상담을 신청하는 학부모·학생)와 **학원관리자**(상담을 접수·관리하는 운영자)가
> 각각 **무엇을 하는지**, 상담이 접수부터 수강등록까지 **어떤 단계로 진행되는지**를 한 문서로 정리합니다.
> 화면 라벨은 실제 UI(한국어) 기준이며, 수강등록 이후(포털계정·수업배정·강의실 입장)는 **[가이드 2](GUIDE-260721-enrollment-to-classroom.md)** 로 이어집니다.

---

## 0. 전체 흐름 한눈에 (End-to-end)

```
[상담신청자]                         [학원관리자 — 상담 관리 /admin/csl]
홈페이지 상담신청 폼        ┌──────────────────────────────────────────────────────────┐
 /web/contact  ──접수──▶   │ 1.접수 → 2.레벨테스트 → 3.데모수업 → 4.등록상담 → 5.결제 → 6.수강등록 → 7.수강중 │
(계정 없이 신청)           └──────────────────────────────────────────────────────────┘
                                    │            어느 단계에서든 ▶ "완료"(상담 종료/이탈) ◀ 재활성화
                                    ▼ 6.수강등록 진입 시 = 자동 전환
                          학생·학부모 레코드 + 포털 로그인 계정 자동 생성 → (가이드 2)
```

- **상담신청자**는 **계정 없이** 공개 폼으로 신청만 합니다. 이 시점엔 "상담 건"만 생기고, 학생·학부모 계정은 아직 없습니다.
- **학원관리자**는 접수된 상담을 **7단계 파이프라인**으로 관리하며, 각 단계의 **진행 조건**을 충족해야 다음 단계로 넘어갑니다.
- **6. 수강등록** 단계에 진입하는 순간, 학생·학부모 레코드와 **포털 로그인 계정이 자동으로** 만들어집니다(관리자 수기 불필요).

## PART A — 상담신청자 (Applicant)

### A-1. 무엇을 하나
학원 홈페이지의 **상담신청 폼**을 작성해 제출합니다. 로그인·회원가입은 필요 없습니다.

| 신청 종류 | 화면(경로) | 성격 |
|---|---|---|
| **상담신청** | `/web/contact` | 일반 상담 문의 (기본) |
| **레벨테스트(MAP) 신청** | `/web/test` | 레벨테스트 응시 신청 |

> 진입: 포털 상단 메뉴의 **"상담신청 / 상담 문의"** 링크 또는 화면 우하단 플로팅 버튼.

### A-2. 상담신청 폼 입력 항목 (`/web/contact`)

| 항목 | 필수 | 설명 |
|---|:---:|---|
| **학생 이름** | ✔ | |
| 학년 | | 초1~초6 · 중1~중3 · 고1~고3 중 선택 |
| **보호자 이름** | ✔ | 최대 50자 |
| **연락처(보호자 전화)** | ✔ | 숫자 및 `+ - ( )` 공백, 7~20자 |
| 상담 목적 | | (다중 선택) MAP TEST 튜터링 / ISEE 튜터링 / 국제학교·외국인학교 입학 준비 / 맞춤형 GPA 관리 / 심화 수업 |
| **개인정보 수집·이용 동의** | ✔ | 체크해야 제출 가능 |

레벨테스트 신청(`/web/test`)은 위에 더해 **학생 영문이름·생년월일·성별·보호자 이메일·응시 국가/도시**를 추가로 받습니다.

### A-3. 제출 후 (What happens)
- 제출하면 **"접수 완료"** 안내가 표시됩니다. 별도 계정이나 확인 페이지는 없습니다.
- 접수된 신청은 학원 운영 콘솔의 **상담 관리(`/admin/csl`)에 "1. 접수" 상태 신규 상담**으로 자동 등록됩니다.
  - 자동 태깅: 유입경로 = **홈페이지**, 신청유형 = **상담만**(레벨테스트 폼은 **시험만**), 시작 단계 = **접수(INTAKE)**.
- 이후 **학원에서 연락**을 드리는 방식으로 진행되며, 상담신청자가 시스템에서 직접 진행 상황을 조회하지는 않습니다.

> ℹ️ **상담신청자에게 안내할 한 줄**: "홈페이지에서 상담을 신청하시면 접수되고, 담당자가 연락드립니다. 이후 레벨테스트·데모수업·등록 상담을 거쳐 수강이 시작됩니다."

## PART B — 학원관리자 (Administrator)

### B-1. 상담 관리 화면 (`/admin/csl`)
- **목록**: 좌측 사이드바 **"상담 관리"** → `/admin/csl`. 컬럼(No./학생/학교·학년/단계/유입/신청/등록일/후속일정), 단계 색상 배지. **칸반 보드** 뷰도 제공.
- **상세**: 행 클릭 → `/admin/csl/:id`. 3영역 구성 —
  1. **상단 헤더**: 학생 정보 + **단계 진행 버튼**(허용된 다음 단계만 노출) + 종료/재활성화
  2. **단계 스테퍼**: 7단계 진행 시각화
  3. **본문 2단**: (좌) 현재 단계 입력 패널 / (우) **기록·타임라인**(단계 이력 + 메모, 삭제 불가)
- **+ 신규 상담**: 전화·방문 등 홈페이지 외 유입을 관리자가 직접 접수할 때 사용.

### B-2. 7단계 파이프라인 (Pipeline)

> ⚠️ **라벨 vs 내부 코드**: 내부 enum 코드는 바뀌지 않았고 **화면 라벨만 개정**되었습니다. 아래 라벨은 현재 UI 실제 표기입니다.

| # | 단계 라벨(UI) | 내부 코드 | 이 단계에서 하는 일 | **다음 단계 진행 조건** |
|:-:|---|---|---|---|
| 1 | **1. 접수** | `INTAKE` | 학생·보호자 정보, 학교·학년, 유입경로, 신청유형·목적 입력 | 조건 없음. **단 익명 문의는 접수 이후 진행 불가** |
| 2 | **2. 레벨테스트** | `MAP_TEST` | 응시료 상태(납부/면제), 응시 예정일·담당강사, 점수(읽기·수학·언어 등) | ① 이전 점수 보유 / ② 응시료 납부·면제 / ③ 점수 1개 이상 — **중 하나** |
| 3 | **3. 데모수업** | `TRIAL_CLASS` | 데모(체험)수업 일정 등록, 강사 피드백 | **데모수업 일정 1건 이상** |
| 4 | **4. 등록 상담** | `ENROLLMENT_COUNSELING` | 코스·수강료·수업시간, 담당강사 배정, 등록 상담 완료 | **"등록 상담 완료 = 완료(YES)"** |
| 5 | **5. 결제** | `PAYMENT` | 수강료 수납 확정 | **"수강료 납부 완료" 체크** (※ **책임자 ADMIN만**) |
| 6 | **6. 수강등록** | `CLASS_STARTED` | (별도 입력 없음) — **진입 시 학생·학부모·포털계정 자동 생성** | (자동 전환·요약 확인) |
| 7 | **7. 수강중** | `ATTENDING` | (별도 입력 없음) 정식 수강 상태 | 마지막 정방향. **학생 연결(stdId) 완료** 필요 |
| — | **완료** (상담 종료/이탈) | `DROPPED` | 종료 사유 기록 | 어느 단계에서든 종료 가능, **재활성화**로 복귀 |

> 💡 `DROPPED`의 화면 라벨은 **"완료"** 이지만, 의미는 **상담 종료(이탈)** 입니다. 실제 수강이 시작된 상태가 아니므로 혼동에 주의하세요.

### B-3. 단계별 진행 게이트 (상세)
진행 버튼은 **현재 단계에서 허용된 다음 단계만** 노출되고, 조건 미충족 시 오류가 뜨며 단계가 바뀌지 않습니다.

- **접수 → 레벨테스트**: 조건 없음. (익명 문의는 학생 정보 입력해 익명 해제 전까지 진행 불가)
- **접수/레벨테스트 → 데모수업**: 이전 점수 보유 **또는** 응시료 납부·면제 **또는** 점수 1개 이상.
- **데모수업 → 등록 상담**: 데모수업 일정 **1건 이상**.
- **등록 상담 → 결제**: **등록 상담 완료 = YES**.
- **결제 → 수강등록**: **수강료 납부 완료 체크**(책임자만 설정 가능).
- **수강등록 → 수강중**: 학생 레코드 연결(`stdId`) 완료.

### B-4. 관리자가 할 수 있는 작업 (Actions)

| 작업 | 설명 | 권한 |
|---|---|---|
| **단계 진행(정방향)** | 헤더 진행 버튼 | 운영자 |
| **단계 되돌리기(역방향)** | **사유(2~500자) 필수**, 타임라인 기록 | **ADMIN / APP_ADMIN** |
| **상담 종료(이탈)** | 사유 코드 선택(기타 시 상세 필수), 종료시각 기록·삭제 불가 | 운영자 |
| **재활성화** | 종료 상태 → 직전 단계로 복귀 | 운영자 |
| **담당자 배정** | 상담 어드바이저 지정/변경 | 운영자 |
| **담당강사 배정** | 강사 다중 배정(PRIMARY/SECONDARY) | 운영자 |
| **메모/타임라인** | 메모 추가(최대 2000자), 삭제 불가 | 운영자 |
| **전화번호 보기(PII)** | 암호화된 보호자 전화 조회 — **감사 로그**(처리자·IP·브라우저) 기록 | 운영자 |
| **레벨테스트 기록** | 응시료·일정·점수(시험 유형별: MAP/ISEE/SSAT/TOEFL 등), 결과 PDF | STAFF↑ |
| **데모수업 일정** | 일정 등록 → **캘린더 자동 연동**, 강사 피드백(작성→확정→학부모 전달) | 운영자·강사 |
| **등록/결제 정보** | 코스·수강료·상담완료·납부완료·수강시작일 upsert | 운영자 (납부완료는 ADMIN) |
| **결제 승인** | 결제 방법·메모 기록 | **ADMIN / APP_ADMIN** |
| **첨부파일** | 성적표·자료·결과 PDF(≤10MB) | 역할별 |
| **상담 삭제/복원** | 소프트 삭제, **90일 내 복원** | 운영자 |

### B-5. 6. 수강등록 진입 시 자동 처리 (핵심)
상담이 **5. 결제 → 6. 수강등록**으로 넘어가는 순간, 시스템이 **자동으로**(관리자 조작 불필요, best-effort):

1. **학생 레코드 생성/매칭** — 상담의 학생 이름+전화로 기존 학생을 찾고 없으면 신규 생성(상태 ACTIVE, 시작일=오늘, 학교·학년 이관). 익명/이름없음 상담은 건너뜀.
2. **학부모 레코드 생성/매칭 + 연결** — 첫 보호자를 대표 보호자로 지정.
3. **포털 로그인 계정 발급** — 학생·학부모 포털 계정 준비(발급 규칙·이메일 필요 여부는 **[가이드 2](GUIDE-260721-enrollment-to-classroom.md)** 참조).
4. **레벨테스트 점수 상속** — 상담에 기록한 점수를 학생 레코드로 복사.
5. **CSL↔학생 연결** — 상담에 `stdId`가 기록되며 상세화면에 **"🎓 수강등록 연결"** 표시. (멱등 — 재진입해도 중복 생성 없음)

> 이 시점 이후의 **포털 로그인 → 수업일정 배정 → 보다스쿨 강의실 입장**은 **[가이드 2](GUIDE-260721-enrollment-to-classroom.md)** 에서 이어집니다.

## C. 자주 묻는 문제 (Troubleshooting)

| 증상 | 원인 / 해결 |
|---|---|
| 진행 버튼을 눌러도 단계가 안 바뀜 | 해당 단계 **진행 조건 미충족** — B-3 확인 후 필요한 정보 입력 |
| 익명 문의가 접수에서 안 넘어감 | 익명은 접수 이후 진행 불가 → 학생 정보 입력해 익명 해제 |
| 데모수업 "추가" 버튼 비활성 | **날짜(데모수업일)** 먼저 선택 |
| 레벨테스트 면제 저장 안 됨 | 응시료 "면제"면 **면제 사유** 필수 |
| "수강료 납부 완료" 저장 시 403 | 권한 부족 — **ADMIN/APP_ADMIN**만 표시 가능(BR-CSL-012) |
| 상담 종료 저장 안 됨 | 사유 코드 "기타"면 **상세 사유** 필수 |
| "완료" 라벨이 헷갈림 | `DROPPED`(상담 종료/이탈)의 화면 라벨이 "완료"임. 수강 시작(수강중)과 다름 |

## D. 부록 — 코드 매핑 (Reference)

**단계**: `INTAKE`(1.접수) · `MAP_TEST`(2.레벨테스트) · `TRIAL_CLASS`(3.데모수업) · `ENROLLMENT_COUNSELING`(4.등록 상담) · `PAYMENT`(5.결제) · `CLASS_STARTED`(6.수강등록) · `ATTENDING`(7.수강중) · `DROPPED`(완료=상담 종료/이탈)
**유입경로**: 홈페이지 `HOMEPAGE` · 카카오 채널 `KAKAO_CHANNEL` · 전화 `PHONE`
**신청유형**: 상담만 `COUNSELING_ONLY` · 시험만 `EXAM_ONLY` · 상담+시험 `BOTH`
**신청목적**: `MAP_TEST_TUTORING` · `ISEE_TUTORING` · `INTL_SCHOOL_PREP` · `GPA_MGMT` · `ADVANCED_COURSES`
**테이블**: `amb_acm_csl_inquiry`(상담 본체) · `amb_acm_csl_enrollment`(등록정보)
