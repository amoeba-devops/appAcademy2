# REQ-261112D Admin content width standard (운영 콘솔 우측 콘텐츠 영역 가로 폭 통일)

## 1. Request (요청)
모든 메뉴 화면의 우측 콘텐츠 영역 가로 사이즈 최적화 제안 — 기본 사이즈 통일.

## 2. Current State (현황, 2026-11-12 main 기준)
공통 틀: `frontend-acm/src/components/layout/admin-content-layout.tsx` + `styles/globals.css` `.admin-content-grid` + `styles/tokens.css` `--admin-content-width`.

| 유형 | 폭 | 화면 (운영 콘솔 라우트 72개 기준) |
|------|----|------|
| A. 공통 카드 | **최대 896px, 왼쪽 붙임** | 신규 상담·학생·학부모·교사·직원·수업 관리·**수업일정(달력)**·수업통계·맵테스트·학교·공지·Q&A·고객불만·드라이브·설정 등 대부분(약 58개) |
| B. 공통 카드 + 화면 자체 추가 제한 | 672~1024px | 마이페이지 672 · 알림함 768 · 테넌트 상세 768 · 학생 등록/수정 896 · 테넌트 목록 896 · Google OAuth 896 · 시스템 관리 1024(실제로는 896에 막힘) |
| C. 전체 폭 카드 | 제한 없음 | 수납관리 (12열 목록 때문에 REQ-261027C 에서 예외) |
| D. 카드 없이 전체 폭 | 제한 없음 | 대시보드 · 프로젝트 상세 · 문서 · 사용자 메뉴(iframe) |
| E. 전용 | 본문+패널 | 채팅 |

화면 너비별 실제 사용 폭 (사이드바 240px, 본문 여백 좌우 24px):

| 모니터 너비 | 쓸 수 있는 폭 | 지금 A 유형 | 오른쪽 빈 공간 |
|-------------|---------------|-------------|----------------|
| 1366 (노트북) | 1,078px | 896px | 182px |
| 1440 | 1,152px | 896px | 256px |
| 1920 (FHD) | 1,632px | 896px | **736px** |
| 2560 (QHD) | 2,272px | 896px | 1,376px |

문제점
1. 넓은 모니터에서 오른쪽이 크게 비는데, 학생·상담 목록 같은 여러 열 표는 896px 안에서 가로 스크롤이 생긴다.
2. 수업일정 달력이 896px 에 갇혀 칸이 좁다.
3. 수납관리만 전체 폭, 나머지는 896 → 메뉴를 옮길 때마다 카드 폭이 달라진다.
4. 일부 화면은 자체 폭(672~1024)을 또 지정해 카드 폭이 제각각이다.

## 3. Proposal (제안)
| ID | 내용 |
|----|------|
| P-1 | **기본 폭 하나로 통일: 최대 1,280px, 왼쪽 정렬**(현재 정렬 유지). 노트북(1366·1440)에서는 화면을 꽉 채우고, FHD 이상에서만 1,280px 에서 멈춘다. |
| P-2 | **전체 폭 예외는 '보드·달력형'만**: 대시보드, 수업일정 달력(`/admin/cal`), 프로젝트 상세, 문서, 사용자 메뉴, 채팅. 수납관리는 1,280 안에 12열이 들어가므로 기본 폭으로 편입. |
| P-3 | **폼·상세 화면**(마이페이지·알림함·학생 등록/수정·테넌트 등)은 카드 폭은 기본 1,280 으로 같게 두고, 입력 영역만 카드 안에서 최대 768px(왼쪽)로 둔다 → 메뉴를 옮겨도 카드 테두리가 같은 자리. |
| P-4 | 폭 값은 토큰 하나(`--admin-content-width`)와 예외 목록 하나(`admin-content-layout.tsx`)로만 관리. 화면별 `max-w-*` 최상위 지정은 없앤다. |
| P-5 | 모바일·태블릿(<1024)은 변경 없음(지금도 화면 폭 100%). |

비교 (1920 모니터)
```
지금   │사이드바│■■■■■■■■■■■■ 896 ■■■■■■■■■■■■│                 빈 공간 736                  │
제안   │사이드바│■■■■■■■■■■■■■■■■■■ 1,280 ■■■■■■■■■■■■■■■■■■│        빈 공간 352       │
```
1440 모니터: 지금 896 + 빈 256 → 제안 1,152(꽉 참).

## 4. Decisions (결정, 2026-11-12 사용자 선택)
| # | 질문 | 결정 |
|---|------|------|
| Q1 | 기본 최대 폭 | 1,280px |
| Q2 | 정렬 | 왼쪽 (현재 유지) |
| Q3 | 전체 폭 예외 | 대시보드·프로젝트 상세·문서·사용자 메뉴·채팅(기존) + 수업일정 달력(`/admin/cal`) + **수납관리**(`/admin/pay*`) + **신규 상담 목록**(`/admin/csl`) |
| Q4 | 폼·상세 화면 | 카드 폭 통일 + 입력 영역 `.admin-form-width`(768px) — 마이페이지(콘솔)·학생 등록/수정·테넌트 상세·Google OAuth. 알림함·테넌트 목록·시스템 관리는 목록이라 기본 폭 |

## 5. Implementation (구현)
- `styles/tokens.css` `--admin-content-width: 1280px`, `styles/globals.css` `.admin-form-width`.
- `components/layout/admin-content-layout.tsx` 전체 폭 예외: `/admin/pay*`·`/admin/cal`·`/admin/csl` (상세 `/admin/cal/:evtId`·`/admin/csl/:id` 는 기본 폭).
- `components/layout/system-shell.tsx` 시스템 콘솔(`/system/*`)도 같은 1,280 상한.
- 화면별 최상위 `max-w-*` 8곳 제거/교체. 포털 마이페이지(`/portal/me`)는 기존 672 유지.

## 6. Verification (확인)
- `tsc`·`vite build` 통과.
- Playwright(목 API) 27개 메뉴 × 1366·1440·1920: 1366=1,078·1440=1,152(꽉 참), 1920=1,280, `/admin/csl`·`/admin/cal`=1,632(전체 폭), 가로 넘침 0. (대시보드·학생·수납 등 7개는 목 응답 모양 문제로 렌더 안 됨 — 폭과 무관, 운영 확인 대상)
- 1920 마이페이지: 카드 1,280 안 입력 영역 768.
