# REQ-260916 — 맵테스트 신청 접수 (아임웹 `/test2` → ACM `/admin/test`) / MAP Test Application Intake

## 1. Requirement (요구사항 — 사용자 원문)

> `https://www.tpi.co.kr/test` · `https://trinityacademy.kr/test`
> 두 사이트의 test 신청 페이지를 **test2 로 별도로 만들어서**
> `https://acm.amoeba.site/admin/test` 페이지에 해당 신청 목록을 저장해야 한다.
> 기존 작업된 입력폼 확인하여 **acm 맵테스트 신청 목록과 상세 페이지**를 작성한다.
>
> 참고 아임웹 폼: TPI `b20251109ad2f5cac244d4`, TRINITY `b20260307b308ad82aec98`

즉 `/contact` → `/contact2` (REQ-260903G) 와 동일한 패턴을 맵테스트 신청 폼에 적용하고, 접수 결과를 콘솔에서 목록·상세로 관리한다.

## 3. Problem Statement (문제 정의)

1. 맵테스트 신청이 아임웹에만 쌓여 ACM 상담 파이프라인·대시보드와 분리되어 있다.
2. 기존 `POST /api/web/test` 는 주요 항목을 메모 문자열로 뭉개 검색·필터·통계가 불가능하다.
3. `/test` 를 직접 교체하면 운영 중인 폼과 누적 51+13건이 영향을 받는다 → **별도 `/test2` 로 병행 운영**이 필요하다.
4. 콘솔에 맵테스트 신청 전용 목록·상세가 없어 운영자가 아임웹과 ACM 을 오간다.

## 5. Non-functional / Constraints (비기능·제약)

- **보안**: 사이트 키는 `external-intake.config.ts` 의 기존 3사이트 키를 재사용한다(신규 키 발급·배포 불필요). 오리진 허용목록도 동일. 개인정보 동의 미체크는 400.
- **PII**: 학생 한글/영문 이름, 연락처, 학부모 이메일은 기존 `inq_*_encrypted/_iv/_auth_tag` 방식(AES-GCM)을 따른다. 생년월일·성별·응시 국가/도시·희망 요일시간은 평문 저장(식별성 낮음, 검색·통계 필요).
- **호환**: 기존 `POST /api/web/test` 와 `/web/test` 페이지는 제거하지 않고 유지하되, 신규 구조화 저장 경로를 함께 쓰도록 보완한다.
- **아임웹**: `/test2` 페이지는 GUIDE-260903G 절차(페이지 생성 → 코드 위젯 → 스니펫 붙여넣기 → 게시)를 따른다. 페이지 주소는 40자 제한.
- **성능**: 접수 API 는 사이트당 10회/분 레이트리밋 유지.

## 6. Out of Scope (범위 외)

- 아임웹 `/test` 페이지 폐지 또는 메뉴 교체 (별도 운영 판단).
- 알림톡 채널 인증·템플릿 신규 검수 신청 (기존 승인 템플릿 활용 또는 이메일 대체 — §9).
- 맵테스트 응시료 결제·일정 배정 자동화 (기존 `amb_acm_csl_map_test` 영역).
- SANTACROCE 사이트 (맵테스트 신청 폼 없음).

## 9. Notification on Intake (접수 알림 — Q5)

| 수신자 | 채널 | 내용 |
|--------|------|------|
| 신청자(학부모) | 알림톡 + 이메일 | 접수 확인 — 학생명·응시 희망 일시·담당 연락 예정 안내 |
| 운영자 | 콘솔 실시간 알림(기존 `acm.csl.created`) + 이메일 | 신규 맵테스트 신청 접수 + 콘솔 상세 링크 |

- 알림톡은 채널 인증·`pfId`·템플릿 검수 완료가 선행 조건이다. 미충족 시 **이메일만 발송하고 알림톡은 건너뛰되, 발송 실패를 접수 실패로 처리하지 않는다**(접수 우선).
- 학부모 이메일은 선택 항목이므로 미입력 시 학부모 이메일은 생략한다.
- 발송 결과는 로그로 남기고 실패해도 접수는 성공 처리한다.
