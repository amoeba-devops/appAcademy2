### 2.1 School Groups (학교별 행)

- 학교명이 비어 있는 행은 같은 학교의 후속 시험대상 행이다. 반복 헤더와 빈 행을 학교로 가져오지 않는다.
- `구분`은 초/중/고 등급이 아니라 `영국 IB 및 IGCSE`, `미국 WASC 인증` 같은 교육과정·인증 설명이다. 기존 `level=FOREIGN`으로 대체할 수 없다.
- 해외 인증 설명과 국내 인가여부는 별개다. `WASC 인증`이라는 이유로 `인가`를 자동 설정하지 않는다.
- 병합된 지원일정: J5:J7, J8:J9, J10:J13, J17:J18, J19:J21, J22:J23. 해당 범위에만 부모 셀 값을 적용한다. 모든 빈 일정에 앞 행 값을 복사하면 안 된다.
- J3 `2026-04-17`, J4 `2026-02-07`은 날짜형이다. 접수 마감일인지 시험일인지 명시되지 않아 임의로 날짜 종류를 정하지 않는다.
- 문장형 일정에는 학년도, 수시모집, 예정, 미정, 유선 확인중이 혼재한다. 원문과 줄바꿈을 보존하고 현재 모집 중이라고 자동 판단하지 않는다.

## 3. Current Gaps (현행과 차이)

운영 목록은 `이름 / 등급 / 지역 / 인가 / 학년대 / 일정 / 작업`이다. 확인 시 학교 18개, 인가 표시 모두 `AUTH'D`, 학년대/일정 건수 모두 0이었다. 엑셀 학교명과 운영 학교명은 앞뒤 공백·탭을 제거하면 18개가 일치한다. 이는 화면 이름 대조이며 DB ID 기반 import dry-run은 구현 단계에서 수행한다.

- `구분`, `시험내용`, `지원자격`, `지원일정 원문` 필드가 없다.
- 학년대는 숫자 최소/최대 학년 기반이라 `Reception`, `JK-G1`, `G8 이상`을 그대로 담기 어렵다.
- 일정은 연도/유형/날짜 중심이며 시험대상별 원문과 연결되지 않는다.
- `isAuthorized`는 boolean이며 기본값 true다. 미입력을 인가로 오인할 가능성이 있다. 운영의 11개 비인가 불일치는 확실하지만 발생 원인은 데이터 이력 추가 확인이 필요하다.
- 목록 로딩에서 학교별 학년대/일정 API를 각각 호출한다. 신규 목록은 집계/전형 정보를 일괄 조회하여 학교 수에 비례한 추가 요청을 없앤다.

## 5. Data Application Policy (데이터 반영안)

계획 승인 후 기능 구현과 원본 초기 반영을 진행하는 안이다. 상시 엑셀 업로드 버튼이나 업로드 CMS 추가는 이번 요청에 포함하지 않는다.

- 운영 이름 대조상 기존 18개 학교의 정보 추가가 예상된다. 실제 매칭은 같은 테넌트의 삭제되지 않은 학교만 대상으로 검증한다.
- 11개 명시적 `비인가`는 변경 전후 비교에 표시하고 원본 기준으로 정정한다. 첫 구역 7개의 인가여부/지역 빈칸은 기존 값 유지 및 원본 미기재로 보고한다. 학교 이름으로 지역을 추정하지 않는다.
- 학교명·구분·지원자격만 동일 학교 블록 안에서 공통값으로 해석한다. 시험내용/시험대상은 빈칸을 앞 행으로 채우지 않는다.
- 33개 원본 정보 행을 학교별 전형 정보로 보존한다. 대상이 비어 있어도 시험내용 또는 일정이 있는 행은 누락하지 않는다.
- 정규화는 앞뒤 공백·탭 제거 및 줄바꿈 통일만 한다. 학교 별칭·캠퍼스를 유사도만으로 합치지 않는다.
- 기존 값과 충돌하는 비고/공통 정보는 비교 자료에 남긴다. 빈 셀로 기존 정보를 삭제하지 않는다.
- 원본 파일 해시·시트명·행번호·병합 범위·실행 ID를 추적해 재실행을 통제한다. 향후 다른 파일을 반영할 때 행번호만으로 기존 전형을 덮어쓰지 않는다.

## 6. Acceptance (완료 기준)

18개 학교/33개 정보 행 및 병합 일정의 연결을 누락 없이 검증한다. 기존 참조 ID 유지, 비인가 11개 정정, 미기재 7개 보존, 전형별 내용 분리, 긴 텍스트·모바일·권한·테넌트 격리·반복 실행을 확인한다.
