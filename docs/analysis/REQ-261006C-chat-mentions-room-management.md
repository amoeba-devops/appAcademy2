# Chat Management Requirements (채팅 관리 요구사항)

## 1. Scope (범위)

ACM 운영자 및 강사 채팅에 멘션 알림, 단체방 제목 수정, 나가기, 개인별 보관/복원을 제공한다. 기존 대화와 알림은 보존한다. 이 문서는 코드 검토 결과이며 운영 화면 검증 결과가 아니다. 운영 URL은 웹 조회 도구로 접근되지 않았다.

## 2. Findings (현황)

- 공용 `talk-chat.tsx`에 참여자 @선택과 멘션 전송이 이미 존재한다.
- `talk.service.ts`는 활성 참여자만 멘션하도록 검증하고 메시지와 같은 트랜잭션에서 CHAT_MENTION outbox를 기록한다. 하지만 USER 대상만 전달하며 강사 TEACHER는 제외한다.
- `inbox-outbox.ts`, `inbox.service.ts`도 채팅 알림을 ADMIN/APP_ADMIN USER로 제한한다. 단순 수신자 추가만으로는 강사 알림이 해결되지 않는다.
- 강사 채팅은 PortalJwtAuthGuard와 TEACHER/refId를 사용한다. 기존 inbox는 amb_acm_user의 usr_id 기반이므로 포털 계정과 혼동하면 안 된다.
- 방장 전용 참여자 변경/방 삭제는 있으나 제목 수정, 본인 나가기, 개인별 보관 API/UI는 없다.
- 회원 테이블에 tlm_left_at은 있으나 개인 보관 필드는 없다. 기존 방 삭제와 개인 나가기는 별개다.

## 3. Behavior (동작 및 권한)

| 기능 | 적용 기준 |
|---|---|
| 멘션 | 활성 참여자를 @선택하여 전송할 때 해당 운영자/강사에게 ACM 내부 알림 1건. 본인 멘션은 제외 |
| 바로가기 | 운영자는 /admin/chat, 강사는 /portal/chat에서 대상 방/메시지로 이동 |
| 제목 수정 | 단체방 방장만 가능. 앞뒤 공백 제거, 1~100자. DM 제목은 대상 이름 유지 |
| 나가기 | 운영자/강사 본인 참여 종료. 과거 메시지는 남은 참여자에게 보존. 나간 사람은 조회·전송·파일·멘션 알림 접근 중단 |
| 방장 나가기 | 남은 운영자에게 방장 위임 후 나가기. 강사만 남는 경우 운영자를 초대한 뒤 위임하도록 안내. 마지막 참여자는 나가기 허용하며 기록 보존 |
| DM 나가기 | 본인 참여만 종료. 남은 상대는 이력 열람 가능, 새 전송은 참여 종료 안내. 이후 새 DM 개설은 새 방 사용 |
| 보관 | 본인 기본 목록에서만 숨김. 참여/대화는 유지. 보관함에서 복원 가능 |
| 보관 중 알림 | 멘션 알림 유지. 새 메시지만으로 자동 복원하지 않음. 알림으로 열어도 보관 상태 유지 |
| 미읽음 | 기본 목록 합계에는 보관방 제외, 보관함에 별도 표시. ACM 종 알림은 미읽은 멘션 기준 유지 |

현재 ADMIN/APP_ADMIN 운영자와 강사 포털 접근 범위를 유지한다. STAFF 등 새 역할 확대는 포함하지 않는다. 제목 변경·보관·나가기 자체의 별도 종 알림, 외부 이메일/메신저 발송, 과거 멘션 소급 생성은 범위 밖이다.

## 4. Acceptance (인수 기준)

운영자→강사, 강사→운영자, 강사→강사 멘션이 각각 해당 계정에만 표시된다. 중복 대상은 1회 처리하고 다른 학원/비참여자/본인에게 알림을 생성하지 않는다. 나가기 이후 기존 알림으로 메시지에 접근할 수 없다. 보관은 다른 참여자의 목록에 영향이 없다. 제목은 모든 참여자의 화면에 갱신된다. 재초대 시 신규 활성 참여 레코드로 복귀하며 종료된 참여 상태와 혼합되지 않는다.

## Implementation Status (구현 현황)

2026-10-06 사용자의 “구현” 승인에 따라 구현 및 로컬 검증을 완료했다. 상세 결과는 [구현 보고서](../report/RPT-261006C-chat-mentions-room-management.md)를 참조한다. 운영 배포 및 실제 계정으로의 메시지 전송은 수행하지 않았다.
