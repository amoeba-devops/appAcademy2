# REQ-260914G — 상담 삭제 · 대시보드 사이트 귀속

## 1. 요구사항

- **R-1** `/admin/csl` 상담신청 목록에 **관리자 삭제 기능** (AMA 접속 사용자만)
- **R-2** 상담신청을 **대시보드의 각 사이트 상담건수로 등록**

## 2. As-Is

### 2.1 삭제 — 백엔드는 있고 UI·권한이 없다

`DELETE /acm/csl/inquiries/:inqId` (소프트 삭제) 와 `POST .../restore` 가 **이미
구현**돼 있었다. 빠진 것은

- 목록·상세 어디에도 **삭제 UI 없음**
- 컨트롤러에 `RolesGuard` 조차 없어 **로그인한 콘솔 사용자 누구나 호출 가능**
- `amb_acm_user.auth_source`(`local`/`ama`) 컬럼은 있으나 **JWT·CurrentUser 에
  실려 있지 않아** AMA 여부를 판정할 수단이 없음

### 2.2 대시보드 — 집계는 자동, 반영이 늦다

`daily-kpi.service` 가 사이트별 상담건수를 이미 자동 집계한다.

```sql
COALESCE(inq_site_override, inq_source_site, 'COMMON') AS site,
COUNT(*) FROM amb_acm_csl_inquiry WHERE inq_registered_at = <날짜> GROUP BY 1
```

빈틈은 두 가지였다.

1. 사이트 귀속(`siteOverride`) 지정 UI 가 **상세 페이지에만** 있다
2. 귀속을 바꿔도 **야간 배치(03:00) 전까지 대시보드가 갱신되지 않는다**

## 3. 결정 (2026-09-14)

| Q | 결정 |
|---|---|
| 삭제 권한 | **A — 계정 기준** (`auth_source='ama'`). 이번 로그인이 로컬 비밀번호여도 AMA 연동 계정이면 허용 |
| 삭제 위치 | **목록 + 상세** |
| 삭제된 건 | **삭제 목록 보기 필요** (복구 포함) |
| 대시보드 | **C — 둘 다** (목록에서 지정 + 즉시 반영) |

## 4. Acceptance Criteria

- **AC-1** AMA 연동 계정만 삭제·복구할 수 있다. 그 외는 403.
- **AC-2** 삭제 버튼은 AMA 계정에만 보인다 (서버도 동일 기준으로 막는다).
- **AC-3** 삭제는 소프트 삭제이며 기본 목록에서 사라진다.
- **AC-4** '삭제 목록 보기' 에서 삭제분만 조회하고 복구할 수 있다.
- **AC-5** 목록에서 대시보드 사이트를 지정할 수 있다.
- **AC-6** 지정 즉시 해당 날짜 대시보드 KPI 가 재계산된다.
- **AC-7** 등록일이 바뀌면 이전·새 날짜를 모두 재계산한다.

## 5. 범위 외

- 삭제 사유 입력·삭제 히스토리 (수업일정에는 있으나 이번 요구에 없음)
- 하드 삭제
