# Consultation English Name and Contact Editing (상담 영문명·연락처 수정)

## 1. Request (요구사항)
- 신규 상담 등록에서 구분=맵테스트일 때 학생 영문이름 입력 항목 추가.
- 상담 상세 접수정보에 학생 영문이름 표시.
- 상단 기본정보 수정에서 학생 영문명, 학년, 구분, 생년월일, 보호자명, 학부모 이메일, 전화, 학교 수정 가능.
- 기존 성별 편집과 모든 단계에서 접근 가능한 강조 버튼 유지.
- 지정 상세 경로 `/admin/csl/463a9051-4b68-4197-b576-ab12c859bf5f`는 현재 튜터링 상담이며 레벨테스트 단계임을 운영 화면에서 확인했다. 수정 확장은 특정 상담/단계에 한정하지 않는다.

## 2. Current State (구현 확인)
- `csl-create-dialog.tsx`: 학생명·보호자명·전화·이메일 등 입력 지원, studentNameEn 입력 없음.
- `BasicInfoEditor`: 구분·학교 자유입력·학년·생년월일·성별만 편집 가능.
- `InquiryService`: 보호자명·전화·이메일 암호화 저장 및 수정 지원, 상세 응답은 복호화된 기존 값을 제공한다. 상담 영문명 저장/응답 필드 없음.
- `MapApplyService`: 별도 맵테스트 접수 행의 studentNameEn 저장·조회·수정 지원. reflectInquiry는 새 부속 행의 영문명을 null로 만들고 기존 행에서는 생년월일·성별만 동기화한다.
- 기존 `/admin/test`와 상담이 영문명을 따로 덮어쓰지 않도록 동일 저장 기준과 원자적 동기화가 필요하다.

## 3. Field Rules (항목 규칙)
| 항목 | 등록/조회/수정 기준 |
|---|---|
| 학생 영문명 | 신규 맵테스트 폼에 선택 입력. 상세 접수정보에 항상 항목 표시. 기본정보에서 모든 구분에 편집 가능. 앞뒤 공백 제거, 공백·하이픈·아포스트로피 허용, 기존 영문명을 임의 변환하지 않음. 최대 길이는 기존 MapApply DTO/컬럼과 통일 |
| 구분 | 튜터링/맵테스트. 변경 시 기존 시험 결과·예약·영문명 보존 |
| 학년 | 기존 자유입력/길이 제한 유지 |
| 생년월일 | 유효한 날짜 검증. 신규 맵테스트의 기존 필수 정책 유지 |
| 보호자 | 보호자명 편집, 기존 암호화 저장 유지 |
| 학부모 이메일 | 선택 입력, 값이 있으면 이메일 형식 검증, 암호화 저장 |
| 전화 | 번호와 제공 상태 일치. 번호 삭제 시 PROVIDED 상태가 남지 않도록 처리. 변경하지 않은 연락처는 저장 요청에서 제외 |
| 학교 | 기존 학교 선택/FK와 직접입력 구분. 직접입력으로 전환 시 이전 FK가 남지 않도록 처리. 미입력 허용 |
| 성별 | 기존 편집 기능 유지 |

영문명은 사용자 요청에 필수 지정이 없어 선택항목으로 설계한다. 읽기 화면의 미입력값은 빈칸, 입력 폼의 안내는 회색 이탤릭 플레이스홀더를 사용한다.

## 4. Data and Side Effects (데이터·영향)
- 상담 본체에 nullable 영문명 암호화 컬럼(암호문/IV/태그)을 추가해 모든 구분에서 영문명을 보존한다. 맵테스트 접수만 강제로 생성해 튜터링 상담이 `/admin/test`에 생기는 부작용을 피한다.
- 기존 연결된 맵테스트 접수 영문명을 상담에 이관한다. 상담 영문명이 이미 있는 경우 덮어쓰지 않으며 충돌은 검토 목록으로 분리한다. 로그/문서에 개인정보 원문을 출력하지 않는다.
- 상담과 맵테스트 접수의 영문명/생년월일/성별 변경은 같은 트랜잭션에서 동기화하고, 외부 접수·일괄 이관 경로도 동일 정책을 적용한다. 원본 rawPayload는 변경하지 않는다.
- 기존 학생·학부모 원장의 정보를 자동 변경하지 않는다. 향후 수강등록 정보 복사 시 영문명 전달 및 기존 학생 원장 보존 정책을 확인한다.
- 업데이트 DTO의 생략(유지)/빈값(삭제)을 명확히 하고, 수정한 필드만 PATCH. 두 화면의 동시 편집은 updatedAt 기반 충돌 감지로 덮어쓰기 방지.
- 목록/상세/맵테스트 조회 캐시 갱신. 단계 전환·레벨테스트 일정 초기화·결과·대시보드 산식 변경 없음.

## 5. Acceptance (검수 기준)
신규 MAP 영문명 저장→접수정보 표시→모든 요청 항목 수정→새로고침 유지. 기존 MAP 영문명 보존·이관 및 양방향 수정 확인. 튜터링 영문명 저장이 MAP 접수 행을 생성하지 않는지 검증. 전화 삭제/제공 상태, 이메일 오류, 학교 FK 정합성, null/생략, 테넌트 격리, 충돌 및 실패 롤백 검증.
