# Site Audit — Requirements Analysis (사이트 감사 요구사항 분석서)

## 1. Overview (개요)

요청 원문: "사이트 감사(Audit) 기능 구현"

| 1depth | 2depth | 설명 |
| --- | --- | --- |
| 감사 | 활동 로그 | 관리자·사용자가 시스템에서 수행한 행위(생성/수정/삭제/조회/다운로드) 기록 |
| | 접속 로그 | 로그인·로그아웃·세션 등 접속 이력 기록 |
| | 접속 통제 | IP 제한, 로그인 실패 잠금, 동시접속 제한 등 정책 설정 |

목표: 운영 콘솔(학원 관리자·교사·직원)과 포털(학생·학부모·포털 교사)에서 일어나는 **행위와 접속을 빠짐없이 남기고**, 테넌트 관리자가 **조회·다운로드·통제 정책 설정**을 할 수 있게 한다. 개인정보보호법 안전성 확보조치 기준의 "접속기록 보관·점검" 대응 근거로 쓸 수 있는 수준을 기준으로 한다.

### 2.2 Gaps (부족한 것)

| # | 문제 | 영향 |
| --- | --- | --- |
| G1 | **로그인·로그아웃·실패 기록이 전혀 없다** | 접속 로그 화면에 보여 줄 데이터가 없음 |
| G2 | **실제 접속 IP를 모른다** — `trust proxy` 미설정, 2단 nginx 뒤라 `req.ip` = 프록시 주소. 기존 감사 IP도 프록시 값 | IP 기록·IP 제한·IP별 실패 잠금 모두 불가. 요청 제한도 전 사용자가 한 묶음일 가능성 |
| G3 | 로그인 실패 잠금이 **서버 메모리**(5회/60초, 60초 잠금, 콘솔만) — 재시작 시 초기화, 포털·AMA SSO 로그인은 실패 횟수 미집계 | 정책 설정 불가, 무차별 대입 방어 약함 |
| G4 | **서버 세션이 없다** — 토큰(JWT)만 발급, 토큰 ID·폐기 목록 없음, 로그아웃은 브라우저 저장소만 지움 | 동시접속 제한·강제 로그아웃·"현재 접속 중" 표시 불가 |
| G5 | 토큰 검증 시 `status='ACTIVE'`만 확인, **잠금 여부 미확인** | 잠근 계정도 토큰 만료(최대 8시간)까지 계속 사용 |
| G6 | 활동 기록이 3곳뿐, 다운로드 엔드포인트 20여 개 중 1개만 기록 | 활동 로그 대부분 공백 |
| G7 | 학생 완전 삭제 시 관련 이력 테이블 행도 하드 삭제 | 감사 기록이 지워짐 — 감사 로그는 삭제 대상에서 제외해야 함 |
| G8 | 메뉴 숨김은 화면에서만 — API 는 막히지 않음 | 감사 API 는 별도 권한 가드 필수 |
| G9 | 브라우저에서 만드는 다운로드(대시보드 CSV, 워크북 xlsx)는 서버를 거치지 않음 | 별도 기록 API 호출 필요 |

## 4. Functional Requirements (기능 요구사항)

### 4.1 Menu (메뉴)

| ID | 요구사항 |
| --- | --- |
| FR-M-1 | 사이드바 '설정' 그룹 위에 **'감사'** 메뉴 1개, 화면 안 탭 3개: 활동 로그 · 접속 로그 · 접속 통제 (현 사이드바는 하위 메뉴가 없어 탭 방식, 경로 `/admin/audit/activity`, `/access`, `/control`) |
| FR-M-2 | 메뉴·API 모두 권한 검사 (`AuditViewerGuard`: TENANT_MASTER 또는 AUDIT_VIEWER). 접속 통제 저장은 TENANT_MASTER 만 |
| FR-M-3 | 4개 언어(ko/en/vi/zh-CN), 운영 콘솔 UI 표준(PageHeader·UnderlineTabs·FilterBar·ResultBar·Section) |

### 4.2 Activity Log (활동 로그)

| ID | 요구사항 |
| --- | --- |
| FR-A-1 | 기록 행위: **생성 · 수정 · 삭제 · 조회 · 다운로드**(+ 개인정보 열람, 권한 변경, 설정 변경, 일괄 처리) |
| FR-A-2 | 기록 항목: 일시, 행위자(종류·ID·이름 스냅숏·역할), 행위, 메뉴(모듈), 대상(종류·ID·표시명), 결과(성공/실패/거부), 변경 필드, 접속 IP, 기기(UA 요약), 요청 ID |
| FR-A-3 | **생성/수정/삭제**: 콘솔·포털의 모든 쓰기 API(POST/PUT/PATCH/DELETE)를 공통 인터셉터로 자동 기록. 수정은 **변경 필드 이름** 기록, 값은 §4.5 규칙 |
| FR-A-4 | **조회**: 모든 GET 이 아니라 **개인정보가 보이는 화면**만 기록 — 학생·학부모·교사 상세, 상담 상세, 연락처 열람, 결제·청구 목록 (§9 Q2) |
| FR-A-5 | **다운로드**: 서버 다운로드 엔드포인트 전부(첨부·성적표 PDF·CSV/엑셀·녹화·자료·채팅 파일·드라이브) + 브라우저 생성 파일(대시보드 CSV, 워크북)은 기록 API 호출 |
| FR-A-6 | 실패도 기록: 권한 거부(403)·검증 실패(400)·오류(5xx)는 결과 '실패'로 |
| FR-A-7 | 화면: 기간·행위자·행위·메뉴·대상·결과·IP 필터, 최신순 목록(페이지 50), 행 클릭 시 상세(변경 필드·UA 전문·요청 ID) |
| FR-A-8 | 엑셀(CSV) 내보내기 — 내보내기 행위 자체도 활동 로그에 기록, 최대 10만 행 |
| FR-A-9 | 대상별 이력: 학생·교사 상세 화면에서 "이 대상 감사 이력" 링크로 필터된 활동 로그 열기 |
| FR-A-10 | 기존 모듈별 이력 테이블은 유지(업무 화면용), 감사 로그는 별도로 공통 기록 |

### 4.3 Access Log (접속 로그)

| ID | 요구사항 |
| --- | --- |
| FR-L-1 | 기록 이벤트: 로그인 성공 · 로그인 실패(사유: 계정 없음/비밀번호 오류/잠김/비활성/IP 차단/임시비번 만료) · 로그아웃 · 세션 만료 · 강제 로그아웃(관리자·동시접속 초과) · 계정 잠금/해제 · 비밀번호 변경·임시비번 발급 · AMA SSO 교환 |
| FR-L-2 | 기록 항목: 일시, 계정(종류·ID·로그인ID·이름), 이벤트, 결과·사유, IP, 기기(OS·브라우저·앱/웹), 세션 ID, 로그인 방식(비밀번호/AMA SSO/OTP) |
| FR-L-3 | 존재하지 않는 계정 실패는 입력한 로그인 ID 를 **마스킹**해 기록(예: `ab***@gmail.com`) |
| FR-L-4 | 화면 탭 2개: **접속 이력**(필터: 기간·계정·이벤트·결과·IP) / **현재 접속 중**(세션 목록: 계정·로그인 시각·마지막 활동·IP·기기, [강제 로그아웃]) |
| FR-L-5 | 요약 카드: 오늘 로그인 수 · 실패 수 · 잠긴 계정 수 · 현재 접속자 수 |
| FR-L-6 | 이상 징후 표시: 같은 IP 에서 다수 계정 실패, 짧은 시간 안 다른 국가/IP 대역 로그인 (P2, §9 Q6) |
| FR-L-7 | CSV 내보내기(활동 로그에 기록) |
| FR-L-8 | **월 1회 점검 기록**: 관리자가 "이번 달 접속기록 점검 완료"와 메모를 남기는 기능(법정 점검 근거) |

### 4.4 Access Control (접속 통제)

| ID | 요구사항 |
| --- | --- |
| FR-C-1 | **IP 제한**: 허용 IP/대역(CIDR) 목록, 적용 대상 선택(콘솔 전체 / 관리자만 / 포털 제외), 모드 OFF·기록만(차단 안 함)·차단. 차단 시 로그인 거부 + 기존 세션 요청 거부(403) |
| FR-C-2 | IP 제한 저장 시 **현재 내 IP 가 목록에 없으면 저장 거부**(스스로 잠김 방지), APP_ADMIN 은 IP 제한 예외(비상 해제) |
| FR-C-3 | **로그인 실패 잠금**: 연속 실패 N회(기본 5) → 잠금 M분(기본 5, 2026-10-21 사용자 지정) 또는 관리자 해제까지. 계정 기준 + IP 기준(같은 IP 계정 다수 실패 시 IP 일시 차단). 콘솔·포털·SSO 공통, DB/Redis 에 저장(재시작 유지) |
| FR-C-4 | 잠금 해제: 접속 통제 화면 '잠긴 계정' 목록에서 해제, 임시비번 발급 시 자동 해제(현행 유지) |
| FR-C-5 | **동시접속 제한**: 계정당 최대 세션 수(기본 무제한, 1~5 설정), 초과 시 동작 선택 — "가장 오래된 세션 종료"(기본) / "새 로그인 거부". 역할별(관리자·교사·직원·포털) 다르게 설정 가능 |
| FR-C-6 | **세션 정책**: 유휴 시간 초과 로그아웃(분), 최대 세션 시간(현행 4h/8h를 정책 값으로 이관) |
| FR-C-7 | 정책 변경은 활동 로그에 이전/이후 값으로 기록, 변경 후 즉시 적용(캐시 최대 1분) |
| FR-C-8 | (선택, §9 Q5) 비밀번호 정책(길이·조합·변경 주기), 관리자 2단계 인증 — 이번 범위 밖으로 제안 |

### 4.5 Data Protection (기록 데이터 보호)

| ID | 요구사항 |
| --- | --- |
| FR-P-1 | 비밀번호·토큰·API 키·인증서·결제 키는 **기록하지 않음**(필드명만). 연락처·생년월일 등 개인정보 값은 마스킹 또는 미기록 |
| FR-P-2 | 감사 로그는 **추가만 가능** — 수정·삭제 API 없음, DB 계정 권한 또는 트리거로 UPDATE/DELETE 차단 |
| FR-P-3 | 학생·사용자 완전 삭제 시에도 감사 로그는 남김(대상 표시명은 스냅숏, 삭제 후 "삭제된 대상" 표시) — G7 해소 |
| FR-P-4 | (P2) 위·변조 확인용 일 단위 해시 체인 |
| FR-P-5 | 보관 기간: 접속 로그·활동 로그 **최소 2년**(§9 Q3), 기간 경과분은 압축 보관(백업 정책 `audit-archive/`)으로 이동 후 삭제 |

## 5. Non-Functional Requirements (비기능 요구사항)

| ID | 요구사항 |
| --- | --- |
| NFR-1 | 기록 실패가 업무 요청을 실패시키지 않음(비동기 큐/배치 저장). 단 **로그인·접속 통제 판단은 동기** |

## 10. Phasing Proposal (단계 제안)

| 단계 | 내용 | 비고 |
| --- | --- | --- |

## 11. Acceptance (인수 기준 요약)

- 로그인 성공·실패·로그아웃이 실제 접속 IP 와 함께 접속 로그에 남는다.
- N회 실패 후 잠기고, 재시작 후에도 유지되며, 잠긴 계정의 기존 토큰도 거부된다.
- 학생 정보 수정·청구 CSV 다운로드·상담 상세 조회가 활동 로그에 행위자·대상·결과와 함께 남는다.
- 허용 IP 밖에서 콘솔 로그인 시 차단되고 접속 로그에 'IP 차단'으로 남는다.
- 동시접속 1 설정 시 두 번째 로그인에서 첫 세션이 종료된다.
- 감사 메뉴·API 는 권한 없는 사용자에게 403.
