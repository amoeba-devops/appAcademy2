# Unified Notification Inbox (통합 알림함)

## 1. Requirements (요구사항)

관리자 콘솔 헤더 우측 언어 선택 왼쪽에 종 아이콘과 안 읽은 알림 수를 표시한다. 상담 접수·상태 변경, 수업일정 등록·변경, 채팅 멘션을 알림함에 저장하고 해당 업무로 바로 이동한다.

## 2. Code Review (현재 구조 확인)

배포된 색상·반복 기능 작업 공간의 소스 기준 검토이며 새 운영 화면 조작은 수행하지 않았다.

- `components/layout/app-shell.tsx`: 공통 헤더의 LanguageSwitcher 앞에 종 버튼 배치 가능.
- `admin-realtime.tsx`: 신규 상담 sticky 토스트 및 채팅 메시지 토스트, fetch SSE 구독 존재. 상담은 목록, 채팅은 채팅 첫 화면으로 이동한다.
- `acm-notification`: 신규 상담 `acm.csl.created` 리스너 및 테넌트 단위 SSE 존재. 개인별 영속 읽음 상태 없음. 기존 notification_log는 외부 발송 이력이며 개인 알림함 용도로 사용하지 않는다.
- `inquiry.service.ts`: `acm.csl.created`, `acm.csl.stage.changed` 이벤트 존재. 다른 상태 변경 경로도 구현 시 함께 조사한다.
- `acm-cal`: 직접 일정 생성·수정, 상담 연계, 반복 생성·범위 수정 등 진입점이 있어 공통 알림 처리 필요.
- `acm-talk`와 채팅 프론트 검색에서 구조화된 멘션 처리를 확인하지 못했다. 메시지의 @대상 선택·저장·검증 및 해당 메시지 이동을 추가한다.

## 3. Event and Recipient Policy (이벤트·수신자 제안)

2026-10-01 사용자 “진행”으로 승인한 기본 정책이다. 테넌트와 원본 업무 조회 권한을 모두 만족하는 활성 계정만 대상이다.

| 이벤트 | 기본 수신자 | 바로가기 |
|---|---|---|
| 상담 접수 | 해당 학원 상담 접근 가능한 관리자·직원 | 해당 상담 상세 |
| 상담 상태 변경 | 해당 학원 상담 접근 가능한 관리자·직원 | 해당 상담 상세, 이전 → 이후 상태 요약 |
| 일정 등록·변경 | 일정 접근 가능한 관리자·직원 및 연결된 담당 강사 콘솔 계정 | 해당 일정 상세 |
| 채팅 멘션 | 해당 채팅방 구성원 중 지정된 본인 | 해당 방의 해당 메시지 |

- 자신이 수행한 작업은 본인 알림에서 제외한다. 외부 접수처럼 작성 콘솔 계정이 없으면 전체 대상에게 전달한다.
- 비활성 사용자·탈퇴한 채팅방 구성원·권한 없는 사용자는 제외한다. APP_ADMIN도 해당 테넌트 범위로 제한한다.
- 강사 포털 계정과 콘솔 계정은 별도 식별한다. 콘솔 계정이 없는 강사에게 접근 불가능한 /admin 링크를 생성하지 않는다. 포털 알림함은 이번 관리자 헤더 범위와 분리한다.
- 반복 등록·전체/이후 일괄 변경은 작업당 요약 1건. 자동 회차 연장·마이그레이션·동일 값 저장·실패 및 롤백은 신규 알림을 만들지 않는다.
- 일정 담당자 교체 시 이전 담당자도 여전히 조회 권한이 있을 경우 변경 알림 대상에 포함한다.
- 우선 위 필수 5종(상담 2, 일정 2, 멘션 1)을 구현한다. 결제·취소·삭제·출결·연장 실패 등 추가 유형은 확장 후보이며 자동 포함하지 않는다.

## 4. Behavior (동작)

- 숫자는 로그인 사용자 본인의 미확인 알림 수. 0이면 배지 숨김, 100 이상은 99+.
- 종 클릭: 최신순 목록, 안 읽음 표시, 종류·요약·시간, 모두 읽음, 전체 보기.
- 항목 클릭: 해당 알림 읽음 처리 및 정확한 대상 화면으로 이동. 목록을 열기만 해서는 읽음 처리하지 않는다.
- 모두 읽음은 누르는 시점 이전까지의 알림에 적용하고 동시에 들어온 새 알림은 유지한다.
- 새로고침·로그아웃 후에도 읽음 상태 유지. SSE 재연결 및 창 포커스 시 서버와 재동기화, 연결 유실 시 저빈도 폴링.
- 삭제되었거나 권한이 사라진 대상은 안전한 안내를 보여주고 원본 정보를 노출하지 않는다.
- 채팅 읽음과 알림 읽음은 구분한다. 같은 메시지에 여러 번 멘션해도 수신자별 1건. 본인 멘션 제외, 최초 버전에서는 @전체와 수정 후 추가 멘션 재알림 제외.
- 기존 토스트와 새 알림함은 같은 이벤트로 연계하여 중복 토스트를 방지한다. 일반 채팅 토스트를 모두 영속 알림으로 적재하지 않는다.
- 브라우저 푸시·OS 알림·소리·이메일 추가 발송은 이번 범위에 포함하지 않는다.
