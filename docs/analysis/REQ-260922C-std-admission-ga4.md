# Admission Dates and GA4 Requirements (입학일 및 GA4 요구사항)

## 1. Scope (범위)

1. `/admin/std`와 `/admin/std/withdrawn` 목록에 입학일 표시.
2. 대상 학원의 현재 재원생 중 입학일이 없는 학생만 수업시작일로 보완.
3. 대시보드 운영 신규학생을 입학일 기준으로 계산. ALL과 TPI·TA·SC에 동일 적용.
4. 2026-09-21 이후 마케팅 GA 방문자 누락 수정.
5. `/admin/tch` 목록에 입사일자·퇴사일자를 함께 표시하고 교사 수정 화면에 퇴사일자를 제공한다.

## 2. Evidence (확인 결과)

2026-09-22 09:57 KST 운영 DB를 읽기 전용으로 확인했다. 학생 이름·연락처·GA 인증키는 조회하지 않았다.

| 사이트 | 재원생 | 입학일 보완 가능 | 입학일·수업시작일 모두 없음 |
| --- | ---: | ---: | ---: |
| TPI | 33 | 32 | 0 |
| TA | 3 | 3 | 0 |
| SC | 14 | 14 | 0 |
| 합계 | 50 | 49 | 0 |

기존 입학일 1건은 유지한다. 다른 테넌트 데이터와 퇴원생은 보완 대상에서 제외한다. 실행 시 상태를 다시 확인하므로 실제 반영 건수는 변동할 수 있다.

`std_admission_date`와 상세 조회·수정 API는 이미 존재한다. 공통 학생 목록에는 입학일 열이 없다. 운영 계산은 현재 재직/수업 기간 `start`로 신규·누적을 계산하므로 별도 입학일 기반 학생 집계가 필요하다.

GA 운영 로그에서 9월 22일 04:00 KST 배치가 `2026-09-18..2026-09-20`만 수집한 사실을 확인했다. 이후 수동 동기화도 9월 20일까지만 요청했다. DB에는 9월 19·20일 3사이트 GA 행이 있고 21·22일 행은 없다. 최신 동기화 상태는 SUCCESS다.

코드의 배치는 KST로 예약되지만 `ga4-sync.service.ts`와 `dashboard.controller.ts`의 `isoDaysAgo`는 UTC 날짜를 사용한다. 오전 09시 전에는 전날을 오늘로 보아 조회 종료일이 하루 더 늦어진다. 인증 실패가 아니라 **조회 기간 산정 오류가 확인된 원인**이다. 수정 후 GA API가 반환하는 9월 21일 실제 데이터는 재수집 시 검증해야 한다.

## 3. Rules (처리 규칙)

- 입학일은 `YYYY-MM-DD`, 미입력은 빈칸. 이름 가까이에 배치하고 기존 수업시작일과 구분한다.
- 보완 조건: 대상 ent_id, deleted_at IS NULL, std_status=ACTIVE, std_admission_date IS NULL, std_start_date IS NOT NULL. 기존 값·수업시작일·상태·교사 배정은 변경하지 않는다.
- 신규학생은 유효한 입학일에 학생 ID별 한 번 집계한다. 수업 기간 행과 조인하여 재입사 횟수만큼 중복 집계하지 않는다.
- 사이트 미분류는 3사이트 합계 밖의 품질 정보로 표시한다. ALL 신규학생 = TPI + TA + SC를 유지한다. 수기값 괄호 병기와 입력된 0은 보존한다.
- 기존 요구의 ‘학생수=신규 누적−퇴원 누적’도 입학일로 바꿀지는 확인 중이다. 한 학생의 복수 수업 기간·재입사·복수 퇴원 이벤트가 있으므로 원장 입학일 한 개를 모든 기간 시작일에 복제하면 안 된다. 결정 전 기존 기간 이력을 변경하지 않는다.
- 퇴원일 집계의 수업종료일 기준과 교사 통계는 별도 요청 없이 변경하지 않는다.
- GA 조회는 KST 업무일 기준 전일까지 한다. 당일 수치를 확정값처럼 표시하지 않는다. 서버 배치·수동 API의 기본 기간과 종료일 제한을 같은 날짜 함수로 통일한다.
- 성공했으나 반환 행이 없는 경우와 실패/미수집을 구분한다. 확인하지 않은 날짜를 0으로 채우지 않는다. 수기 방문자값·비용은 보존한다.

## 4. Acceptance (완료 조건)

재원·퇴원 목록 입학일 표시, 조건에 맞는 재원생만 보완, 입학일별 신규학생과 3사이트 합계 일치, 수기값 보존, KST 오전 04시·08시에도 전일까지 GA 요청, 9월 21일 재수집 결과와 원본→저장→대시보드 일치 검증을 완료한다.

## 5. Teacher Dates Addition (교사 날짜 추가 요구)

교사 목록은 이름 다음에 `입사일자`, `퇴사일자`를 나란히 표시한다. 두 날짜 모두 `YYYY-MM-DD`, 미입력은 빈칸이다. 수정 화면에도 같은 명칭으로 날짜 입력을 제공한다. 퇴사일자 미입력 안내는 회색 이탤릭으로 표시하고 실제 값은 null로 보관한다.

기존 교사 날짜 구현(`feat/tch-employment-dates`, `01db457`)에는 목록 입사일과 수정 화면 퇴사일이 포함되어 있으나 아직 운영 미배포다. 이번 추가분은 목록 퇴사일 열과 라벨 통일이며, 수정 입력을 중복 생성하지 않는다. 기존 재직 기간 동기화·유효 날짜 검증·계정 상태 유지 규칙을 재사용한다.

## Execution Update (진행 현황)

2026-09-22 “작업 진행” 승인으로 구현했다. 학생수 산식의 별도 답변은 아직 없으므로 요청된 신규학생만 입학일로 변경하고 학생수는 수업기간 기준을 유지한다. 화면에 두 기준을 구분했다. 교사 날짜 기존 구현 및 추가 목록 퇴사일을 함께 반영한다. 재원생 49명 입학일 보완 완료(TPI 32·TA 3·SC 14), 기존 입학일 1명 유지. 운영 코드 배포 및 GA 재수집은 진행 중이다.
