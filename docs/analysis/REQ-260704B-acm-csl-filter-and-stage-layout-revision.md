# REQ-260704B — CSL 목록/단계 화면 재구성 요구사항 분석서

## 1. Overview

대상 화면은 아래 2곳이다.

- `https://acm.amoeba.site/admin/csl`
- `https://acm.amoeba.site/admin/csl/:id`

이번 요구는 신규 데이터모델 추가보다, 이미 구현된 CSL 운영 화면을 더 실무 친화적으로 다듬는 **후속 UX 재구성**에 가깝다.

핵심 목표는 3가지다.

1. 목록 상단 필터를 줄여 검색 집중도를 높인다.
2. 4단계 `등록상담` 과 5단계 `결제` 의 역할을 분리한다.
3. 6단계 라벨과 내용을 `수강 시작` 중심에서 `수강 현황` 중심으로 바꾼다.

---

## 2. 현행 구현 분석

### 2.1 `/admin/csl` 목록 화면

현재 목록/칸반 공통 상단 필터는 아래 값을 모두 포함한다.

- 학생/학부모 검색
- 진행단계
- 유입경로
- 신청유형
- 신청목적
- 접수일 From/To
- 팔로업 상태

현행 구조의 특징:

1. **목록형과 칸반형이 같은 필터 바를 공유**한다.
2. 세부 필터가 상단에 모두 노출되어 첫 화면 정보량이 많다.
3. 목록 헤더에는 컬럼 제목만 있고, **제목칸 기반 필터 UI가 없다**.
4. `신청목적` 필터는 존재하지만, 목록형 테이블에는 대응하는 전용 컬럼이 없다.

### 2.2 `/admin/csl/:id` 상세 화면

현재 4/5/6 단계는 모두 `EnrollmentPanel` 을 공유한다.

현행 구조의 특징:

1. 패널 제목 locale 은 `detail.enrollment.title = "등록 / 결제"` 이다.
2. 4단계 `ENROLLMENT_COUNSELING`, 5단계 `PAYMENT`, 6단계 `CLASS_STARTED` 가 같은 입력 블록을 재사용한다.
3. 따라서 아래 항목이 사실상 한 패널에 섞여 있다.
   - 등록상담 내용
   - 결제 정보
   - 수강 시작 여부
   - 수강료 납부 완료
4. 6단계 요약 패널은 이미 `ClassStatusSummaryPanel` 로 별도 존재하지만, 스테퍼 라벨은 여전히 `6. 수강 시작` 이다.

### 2.3 6단계 `수강 현황` 현재 상태

현재 `ClassStatusSummaryPanel` 은 아래 5개 아코디언을 보여준다.

1. 접수 내용
2. 레벨테스트 점수
3. 데모수업 정보
4. 수강강좌 정보
5. 결제 정보

하지만 이번 요청은 6단계를 "최종 결제 확인 화면의 반복"이 아니라, **접수한 내용 + 수업정보 중심의 현황 화면**으로 재정의한다.

## 3. 요구사항 해석 및 설계 결정

## 3.1 목록 상단 필터는 `검색 + 기간`만 유지

상단 공통 필터 바에는 아래만 남긴다.

- 학생/학부모 검색
- 접수일 From
- 접수일 To
- 초기화

이 결정의 의미:

- 목록형과 칸반형 모두 상단에서는 **검색과 기간만** 다룬다.
- 이전 상단 필터 중 나머지 값은 모두 목록형 헤더 필터로 내린다.

## 3.2 나머지 세부 필터는 `목록형 제목칸` 전용으로 이동

목록형에서만 컬럼 헤더 하단 또는 동일 헤더 셀 내부에 필터를 둔다.

대상 필터:

- 유입경로
- 신청유형
- 신청목적
- 진행단계
- 팔로업 상태

해석상 중요한 점:

- 칸반형은 제목칸 기반 필터 UI를 가질 수 없으므로, **세부 필터는 목록형 전용**으로 본다.
- 칸반형은 상단 `검색 + 기간` 만 유지한다.

## 3.3 `신청목적` 필터는 전용 컬럼이 필요

기존 요구를 그대로 반영하면 `신청목적` 필터를 둘 제목칸이 없다.

따라서 권고안은 아래와 같다.

- 목록형 테이블에 `신청목적` 컬럼을 추가한다.
- `학년` 단일 컬럼 구조는 유지한다.
- 컬럼 수 증가는 있으나, 이미 `학교` 컬럼이 제거된 상태이므로 정보 밀도는 감당 가능하다.

> 결론: 이번 화면구성안에서는 `신청목적` 컬럼을 추가하는 방향이 가장 자연스럽다.

## 3.4 4단계는 `등록상담` 전용 화면으로 축소

4단계에서는 아래만 보여준다.

- 상담 내용
- 강좌 코스 / 코스 직접 입력
- 수강 회수
- 시작일 / 종료일
- 수업 시간
- 수강료
- 수강료안내발송
- 담당 강사 배정

4단계에서 제거할 항목:

- 결제일
- 결제 방법
- 결제금액
- 비고
- 수강 시작 여부
- 수강료 납부 완료

또한 패널 제목 `등록 / 결제` 는 `등록상담` 으로 바꾼다.

## 3.5 5단계는 `결제` 전용 화면으로 역할을 명확히 분리

5단계에서 보여줄 항목:

- 결제일
- 결제 방법
- 결제금액
- 비고
- 수강 시작 여부
- 수강료 납부 완료

즉, 4단계에서 등록상담을 마친 뒤 5단계에서 실제 결제/개강 여부를 입력하는 흐름으로 정리한다.

## 3.6 6단계는 `수강 시작`이 아니라 `수강 현황`

라벨 변경 범위:

- 단계 스테퍼
- 칸반 컬럼 제목
- 상세 내부 제목
- locale 키의 기본 표시값

6단계 화면의 역할:

- 접수한 내용 요약
- 실제 수업 운영 정보 요약

이번 요구 기준의 강조점:

- 결제 정보 상세를 6단계에서 다시 반복하기보다,
- **학생이 어떤 내용으로 접수되었고 어떤 수업으로 운영 중인지**를 보여주는 쪽이 우선이다.

## 5. 개선 화면구성안

### 5.1 `/admin/csl` 목록형

```text
┌─ 상담관리 ───────────────────────────────────────────────────────────────┐
│ [학생/학부모 검색] [접수일 From] [접수일 To] [초기화]     [List|Kanban] │
├──────────────────────────────────────────────────────────────────────────┤
│ No │ 학생명 │ 학년 │ 유입경로 ▾ │ 신청유형 ▾ │ 신청목적 ▾ │ 단계 ▾ │ 팔로업 ▾ │
│ 91 │ 김OO  │ 중2  │ 홈페이지    │ 상담+시험   │ ISEE       │ 결제    │ 있음      │
│ 90 │ 박OO  │ 고1  │ 전화        │ 상담만      │ MAP        │ 접수    │ 없음      │
├──────────────────────────────────────────────────────────────────────────┤
│                                    ◀ 1 2 3 4 ▶                          │
└──────────────────────────────────────────────────────────────────────────┘
```

핵심 변화:

- 상단은 `검색 + 기간`만 유지
- 나머지 세부 필터는 컬럼 헤더 안으로 이동
- `신청목적` 컬럼을 추가하여 필터 위치를 명확히 한다

### 5.2 `/admin/csl` 칸반형

```text
┌─ 상담관리 ───────────────────────────────────────────────────────────────┐
│ [학생/학부모 검색] [접수일 From] [접수일 To] [초기화]     [List|Kanban] │
├──────────────────────────────────────────────────────────────────────────┤
│ 1.접수      2.레벨테스트      3.데모수업      4.등록상담                │
│ [카드]      [카드]            [카드]          [카드]                    │
│                                                                         │
│ 5.결제      6.수강현황                                                │
│ [카드]      [카드]                                                     │
└──────────────────────────────────────────────────────────────────────────┘
```

핵심 변화:

- 상단은 목록형과 동일하게 단순화
- 세부 헤더 필터는 목록형 전용
- 칸반은 단계별 분포 확인에 집중

### 5.3 상세 4단계 `등록상담`

```text
┌─ 4. 등록상담 ───────────────────────────────────────────────────────────┐
│ 상담 내용                                                               │
│ 강좌 코스 / 코스 직접 입력                                              │
│ 수강 회수 / 시작일 / 종료일 / 수업 시간 / 수강료                        │
│ 수강료안내발송                                                          │
│ 담당 강사 배정                                                          │
│                                                  [저장] [결제 단계로]   │
└──────────────────────────────────────────────────────────────────────────┘
```

핵심 변화:

- `등록 / 결제` 혼합 패널이 아니라 `등록상담` 전용 패널
- 결제/개강/납부 상태는 여기서 제거

### 5.4 상세 5단계 `결제`

```text
┌─ 5. 결제 ───────────────────────────────────────────────────────────────┐
│ 결제일 [date]    결제방법 [계좌이체|카드|기타]                         │
│ 결제금액 [number]    비고 [text]                                        │
│ 수강 시작 여부 [YES/NO]    수강료 납부 완료 [checkbox]                 │
│                                                         [저장]          │
└──────────────────────────────────────────────────────────────────────────┘
```

핵심 변화:

- 결제 정보와 운영 상태값을 5단계에 집중
- 4단계와 5단계의 의미 경계를 명확히 한다

### 5.5 상세 6단계 `수강현황`

```text
┌─ 6. 수강현황 ───────────────────────────────────────────────────────────┐
│ ▼ 1. 접수한 내용                                                       │
│   학생/학부모/연락처/학년/유입경로/신청유형/신청목적                    │
│   접수일/팔로업 메모                                                    │
│                                                                        │
│ ▼ 2. 수업 정보                                                         │
│   강좌코스/담당강사/수강회수/수업시간/시작일/종료일                     │
│   레벨테스트 결과 요약/데모수업 이력 요약                              │
└──────────────────────────────────────────────────────────────────────────┘
```

핵심 변화:

- `수강 시작` 단일 상태 페이지가 아니라 운영 현황 요약
- 접수 정보와 수업 운영 정보를 2개 큰 축으로 정리

## 6. 영향 분석

### 6.1 Frontend 영향

주요 변경 대상:

- `frontend-acm/src/modules/csl/pages/csl-list-page.tsx`
- `frontend-acm/src/modules/csl/components/csl-list-filters.tsx`
- `frontend-acm/src/modules/csl/components/csl-kanban-board.tsx`
- `frontend-acm/src/modules/csl/pages/csl-detail-page.tsx`
- `frontend-acm/src/modules/csl/components/enrollment-panel.tsx`
- `frontend-acm/src/modules/csl/components/class-status-summary-panel.tsx`
- `frontend-acm/src/i18n/locales/ko/csl.json`

주요 변경 성격:

1. 목록형 필터 UI 재배치
2. 칸반형 필터 단순화
3. 4/5단계 조건부 렌더 재정리
4. 6단계 요약 구조 축소/재배열
5. 단계 라벨/i18n 정리

### 6.2 Backend 영향

이번 요구만 놓고 보면 **필수 백엔드 변경은 크지 않다**.

이유:

- 검색 `q`, 기간 `registeredFrom/registeredTo`, 세부 필터 파라미터는 이미 존재한다.
- 결제 관련 필드도 이미 enrollment row 저장 구조가 마련되어 있다.

백엔드에서 확인할 항목:

1. 목록 응답에 `applyPurposes` 가 안정적으로 포함되는지
2. 목록형 전용 헤더 필터 조합 시 기존 pagination/total 계산이 유지되는지

### 6.3 DB 영향

신규 스키마 추가는 이번 요구의 필수 조건이 아니다.

- 기존 `993-acm-csl-enrollment-payment-fields.sql` 범위 재사용 가능
- 이번 변경은 주로 **표시 위치와 단계 책임 분리** 문제다

## 7. Acceptance Criteria

- AC-1: `/admin/csl` 상단 필터에는 검색과 접수일 기간만 노출된다.
- AC-2: 유입경로/신청유형/신청목적/단계/팔로업 상태는 목록형 제목칸 필터로 제공된다.
