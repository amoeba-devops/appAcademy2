# Teacher Employment Dates Requirements (교사 입사일·퇴사일 요구사항)

대상: `/admin/tch`. 목록에 입사일을 표시하고, 교사 정보 수정 상세화면에 퇴사일을 추가한다. [작업계획서](../plan/PLN-260922B-tch-employment-dates.md)의 화면 구성안과 함께 승인 후 구현한다.

## 3. Functional Requirements (기능 요구사항)

- R1: 교사 목록의 이름 다음에 `입사일`을 표시한다. 날짜는 `YYYY-MM-DD`, 미입력은 빈칸으로 표시한다. 기존 입사일 열을 중복 생성하지 않는다.
- R2: 교사 정보 수정의 기본 정보에 `입사일`, `퇴사일` 날짜 입력을 함께 제공한다. 미입력 안내는 회색 이탤릭으로 표현하며 실제 저장 값은 `null`이다.
- R3: 기존 교사의 날짜를 조회·수정·저장·재조회할 수 있어야 한다. API 미전송은 기존 값 유지, 명시적 `null`은 지우기로 구분한다.
- R4: 실제 달력 날짜를 검증하고 두 날짜가 있으면 퇴사일은 입사일 이상이어야 한다. 날짜를 바꾸지 않는 다른 정보 수정은 과거 날짜 누락 때문에 차단하지 않는다.
- R5: 별도 재직 이력이 있으면 대표 입사일과 일치하는 취소되지 않은 기간 한 건만 수정한다. 매칭이 없거나 여러 건이면 날짜 저장을 차단하고 재직 기간 편집으로 안내한다. 재입사 이력을 한 기간으로 합치거나 최신 기간을 임의 선택하지 않는다.
- R6: 기간 편집기로 대표 기간을 변경할 때도 목록·상세의 대표 날짜와 대시보드가 일치해야 한다. 다른 과거 기간 편집은 대표 날짜를 바꾸지 않는다.
- R7: 날짜 변경은 교사의 재직 상태, 계정 접근권한, AMA 프로필을 자동 변경하지 않는다. 날짜가 없는 교사의 날짜는 추정하여 채우지 않는다.
- R8: 기존 테넌트 격리와 수정 권한을 유지한다. 재직 기간 변경은 대시보드의 교사 통계와 감사 이력에 반영한다.

## 4. Acceptance Criteria (완료 기준)

목록에서 입사일을 쉽게 확인하고, 상세에서 퇴사일을 저장한 뒤 재조회해도 동일한 날짜가 표시된다. 미입력·지우기·유효하지 않은 날짜·날짜 역전·재입사·동시 수정·다른 테넌트 접근을 검증한다. 기존 수기 통계는 유지하고 계산 통계만 변경된 재직 기간에 따라 갱신한다.
