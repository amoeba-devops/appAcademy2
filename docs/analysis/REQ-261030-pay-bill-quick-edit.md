# REQ-261030 Quick bill write, edit & delete (청구 간편 작성·수정·삭제)

## 1. Request (요청)
`/admin/pay?view=detail` (청구 상세) 수납 관리 기능 재검토.
1. 청구 **작성 시 간단히 입력**.
2. 작성 후 **수정·삭제** 필요.

## 2. As-Is (현재, 53be651)
| 동작 | 현재 흐름 | 문제 |
|------|-----------|------|
| 작성 [작성] | 다중 학생 청구 창(학생 상태·검색·수업 필터 영역) → 제목·납기·월·메모·수업·종류·청구액·할인 입력 → [미리보기] → [등록 확정] | 학생 1명인데 다중 선택 창, 입력 8칸 + 2단계 확정 |
| 작성 (표 입력) | 청구액·할인 칸 입력 → 상단 [변경 저장] | 청구 1건 이하일 때만, 저장 버튼이 표와 떨어져 있음 |
| 수정 [수정] | 청구 상세 창(여러 건이면 탭) → '청구 수정' 칸에 제목·납기·청구액·할인·메모 + **사유 필수** → [수정 저장] | 사유 입력 강제, 수납 기록·이력과 한 창에 섞여 길다 |
| 삭제 | 같은 창의 [청구 취소] — **관리자만**, 사유 필수, 수납 0원일 때만, 확인창 | '삭제' 버튼이 없어 찾기 어렵다, 직원은 불가 |
| 복구 | UI 없음 (REQ-261027C) | — |

## 3. Requirements (요구사항)
| ID | 내용 |
|----|------|
| FR-1 | **간편 작성**: 행의 [+ 청구] → 학생 고정 작은 창. 필수 입력은 **종류·청구액** 2개, 할인·납기는 기본값(할인 0, 기본 납기), 제목은 자동(`{월} {종류}`), 수업은 수강 1개면 자동. [저장] **한 번**으로 등록(미리보기 단계 없음). 제목·메모·수업은 '더 보기'로 접어 둠. |
| FR-2 | **수정**: [수정] → 그 학생·그 달의 **청구 목록 창**. 청구마다 한 줄(종류·제목·청구액·할인·납기·수납액) 바로 편집 → 줄별 [저장]. 사유는 **선택**(비우면 자동 사유 "청구 수정"). |
| FR-3 | **삭제**: 청구 줄마다 [삭제] → 확인 1회 → 목록에서 사라짐. 수납 기록이 있는 청구는 [삭제] 비활성 + "수납 기록을 먼저 취소하세요" 안내. 삭제는 취소 상태(`CANCELED`)로 저장하여 이력 보존. |
| FR-4 | 같은 창 하단에 [+ 청구 추가](FR-1과 같은 간편 입력 줄). |
| FR-5 | 수납 입력·환불·이력은 청구 줄의 [수납]으로 펼쳐 보기(기존 기능 유지). |
| NFR | 4개 언어, 모바일 규칙(입력 16px·터치 36px+), 감사 이력(`amb_acm_pay_bill_audit`) 유지. |

## 4. Open Questions (확인 필요)
| # | 질문 | 권장안 |
|---|------|--------|
| Q1 | 삭제 방식 — 이력 남는 취소 처리 vs DB 실제 삭제? | **취소 처리**(화면에서는 '삭제', 목록·합계에서 제외, 감사 이력 보존) |

## 5. Decisions (결정, 2026-10-30 — 권장안 승인)
