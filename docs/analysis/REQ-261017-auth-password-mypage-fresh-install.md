# Login, Password, My Page & Fresh Install Requirements (로그인·비밀번호·마이페이지·새 환경 구축 요구사항)

## 1. Request (요청)
1. `main` 필수 체크(브랜치 보호).
2. `/admin/login`: 비밀번호 **보기 아이콘**, **비밀번호 찾기**(관리자에게 재발급 요청 → 이메일로 임시 비밀번호), 임시 비밀번호로 로그인 후 **비밀번호 변경**.
3. 관리자: 사용자 **임시 비밀번호 생성** 기능.
4. 로그인 후 좌측 메뉴 하단: 이메일 대신 **이름**, 이름 옆에 **마이페이지** 텍스트.
5. `/admin/me`: **비밀번호 변경**, **가입일**, **비상연락망**, **자기소개** 항목.
6. **새 환경 구축**: 빈 DB에서도 배포(CD)로 마이그레이션이 끝까지 적용되게.

## 3. Requirements (상세 요구사항)
### FR-1 Login screen (로그인 화면)
- 비밀번호 칸 오른쪽에 **보기/숨기기** 아이콘(눈). 키보드·스크린리더로 조작 가능.
- “비밀번호를 잊으셨나요?” 링크 → 창: 이메일 입력 → [재발급 요청].
  - 응답은 계정 존재 여부와 관계없이 같은 안내(“등록된 계정이면 관리자에게 요청이 전달됩니다”) — 계정 확인용 악용 방지.
  - 같은 이메일·IP 요청 제한(예: 10분에 1회, 하루 5회).
- 잠긴 계정은 “계정이 잠겼습니다. 관리자에게 문의하세요”로 구분 표시(현재 서버는 이미 구분 코드를 보냄).

### FR-2 Reset request → admin issues temp password (재발급 요청 처리)
- 요청이 접수되면 해당 테넌트 **관리자(ADMIN·테넌트 마스터)** 알림함에 “비밀번호 재발급 요청” 알림.
- 관리자 화면 **비밀번호 재발급 요청** 목록(요청자·이메일·요청 시각·상태): [임시 비밀번호 발급] / [거절].
- 발급하면: 정책에 맞는 임시 비밀번호(10자, 혼동 문자 제외) 생성 → 저장(해시) + **다음 로그인 시 변경 필수** + **유효기간**(Q2) → 사용자 이메일로 발송.
  - 메일이 설정되지 않았거나 발송 실패 시: 관리자 화면에 임시 비밀번호를 **한 번만** 표시해 직접 전달하게 한다.
- 처리 이력(누가·언제·발급/거절) 보관.

### FR-3 Admin temp password (관리자 임시 비밀번호 생성)
- 기존 “비밀번호 재설정(직접 입력)” 자리에 **[임시 비밀번호 발급]** 추가: 시스템 관리자 사용자 상세, 교사·직원 수정 창. 동작은 FR-2 발급과 같다(메일 발송, 실패 시 1회 표시).
- 직접 입력 방식은 유지할지 Q3.

### FR-4 Temp password login → change (임시 비밀번호 로그인 후 변경)
- 임시 비밀번호로 로그인하면 기존 강제 변경 화면으로 이동(현재 동작 유지). 변경 전에는 다른 화면 사용 불가.
- 유효기간이 지난 임시 비밀번호는 로그인 거부 + “임시 비밀번호가 만료되었습니다. 다시 요청하세요” 안내.

### FR-5 Sidebar bottom (좌측 하단)
- 이메일 대신 **사용자 이름**, 오른쪽에 **마이페이지** 텍스트 링크(→ `/admin/me`). 접힌(아이콘) 상태에서는 사용자 아이콘만.
- 이름이 없으면 이메일 앞부분.

### FR-6 My page (`/admin/me`)
- **비밀번호 변경** 섹션: 현재·새·확인(보기 아이콘 포함), 정책 안내. AMA 전용 계정(비밀번호 없음)은 “AMA 로그인 계정은 AMA에서 변경” 안내.
- **가입일**: 계정 생성일(읽기 전용, 테넌트 시간대).
- **비상연락망**: 이름·관계·연락처. 연락처는 개인정보 → 암호화 저장(NFR-005, AES-GCM).
- **자기소개**: 1,000자 이내 텍스트.
- 본인만 수정. 4개 언어.

### FR-7 Fresh install (새 환경 구축)
- 마이그레이션 적용을 공통 스크립트 하나로: **버전 순**(번호 → 접미사 → 이름) + 의존 역순 3개(999m·999r·999y)는 의존 대상(1006·1007·1025) 뒤로 명시 배치.
- 스테이징·운영 배포 스크립트와 로컬 docker 초기화가 같은 스크립트를 쓴다. 이미 적용된 파일은 기존 표시(marker)로 건너뛰므로 **기존 환경에서는 다시 실행되는 것이 없다**.
- CI에 “빈 DB 전체 적용” 검사를 추가해 새 마이그레이션이 순서를 깨면 PR에서 실패하게 한다.
- 새 환경 구축 절차서(RUNBOOK) 작성: 빈 DB → 배포 → 시드·첫 관리자 확인.

### NFR
- 4개 언어 i18n, 비밀번호·임시 비밀번호는 로그에 남기지 않음, 요청 API 속도 제한, 멱등 마이그레이션, 통합 테스트.
