# Site Marketing Metrics (사이트별 방문자 보정·광고비)

## 1. Scope (요청 범위)
- 대시보드 일별 수동 입력 모달에서 통합과 TPI·TA·SC 방문자 수를 함께 확인한다.
- 사이트별 `방문자 GA 수치 + [추가 수치] | 사용광고비 | 효과`를 표시한다.
- 사이트를 선택해도 효과를 표시한다. 각 사이트의 기존 “전체 비용” 표기를 “사용광고비”로 변경한다.
- 광고매체명과 광고비를 입력하고, “광고매체 추가” 버튼으로 여러 행을 등록한다.
- 모달 저장 결과를 사이트별/통합 카드, 일별 목록, 기간 집계, 사이트 비교 및 CSV에 일관되게 반영한다.

## 2. Observed Behavior (현재 구현 확인)
2026-09-23 운영 모달을 열어 조회만 수행했다. 기본 선택은 공통(미지정)이며, 사이트 선택 시 방문자·전체 비용·불만만 표시되고 효과가 사라진다. 저장 없이 취소했다.

## 3. Calculation Rules (산출 기준)
### 3.1 Visitors (방문자)
- 입력 단위: **사이트 × 일자**. UI 명칭 TPI/TA/SC는 저장 코드 TPI/TRINITY/SANTACROCE에 매핑한다.
- GA 값은 읽기 전용, 추가 수치는 0 이상의 정수. 음수/소수는 이번 범위에서 허용하지 않는 제안이다.
- `최종 방문자 = GA 원본 + 저장된 추가 수치`. 추가 입력은 매번 누적하는 명령이 아니라 **그 날짜의 보정값을 교체 저장**한다. 반복 저장으로 두 번 더해지지 않는다.
- 빈칸/보정 삭제는 추가값 미설정(산출 시 0). GA=0은 실제 값, GA 미수집은 null로 구분한다. 미수집 사이트는 최종 방문자를 임의로 0 또는 보정값만으로 확정하지 않고 “미수집/미산출” 표시한다. 보정값 저장은 가능하며 GA 수집 후 계산한다.
- 통합은 사이트별 최종값 합산이다. 일부 사이트 미수집이면 확인된 부분합과 누락 상태를 구분하며 완전한 합계로 표시하지 않는다. 사이트 간 동일 방문자 중복 제거는 수행하지 않는다.
- GA 재수집 시 원본만 갱신하고 보정값은 유지한다. 기간 값은 해당 날짜들의 일별 방문자 합이며 기간 순방문자와 동일하다고 설명하지 않는다.

### 3.2 Advertising Cost (사용광고비)
- 사이트·일자마다 광고매체명(앞뒤 공백 제거, 최대 100자)과 광고비(원화, 0 이상 정수)를 여러 행으로 입력한다. 0원은 유효한 입력이다.
- 완전히 빈 새 행은 저장하지 않는다. 이름/금액 중 하나만 있으면 해당 행에 오류를 표시한다. 저장된 행은 고유 ID로 수정·삭제하고 반복 저장 시 중복 생성하지 않는다.
- `사이트 사용광고비 = 해당 사이트·일자의 유효한 광고매체별 비용 합계`.
- 통합 비용은 3사이트 비용과 별도 공통 비용의 합이다. 공통 비용은 사이트에 임의 배분하지 않고 구분해서 표시한다. 사이트 비용 라벨은 카드·목록·모달·비교·CSV에서 “사용광고비”로 통일한다. 통합 “전체 비용” 라벨은 유지한다.
- 비용 금액은 DB numeric 정수로 저장한다. 기존 NUMERIC(12,0)과 일별 합계의 범위를 서버에서 검증하고 부동소수점 오차를 피한다.

### 3.3 Effect (효과)
- **기존 정의인 상담 건수 + 지원 건수 유지**, 사이트별 서버 집계값을 읽기 전용으로 표시한다.
- 방문자 보정이나 광고비 변경으로 효과 건수가 바뀌지 않는다. 전환율/ROAS/매체별 광고 성과로 재해석하지 않는다.
- 사이트 효과는 해당 사이트 귀속 상담·지원만 사용한다. 통합은 기존 공통 귀속 포함 정책을 유지한다.

## 4. Existing Data (기존 입력 보존·전환)
- 과거 방문자 절대 수기값을 GA 추가 수치로 간주하거나 자동으로 더하지 않는다. 원본과 이력은 보존한다.
- 날짜별 방문자 정책을 `LEGACY_OVERRIDE`/`GA_PLUS_ADJUSTMENT`로 구분한다. 아직 편집하지 않은 과거 날짜는 기존 결과를 유지한다.
- 기존 수기 방문자가 있는 날짜를 새 방식으로 처음 저장할 때, 모달에 **기존 통합·사이트 값 → GA+보정 적용 후 값**을 보여준다. 방문자 보정 저장 시에만 해당 날짜의 통합 우선 수기 정책을 해제하고 3사이트 GA+보정 합산으로 전환한다. 광고비만 저장할 때는 방문자 정책이 바뀌지 않는다.
- 정책 전환, 사이트 보정값 저장 및 이력 기록을 한 트랜잭션으로 처리한다. 이전 수기값은 비교/복원용으로 보존한다. 모든 과거 날짜 일괄 전환은 이번 범위에서 제외한다.
- 기존 비용 합계는 “기존 입력(매체 미지정)” 행으로 보여준다. 최초 광고비 편집 시 같은 금액을 한 번만 명세로 전환한다. **명세가 전환된 날짜·사이트는 명세 합계만 사용**하고 기존 합계와 다시 더하지 않는다.
- 기존 공통 비용은 공통에 보존한다. 기존 명세 없는 비용의 실제 광고매체를 추정하지 않는다.

## 5. Data Integrity and Acceptance (정합성·검수)
- GA 원본, 기존 수기 원본, 보정, 광고비 명세는 분리한다. 변경자·시각·전후 값, 수정 버전을 남긴다.
- 기존 수동 입력 권한을 확인해 같은 범위로 적용하고 서버에서도 검사한다. 모든 조회/변경은 ent_id로 격리한다.
- 일부 필드만 저장할 때 다른 사이트/날짜 및 CS·운영·수업 수기값을 변경하지 않는다. 충돌은 409로 알리고 편집값은 보존한다.
- 예: TPI GA 100 + 20 = 120, TA 50 + 0 = 50, SC 30 + 5 = 35 → 통합 205. GA 재수집으로 TPI가 110이 되면 보정은 20을 유지해 통합 215.
- 광고매체 30,000원 + 20,000원 → 사용광고비 50,000원. 한 행 삭제/보정 해제/저장 재시도/다른 사이트 전환 후 재조회 검증.
- 오류 응답을 빈 데이터로 취급하지 않는다. 미저장 편집 중 날짜/사이트 변경은 저장 또는 변경 취소를 선택할 수 있도록 한다.

## Implementation Decisions (구현 확정 사항)
- 2026-09-23 사용자 “진행” 승인 후 구현.
- 방문자 보정과 광고비 전환 상태는 `amb_acm_dsh_marketing_site`에 함께 저장한다.
- `마케팅 저장`과 `CS·수업 저장` 버튼을 분리한다. 마케팅 미저장 변경이 있으면 CS·수업 저장을 비활성화하며 날짜 변경/닫기 시 미저장 내용을 보호한다.
- 캐시 재집계 대신 조회 공통 resolver로 최신 GA4 원본과 보정/명세 비용을 합산한다. GA 동기화와 기존 배치가 원본 캐시를 갱신해도 신규 값을 덮어쓰지 않는다.
- 공통 비용은 최초 비용 전환 시 기존 통합 비용과 사이트 비용의 차이를 보존한다. 음수 차이는 자동 추정하지 않고 충돌로 알린다.
