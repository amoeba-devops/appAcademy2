# Calendar Corrections (수업일정 수정 요구사항)

## 1. Scope (범위)

사용자 요청: 수업을 정규수업으로 이관하고 수업·개인·행사 카테고리를 제거한다. 10월까지만 의도한 수업이 11월 이후 반복된 문제를 정리한다. 수정 사유 없이 저장할 수 있게 하고 강사 포털 월 달력의 +N을 통해 숨겨진 모든 일정을 열람한다.

이번 요청의 반복 종료는 앞선 원본 무기한 반복 유지 요청을 변경한다. 신규 반복 기능 자체는 유지한다. 사용자의 “진행” 확인 후 구현·로컬 검증을 완료했다. 운영 배포와 데이터 적용을 완료했다. 결과는 RPT-261002D 보고서를 참조한다.

## 2. Evidence (확인 결과)

2026-10-02 운영 DB에서 지정된 배예리 계정의 단일 테넌트를 확인하고 READ ONLY 트랜잭션으로 집계했다. 개인정보·일정 제목은 보고서에 기록하지 않는다. 실제 실행 전 재집계한다.

| 현재 활성 카테고리 | 건수 |
|---|---:|
| 수업 CLASS | 6,373 |
| 정규수업 REGULAR_CLASS | 56 |
| 행사 EVENT | 9 |
| 개인 PERSONAL | 0 |
| 레벨테스트 LEVEL_TEST | 304 |
| 기타 OTHER | 297 |

테넌트 시간대는 Asia/Seoul이다. 컷오프는 **2026-11-01 00:00 KST (2026-10-31T15:00:00Z)**로 제안한다. 시작 시각이 컷오프 이상인 활성 일정은 ICS 반복 수업 827건과 자체 반복 정규수업 1건, 총 828건이다. 같은 구간의 단일 일정은 집계상 0건이다. ICS 반복 판별은 원본 RRULE/RDATE 존재를 사용한 예비 집계로, 실행 dry-run에서 파서로 재검증한다.

ICS 수업 원본은 단일 2,407개, 유한 반복 693개, 무기한 반복 13개다. 자체 정규수업 반복 시리즈는 8개다. 레벨테스트·기타 원본도 존재하므로 수업만 대상으로 제한한다.

- 관리자/포털 조회 및 Cron이 반복을 자동 전개한다. 행만 삭제하면 충분하지 않다.
- `ics-import.service.ts`의 stopped_at은 생성 중단에 사용된다. 중단된 원본은 ensureRange 대상에서 빠지므로 10월까지 누락 회차가 없는지 먼저 검증해야 한다.
- 자체 반복은 crs_stop_at을 사용하지만 시간 이동 적용 후 시작 시각 경계도 검증해야 한다.
- 수정 사유는 모달과 UpdateCalEventDto에서 필수다. 반복 변경의 ChangeRecurrenceDto는 수정·삭제가 공유하며 reason 일치 검사도 존재한다.
- 포털 MonthGrid의 +N은 클릭 처리 없는 div다. 상세 모달로 연결되지 않는다.

## 3. Requirements (요구사항)

1. CLASS의 기존 데이터 및 향후 생성 기본값을 REGULAR_CLASS로 전환한다. 편집·필터·색상 설정·API·생성 템플릿에서 수업/개인/행사 선택을 제거한다. 기존 정규수업 색상은 우선 보존한다.
2. 대상 테넌트의 기존 수업 반복을 컷오프에서 종료하고 미래 828건(예비 수치)을 soft-delete한다. 이전 일정, 수동 단일 일정, 레벨테스트·기타 일정은 보존한다. 원본 키와 삭제 기록을 유지해 자동 재생성을 방지한다.
3. 수정 사유는 선택 입력, 빈값은 일관되게 null 처리한다. 수정자·시각·변경 내역은 계속 기록한다. 삭제 사유 필수 정책은 별도로 유지한다.
4. +N 더보기는 해당 날짜의 전체 일정 목록을 열고, 항목 선택 시 기존 상세 화면을 연다. 로그인 강사가 볼 수 있는 일정만 표시하며 모바일·키보드 조작을 지원한다.

## 4. Confirmed Decision (확정 사항)

사용자가 행사 9건은 보존하고 기타로 이동하도록 확정했다. 행사 카테고리만 제거하고 기존 일정 ID·내용·연결은 유지한다.
