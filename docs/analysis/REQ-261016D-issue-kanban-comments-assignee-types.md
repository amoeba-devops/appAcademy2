# Issue Kanban, Rich Comments, Assignee Change, Issue Types Requirements (프로젝트 이슈 칸반·댓글 리치에디터·담당자 지정·이슈 유형 요구사항)

## 1. Request (요청)
1. 프로젝트 상세의 이슈 탭(`/admin/projects/:id?tab=issues`)에 **칸반 보기**를 추가한다.
2. 이슈 상세(`/admin/issues/:id`)의 **댓글**에서도 리치 에디터를 쓴다.
3. 담당자 변경: 지금의 **검색으로 고르는 방식을 없애고**, 변경할 사람을 **먼저 선택한 뒤 [지정]을 눌러 변경**한다.
4. 이슈 유형은 작업·기능·버그·의견·기타 5종에서 **업무요청·기타 2종**만 남긴다.

## 2. Current State (현재)
| 영역 | 현재 |
|------|------|
| 프로젝트 이슈 탭 | 카드 목록만 있음. 상태·담당자 필터. 설명을 텍스트로 미리보기해 **HTML 설명은 태그가 그대로 보인다**(REQ-261016C 이후 발생한 표시 결함) |
| 전체 이슈(`/admin/issues`) | 목록·칸반 전환이 있다. 칸반은 상태 4열(열림·진행·완료·반려), 카드를 끌어 상태 변경 |
| 이슈 상세 댓글 | 일반 textarea, 텍스트 저장·표시(최대 10,000자). 운영 댓글 9건 모두 텍스트 |
| 담당자 | 이슈 등록/수정 창의 **검색 콤보**로 선택. 상세 화면에는 변경 기능 없음 |

## 3. Requirements (상세 요구사항)
### FR-1 Project Issue Kanban (프로젝트 이슈 칸반)
- 이슈 탭 상단에 [목록 | 칸반] 전환을 둔다(전체 이슈 화면과 같은 모양). 선택은 브라우저에 기억.
- 칸반은 상태 4열(열림·진행·완료·반려). 카드: 번호(ISS-n)·제목·유형·담당자·마감. 카드 클릭 → 이슈 상세.
- 카드를 다른 열로 끌면 상태를 바꾼다(서버 전이 규칙 적용, 실패 시 안내). 보관된 프로젝트는 끌기 불가.
- 기존 검색·상태·담당자 필터는 칸반에도 적용한다(상태 필터 선택 시 해당 열만).
- 목록 카드의 설명 미리보기는 태그를 뺀 텍스트로 보여 준다(결함 수정).

### FR-2 Rich-text Comments (댓글 리치 에디터)
- 댓글 작성·수정 입력을 이슈 설명과 같은 리치 에디터(굵게·기울임·취소선·목록·인용·코드)로 바꾼다.
- 댓글은 HTML로 저장하고, 표시는 읽기 전용 리치 뷰로 한다(`dangerouslySetInnerHTML` 미사용). 기존 텍스트 댓글은 줄바꿈을 유지해 그대로 보인다.
- 빈 내용(태그만 있는 경우) 등록 불가. 최대 길이 10,000 → 50,000자(HTML 포함).

### FR-3 Assignee: Select then Assign (담당자 지정 방식)
- **이슈 상세 우측 패널**에 ‘담당자’ 영역을 둔다: 현재 담당자 + 프로젝트 참여자 목록(이름·이메일, 현재 담당자 표시). 한 명을 **선택**하면 [지정] 버튼이 활성화되고, 누르면 확인 후 담당자를 바꾼다. [담당 해제]로 비울 수 있다.
- 담당 변경 시 배정 시각을 갱신하고, 이력 탭에 “담당자 변경: A → B”를 남긴다.
- **이슈 수정 창의 담당자 검색 칸은 없앤다**(담당 변경은 상세에서만).
- **이슈 등록 창**의 담당자도 검색 대신 참여자 목록에서 선택한다(기본: 나). — 미결 Q1
- 권한: 프로젝트 참여자(현재 이슈 수정 권한과 동일). 보관된 프로젝트는 불가.

### FR-4 Issue Types (이슈 유형 2종)
- 유형은 **업무요청(TASK)**·**기타(OTHER)** 2종만 둔다. 기본값 업무요청.
- 기존 FEATURE·BUG·OPINION 이슈는 업무요청으로 바꾼다(운영 0건). DB 제약도 2종으로 줄인다.
- 전체 이슈 목록의 유형 필터·칩, 등록 폼, 상위 이슈 검색 칩 모두 2종 기준. 4개 언어 라벨 변경(작업 → 업무요청).
