# Visitor Reconciliation Review (방문자 수치 차이 보정 검토)

## 1. Recommendation (권장 방향)

먼저 두 서비스의 집계 조건을 맞추고, 아임웹 원본과 GA4 원본을 별도로 표시한다. 운영 보고에 사용할 기준 방문자는 출처를 명시하여 선택한다. 보정계수는 동일 조건의 실제 비교 자료로 검증한 뒤 아임웹 누락 기간의 **추정값**에만 제한적으로 적용한다. 숫자를 같게 만드는 것 자체를 정확성의 기준으로 삼지 않는다.

이번 요청은 검토·제안이다. 코드 변경, 수기값 수정, 운영 데이터 보정은 수행하지 않았다. 실제 사이트별 보정계수는 아직 산출하지 않았다.

## 2. Current Implementation (현재 구현 확인)

최신 구현 작업트리 `/private/tmp/acm-tch-employment-dates`, 커밋 `5d1c96e`를 확인했다.

- `ga4-sync.service.ts`는 설정의 `cfg.metric`을 방문자 수로 가져온다. 운영 설정의 실제 지표는 이번 검토에서 조회하지 않았으므로 activeUsers/totalUsers 중 어느 것인지 단정하지 않는다.
- `site-visit.typeorm-entity.ts`는 `(ent_id, site, date)`별 단일 방문자 값과 source를 저장한다. 현재 키로는 같은 날의 아임웹·GA4 원본을 동시에 보관할 수 없다.
- 날짜별 원본에 지표 정의 버전이 없다. 지표를 바꾸어 재수집하면 과거와 현재의 집계 기준이 섞일 수 있다.
- 대시보드 기간 방문자는 일별 집계값을 합하는 구조다. 월간 순방문자와 직접 비교하면 안 된다. 같은 사람이 여러 날짜에 방문하면 일별 합계에 반복 포함된다.
- 기존 수기 방문자 우선순위와 비용 입력을 보존해야 한다. 출처가 확인되지 않은 기존 수기 입력을 일괄 아임웹 원본으로 간주해서는 안 된다.
- 최근 GA 조회 날짜 및 수기 입력일의 방문자 갱신 문제는 별도 수정 보고서에 기록되어 있다. 수집 장애 기간은 재수집·검증 후 비교에 사용한다.

참조: [GA 수정 보고서](../report/RPT-260922C-std-admission-ga4.md), [수기 입력일 갱신 수정](../bug-fix/FIX-260922-ga4-manual-day-visitors.md).

## 3. Comparison Rules (차이 원인 확인 순서)

| 확인 대상 | 검토 방법 |
|---|---|
| 방문자 지표 | 아임웹의 해당 화면 지표 정의를 확인하고 GA4 totalUsers, activeUsers, sessions 중 비교 대상을 결정한다. |
| 집계 기간 | 양쪽 모두 동일 일자·시간대·조회 범위를 사용한다. 일별 합계는 일별 합계끼리 비교한다. |
| 사이트 범위 | TPI·TA·SC의 실제 도메인, GA 속성·스트림 연결, 중복 태그 및 누락 페이지를 확인한다. |
| 데이터 성숙도 | 당일과 최근 처리 중 수치를 분리한다. 재수집 후 차이가 유지되는지 확인한다. |
| 수집 조건 | 동의 설정, 태그 실행 여부, 내부 방문 제외 및 필터 설정 차이를 점검한다. 실제 원인으로 확인되기 전에는 가설로 취급한다. |
| 수기 자료 | 작성 시점·원본 출처·날짜 의미를 확인한다. 입력된 0과 미입력을 구별한다. |

GA4 totalUsers는 기간 내 이벤트를 발생시킨 순사용자, activeUsers는 참여 조건 등을 충족한 순사용자다. 서로 같은 지표가 아니다. 아임웹 정의를 확인한 후 totalUsers를 비교 후보로 검토하며 기존 GA 지표를 즉시 교체하지 않는다. [Google 사용자 지표 정의](https://support.google.com/analytics/answer/12253918?hl=en)

Google은 데이터 처리에 24~48시간이 걸릴 수 있고 이후에도 일부 지연 데이터가 있을 수 있다고 안내한다. 최근 값을 확정값으로 취급하지 않고, 최근 7일 재수집과 변경 이력 보관을 검토한다. 7일은 본 제안의 운영 정책이며 모든 데이터의 확정을 보장하는 기한은 아니다. [Google 데이터 최신성](https://support.google.com/analytics/answer/11198161?hl=en)

아임웹 방문자 계산의 정확한 식별·중복 제거 기준은 현재 확보한 자료로 확인하지 못했다. IP 기준·쿠키 기준·봇 포함 여부를 단정하지 않는다. 해당 통계 화면 설명 또는 아임웹 지원 답변 확인이 필요하다.

## 4. Options (대안 비교)

| 방안 | 적용 판단 |
|---|---|
| 모든 GA 값에 고정 배수 적용 | 비권장. 사이트별 유입 특성·수집 장애·기준 변경을 구별하지 못한다. |
| 원본 병기 및 차이 표시 | 우선 권장. 오류 원인을 찾을 수 있고 기존 자료를 보존한다. |
| 운영 기준값 선택 | 권장 후보. 아임웹 제공일에는 아임웹, 미제공일에는 GA를 쓰되 출처를 표시한다. 혼합 기간은 혼합 출처임을 명시한다. |
| 사이트별 추정 보정 | 비교 검증 이후 선택 적용. 원본과 별도 저장하고 누락 아임웹 값의 추정으로만 사용한다. |

운영 기준값 정책은 사용자의 선택이 필요하다. 승인 전 기존 대시보드 계산 및 수기 우선순위를 유지한다. 아임웹 우선 선택은 운영 보고의 일관성을 위한 정책이며 아임웹이 실제 방문자를 더 정확하게 센다는 의미가 아니다.

## 5. Optional Calibration (선택적 추정 보정)

제안식: `사이트별 계수 k = 동일 비교일의 아임웹 방문자 합 / GA 방문자 합`, `아임웹 추정값 = round(해당일 GA 방문자 × k)`.

- 사이트마다 최소 28개 유효 비교일을 확보하고 이후 7개 비교일을 별도로 검증하는 방안을 제안한다. 표본 수는 운영 정책 후보이며 정확성을 보장하지 않는다.
- 같은 지표·시간대·범위의 성숙한 자료만 사용한다. 미수집, 장애, 태그 변경 및 출처 불명 자료는 제외 사유를 남긴다. 차이가 크다는 이유만으로 정상 데이터를 임의 제외하지 않는다.
- 검증 기간에서 보정 전후 MAE 및 전체 절대오차 비율을 비교한다. 오차가 개선되지 않거나 주별 계수가 불안정하면 적용하지 않는다. 허용 오차는 실제 자료 확인 후 합의한다.
- GA가 0 또는 누락이거나 태그 장애가 있으면 추정하지 않는다. 계수 계산 분모가 0이거나 표본이 부족한 경우도 미산출로 둔다.
- 계수, 학습·검증 기간, 제외일, 적용 기간, 지표 버전과 승인 이력을 저장한다. 원본 및 기존 수기값을 덮어쓰지 않는다.
- 예: 검증된 계수가 1.20이고 GA가 100이면 추정은 120이다. 이는 설명용 가상값이며 현재 서비스 보정계수가 아니다.

## 6. UI Proposal (화면 구성 제안)

아래는 가상 데이터다. 신규 지표는 명시적 열로 구분해 기존 수기값 괄호 표기와 혼동을 줄인다.

```text
마케팅 · 방문자 비교     [기간] [통합 / TPI / TA / SC]
집계: 일별 방문자 합계   기준: [현재 운영 기준]   최근 동기화: …
┌────────┬───────┬────────┬───────┬──────┬────────────┐
│ 날짜   │ 사이트│ 아임웹 │ GA4   │ 차이 │ 운영 기준값│
├────────┼───────┼────────┼───────┼──────┼────────────┤
│ 09-15  │ TPI   │ 120    │ 100   │ +20  │ 120 아임웹 │
│ 09-16  │ TPI   │ 미수집 │ 110   │ —    │ 110 GA4    │
└────────┴───────┴────────┴───────┴──────┴────────────┘
[원본·수기 이력 보기] [추정 비교: 승인 후 사용]
```

차이 = 아임웹 − GA, 차이율 = 차이 / GA × 100. GA가 0인 날에는 차이율을 계산하지 않는다. 추정 사용 시 `132 추정`처럼 명시한다. 표의 GA 지표명은 실제 선택한 `전체 사용자` 또는 `활성 사용자`를 표시한다.

통합은 TPI+TA+SC의 사이트별 일별 합계로 정의하고 `사이트 합산 방문자`로 표시한다. 사이트 간 동일인의 중복은 제거한 수치가 아니다. 월간 순사용자는 별도 기간 조회·지표로 제공해야 한다. 일부 사이트가 미수집이면 완전한 통합값처럼 표시하지 않는다.

## 7. Implementation Boundaries (구현 영향 및 후속 범위)

1. 비교 자료 확보: TPI·TA·SC별 동일 날짜의 아임웹 일별 내보내기와 GA 일별 값을 확보한다. 현재 운영 GA 지표, 속성 시간대 및 스트림 매핑을 확인한다. 아임웹 자동 API 제공 여부는 확인 전 전제하지 않는다.
2. 원본 분리: tenant/site/date/source/metric/version을 식별하는 별도 원본 저장 구조와 수집 시각·품질 상태를 설계한다. 수기값은 기존 저장·이력과 구분한다. 기존 API는 호환 유지한다.
3. 비교 화면: 원본 열, 차이, 기간 집계 정의, 출처 및 미수집 상태부터 추가한다. 선택 기준값은 계산 결과로 제공하고 원본을 수정하지 않는다.
4. 영향 검증: 재수집 멱등성, 입력된 0 보존, 테넌트 격리, 부분 누락, 지표 전환, 사이트 합계 및 기간 합계를 확인한다. 원본 병기로 시작해 롤백 시 기존 표시로 복귀할 수 있게 한다.
5. 파생 비율: 방문자를 분모로 쓰는 전환율·방문당 비용 등은 선택 기준과 같은 분모를 사용하도록 별도 검토한다. 방문자만 바꾸어 기존 비율과 불일치시키지 않는다. 상담·학생·교사 통계 원본은 이 변경의 대상이 아니다.
6. 추정 적용: 자료 검증을 통과한 경우에만 별도 정책 승인 후 활성화한다. 실제 구현 전 요구사항·작업계획서에 확정 기준 및 본 화면 구성을 반영한다.

현재 확보되지 않은 핵심 자료는 사이트별 아임웹 일별 원본과 해당 지표의 공식 집계 정의다. 이를 확인해야 원인별 차이와 보정 필요성, 실제 계수를 판단할 수 있다.
