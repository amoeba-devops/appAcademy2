# Payment Management Requirements (수납관리 요구사항)

## 1. Request and Evidence (요청 및 확인 범위)

ACM 관리자에 수납관리 메뉴를 추가하고 [MakeEdu 상세수납](https://school.makeedu.co.kr/pay/payUnionDeList.do)을 분석하여 구현한다.

2026-10-01 로그인된 참고 화면을 직접 열어 검색 영역·표·행별 입력·메뉴를 확인했다. 저장·삭제·환불·결제·영수증 발급·문자 발송은 실행하지 않았다. 참고 사이트의 내부 계산식, 저장 트랜잭션, 권한 및 연동 성공 여부는 확인하지 않았으며 아래 ACM 정책과 구별한다. 실제 학생 이름·금액·연락처는 본 문서에 복제하지 않는다.

사용자가 전체 수납 모듈 범위를 별도로 확정하지 않은 상태이므로, 제공 URL의 **상세수납 중심 1차 구현**을 제안한다. 주변 메뉴는 후속 범위로 구분하며 이번 승인 대상에 포함되는지 명시한다.

## 3. ACM Gap Analysis (기존 기능과 차이)

| ACM 현재 소스 | 확인 결과 및 적용 방향 |
|---|---|
| frontend-acm의 app-shell / router | 관리자 수납 전용 메뉴·라우트 없음. `/admin/pay` 신규 추가 |
| acm-csl EnrollmentTypeormEntity | 상담별 수강료, 납부금액·수단·날짜·메모·승인 정보 존재. 월별 여러 청구/분할납부 구조가 아님 |
| acm-pay PayOrderService | Toss 주문 중심 기본 CRUD. 월별 청구월·납기·할인·기타수납을 표현하는 운영 화면 API가 없음 |
| acm-pay PayLedgerService | CHARGE/REFUND/ADJUSTMENT 기본 원장. 기존 메서드는 orderId 중심이며 새 API에서는 tenant 검증·동시성 보완 필요 |
| AcmPayModule | 엔티티·서비스 묶음이 있으나 관리자 controller 없음. 확인한 app.module에는 모듈 등록도 없음 |
| ParentPortalService.getPayments | pay_order → cls enrollment → student 연결 조회. 새 수납을 곧바로 PG 주문으로 저장하면 오인·중복 위험 |
| 기존 trinity-pay.html | 과거 결제/환불 시안. 현재 상세수납 요구 UI로 새 구성 필요 |

따라서 메뉴만 연결하는 변경이 아니다. 기존 PG 주문을 보존하면서 청구·수납 기록을 별도로 추가하고 필요한 연결을 명시한다.

## 4. Proposed Release Scope (승인 제안 범위)

### Phase 1 — Detailed Collections (상세수납 중심)

- 왼쪽 메뉴에 **수납관리** 추가, 수강신청 다음 배치. 상세수납·월별 청구 생성·취소 청구 보기 제공.
- 요약: 청구총액, 할인/감액, 순청구액, 수납총액, 환불액, 순수납액, 미납액. 검색 조건 전체 기준 집계.
- 검색: 청구월/수납일, 월/일 기간, 이전 월 미납 포함, 납기, 미납/부분납/완납/연체, 학생·학교·학년·상태·사이트, 수업·강사, 수납구분, 결제수단, 메모.
- 수업 및 기타 청구 단건 등록, 월별 여러 학생 청구 미리보기 후 일괄 생성. 수업 없이 기타 항목 등록 가능.
- 청구액·할인·납기·메모 편집 및 선택 행 일괄 변경. 변경된 셀 표시, 저장 전 변경 건수, 오류 행 유지.
- 납부 내역 추가(현금·계좌·외부 카드·기타), 분할납부·복수 결제수단, 수납 취소/정정 및 환불 **기록**. 실제 계좌송금/카드 취소 아님.
- 표에는 합계 실제 납부액 및 여러 결제수단이면 '복수' 표시. 세부 내역은 우측 패널에서 확인.
- 청구 취소·복구 및 이력, 학생별 내역, XLSX 내보내기. 검색조건·열 설정은 사용자별 저장.
- 3자리 콤마, 4개 언어, 관리자/직원 권한, 테넌트 격리, 업무 변경 감사 이력.

### Phase 2 — Integration and Reports (별도 연동·확장)

- Toss 결제 요청/승인/부분 취소 연결, 전용 영수증·현금영수증 발급, 문자/알림톡 청구 안내.
- 상세 월별·일별·강사별·수업별 보고서 및 학부모 포털 통합 조회.
- 단말기/카드사/지역화폐 연동은 실제 사용할 업체·계약을 확인한 뒤 결정한다.
- 적립금은 거래 원장과 사용·취소 규칙이 별도로 필요하므로 1차에서 임의 숫자 필드로 만들지 않는다.
- 정기 자동결제는 기존 프로젝트 제외 항목이다. 새 요구 확인 없이 활성화하지 않는다.
- MakeEdu 과거 데이터 이관은 별도 매핑·중복 검토 및 승인 대상이다. 분석 요청만으로 가져오지 않는다.

## 5. Business Rules (제안 업무 규칙)

- 초기 통화 KRW, 정수 금액. 청구월과 실제 수납일은 별도 필드다. 기존 상담과 일치하는 금액 상한을 적용한다.
- 순청구액 = 청구액 - 할인액 - 승인된 청구감액. 순수납액 = 확정 납부 합계 - 환불/납부취소 합계. 미납 = max(순청구액 - 순수납액, 0).
- 할인/감액은 순청구액이 음수가 되지 않게 검증한다. 초기 범위는 초과납부를 거부하고 별도 선수금은 후속 설계한다.
- 미납>0이고 학원 현지 날짜에서 납기<오늘이면 연체. 0원 청구는 '납부불필요'로 구분한다.
- 분할납부와 환불상태를 별도 표시한다. 완납은 체크박스가 아닌 계산 결과다. '잔액 수납'은 금액·수단·날짜를 확인해 납부 내역을 생성한다.
- 환불은 원 납부 내역을 참조하며 누적액이 환불가능 잔액을 넘지 못한다. 수업 취소 환불은 청구감액도 같은 거래에서 기록해 잘못된 미납을 만들지 않는다. 오입금 취소는 납부만 되돌려 미납을 복구한다.
- 납부가 있는 청구는 삭제할 수 없다. 취소·정정 기록을 통해 감사 이력을 보존한다. 복구는 취소 청구에만 제공하고 외부 결제 취소를 되돌리는 의미로 사용하지 않는다.
- 검색 '수납일'로 일치한 청구를 반환하되 청구 잔액은 전체 원장 기준으로 계산한다. 기간 수납 합계는 별도로 표시한다. 다른 날짜의 납부를 미납으로 오인하지 않는다.
- 청구 일괄 생성은 요청 멱등키 및 원본 연결키로 중복을 방지한다. 같은 학생·월이라도 다른 수업/기타 청구는 허용한다.
- 상담 납부를 자동 복제하지 않는다. 기존 납부 내역 연결을 미리보기·중복 검사 후 처리하며, 연동 전에는 상담 승인 및 New St 통계를 이 화면의 수동 입력으로 자동 변경하지 않는다.

## 6. Acceptance Criteria (인수 기준)

1. ACM 메뉴에서 직접 이동·새로고침 가능, 허용되지 않은 역할의 API 직접 호출도 차단.
2. 청구 300,000 / 할인 20,000 / 납부 100,000이면 미납 180,000. 추가 180,000 납부 후 완납.
3. 50,000 수업 취소 환불 + 50,000 청구감액이면 미납 0 유지, 원장·담당자·사유 보존.
4. 월별 일괄 생성 재시도/동시 클릭에도 중복 청구 없음. 동시 납부 시 초과 수납 방지.
5. 수납일 검색에서도 전체 잔액 계산이 맞고 요약·엑셀의 필터 범위가 일치.
6. 사이트·학생·수업·강사 관계와 테넌트를 검증. 다른 테넌트의 이름/금액/다운로드 접근 차단.
7. 조회는 페이징·인덱스 적용. 정정·환불은 사유 필수이며 기존 기록을 덮어쓰지 않음.
8. 기존 상담·대시보드·PG 주문·학부모 조회 회귀 없음.
