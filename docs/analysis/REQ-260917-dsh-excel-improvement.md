# Dashboard Improvement Proposal (엑셀 분석 기반 대시보드 개선안)

## 1. Recommendation (핵심 제안)

**지표의 의미와 집계 신뢰성을 먼저 바로잡고, 마케팅 성과와 운영 후속 조치를 한 화면에서 판단하도록 개선한다.** 현재의 사이트 탭·기간 필터·일별 표는 유지하면서, 상단을 핵심 지표와 데이터 상태, 중단을 추이·사이트 비교·처리할 업무, 하단을 상세 원장으로 재구성한다.

이번 분석의 가장 중요한 발견은 다음과 같다.

1. 엑셀의 `Apply`는 **MAP 테스트 신청**, `Beginning`은 **상담 시작**, `New St.`는 **최초 납부 학생**이다. 현행 집계와 의미가 달라 라벨 변경만으로 해결되지 않는다.
2. 파일명이 TPI이지만 **3개 브랜드의 합산 자료**다. 방문자·재학생의 브랜드별 값이 셀 메모에 보존되어 있다.
3. 운영 화면의 통합 방문자 4,617과 사이트별 합계 303이 일치하지 않는다. 서로 다른 집계표와 수집 구간을 함께 보여주며, 전체를 GA4 출처처럼 표시하고 있다.
4. 미래일·미입력·실제 0, 예정·완료를 구분해야 한다. 특히 9월 엑셀은 방문자 15일, 주요 상담 지표 16일, 미래 예약 일부가 섞인 상태다.
5. 광고비가 월 합계에만 있는 달이 있어 **일별 행만 이관하면 비용이 사라진다.** 비용 수집 구조와 출처 추적을 함께 설계해야 한다.

작성 범위는 분석·개선안·실행계획이며, 원본 엑셀 및 서비스 데이터·코드는 변경하지 않았다.

## 5. Proposed Experience (화면 개선안)

### 5.1 Information hierarchy (정보 우선순위)

1. **상단 필터와 집계 상태:** 통합/TPI/Trinity/Santa Croce 유지. 조회 기간과 실제 실적 기준일, 전기 비교 범위, 누락 원천 표시.
2. **핵심 카드 6개:** 방문자 합, 상담 신청, MAP 신청, 최초 납부 학생, 광고비, 재학생. 각 카드에는 핵심 값·단위·기준일·비교 한 줄만 표시. 정의 미확정 지표는 임의 숫자 대신 ‘정의 확인 필요’.
3. **마케팅 추이:** 방문자와 신청을 같은 날짜 축의 분리 차트로 표시. 비용은 별도 차트. 수집 원천 변경일을 주석으로 표시하고 미수집·미래일은 0으로 연결하지 않음.
4. **사이트 비교:** 브랜드별 방문·상담·MAP·비용·수집 범위. 공통 귀속과 미분류 이관 자료를 구분. 불일치가 있으면 차이 행과 확인 링크 제공.
5. **후속 조치:** 일정 미확정, 응답 지연, MAP 예정, 내일·오늘 첫 수업, 미해결 불만. 원장 레코드·담당자·기한과 연결해야 하며 일별 합계 차감으로 목록을 만들지 않음.
6. **상세 표:** 마케팅/상담/학생·강사/수업 탭으로 열 수 축소. 날짜·헤더 고정, 합계·일평균·기준일 현황 구분. 셀 클릭은 상세 근거, 편집은 별도 버튼.

사이트별 운영·수업 지표는 현재 시스템에 브랜드 차원이 부족하므로 통합 전용을 유지한다. 엑셀 메모의 브랜드별 재학생은 ‘이관 당시 현황’ 참고로 보존할 수 있지만, 지속적인 실시간 지표는 학생·수업의 브랜드 귀속 모델을 별도로 정의해야 한다.

### 5.2 Funnel and efficiency (전환 및 비용 분석)

상담 신청과 MAP 신청은 유입 경로가 다른 **두 진입 지점**이다. 두 수치를 단순한 순차 퍼널로 그리지 않는다. 학생/상담 식별자 연결 이후, 상담 시작·MAP 완료·체험·최초 납부·첫 수업 완료의 경로를 추적한다. 모든 단계가 필수라는 가정도 하지 않는다.

| 지표 | 계산·표시 규칙 | 선행 조건 |
|---|---|---|
| 신청 이벤트 수 | 상담 신청 + MAP 신청 | 중복 가능 ‘건수’로 표시 |
| 방문 대비 신청 비율 | 동일 날짜·브랜드 범위의 신청 이벤트 / 방문자 합 | 전화·카카오 포함 여부 표시. 웹 전환율은 웹 유입 분자만 별도 |
| 고유 리드 수 | 동일인 중복 제거 리드 | 고객 키 및 중복 판정 기준 필요 |
| 상담→최초 납부 전환율 | 선택 기간에 유입된 고유 상담자 중 관찰기간 내 최초 납부자 / 해당 고유 상담자 | 코호트와 관찰기간 명시. 이번 달 납부 ÷ 이번 달 신청을 대체하지 않음 |
| 신청 이벤트당 비용 | 귀속·기간이 같은 비용 / 신청 이벤트 | 귀속 불명확 시 ‘참고 비용’으로 제한 |
| 신규 납부 고객 획득비용 | 귀속 비용 / 중복 제거 최초 납부 고객 | 결제·고객·마케팅 연결 및 비용 배분 정책 확정 |
| 재학생 현황 | 기준일 확정 재학생 수 | 입학·복귀·중단·완료·조정 이력 |
| 수업시간 | 완료 수업 분 합 / 60 | ‘예정 수업’과 분리 |

기간 순방문자는 일별 순방문자를 더해 만들 수 없다. 사이트 간 동일인도 중복될 수 있으므로 초기에는 ‘일별 방문자 합’으로 명시하고, 필요 시 동일 측정 기준의 기간 고유 이용자 조회를 별도로 설계한다. ROAS/ROI는 광고별 매출·비용 귀속이 갖춰진 후에 도입한다.

## 6. Data and Migration Design (데이터 및 이관 방향)

- **일자 원장:** 날짜, 지표, 사이트, 값, 단위, 예정/실적, 수집상태, 원천, 원본 셀/메모 위치, 수집 시각, 수정 이력 보존. 기존 daily KPI는 조회용 집계로 활용.
- **기간 비용 원장:** `period_from/to`, 사이트, 채널, 금액, 원천 증빙과 입력 기준. 월 비용은 월 범위 보고에 사용하고 부분 기간은 일별 근거가 없으면 ‘배분 불가’로 표시. 일별 비용과 월 총액 중복 합산 방지.
- **이관 상태:** `누락`, `미수집`, `확정 0`, `부분 집계`, `확정`, `미래 예정`을 구분한다. 지표별 마지막 확정일과 데이터 범위를 반환한다.
- **브랜드 메모:** 방문자 메모 15일은 숫자 파싱 후 원래 합과 검증 가능. 이름이 섞인 메모는 검수 목록에서 내부 식별자와 연결한다. 원본과 별도 보존하며 개인정보를 요약 화면에 노출하지 않는다.
- **원천 우선순위:** 엑셀 이관·GA4·수동 수정이 같은 지표/일자/사이트에 있으면 병합 또는 우선순위를 명시한다. 재계산으로 과거 확정값이 조용히 바뀌지 않도록 한다.
- **통합 검증:** 동일 정의·기간·원천의 가산 지표만 `사이트 + 공통 + 검증된 미분류 = 통합`을 검증한다. 설명되지 않은 잔차는 ‘집계 차이’로 표시하고 별도 조사한다.
- **구현 표준:** `frontend-acm`, PostgreSQL `db_acm` / `amb_acm_*` / `ACM_DS`, `ent_id` 격리 사용. 개념적 저장 구조는 제안이며 상세 스키마는 구현 전 설계한다.
