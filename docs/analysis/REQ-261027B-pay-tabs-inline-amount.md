# REQ-261027B Collections: tabs, list-level entry, inline amount (수납 관리 탭 분리·목록 직접 입력)

## 1. Request (요청)
`/admin/pay` 수납 관리
1. 대시보드/통계 화면과 월별 납부목록 화면을 **탭으로 분리**
2. 상단 [재원생 일괄 등록] · [청구 등록 / 월별 생성] 버튼 **삭제**
3. **목록에서** 개별 학생 선택 입력 + 엑셀 일괄등록
4. **목록에서 청구액 직접 입력**

선행: REQ-261027 (PR #393 — 행별 [+ 청구], 엑셀 일괄등록, 미리보기 400 해소).

## 2. As-Is (현황)
```
수납 관리      [재원생 일괄 등록] [엑셀 일괄등록] [청구 등록 / 월별 생성]
◀ 2026-10 ▶ [이번 달] [전체 사이트] [새로고침]     ← 상단 통계(항상 표시)
┌ 학생 현황 그래프 ┐┌ 9월 수납 ┐┌ 10월 수납 ┐
[월별 보기] [기간 상세조회] [통계 대시보드]          ← 보기 전환 버튼
월별 목록: 학생 · 사이트 · 수업기간 · 청구상태 · 순청구액 · 수납 · 미납 · 작업
           작업 = [상세] [청구 수정] [미입력 청구 등록] [+ 청구]
```
- 통계와 목록이 한 화면에 섞여 목록이 아래로 밀린다.
- 월별 목록에서 금액을 바꿀 수 없다 — [청구 수정] → 기간 상세조회로 이동해 입력 후 사유와 함께 저장.
- [재원생 일괄 등록]은 금액 없는 초안을 만든 뒤 다시 금액을 입력하는 2단계.

## 3. Requirements (요구사항)
| ID | 내용 |
|----|------|
| FR-1 | 탭: **[대시보드·통계]** (상단 통계 그래프 + 통계 대시보드) / **[월별 납부목록]** (학생별 월 목록). 탭은 URL `?view=` 로 유지. |
| FR-2 | 상단 [재원생 일괄 등록], [청구 등록 / 월별 생성] 버튼 삭제. 월별 목록 행의 [미입력 청구 등록](초안)도 함께 삭제 — 청구액 직접 입력이 대체. |
| FR-3 | 월별 납부목록 도구줄: **[학생 선택해 청구]** (학생 검색 → 해당 학생 고정 청구 등록 창) + **[엑셀 일괄등록]**. 행별 [+ 청구]는 유지. |
| FR-4 | 월별 납부목록 각 행에 **청구액 입력칸**. ① 그 달 청구 0건 → 입력 시 수업료 청구 신규 생성(제목 `{월}월 수업료`, 납기 = 도구줄 기본 납기, 수강 수업이 1개면 자동 지정). ② 청구 1건(초안 포함) → 그 청구의 청구액 수정(초안은 확정). ③ 청구 2건 이상 → 입력칸 대신 합계 + [청구 수정]. |
| FR-5 | 입력한 행은 노란색 표시, 도구줄 **[변경 저장 (N)]** 한 번으로 일괄 저장, [취소]로 되돌림. 저장 결과(생성 n · 수정 n · 실패 사유) 표시. 저장 전 페이지·월 이동 시 확인. |
| FR-6 | 수정 사유는 자동 기록(`목록 직접 입력`), 수납액보다 작게 줄이는 등 기존 규칙 위반은 행별 오류로 표시. |
| NFR | 4개 언어 동시 반영, 기존 API 규칙(중복 청구 방지·버전 충돌) 유지. |

## 4. Decisions (결정 사항, 2026-10-27)
- **기간 상세조회**(청구 단위 목록, 수납 입력·환불·취소) → **세 번째 탭 [청구 상세]로 유지** (월별 목록 [상세]·[청구 수정]이 이 탭으로 이동).
- 배포 단위 → **PR #393(REQ-261027)에 합쳐 한 번에 배포**.

## 5. Out of Scope (범위 외)
- 할인·납기·제목의 목록 직접 입력(청구액만), 수납(입금) 목록 입력.
