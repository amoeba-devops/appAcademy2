# Notification — Mobile Chat Push & Inbox Header Requirements (알림 — 모바일 채팅 알림·알림 화면 요구사항)

## 1. Overview (개요)

요청 원문: "알림 - 모바일 채팅 알람 오지 않음. 알람에 채팅 멘션 추가 / 알림 화면 알림설정 - 전체/안읽은 한 줄로 처리" (대상 화면 `/admin/dashboard` 상단 알림)

## 2. Findings (조사 결과, 2026-10-20)

| 항목 | 사실 |
| --- | --- |
| 채팅 알림 생성 | 메시지 → `CHAT_MESSAGE`, 멘션 → `CHAT_MENTION` 이 알림함에 저장됨(운영: 최근 14일 메시지 8건·멘션 7건). 알림 목록에도 표시됨 |
| **모바일 푸시** | **운영 DB 푸시 구독 0건, 발송 기록 0건 — 이전 서버 포함 한 번도 없음.** 서비스워커(`acm-sw.js`)는 정상 로드되지만 구독 API 호출 기록이 없다 |
| 원인 1 | 푸시는 기기마다 **수동**으로 켜야 한다: 알림 창 → [알림 설정] → "이 기기 알림 켜기". 이 버튼을 누른 사용자가 없었다 |
| 원인 2 | 로그인 만료(PC·브라우저 4시간, 앱 8시간)나 로그아웃 때 이 기기 구독을 **자동 삭제**한다 → 켜도 몇 시간 뒤 꺼진다 |
| 원인 3 | 구독 갱신이 [알림 설정] 창을 열 때만 일어나 **30일 지나면 조용히 끊긴다** |
| 푸시 문구 | 종류와 관계없이 "새 알림이 도착했습니다" — 채팅인지 알 수 없다 |
| 다른 기기에서 읽음 | PC 에서 채팅을 보고 있으면 휴대폰 푸시는 보내지 않는다(의도된 동작) |
| iOS | 홈 화면에 설치한 앱에서만 푸시 가능(Safari 탭 불가) |
| 알림 창 머리 | "알림" 제목 아래 [알림 설정] 버튼이 한 줄, 그 아래 [전체][안 읽음] … [모두 읽음] 이 또 한 줄 — 모바일에서 세로 공간을 많이 차지 |

## 3. Functional Requirements (기능 요구사항)

| ID | 요구사항 |
| --- | --- |
| FR-1 | 이 기기 알림이 꺼져 있으면 알림 창 맨 위에 **"이 기기에서 알림 받기 [켜기]"** 안내를 보여 준다(한 번 탭으로 켜기, 거절·차단·미지원 기기는 안내 문구) |
| FR-2 | 로그인 만료로는 구독을 지우지 않는다. **로그아웃하거나 다른 계정으로 로그인할 때만** 지운다(같은 기기 같은 계정은 다시 로그인하면 계속 받음) |
| FR-3 | 앱을 열 때마다(알림 권한이 허용된 기기) 구독을 자동 갱신해 30일 만료가 없게 한다 |
| FR-4 | 푸시 문구를 종류별로: 채팅 멘션 "○○님이 나를 멘션했습니다 · 채널명", 채팅 메시지 "○○님의 새 메시지 · 채널명", 그 외는 알림함 문구와 같게. **메시지 본문은 넣지 않는다**(잠금 화면 노출 방지) |
| FR-5 | 채팅 멘션 알림: 현재처럼 알림함에 표시하고, 알림 목록에 "멘션" 표시(배지)를 붙여 일반 채팅 메시지와 구분한다 |
| FR-6 | 알림 창 머리를 한 줄로: `알림` 제목 줄에 닫기만, 그 아래 한 줄에 `[전체] [안 읽음]` 왼쪽 · `[모두 읽음] [⚙ 알림 설정]` 오른쪽 |
| FR-7 | 4개 언어(ko/en/vi/zh-CN) |

## 4. Open Questions (확인 사항)

| Q | 내용 | 제안 |
| --- | --- | --- |
| Q1 | "알람에 채팅 멘션 추가"의 뜻 | 채팅 멘션은 이미 알림에 들어간다. FR-5(멘션 표시 구분) + FR-4(멘션 푸시 문구)로 해석. 다른 뜻이면 알려 주세요(예: 직원(STAFF)도 채팅 알림 받기) |
| Q2 | 일반 채팅 메시지도 휴대폰 푸시를 보낼까? | 보냄(현재와 같음). 멘션만 받고 싶으면 개인 설정을 추가 — 이번 범위 밖으로 제안 |
