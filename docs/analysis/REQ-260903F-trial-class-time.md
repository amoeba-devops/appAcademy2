# REQ-260903F — 데모수업 시간설정 당일 허용 + 강사 포털 시간 불일치 수정 / Trial-Class Same-Day Scheduling & Portal Time Mismatch Fix

## 1. Overview (개요)

1. 데모수업(3단계) 시간을 **당일로도** 정상 설정 가능하게 한다 (현재 "다음날 갔다 돌아와야" 되는 것처럼 보임).
2. 설정한 시간과 **강사 포털 캘린더에 표시되는 시간이 다른** 문제를 수정한다.

## 2. Root Cause (원인 규명 — 조사 결과)

### 2.1 시간 불일치 — CSL→CAL 연동의 9시간 시프트 (핵심)
- `csl-cal-linker.service.ts:153` 이 `"YYYY-MM-DDTHH:MM:00"` **offset 없는 naive 문자열**을 만들고, `cal-event.service.ts:511`이 `new Date()`로 파싱 — ECMA 규격상 **서버 프로세스 타임존**으로 해석된다. 프로덕션 컨테이너는 UTC → 한국시간 14:00 설정이 **23:00(KST)로 표시**(+9h).
- 15:00 이후 설정은 다음날 00시 이후 instant 가 되어 **캘린더의 "다음날" 칸에 표시** — 사용자가 겪은 "다음날로 넘어갔다 돌아와야" 증상의 실체.
- 레벨테스트 연동 일정도 동일 경로로 동일 버그.
- **추가 결함 2건**: ① 링커는 최초 1회만 생성 — 이후 시간 변경이 캘린더 일정에 **영원히 반영 안 됨**(no-op) ② 연동 일정을 삭제하면 `tcl_cal_event_id`가 남아 재연동 불가.

### 2.2 당일 설정 "불가" — 코드상 제한은 없음 (체감 버그 3건)
- (a) 행의 시간 select 가 저장 후/재방문 시 **빈 값으로 보임**: 서버는 `"14:00:00"`을 주는데 옵션 값은 `"14:00"` — 매칭 실패로 placeholder 표시, 재동기화 effect 도 없음 → "저장 안 됐다"로 오인. 빈 상태에서 저장하면 시간 필드가 아예 전송되지 않아 조용히 no-op.
- (b) 위 2.1의 다음날 칸 표시 — 당일에 안 보이니 "당일 설정 불가"로 체감.
- (c) 생성 후 날짜(`heldAt`) 수정 UI 없음(시간만 수정 가능), 삭제 API도 없음 — 잘못 만들면 정정 불가.

## 3. Requirements (요구사항)

| ID | 요구사항 |
|----|---------|
| FR-1 | **시간 변환 수정**: 링커가 테넌트 타임존(REQ-260903 `TenantSettingsService`) 기준으로 벽시계 → UTC 변환한 올바른 instant 를 생성 (데모수업·레벨테스트 공통). 종료 = 시작 +1h(instant 연산) |
| FR-2 | **변경 동기화**: 이미 연동된 일정이 있으면 시간 변경 시 해당 캘린더 일정의 시작/종료를 **업데이트**. 연동 일정이 삭제됐으면 재생성(잔존 id 자가 복구) |
| FR-3 | **기존 데이터 복구**: 연동으로 생성된 기존 일정의 시각을 CSL 원본(held_at/held_time, scheduled_at/time)에서 **재계산하는 멱등 마이그레이션**(1008) — 원본 기준 재계산이라 수동 수정 여부와 무관하게 결정론적 |
| FR-4 | **패널 표시 수정**: 시간 select 값 정규화(`HH:MM`)+props 재동기화 — 저장 후에도 설정값이 그대로 보임 |
| FR-5 | **날짜 수정 허용**: 데모수업 행 수정 폼에 날짜(heldAt) 입력 추가 (Update DTO 는 이미 지원) |
| NFR | i18n 4 locale(신규 문자열 발생 시), 당일 포함 과거/미래 날짜 제한은 두지 않음(현행 유지) |

## 4. Out of Scope (범위 외)

- 데모수업 행 삭제 API 신설 — 후속 (날짜 수정으로 대부분 해소)
- 포털 캘린더의 테넌트 TZ 전환(REQ-260903 P2 후속) — 데이터가 올바른 UTC 면 KST 브라우저에선 정상 표시됨
