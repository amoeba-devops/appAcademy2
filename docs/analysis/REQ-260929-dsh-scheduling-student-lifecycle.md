## 3. Metric Contract Proposal (지표 정의 제안)

Scheduling/Scheduled/New Class의 의미는 2026-09-29 사용자 정정으로 확정했다. 집계 세부 방식은 아래 구현안으로 정리한다. 첫 수업만으로 Scheduling/Scheduled의 범위를 제한하지 않는다.

| 지표 | 제안 정의·단위 | 일별/기간 집계 |
|---|---|---|
| Scheduling | 수업 스케줄 조율 중인 학생, 명 | 기준시점의 조율 중 고유 학생 수; 기간 요약은 종료 기준일 상태 |
| Scheduled | 수업 스케줄 조율이 완료된 학생, 명 | 기준시점의 조율 완료 고유 학생 수; 기간 요약은 종료 기준일 상태 |
| New Class | 학생정보의 수업시작일이 해당일인 학생, 명 | `std_start_date = 해당일`인 고유 학생 수와 학생정보 목록. 기간 요약은 시작일이 기간 내인 고유 학생 수 |
| New St. | 최초 유효 수강료 납부 완료, 첫 정규 수업 미시작 학생, 명 | 일말 대기 인원; 기간 요약은 종료 기준일 인원. 일정 확정 여부는 별개 |
| Returning St. | 과거 상담 또는 수업 중단 이력이 있고 복귀가 확인된 학생, 명 | 복귀 확인일 기준 기간 내 고유 학생 수. 상담만 했던 학생도 포함 |
| Referral St. | 기존 학생/학부모의 소개로 유입됐고 소개자가 확인된 학생, 명 | 소개 유입일 기준 기간 내 고유 학생 수. 납부를 필수 조건으로 두지 않음 |

- New Class는 학생정보의 수업시작일(`std_start_date`)을 원천으로 한다. 반 생성일, 입학일, 실제 세션 진행일로 대체하지 않는다. 당일 수업시작일이면 실제 진행 완료 여부와 무관하게 포함한다. 시작일 누락은 확인 필요로 표시한다. Beginning의 기존 상담 수업시작일 집계와 출처를 구분한다.
- New St.는 기존 입학자 수에서 대기 인원으로 의미가 바뀐다. 기존 수기값을 새 정의에 재사용하지 않고 정의 버전과 시행일을 표시한다. 입학일 기반 `# of Students` 산식은 유지하며 `학생수 = 전일 학생수 + New St. - Out St.`로 계산하지 않는다.
- 각 지표는 독립된 관점이다. 소개 학생이 첫 납부 대기 학생일 수도 있고, 상담 후 복귀자가 첫 납부자일 수도 있다. 상호 배타 항목으로 합산하지 않는다.
- 첫 납부는 동일 테넌트의 식별된 학생 기준, MAP 응시료/체험비/미납/면제 제외를 권고한다. 전액 환불·등록 취소 시 대기 집계 제외. 실제 결제·환불 원장과 수기 확인 데이터의 우선순위 및 과거 첫 납부 확인 절차를 구현 전 확정한다.
- 첫 수업 실제 시작 시 New St.에서 제외한다. Scheduled는 수업 시작만으로 제외하지 않고 해당 스케줄 조율 완료 상태를 따른다. 과거 완료된 수업 이력이 있으면 재납부를 New St.로 세지 않는다. 결석/일정 취소만으로 첫 수업 완료 처리하지 않는다.
- Returning은 단순 상태 수정, 사이트 이동, 추가 과목 등록을 제외한다. 중단 근거와 복귀 확인을 필수로 하고 여러 번 복귀한 사람은 기간 요약에서 1명, 상세에는 모든 복귀 건을 제공한다. 일별 합과 기간 고유 인원이 다를 수 있음을 표시한다.
- 일별 경계는 현행 대시보드와 같은 Asia/Seoul. 조회 종료일이 미래이면 오늘 현재를 기준으로 하며 미래 실적은 0으로 확정하지 않는다. 기간 전 시작한 대기 학생도 종료일에 대기 중이면 포함한다.
- 이벤트 발생 당시 사이트를 보관한다. ALL 인원 지표는 테넌트 전체 학생 중복 제거, 사이트 미분류는 별도 표기한다. 사이트 합산과 ALL이 달라질 수 있으면 중복/미분류 사유를 보여준다. 기존 운영 학생수의 사이트 합산 계약과 분리한다.
- 과거 이력 부족은 미확인/PARTIAL/UNAVAILABLE로 표현한다. 데이터가 없다는 이유로 확정 0 또는 복귀 아님/소개 아님으로 채우지 않는다.

## 4. Source Input Requirements (원천 입력 요구사항)

1. **수강신청·학생 상세**: 스케줄 조율 상태(미착수/조율 중/조율 완료/종료/취소), 상태 기준일, 담당 강사, 수업 예정일시, 연결 반·세션/일정. 수업 시작 여부와 조율 상태는 별개로 관리한다. 확정에는 학생·강사·예정일시가 필요하다. 변경 이력을 남겨 이전 날짜의 상태를 재현한다.
2. **기존 납부 영역 보완**: 납부일·금액·확인 상태를 재사용하고, 최초 수강료 납부 여부의 확인 근거를 제공한다. 최초 납부일을 일반 메모 수정일로 대체하지 않는다.
3. **상담/수강신청 및 학생 상세의 복귀 기록**: 학생 이름 검색 입력 → 기존 학생 또는 과거 상담 선택, 중단일/근거, 복귀일, 상담 복귀/수업 복귀 구분. 학생 등록 전 상담도 연결 가능하게 한다. 이름만 같다고 자동 병합하지 않는다. 기록이 없는 과거 학생은 이름 입력과 확인 근거를 받아 미확인으로 저장하고 확인 후 집계한다.
4. **상담/학생 상세의 소개 정보**: 소개 여부(미확인/없음/있음), 소개자 유형(학생/학부모), 이름 검색·선택, 소개 유입일. 수기 소개자명은 임시 저장 가능하되 실제 마스터 연결/확인 전 집계에서 제외한다. 상담에서 학생 등록 시 정보를 승계한다.
5. **지표 상세 조회**: 숫자 클릭 시 해당 학생, 집계 기준일, 상태, 연결 근거, 누락 항목을 보여주고 원천 수정 화면으로 이동한다. 원천 정정 후 영향 날짜와 기간 요약을 갱신한다.

## 5. Today Live Overview (오늘 실시간 현황)

- 기존 **원장 현재 현황 → 오늘 실시간 현황**으로 제목을 변경한다.
- 현재 재원학생, 재직강사, 수업배정학생, 수업배정교사 4개 수치는 유지하고, **마케팅/스케줄/운영/수업의 대시보드 목록에 있는 모든 항목**을 추가한다. 이번 신규 5개 항목도 포함한다.
- 선택 기간(from/to/preset)과 독립적으로 서버 기준 오늘(Asia/Seoul)을 조회한다. 현행 패널은 통합 화면에만 노출되며 API scope도 ALL이다. 우선 이 위치·범위를 유지하고 ‘전체 사이트 · 오늘’이라고 명시한다. 사이트별 실시간 확장은 별도 범위다.
- 발생 지표는 오늘 00:00부터 현재까지 기록된 오늘 통계, 상태 지표는 현재 상태 인원으로 보여준다. New Class는 수업시작일이 오늘인 학생을 모두 표시한다. 비율/효과는 오늘 분자·분모로 재계산하고 분모가 0이면 계산 불가로 표시한다.
- 목록의 공통 지표 정의·정렬·단위를 재사용하여 일부 대표 항목만 노출하거나 신규 항목을 빠뜨리지 않는다. 현재 재원학생(원장 상태)과 Operating 학생수(입학/기간 기준)는 기준 설명을 함께 제공한다.
- 현행 `SourceCurrentPanel`은 `/acm/dsh/source-current`를 활성 화면에서 5초마다 조회한다. 이 갱신 방식과 수동 새로고침·화면 복귀 갱신을 유지한다. 내부 원천 변경은 저장 후 즉시 갱신하고, 오늘 자동 통계가 야간 일별 KPI 배치를 기다리지 않도록 한다.
- GA/광고비 등 외부 집계는 마지막 동기화 자료가 기준이다. 패널 조회 시각과 각 원천의 마지막 동기화 시각을 구분하며 미동기화/지연/오류를 0으로 표시하지 않는다. 5초마다 외부 API를 호출하지 않는다.
- New Class 수치 클릭 시 이름·소속·수업시작일·학생 상세 링크를 제공한다. 오늘 날짜 변경, 저장/수정/취소, 새로고침 후 집계가 일치해야 한다.

## 6. Decision Status (확정 사항·계획 상태)

사용자 확정: Scheduling=수업 스케줄 조율 중, Scheduled=조율 완료, New Class=학생정보의 수업시작일이 해당일인 학생, 오늘 실시간 현황에 모든 대시보드 항목 표시.
