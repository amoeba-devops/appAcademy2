# REQ-260903D — 접수 이전점수 반영 일관화 + 레벨테스트 미진행 데모수업 진행 / Intake Prior-Score Consistency & Level-Test Skip

## 1. Overview (개요)

1. 접수(1단계) '이전점수'에 레벨테스트(2단계) MAP 점수가 **어떤 때는 반영되고 어떤 때는 안 되는** 불일치를 제거한다.
2. 레벨테스트를 **미진행(NOT_HELD)** 처리하고도 데모수업(3단계)으로 진행할 수 있게 한다 (현재는 점수 입력 없이는 차단).

## 2. Root Cause (원인 규명 — 조사 결과)

### 2.1 이전점수 불일치 — "반영 코드"는 존재하지 않음
- 접수 이전점수와 2단계 레벨테스트 결과가 **같은 테이블·같은 컬럼**(`amb_acm_csl_map_test`의 `mpt_score_reading/math/language`)을 공유한다.
- 접수 측 조회/저장(`getMapTest`/`upsertMapTest`)은 `findOne({inqId})` — **testType 필터도 ORDER BY도 없음**. 987 마이그레이션 이후 시험종류별 1:N 행이 되면서, 행이 2개 이상이면 **어느 행을 집을지 비결정적**(Postgres UPDATE로 튜플 위치가 바뀌면 같은 상담도 날마다 결과가 달라짐).
  - MAP 행 1개뿐이면 → 반영됨 (사용자가 관찰한 "되는 경우")
  - ISEE/SSAT 등 행 추가·비MAP 유형·`MAP_TEST_TUTORING` 목적 미포함이면 → 안 됨/빈 칸
- **부수 손상 버그 2건**: ① 비MAP 결과 입력이 MAP 점수 컬럼을 null로 덮어씀(레거시 단일 행에서 이전점수 소실) ② 접수 저장이 비MAP 행에 이전점수를 붙일 수 있음.

### 2.2 데모수업 진행 차단
- 백엔드 `assertEntryGate`: `MAP_TEST → TRIAL_CLASS` 전환 시 **MAP 점수 3컬럼 중 하나 이상 존재(또는 이전점수 flag/응시료 PAID·WAIVED)** 를 요구 — 미진행(NOT_HELD) 상태는 게이트에 아무 효과 없음.
- 프론트는 진행완료(COMPLETED) 상태에서만 점수 입력을 허용 → 결과적으로 "진행완료+점수입력 없이는 3단계 불가".
- 비MAP(ISEE 등)만 완료·점수입력한 학생도 게이트가 MAP 컬럼만 보기 때문에 차단되는 부작용도 존재.

## 3. Requirements (요구사항)

| ID | 요구사항 |
|----|---------|
| FR-1 | **이전점수 결정론화**: 접수 측 조회/저장/레거시 결과 경로와 게이트 조회를 전부 `testType='MAP'` 행으로 고정 — MAP 레벨테스트 점수는 접수 이전점수 칸에 **항상** 반영(동일 컬럼 공유를 명시적 동작으로 확정), 다른 유형 행 수와 무관 |
| FR-2 | **손상 방지**: 비MAP 결과 입력 시 MAP 점수 컬럼을 건드리지 않음(null 덮어쓰기 제거) |
| FR-3 | **미진행 → 데모수업**: `MAP_TEST → TRIAL_CLASS` 전환의 점수 게이트 제거 — 미진행(NOT_HELD) 포함 운영자 판단으로 진행 가능. (INTAKE→TRIAL_CLASS 바로 스킵 게이트는 현행 유지) |
| FR-4 | 2단계 안내 문구 갱신 — "미진행 상태여도 데모수업으로 이동할 수 있습니다" (i18n 4 locale) |
| NFR | 기존 데이터 무변경(마이그레이션 없음), 진행완료 시 점수입력 잠금(UI)은 현행 유지 |

## 4. Out of Scope (범위 외)

- 이전점수와 레벨테스트 결과의 **스키마 분리**(별도 컬럼) — 동일 컬럼 공유가 확정 동작이므로 불필요
- INTAKE→TRIAL_CLASS 바로 스킵 정책(Q-CSL-003) 변경, ADR의 12개월 룰 구현
- 비MAP 유형 점수의 접수 이전점수(JSONB) 자동 반영 — 현행(접수 입력값 유지) 유지
