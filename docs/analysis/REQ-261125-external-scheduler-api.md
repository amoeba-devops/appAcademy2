# External Scheduler API Requirements (외부 스케줄 앱 API 요구사항)

## 1. Overview (개요)

별도 내부 스케줄 앱에서 강사 가능 시간과 수업 배정을 관리하고, 배정 결과를 ACM의 기존 수업일정에 반영한다. 연동 대상은 이 저장소의 학원 관리 시스템이며 AMA 플랫폼 전체 일정 API를 신설하는 작업은 아니다. 이 문서는 설계안이며 API 또는 실제 키가 발급된 상태가 아니다.

## 2. Current Implementation (현재 구현)

분석 기준: 운영 배포된 main `e4f943d3e2d402286bf40d9dace1849de2352851`의 애플리케이션 소스.

| 항목 | 확인 결과 | 설계에 미치는 영향 |
| --- | --- | --- |
| 일정 CRUD | `acm-cal/presentation/cal-event.controller.ts`의 `/api/acm/cal/events`, 관리자 JWT와 OwnEntityGuard 사용 | 기존 관리자 토큰을 공유하지 않고 외부 전용 인증 경계 추가 |
| 일정 필드 | 담당 강사 UUID, 학생 참석자 UUID, 시작/종료 TIMESTAMPTZ, 카테고리, 장소/화상 제공자 | 외부 계약을 기존 CAL 데이터로 매핑 |
| 강사 필터 | 담당 강사 OR 강사 참석자 OR 강사에 연결된 콘솔 소유자 | 점유 일정 조회도 동일 범위를 포함 |
| 카테고리 | `DEMO_CLASS`, `REGULAR_CLASS`를 이미 지원 | 신규 카테고리 불필요 |
| 대면/비대면 | 별도 명시 필드 없음. 데모·정규 일정은 `prepareCreate`에서 테넌트 화상 제공자 일치 검증 | 대면 구분 및 화상 검증 분기 보완 필요 |
| 강사 마스터 | 이름·이메일(nullable), 상태 `ACTIVE / LEAVE / RESIGNED` | 이메일 매칭 및 재직 상태 조회 가능 |
| 트랜잭션 | 이벤트·참석자·inbox를 함께 저장, 화상 설정과 일정의 테넌트 잠금 존재 | 외부 매핑·멱등 요청까지 하나의 원자적 저장 경계로 확장 |
| 수정/삭제 | 변경 이력, 삭제 사유, soft delete, 반복 일정 별도 처리 | 외부 작성자/클라이언트 감사 및 삭제 사유 유지 |
| 기존 외부 접수 | 공개 상담 접수용 사이트 키 구현은 별도 용도 | 수업 CRUD용 권한으로 재사용하지 않음 |

참조: `docs/standard/SPEC.md`, `docs/plan/PLN-260903G-external-intake-api.md`, `docs/plan/PLN-260526-acm-cal-boda-integration.md`. `/memories`, `/memories/session`, `/memories/repo`는 현재 환경에 없다.

## 3. Functional Requirements (기능 요구사항)

| ID | 요구사항 / 수용 기준 |
| --- | --- |
| FR-01 | 외부 수업 ID로 등록·수정·삭제. 담당 강사, 학생 이름, 시간, 데모/정규, 대면/비대면을 저장하고 기존 관리자·강사 수업일정에 표시 |
| FR-02 | 기간 및 선택 강사로 기존 점유 일정 조회. 외부 작성 일정뿐 아니라 기존 수동·반복·가져오기 등 CAL에 반영되는 일정을 포함 |
| FR-03 | 강사 ID·이름·이메일·재직 상태 조회. 기본 상태 전체, 상태/이메일 정확 일치 필터, 페이지 조회 지원. 삭제 강사는 제외 |
| FR-04 | 테넌트 마스터가 연동 클라이언트 및 권한별 API 키 발급·교체·폐기. 키 원문은 발급 시 1회 표시 |
| FR-05 | 실제 배포 주소, 요청/응답, 오류, 키 발급·보관·교체, 재시도 절차를 Markdown 문서와 OpenAPI로 제공 |
| FR-06 | 강사는 이메일 trim·대소문자 무시 정확 일치로 매칭. 미등록·중복·휴직·퇴직 강사는 새 배정 불가. 기존 과거 일정은 조회 가능 |
| FR-07 | 학생은 ID가 있으면 동일 테넌트 검증 후 연결. 이름만 있으면 활성 학생의 정확 일치가 1명일 때 연결. 동명이인은 임의 연결하지 않고 422 반환 |
| FR-08 | 사용자 확인 완료: 미등록 데모 학생은 이름으로 일정에 보관 가능. 정규수업은 기존 학생 연결 필요. 미등록 이름은 계정 생성·초대·알림을 유발하지 않음 |
| FR-09 | 강사 일정 겹침은 409. `existing.start < new.end AND existing.end > new.start`; 연속된 두 수업은 허용. 수정 시 자기 자신, 삭제 일정은 제외 |
| FR-10 | 동일 클라이언트의 안정적인 외부 ID와 멱등 키로 재시도 중복 방지. 같은 클라이언트의 키를 교체해도 기존 수업 수정 가능 |
| FR-11 | 수정·삭제는 해당 클라이언트가 등록한 수업만 허용. 수동 생성·타 연동 일정은 읽기만 가능. 수정 충돌은 버전 조건으로 412 반환 |
| FR-12 | 기간은 UTC offset이 있는 ISO-8601로 입력, UTC 저장. 응답은 ISO-8601; 포털 표시는 기존 테넌트/사용자 시간대 정책 유지 |
| FR-13 | `/admin/config` 서비스 설정에 **API 사용안내** 메뉴/카드를 추가하고 `/admin/config/api`로 연결. 외부 오픈 API / API 연동 / API 사용 설정 3개 탭 제공 |
| FR-14 | 외부 오픈 API 탭에서 제공 종류·버전·제공 상태·Base URL·HTTP 메서드·엔드포인트·설명·필요 권한 표시. 최초 대상은 강사 조회 및 수업일정 조회·등록·수정·삭제 |
| FR-15 | 각 API에 path/query/header/body 파라미터 이름·필수 여부·타입·허용 값(enum)·형식·기본값·범위·설명·예제 값과 성공/오류 응답·상태 코드·curl/JSON 예제 제공. 복사 및 OpenAPI 다운로드 지원 |
| FR-16 | API 연동 탭에 사용 설정 → 앱 등록 → 키 발급 → 서버 비밀값 보관 → 강사 매칭 → 일정 조회/반영 → 오류·재시도·키 교체 순서 안내. 인증·시간대·페이지·충돌·멱등·버전 조건 설명 |
| FR-17 | API 사용 설정 탭에서 테넌트 외부 API 전체 사용 여부 및 강사 조회/일정 조회/일정 쓰기 제공 여부를 저장·재조회. 신규 테넌트 기본 전체 OFF. OFF이면 기존 키가 있어도 외부 요청 차단 |
| FR-18 | 같은 설정 화면에서 앱별 사용/중지 및 키 발급·권한·만료·최근 사용·교체·폐기를 관리. 유효 권한은 테넌트 허용 기능 ∩ 앱 활성 상태 ∩ 키 권한 ∩ 기존 서비스 이용 권한으로 결정 |
| FR-19 | 설정·키 변경은 동일 테넌트 마스터만 허용하고 서버에서 검증. 서비스 설정 화면 열람은 기존 콘솔 접근 정책을 유지하며 권한 없는 사용자에게 변경 컨트롤과 비밀값을 노출하지 않음 |
| FR-20 | 안내 화면은 서버 API 카탈로그/OpenAPI와 동일한 계약 원본에서 생성하고 아직 배포하지 않은 API는 예정 상태로 구분. 도움말 열람·복사·예제 보기는 실학생 일정 생성 또는 실제 API 호출을 실행하지 않음 |

FR-08은 사용자가 “있음 — 미등록 학생도 이름으로 일정 등록”으로 확인했다. 이름 전용 보관 분기를 구현 범위에 포함한다. 이 답변은 학생 처리 방식의 확인이며 전체 구현 계획 승인을 대신하지 않는다.

## 4. Access and Reliability (접근·신뢰성)

- 키별 `teachers:read`, `lessons:read`, `lessons:write` 권한. 테넌트는 키에서 결정하며 요청의 `entId`로 변경 불가. 중지된 테넌트 및 미허용 기능은 기존 테넌트 정책으로 거부한다.
- 클라이언트별 안정적인 식별자와 활성 키 여러 개를 허용하여 새 키 적용 후 기존 키를 폐기할 수 있다. 키는 CSPRNG 원문을 발급하고 해시만 저장; 로그·URL에 원문 기록 금지.
- 연동 앱 서버가 키를 보관한다. 브라우저 JavaScript에 키를 넣지 않는 서버 간 연동 구조다.
- 조회 최대 31일, 페이지 최대 200개, 키별 기본 60회/분 제안. 초과는 429와 Retry-After, 장애는 5xx. 운영 측정 후 제한 조정.
- 원자적 충돌 확인은 외부 요청끼리만 잠그지 않고 기존 CAL 쓰기·반복 생성·가져오기 경로와 공유하는 잠금 규약을 검증한다. 모든 경로가 참여하기 전에는 동시 배정 방지를 완료로 판정하지 않는다.
- 조회 이후 다른 배정이 발생할 수 있으므로 최종 저장 시 충돌 검사 필수. 전체 조회 페이지를 소진하지 않은 결과로 빈 시간을 확정하지 않는다.
- 이벤트/참석자/외부 매핑/멱등 결과/감사 저장을 동일 DB 트랜잭션으로 처리. 실패 시 부분 일정이 남지 않아야 한다. 외부 부작용은 기존 outbox 등 커밋 이후 처리 경계 검토.
- 운영 데이터 또는 실제 비밀 키는 분석·테스트 문서에 포함하지 않는다.
- 외부 API 전체/종류별 OFF는 인증 후 멱등 결과 재생 전에 검사한다. 차단은 모든 서버 인스턴스에 즉시 반영되도록 DB 조회 또는 일관된 무효화 방식을 사용한다. 저장된 키·기존 일정은 삭제하지 않으며 ON 재전환 시 유효한 미폐기 키만 다시 사용할 수 있다.
- 외부 API 사용 OFF는 이번에 신설하는 `/api/integrations/v1` 범위에 적용한다. 기존 관리자·포털 API 및 상담 접수 API의 설정은 변경하지 않는다. “오픈 API”는 문서화된 외부 연동 API이며 무인증 공개 API를 뜻하지 않는다.

## 6. Settings Navigation (설정 메뉴 변경)

기존 제안의 테넌트 설정 > 외부 스케줄 연동 전용 화면을 **서비스 설정 > API 사용안내** 통합 화면으로 변경한다. 초기 API 종류는 스케줄 연동에 필요한 범위를 제공하고 후속 외부 API도 같은 카탈로그에 추가할 수 있는 구조로 한다. 일반적인 타사 API 연동 기능을 새로 만드는 요구사항으로 확장하지 않는다.

## 5. Scope and Decisions (범위·결정)

강사 가능 시간 관리·최적 배정 알고리즘·내부 스케줄 앱 자체 수정은 대상이 아니다. 이번 API는 확정된 단건 수업의 단방향 반영이다. 반복 수업은 외부 앱이 회차마다 별도 externalId로 보낸다. 기존 반복 시리즈 자체를 외부에서 수정하지 않는다. 대면 수업은 화상방을 생성하지 않고 비대면은 테넌트의 기존 제공자 정책을 따른다. 이메일/메시지 자동 발송은 기본 비활성이다.

운영 수동 수정과 외부 앱 수정이 경합하면 버전 불일치로 중지하고 재조회한다. 삭제한 externalId의 재사용은 409이며 복구는 이번 범위에서 제외한다. 외부 앱에서 다른 식별자로 재등록할 수 있다.
