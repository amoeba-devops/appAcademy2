## 2. Cell Analysis (셀·내용 분석)

48열 중 값이 있는 열은 25개, 전체가 빈 열은 23개다. 빈 값과 0, X는 구분해서 보존한다.

- `Y2:Y68` 재원여부와 `AB2:AB68` 휴원여부는 모두 X, `Z2:Z68` 퇴원일은 67명 모두 유효한 날짜이다.
- 입학일은 2025-11-28~2026-09-10, 퇴원일은 2025-12-05~2026-09-17이다. 퇴원일이 입학일보다 이른 행은 없고, 같은 날 입학·퇴원한 행은 3개다.
- 생일은 33명에게 있고 모두 유효한 YYYYMMDD 문자열이다. 날짜는 Excel 숫자 serial로 가정하지 않는다.
- AV 등록일은 시각과 `.0`이 있는 문자열이며 시간대 정보가 없다. 원문 및 출처 시각으로 보관하고 ACM 시스템 등록일 `created_at`을 덮어쓰지 않는다.
- 원생고유번호는 5자리 문자열 52개·4자리 문자열 15개다. 앞자리 0과 길이를 보존하고 ACM UUID나 임의 정수로 변환하지 않는다.
- 학생 전화는 1명, 학생 이메일은 1명만 있다. 보호자 연락처는 55명, 보호자 구분은 모 48·부 7이며 보호자 이름은 전원 미입력이다.

## 5. Import and Preservation Rules (반영 규칙)

1. 원본 시스템을 구분하는 import namespace와 원생고유번호로 재반영을 식별한다. 기존 번호 연결이 없는 최초 반영에서는 이름+생일 및 보호자 정보로 후보를 확인한다. 번호만으로 다른 시스템의 레코드를 합치지 않는다.
2. 신규 후보는 명시적으로 확인된 대상만 WITHDRAWN으로 생성한다. 사이트 근거가 없으면 미분류(NULL), 이메일은 없는 채로 저장 가능하게 한다. 별도 계정 발급·알림 전송은 하지 않는다.
3. 기존 학생은 빈 값만 채우고, 다중행 메모/이력은 출처와 중복 여부를 확인하여 보완한다. 기존 학교·학년·연락처·사이트·수업 시작일을 원본의 오래된 값으로 덮어쓰지 않는다.
4. 기존 상태 정책은 확인 대기이다. 제안은 기존 상태 유지 + 과거 퇴원 이력 추가이다. 사용자가 기존 학생도 퇴원으로 변경하도록 선택하면 변경 전후를 명시하고 재등록/최근 수업 시작일 등 충돌 행은 보류한다. 답변 전 기존 상태 변경을 실행하지 않는다.
5. 퇴원 이력은 현재 상태와 별도로 저장한다. 재원 학생에 과거 퇴원일이 존재할 수 있으므로 목록의 현재 상태를 과거 이력으로 자동 덮어쓰지 않는다. 원본 퇴원일을 오늘 날짜로 대체하지 않는다.
6. 보호자 이름이 없으면 가짜 이름으로 부모 마스터를 생성하지 않는다. 학생 상세의 미연결 보호자 연락 정보로 보존하고 기존 보호자 연결 후보를 제시한다. 관계가 확인된 경우에만 기존 parent/학생-parent 구조와 연결한다. 공유 전화 3쌍은 별도 검토한다.
7. 기존 로그인·학부모/교사 연결·출결·수업·납부·소속 사이트는 승인된 변경 집합 외에 유지한다. 퇴원 상태 변경과 수업 취소·환불·자동결제 해지는 분리한다.
8. 동일 파일 재실행과 행 정렬/빈 열 위치 변경에도 고유번호 기반으로 중복 학생·이력이 생기지 않아야 한다. 삭제 학생 후보는 자동 복원/신규 생성하지 않는다.

## 6. Acceptance and Open Decision (완료 조건과 확인 사항)

- 67명과 48열을 누락 없이 분석하고 신규/보완/유지/보류 및 셀별 변경 내역을 제시한다.
- 최신 미리보기에서 대상 ID와 상태 정책을 확정하며, 보류 행은 반영에서 제외된다.
- 이메일 없는 퇴원생을 등록·수정할 수 있다. 재원 등록 및 계정 발급의 기존 필수 조건은 별도 검증한다.
- 원본 67개 퇴원일과 67개 고유번호를 보존하고 날짜·전화·앞자리 0·NULL/0/X 변환을 검증한다.
- 기존 학생 ID와 비대상 정보·관계를 보존하고, 재실행 추가 생성/중복 이력은 0건이다.

## 7. Detail Presentation Amendment (학생 상세 표시 추가 요구사항)

대상은 `/admin/std/:id`의 모든 학생 상세이며, 사용자가 지정한 상세 페이지에서 기본 인적사항·MAP 점수·수업 정보·메모/상태의 미입력 값이 `—`로 표시되는 현행을 확인했다. 특정 학생 데이터만 변경하는 요청이 아니라 상세화면 공통 표현 규칙이다.

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| STD-W-UI01 | 박스 제목 글자 크기 +1px 및 Bold | 현행 코드의 text-xs(기본 12px)/font-semibold(600)를 기준으로 13px/font-bold(700) 적용; 테마가 다르면 실제 계산 크기 기준 +1px 확인 |
| STD-W-UI02 | 각 항목을 `항목 : 값`으로 표현 | 기본 인적사항·MAP·수업·메모·보호자 등 상세 정보에 일관되게 적용; 긴 값은 줄바꿈, 레이블과 값의 의미 구조 유지 |
| STD-W-UI03 | 미입력 값은 `입력필요` 표시 | NULL, undefined, 빈 문자열, 공백만 있는 값 및 이들에 대한 기존 `--`/`—` 대체 표시를 변경 |
| STD-W-UI04 | 실제 값과 업무 상태 보존 | 숫자 0·false는 정상 값으로 표시하고, 미분류·미발급 같은 유효한 상태 문구는 유지; DB에 `입력필요`를 저장하지 않음 |
| STD-W-UI05 | 적용 범위 일관성 | 기본 인적사항·MAP 점수·수업 정보·메모/상태·학부모 정보·포털 계정 등 박스 제목, 이번 계획의 신규 상세 박스에도 동일 규칙 적용 |

제목 외 항목명과 값의 글자 크기는 유지한다. `입력필요`는 보조 텍스트 색으로 표시하되 읽기 쉬운 대비를 유지하며 오류나 저장 실패로 표현하지 않는다. 긴 메모는 `항목 :` 다음 줄에 원문 줄바꿈을 유지할 수 있다. 학부모 미등록 등 영역 전체의 빈 상태 안내는 해당 안내를 유지하고, 개별 미입력 필드에 위 문구를 적용한다. 번역 키를 사용해 다른 언어 화면도 일관되게 처리한다.
