# Customer Complaint Management (고객불만 관리 요구사항)

## 1. Request (요청)

대시보드에서 등록한 고객불만의 목록과 상세 내용을 확인하고 수정할 수 있도록 제공한다. 좌측 메뉴의 ‘수업통계’ 바로 아래에 ‘고객불만’을 추가한다.

## 2. Existing Implementation (현행 확인)

최신 main `06e6922` 기준 소스를 확인했다. 원본 IDE 작업 폴더는 이전 버전과 미완료 변경이 있으므로 별도 `/private/tmp/acm-complaints-261006` 체크아웃으로 검토했다. 운영 URL의 직접 웹 조회는 접근되지 않아 로그인 후 실제 화면은 이번 검토에서 확인하지 않았다.

- `ComplaintDialog`는 등록용 POST만 사용한다. 설명은 한 줄 Input이며 편집 모드·목록 화면이 없다.
- `amb_acm_dsh_complaints`에 날짜, 사이트, 채널, 중요도, 제목, 내용, 연결 Q&A, 작성자, 생성·수정 시각, 삭제 시각이 존재한다.
- `GET /api/acm/dsh/complaints?yearMonth=...`와 `PUT /api/acm/dsh/complaints/:id`는 이미 존재한다. 목록은 월별 전체 조회뿐이며 기간·검색·페이징 검증이 없다.
- 기존 수정은 날짜 변경을 받지 않으며 `??` 병합 때문에 null로 값을 지우는 동작이 제한된다. 사이트 변경은 해당 일 KPI를 재계산한다.
- 사이드바 NAV뿐 아니라 프론트/백엔드 메뉴 키 목록과 테넌트별 메뉴 표시·정렬 설정도 함께 반영해야 한다.
- 기존 설계 `docs/design/acm-v1.0a-fn-dsh-001.md`는 불만 목록·상세를 정의하지만 현재 엔티티와 다른 처리 상태 모델도 포함한다. 이번 작업은 현재 PG 구조를 기준으로 한다.

## 3. Scope (범위)

- 메뉴: 수업통계 → 고객불만 → 다음 기존 메뉴. 경로 `/admin/complaints`.
- 목록: 기본 이번 달, 기간·사이트(전체/공통/TPI/Trinity/Santa Croce)·채널·중요도 필터, 제목/내용 검색, 전체 건수와 페이지 이동. 기본 최신 날짜순, 동일 날짜는 생성 시각/ID로 안정 정렬.
- 열: 불만일, 사이트, 채널, 중요도, 제목, 내용 요약, 최종 수정일, 상세/수정 버튼. 빈 제목/내용을 가진 기존 자료도 표시.
- 상세·수정: 날짜, 사이트, 채널, 중요도, 제목, 여러 줄 내용, 기존 연결 Q&A 확인/변경/해제. 기존 값 사전 입력, 저장/취소, 입력·서버 오류 안내.
- 목록의 신규 등록 버튼과 대시보드 등록 버튼은 같은 등록/수정 폼을 재사용한다. 대시보드에 ‘불만 목록’ 바로가기를 추가해 현재 기간/사이트를 전달한다.
- 저장 시 목록/상세/대시보드 통계 캐시 갱신. 날짜·사이트 변경은 변경 전후 날짜의 전체/사이트 통계를 재계산하며 총 건수가 중복 증가하지 않도록 한다.
- 기존 불만 원장 데이터를 그대로 조회하며 새 DB 테이블/데이터 이관은 기본적으로 필요 없다.

## 4. Boundaries and Integrity (범위 및 정합성)

등록된 불만 원장만 목록화한다. 대시보드 숫자에는 수기 입력 건수가 포함될 수 있어 원장 목록 건수와 다를 수 있다. 수기 합계로 가짜 불만 레코드를 만들지 않는다.

테넌트 및 기존 운영자 접근정책을 적용한다. 메뉴 숨김 설정은 API 접근권한을 대신하지 않는다. 수정 시 최신 수정 시각 기반 충돌 검사를 적용하고 삭제/타 테넌트 자료를 수정하지 못하게 한다. null/빈 문자열에 의한 해제와 미전송에 의한 유지의 의미를 구분한다. 연결 Q&A는 같은 테넌트의 유효 자료만 허용한다.

이번 범위는 목록·상세·내용 수정이다. 별도 처리상태/담당자/답변 워크플로, 삭제 UI, 외부 알림 발송은 추가하지 않는다.
