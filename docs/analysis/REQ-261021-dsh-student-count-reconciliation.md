# Dashboard — Student Count Reconciliation Requirements (대시보드 — 재원 학생·운영 학생수 차이 사유 요구사항)

## 1. Overview (개요)

요청 원문: "대시보드 - 오늘 실시간 현황의 재원학생과 하단 목록에서 운영 - 학생수 차이 나는 원인 확인하고 사유를 페이지하단에 기입한다." 대상 `/admin/dashboard?site=ALL`.
표시 방식: 사용자 선택 **(나) 사유별 인원을 매번 자동 계산해 "재원 X = 운영 Y + 사유별 인원" 형태로 표시**.

## 2. Findings (조사 결과, 2026-10-21)

두 숫자는 **서로 다른 원장**을 센다. 같은 날(오늘, KST) 기준이지만 포함 조건이 다르다.

| 구분 | 오늘 실시간 현황 · 재원 학생 | 하단 표 · 운영 학생수 (오늘 행 · 합계 행) |
| --- | --- | --- |
| 코드 | `source-current.service.ts` `activeStudents` | `operating-calculation.ts` `ops_count_st` (`studentEnrollmentIntervals`) |
| 기준 | 학생 상태 = 재원(ACTIVE), 삭제 제외 | 오늘이 수업기간 안(시작일 ≤ 오늘 < 종료일)인 학생 |
| 사이트 | 전체 (사이트 미지정 포함) | TPI + TRINITY + SANTACROCE **사이트별 합** (미지정 제외) |
| 날짜 | 보지 않음 | 입학일 필수(없거나 미래면 제외), 운영기간 확정·취소 여부 반영 |
| 학생 상태 | 재원만 | **보지 않음** (휴원·퇴원이라도 기간이 열려 있으면 포함) |
| 수동 입력 | 없음 | 해당 날짜 수동 입력값이 있으면 그 값 표시 |

따라서 차이는 다음 사유로 생긴다.

| 코드 | 사유 | 방향 |
| --- | --- | --- |
| R1 | 재원생인데 사이트 미지정(또는 3개 사이트 외) | 재원에만 + |
| R2 | 재원생인데 입학일 없음 | 재원에만 + |
| R3 | 재원생인데 입학일이 오늘 이후 | 재원에만 + |
| R4 | 재원생인데 오늘 열린 수업기간 없음 (종료일 경과·시작 전·미확정·취소) | 재원에만 + |
| R5 | 휴원·퇴원 등 비재원인데 수업기간이 열려 있음 (종료일 미입력·미래) | 운영에만 + |
| R6 | 같은 학생이 오늘 2개 이상 사이트 기간에 걸침 (사이트 합이라 중복 집계) | 운영에 + |
| R7 | 운영 학생수 수동 입력값 — 표에는 계산값이 크게, 수동값은 괄호로 따로 표시되므로 등식에는 넣지 않고 안내 문구로만 표시 | (참고) |

등식: **재원 X = 운영 계산값 Y + R1 + R2 + R3 + R4 − R5 − R6**

과거 사례(RPT-260922D): 퇴원생 수업 종료일 누락(R5) 33명, 사이트 미지정 재원(R1) 12명, 수업 시작일 없는 재원(R4) 2명. 운영 DB 실측은 조회 권한 승인 후 §7 에 기록한다.

## 3. Functional Requirements (기능 요구사항)

| ID | 요구사항 |
| --- | --- |
| FR-1 | 대시보드 **전체(ALL) 탭** 페이지 맨 아래에 "재원 학생·운영 학생수 차이" 섹션을 표시한다 (사이트 탭에서는 실시간 패널이 없으므로 숨김) |
| FR-2 | 첫 줄에 등식 "재원 X명 = 운영 Y명 + …" 을 숫자로 보여 준다. 차이가 0이면 "두 숫자가 일치합니다" |
| FR-3 | 사유 R1~R7 을 행으로 나열: 사유 · 인원(±) · 조치 방법. 0명인 사유는 접어서 숨김 |
| FR-4 | 각 사유 행을 펼치면 해당 학생 이름(최대 50명, 초과 시 "외 n명")을 보여 주고 학생 상세로 이동 링크 |
| FR-5 | 매 조회 시 자동 계산(저장·소급 없음). 기준일 = 오늘(KST), 조회 기간과 무관 |
| FR-6 | 계산은 운영 학생수와 **같은 함수**(`studentEnrollmentIntervals`)를 재사용해 등식이 항상 맞도록 한다. 맞지 않으면 "기타 n명" 행으로 드러낸다 |
| FR-7 | 4개 언어(ko/en/vi/zh-CN) |

## 4. Non-Functional (비기능)

- 권한: 대시보드 조회 권한과 동일 (`OwnEntityGuard`, ent_id 격리).
- 성능: 학생 수천 명 수준 단일 쿼리 + 메모리 계산, 응답 < 500ms.
- 개인정보: 학생 이름·ID만 반환(연락처 등 제외).

## 5. Out of Scope (범위 외)

- 데이터 자동 수정(종료일 백필 등) — 사유 표시만. 수정은 학생관리에서 사용자가 직접.
- ALL 정의 변경(사이트 미지정 포함 여부) — 정책 결정 사항, 이번 범위 아님.

## 6. Acceptance (인수 기준)

- 테스트 데이터에서 R1~R7 각각 1건 이상 → 등식 성립, "기타" 0.
- 실제 운영 화면에서 X, Y 가 실시간 패널·하단 표 숫자와 일치.

## 7. Production Measurement (운영 실측)

2026-10-21 운영 DB 읽기 전용 조회(`BEGIN READ ONLY … ROLLBACK`, 기준일 2026-10-21 KST, ent `…0001`):

| 항목 | 값 |
| --- | --- |
| 재원 학생 (ACTIVE) | **50명** |
| 운영 학생수 (기간 기준, 3사이트 합) | **49명** |
| 차이 | **1명** |
| R2 재원생·입학일 없음 | 1명 — 정이태 |
| R1·R3·R4·R5·R6 | 0명 |
| R7 오늘 수동 입력값 | 없음 |

**결론**: 차이 1명은 재원생 정이태의 **입학일 미입력** 때문이다. 운영 학생수는 입학일을 첫 재원 경계로 쓰므로 입학일이 없으면 집계에서 빠진다(`studentEnrollmentIntervals`). 학생관리에서 입학일을 입력하면 두 숫자가 일치한다. 9월 원인이던 퇴원생 종료일 누락(R5)·사이트 미지정(R1)은 현재 0건.
