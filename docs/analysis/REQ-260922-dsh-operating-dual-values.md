# Operating Calculated and Manual Values (운영 계산값·수기값 병기)

## 1. Scope (범위)

통합 대시보드 Operating의 학생·교사 6개 지표를 데이터 기반 계산값 우선으로 표시하고, 해당 날짜·항목에 수기 입력이 확인된 경우에만 괄호로 병기한다. **TPI·TA·SC 각 사이트 대시보드에도 운영 학생 통계 3개(신규학생·퇴원학생·학생수)를 추가한다.** 통합 보기는 유지한다. 기존 CS·Marketing·Class 산식과 수기 원본은 보존한다. 본 요구는 PLN-260921E의 Operating 기간 지표 정의를 구체화하며, 학생의 기준일은 입학일/퇴원일 대신 **수업 시작일/수업 종료일**로 변경한다.

## 2. Metric Contract (지표 정의)

| 항목 | 계산 |
|---|---|
| 신규학생 | 당일 시작한 유효 수업 기간 수. 재등록의 새 기간도 1건 |
| 퇴원학생 | 당일 종료한 유효 수업 기간 수. 상태 WITHDRAWN 여부로 제한하지 않음 |
| 학생수 | 2024-12-02부터 해당 일자까지 시작 누적 − 종료 누적(당일 종료 포함) |
| 신규교사 | 당일 시작한 유효 강사 재직 기간 수 |
| 퇴직교사 | 당일 종료한 유효 강사 재직 기간 수 |
| 교사수 | 기준선부터 입사 누적 − 퇴직 누적 |

- 신규/퇴원학생은 이 정의에서 고유 인원 수가 아니라 시작/종료 사건 수다. 동일 학생의 재등록 기간을 합치거나 최신 한 쌍으로 덮어쓰지 않는다.
- 동일 학생의 강사별 수업 배정 수와는 무관하다. 여러 강사를 배정해도 한 재원 기간의 시작/종료는 각각 1건이다.
- 기간 시작일 이전의 누적값을 openingBalance로 포함한다. 2025-12-01부터 조회해도 그날 0으로 초기화하지 않는다.
- 일자별 신규/종료가 없으면 0, 학생수/교사수는 전일 누적을 유지한다. 기간 합계는 신규/종료 합계와 마지막 유효일 인원이며 인원을 일별 합산하지 않는다.
- 업무 일자는 DATE/KST 기준. 미래일은 실제 실적으로 계산하지 않고 공란 처리한다. 미래 입력 기간을 삭제하지 않는다.
- 강사는 isInstructor와 재직 기간으로 구분하고 계정 유무와 현재 ACTIVE 상태로 과거를 제외하지 않는다. 기준선 이전 입사자는 확인된 기초 인원으로 반영한다. 누락된 입사/퇴사일을 계정 생성일이나 조회일로 추정하지 않는다.

## 3. Display Contract (표시 규칙)

| 계산값 | 수기값 상태 | 표시 |
|---:|---|---|
| 1 | 명시적 1 | `1 (1)` |
| 0 | 명시적 0 | `0 (0)` |
| 1 | 입력 없음 | `1` |
| 0 | 입력 없음 | `0` |
| 미확정 | 명시적 14 | `— (14)` + 데이터 확인 안내 |
| 미확정 | 입력 없음 | `—` |

0과 미입력을 구분한다. 수기 입력이 없는 날짜/항목은 괄호를 생략하고 이전 수기값을 이월하지 않는다. 과거 특정 시점 이후 수기를 재입력하면 해당 셀의 괄호는 다시 표시한다. 자동 산출값이나 DB 기본값 0을 수기값으로 간주하지 않는다. 계산 실패는 0으로 표시하지 않는다.

숫자는 계산값을 앞에, 수기값은 회색 괄호로 표시하고 범례를 제공한다. 스크린리더에는 계산/수기 의미를 제공한다. 일별 표·요약·그래프·CSV는 같은 정의를 사용한다. 그래프는 계산값 실선, 확인된 수기값은 보조 점/점선으로 구분하며 미입력 구간을 연결하지 않는다. CSV는 문자열 병합 대신 계산/수기/입력여부/품질을 별도 열로 제공한다.

## 4. Evidence and Data Gaps (현행 근거·차이)

- `daily-kpi.service.ts::upsertManualKpi`: 일부 필드만 입력해도 전체 행 manuallyOverridden=true이며 신규 행의 운영 6개 필드는 기본 0. 따라서 행 플래그만으로 괄호 표시 여부를 결정할 수 없다.
- `manual-input.typeorm-entity.ts`: 방문자·비용·효과·불만용이며 운영 6개 항목의 수기 존재 여부를 제공하지 않는다.
- 학생 DB에는 std_start_date/std_end_date가 있지만 API/상세화면은 종료일 연결이 없다. 단일 날짜 쌍은 재등록 이력을 보존하지 못한다.
- 교사 엔티티에는 hiredAt이 있지만 종료일은 없다. 앞선 1차 대사에서 재직 강사 14명의 입사일이 모두 없었다. 실제 구현 시 최신 자료를 재확인한다.
- 기존 dashboard controller는 365일 조회 제한. 기준선부터의 누적 계산과 조회창 길이는 별개다. 전체 2024-12-02~현재 조회도 지원하려면 운영 전용 조회를 별도로 확장해야 한다.

## 5. User Reference Reconciliation (사용자 기준표 대사)

제공 기준은 2024-12-02 신규2/누적2, 2026-09-22까지 신규90/종료40/누적50이다. 이는 **제공 명부에 대한 기대값**이며 다른 운영 학생까지 포함한 전체 원장 결과가 반드시 50이라고 가정하지 않는다.

이전 입력 요청의 90행은 고유 이름 87명이며 이태오·임민규·이제인의 각 2개 기간을 모두 보존해야 기준표를 재현할 수 있다. 이번 기준표는 양 기간을 집계하는 근거이지만, 단일 대표 날짜의 선택 문제와는 구분한다. 이름 미일치 손정연, 김라엘 기존 종료일과 새 기간 충돌은 원장 연결/기간 확인 대상으로 유지한다. 신규 학생을 임의 생성하거나 다른 학생에 연결하지 않는다.

제공 기간 원본으로 일별 모든 행과 총계를 재계산하여 표 자체도 검증한다. 운영 원장 추가 학생·종료 없는 과거 기록·취소·중복은 학생/기간 ID별 차이표로 설명한다. 결과를 50에 맞추기 위해 임의 제외/보정하지 않는다. 미확정 행은 staging에서 보존하고 전체 확정값처럼 게시하지 않는다.

## 6. Safety and Acceptance (보존·완료 기준)

수기 원본과 기존 daily KPI를 덮어쓰지 않는 별도 계산 구조를 사용한다. tenant 격리, 변경 감사, 멱등 이관, 기간 정정/취소 이력, 코드 롤백 후 입력 보존을 보장한다. 계산을 위해 학생 상태·입학일·퇴원일·교사 계정·AMA 정보를 변경하지 않는다. 사이트별 과거 귀속은 현재 소속으로 추정하지 않고 수업 기간에 기록한 사이트를 기준으로 계산한다. 통합 및 세 사이트 학생 통계를 이번 구현 범위에 포함한다.

완료 기준: 기준표 전행 대사, 원장 차이 설명, 항목별 수기 0/미입력 구분, 365일 이전 openingBalance, 교사 날짜 누락 표시, 수기/비용 원본 불변, UI/CSV 일치, 날짜 소급 정정 후 이후 인원 일괄 갱신, 테넌트 격리 및 복구 검증.

## 7. Site Student Statistics (사이트별 학생 통계)

- 표시 사이트: TPI / TA(Trinity Academy, 코드 TRINITY) / SC(Santa Croce, 코드 SANTACROCE). 통합은 ALL.
- 사이트별 신규학생=해당 사이트 기간의 당일 시작 수, 퇴원학생=해당 사이트 기간의 당일 종료 수, 학생수=해당 사이트 시작 누적−종료 누적. 2024-12-02부터 조회 시작 전 openingBalance를 포함한다.
- 카드·일별 표·그래프·CSV 모두 선택 사이트와 동일한 필터를 사용한다. 사이트 학생 통계를 기존 사이트 Marketing/CS 화면에 추가하며 기존 지표는 유지한다.
- 수기값은 동일 사이트·날짜·항목의 입력이 확인된 경우만 괄호로 병기한다. 통합 수기값을 세 사이트에 복제하거나 비율로 배분하지 않는다. 사이트별 수기가 없으면 계산값만 표시한다. 통합 수기와 사이트 수기의 합이 반드시 같다고 간주하지 않는다.
- 사용자 명부의 사이트를 수업 기간 귀속 근거로 보존한다. 학생 마스터 사이트가 미지정이어도 명부의 기간 사이트가 확인되면 해당 사이트로 집계한다. 마스터의 현재 사이트를 이번 집계를 위해 일괄 변경하지 않는다.
- 사이트 근거가 없는 유효 기간은 집계에서 제외하고 미분류 확인 건수로 별도 표시한다. 세 사이트에 임의 배정하지 않는다. 계산값 대사 관계는 ALL=TPI+TA+SC. 미연결/충돌 자료의 품질 상태는 별도 유지한다.
- 현재 소속 수정만으로 과거 기간 사이트를 바꾸지 않는다. 기간 귀속 정정 시 이전/새 사이트의 해당 날짜 이후 누적을 모두 재계산한다. 실제 전원으로 기간을 나눌 경우 근거 날짜 확인과 별도 사건 정의가 필요하며, 단순 소속 수정으로 허위 시작/종료 사건을 생성하지 않는다.
- 제공 명부 기준 기대 합계(2026-09-22): TPI 시작63/종료30/잔여33, TA 7/4/3, SC 20/6/14. 합계90/40/50. 이는 제공 자료 기준 대사 목표이며 운영 전체 인원을 강제로 맞추는 기준은 아니다.
- 이번 추가 범위는 사이트별 **학생** 통계다. 교사 통합 3개 지표는 기존 계획대로 진행하며 사이트별 교사 지표는 소속·겸임 이력 정의 없이 복제하지 않는다.
