# REQ-260626 — ACM 상담관리 파이프라인 개편 요구사항 분석서
## (CSL Consultation Pipeline Revision — Level Test · Demo Class · Enrollment Counseling)

---

## 1. 개요 (Overview)

`acm.amoeba.site/admin/csl` 상담관리의 **단계별 명칭·입력 항목·운영 흐름**을 개편한다. 핵심 변경은
(1) 접수 단계에서 **MAP 이전 점수 입력**(Reading/Math/Language)과 **성적표 멀티 파일 업로드**,
(2) "MAP 테스트" 단계를 **다종(多種) 레벨테스트**로 일반화(MAP/ISEE/SSAT/Duolingo/TOEFL + 자유입력),
(3) "청강"을 **데모수업**으로 개편하고 **담당강사 배정·수업자료·강사 피드백→학부모 전달** 흐름 추가,
(4) 등록상담에 **커리큘럼·강좌코스·시간·회수·복수 강사 배정** 구조화,
(5) 결제를 **관리자 수동 확인·승인** 모델로 명문화 — 이다.

> **사전 확인 결론**: 현 구현은 이미 **6단계 파이프라인**(접수 → MAP 테스트 → 청강 → 등록 상담
> → 결제 → 수강 시작, `INTAKE…CLASS_STARTED`)을 갖추고 있다(MANUAL-260624). 따라서 본 요구는
> **신규 파이프라인이 아니라 기존 단계의 개명·항목 재배치·신규 입력·연동 추가**다. 사용자가 기술한
> "5단계"는 현 1~5단계(접수~결제)에 대응하며, **6단계 "수강 시작(CLASS_STARTED)"은 그대로 유지**한다
> (사용자 확인 2026-06-26). 데모수업→이슈/고객사 프로젝트(학부모=고객사 / 코스=프로젝트 / 수업=이슈)
> 모델은 **개념·향후 방향으로만** 기술하며 본 범위에서 구현하지 않는다(§7, §9).

## 2. 배경 (Background)

### 2.1 현 파이프라인 (AS-IS)

```
1. 접수      2. MAP 테스트   3. 청강        4. 등록 상담            5. 결제      6. 수강 시작
 INTAKE  ─▶  MAP_TEST   ─▶  TRIAL_CLASS ─▶ ENROLLMENT_COUNSELING ─▶ PAYMENT  ─▶ CLASS_STARTED
   └──────────────────── 어느 단계든 ▶ 이탈(DROPPED) ◀ 재활성화 ────────────────────┘
```

현 단계별 진행 게이트·입력 항목은 MANUAL-260624 기준이며, 본 문서의 TO-BE는 이 매뉴얼을 AS-IS
기준선으로 삼는다.

### 2.2 사용자 요구 단계 매핑

| 사용자 요청 단계 | 현 단계(코드) | TO-BE 명칭 | 변경 성격 |
|------------------|---------------|------------|-----------|
| 1단계 접수화면 | 1. 접수 (INTAKE) | 접수 | 입력 항목 추가·재배치 |
| 2단계 (MAP→레벨테스트) | 2. MAP 테스트 (MAP_TEST) | **레벨테스트** | 개명 + 시험 다종화 + 일정·점수 운영자 입력 |
| 3단계 청강→데모수업 | 3. 청강 (TRIAL_CLASS) | **데모수업** | 개명 + 강사배정·자료·피드백 전달 |
| 4단계 등록상담 | 4. 등록 상담 (ENROLLMENT_COUNSELING) | 등록 상담 | 커리큘럼·강좌·시간·회수·복수강사 구조화 |
| 5단계 결제 | 5. 결제 (PAYMENT) | 결제 | 수동 확인·승인 모델 명문화 |
| (요청에 없음) | 6. 수강 시작 (CLASS_STARTED) | 수강 시작 | **유지** (변경 없음) |

> 내부 단계 코드(`INTAKE`, `MAP_TEST` 등)는 **변경하지 않는다**(데이터·전이 로직 호환). `MAP_TEST`,
> `TRIAL_CLASS` 코드는 그대로 두고 **UI 라벨만** "레벨테스트", "데모수업"으로 표기한다(BR-CSL-101).
> 코드까지 개명할지 여부는 §9 Q-CSL-110 미결.

## 3. 목표 / 비목표 (Goals / Non-Goals)

### 3.1 Goals
1. 접수 단계에서 **MAP 이전 점수(R/M/L)** 입력과 **성적표 멀티 파일 업로드**를 지원한다.
2. 2단계를 **레벨테스트**로 일반화하여 MAP 외 시험(ISEE/SSAT/Duolingo/TOEFL + 자유입력)을 수용한다.
3. 레벨테스트 **응시예정일을 운영자가 상담으로 지정**하고 **수업일정(CAL) 스케줄에 등록**한다.
4. 레벨테스트 **결과를 운영자가 입력**하고, **강사 공유용 PDF**(학생/시험/점수)를 다운로드한다.
5. 3단계를 **데모수업**으로 개편: 운영자 **담당강사 배정**, **수업자료 업로드/다운로드**, 종료 후
   **강사 피드백 작성 → 운영자 확인 → 학부모 전달**(카카오 채널 복사) 흐름을 갖춘다.
6. 4단계 등록상담에서 **상담내용 기록 + 강좌코스·시간·회수·시작/종료일 + 복수 강사 1차 배정**을 입력한다.
7. 5단계 결제를 **관리자 수동 확인·승인**(카드/계좌이체) 모델로 명문화한다(현 BR-CSL-012 유지·확장).

### 3.2 Non-Goals
- 데모수업/등록건을 **GitHub·고객사 프로젝트의 이슈로 자동 생성**하는 연동 — 본 범위 제외, 개념만(§7).
- Toss PG 온라인 결제·자동결제 — 제외(결제는 수동 확인). (Q-019/Q-020 Out of scope 유지)
- 카카오 채널 **자동 발송 API 연동** — 본 범위는 "복사하여 전달" 수동 운영(§9 Q-CSL-108).
- 내부 단계 코드(enum) 개명 — 본 범위 보류(Q-CSL-110).

## 7. 데이터·연동 영향 (개념 수준 / Conceptual)

> 상세 스키마·시퀀스는 설계 단계(ERD/기능정의서)에서 확정. 여기서는 영향 범위만 식별한다.

### 7.1 데이터 영향 후보
- **접수**: MAP 점수 컬럼은 학생(STD) 또는 상담(CSL) 중 보관 위치 결정 필요(Q-CSL-102). 성적표 첨부용
  **파일 메타 테이블**(예: `amb_acm_csl_attachment`) 신설 후보.
- **레벨테스트**: 시험 종류(enum+자유입력) 컬럼, 종류별 점수 스키마(JSONB 후보), 응시예정일·CAL 이벤트 FK.
- **데모수업**: 담당강사 FK(복수 → 별도 배정 테이블), 수업자료 파일 메타, 강사 피드백 본문·전달 상태.
- **등록상담**: 상담내용 텍스트, 강좌코스 FK, 시간/회수/시작·종료일, 복수 강사 배정.

### 7.2 강사 공유 PDF (FR-CSL-116)
- 구성: 학생 기본정보 + 시험 종류·응시일 + 점수표. 생성 시점은 결과 입력 후 on-demand.
- 다운로드 권한: 운영자·배정 강사. 다운로드 감사 기록(NFR-CSL-104).

### 7.3 데모수업 → 이슈 / 고객사 프로젝트 모델 (향후 방향 / FUTURE — 본 범위 제외)
사용자 구상(개념 기록용, 미구현):
- **학부모 = 고객사**, **학생 강좌코스(MAP/ISEE) = 프로젝트**, **코스 내 수업 = 이슈/클래스**(시작/진행/완료 상태).
- **데모수업 건을 이슈로 생성**하고, 정식 등록 후 **등록 고객사 프로젝트로 이동**시킨다.
- 본 모델은 AMA 통합 아키텍처(project_ama_integration_architecture)와 정합성 검토 후 별도 REQ로 구체화.

### 7.4 연계 시스템
- **CAL(수업일정)**: 레벨테스트 예정일·데모수업 일정 등록(REQ-260526).
- **강사 마스터(AMA Client)**: 담당강사 배정은 AMA Client 1:1 참조(로컬 중복 저장 금지).
- **카카오 채널**: 피드백 전달은 수동 복사(자동 API 미연동).
- **S3**: 성적표·수업자료·PDF 저장.

## 8. 범위 정의 (Scope)

**In-Scope**: §5의 FR-CSL-101~143 (5개 단계 UI/항목/흐름 개편 + 6단계 유지), 관련 파일 업로드·PDF·CAL 등록.
**Out-of-Scope**: 이슈/프로젝트 자동 생성(§7.3), 카카오 자동 발송, 온라인 PG 결제, 단계 enum 코드 개명.
**MVP 우선순위**: P0 우선 — 접수 점수/첨부(FR-101~109), 레벨테스트 개명·결과/PDF(111~116),
데모수업 강사배정·자료·피드백(121~128), 등록상담 구조화(131~138), 결제 승인(141~143).
