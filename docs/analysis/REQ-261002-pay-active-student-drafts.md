# Active Student Billing Drafts (재원생 청구 준비 등록)

## 1. Request (요구사항)

수납관리에 현재 재원생을 일괄 등록하고 금액은 미입력 상태로 둔다. 학생 검색은 재원 상태를 기본 대상으로 한다. 신규 학생 생성이 아니라 기존 학생의 수납관리 청구 준비 행 생성으로 해석한다.

## 2. Current Constraints (현재 구조)

청구액은 DB NOT NULL 및 DTO 정수 필수이며 0원은 납부불필요(FREE)로 판정된다. 따라서 금액 미입력을 0원으로 저장하면 의미가 달라진다. 기존 API 학생 옵션은 모든 상태를 반환하고 화면에서 재원생만 추가 가능하게 처리한다. 검색 결과 100명 제한이 있어 현재 표시된 결과만으로 일괄 등록하면 누락 위험이 있다.

## 3. Proposed Rules (변경 규칙)

- 테넌트 내 삭제되지 않은 ACTIVE 학생을 대상으로 선택 청구월에 학생별 준비 행을 생성한다. 초기 청구월은 학원 현지 날짜의 현재 월(이번 요청 기준 2026-10), 수납명은 월 수업료로 제안한다.
- 금액 null 및 명시적 DRAFT 상태로 미입력을 구분한다. 할인·미납 등도 확정된 금액처럼 표시하지 않는다. 기존 명시적 0원 청구는 그대로 유지한다.
- 준비 행은 청구/수납/미납 금액 합계 및 완납·연체 판정에서 제외하고 미입력 건수를 별도 표시한다. 엑셀도 금액 빈 셀과 미입력 상태를 유지한다.
- 청구액과 납기를 입력하여 확정한 뒤 기존 청구·수납 흐름으로 전환한다. 준비 단계에는 납기를 강제로 정하지 않는다. 수납/환불/감액 API는 준비 행을 차단한다.
- 일반 학생 선택은 이름 검색 후 한 명씩 추가하는 기존 방식 유지. 기본 검색은 ACTIVE만 서버에서 조회하며 전체/휴원/퇴원 조회는 상태 필터로 명시적으로 변경한다. 신규 청구 추가 가능 대상은 재원생으로 유지한다.
- 일괄 등록은 별도 재원생 일괄 등록 동작으로 제공한다. 실행 시 대상·기존 청구·준비 행을 재검증하고 학생별 중복 없이 생성한다. 기존 청구/금액은 덮어쓰지 않는다.
- 같은 학생·월에 기존 수업료 청구가 있으면 자동 생성하지 않고 검토 대상으로 표시한다. 재시도 및 동시 실행은 원본 학생/월 기반 키와 잠금으로 중복 방지한다. 화면 검색 100명 제한에 관계없이 전체 재원생을 처리한다.
- 기존 상담 납부 이관과는 별개다. 이번 등록으로 납부 내역이나 상담 승인/대시보드 통계를 생성·변경하지 않는다.
