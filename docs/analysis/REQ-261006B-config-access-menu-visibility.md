# Configuration Access Requirements (설정 접근 권한 요구사항)

## 1. Request (요청)

`/admin/config` 접근 권한을 별도 레벨로 분리하고 `fremd@naver.com`에게 부여한다. 설정 페이지에서 좌측 메뉴 노출 여부를 관리한다.

## 2. Current State (현황)

- 운영 계정 읽기 전용 조회: 대상 이메일과 일치하는 계정 1개, ACTIVE / ADMIN / AMA 연동 계정. 아직 권한 변경 없음.
- 설정 랜딩은 카드 링크 화면으로 전용 권한 검사가 없으며 설정 API들은 주로 ADMIN 역할을 검사한다.
- 기존 테넌트별 메뉴 가시성/순서 저장 및 `/acm/me/menus` 조회가 있다. 저장 API는 `/acm/system/tenants/:entId/menus`로 APP_ADMIN 전용이다.
- 공통 시간대, 화상강의 capabilities 같은 설정의 소비 API는 일반 업무 화면에서도 사용한다. 관리 API와 구별해야 한다.
- 일반 웹 조회 도구로 운영 설정 화면은 열리지 않아 소스 및 운영 계정 조회 기준으로 분석했다.

## 3. Requirements (요구사항)

1. 별도 설정 관리 레벨 `CONFIG_ADMIN`을 추가 권한으로 만든다. 기존 ADMIN/STAFF 등의 기본 역할을 대체하지 않는다.
2. `fremd@naver.com`의 확인된 단일 계정에 소속 테넌트 한정으로 부여한다. 이메일을 프런트엔드 조건에 하드코딩하지 않는다. 전체 ADMIN에게 자동 부여하지 않는다.
3. `/admin/config` 및 하위 경로, 해당 설정의 조회·수정·연결 테스트 API는 전용 권한으로 검사한다. 주소/API 직접 호출도 미보유자는 거부한다.
4. 기존 일반 업무용 읽기 API(시간대, 화상강의 종류 등)는 유지한다. 비밀정보를 노출하는 관리 조회와 분리한다.
5. 기존 ADMIN 역할과 AMA 로그인 동작을 보존한다. 재로그인·SSO 동기화로 추가 권한이 사라지지 않아야 한다. 권한 철회는 서버의 최신 상태로 반영한다.
6. `/admin/config`에 좌측 메뉴 노출 설정 영역을 추가한다. 기존 저장소와 서비스 재사용, 자기 테넌트만 변경 가능.
7. 메뉴 노출 설정은 개인 취향이 아니라 해당 학원 사용자에게 공통 적용한다. 업무 데이터 접근권한 자체를 변경하는 기능은 아니다.
8. 기존 메뉴 순서는 보존한다. 대시보드는 기존 정책대로 항상 노출한다. 설정 접근권한 보유자는 설정 메뉴를 항상 볼 수 있게 하여 스스로 관리 진입점을 잃지 않도록 한다. 미보유자는 설정 메뉴를 숨긴다.
9. 저장 완료/실패/미저장 변경을 표시하고 캐시를 갱신한다. 계정·테넌트 전환 시 캐시를 분리하며 설정 권한 조회 실패 시 접근을 허용하지 않는다.
10. 권한 부여·철회는 시스템 관리자 또는 통제된 운영 절차로 제한한다. 설정 권한으로 다른 사용자에게 권한을 부여할 수 없다.

## 4. Scope (범위)

설정 권한, 대상 계정 권한 부여, 테넌트 메뉴 노출 설정을 포함한다. 전체 역할 체계 개편, 다른 업무 페이지의 권한 재설계, 메뉴별 데이터 접근 제어는 범위 밖이다. 기존 시스템 관리자 테넌트 관리 기능의 권한은 유지한다.


구현 메모: 최신 권한은 `/acm/me/config-access`에서 조회하며 관리 API는 매 요청 DB 권한을 검사한다. 기존 로그인/JWT/AMA 기본 역할은 변경하지 않는다. 2026-10-06 운영 버전 4696a58 배포와 대상 계정 CONFIG_ADMIN 부여를 완료했다.
