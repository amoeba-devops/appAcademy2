# 사용 매뉴얼 — BODA 화상 강의실 (강사 등록 → 학생 입장)

> ACM 운영 콘솔에서 강사가 **화상 수업 일정을 등록**하고, 등록된 수업에 **참여자로 지정된 학생**이 수업 시간이 되면 **수업 시간표에서 직접 입장**하는 전체 흐름을 안내합니다.
> 본 매뉴얼은 운영 도메인 `https://acm.amoeba.site` 기준이며, 스테이징 (`acm-stg.amoeba.site`) 에서도 동일하게 동작합니다.

---

## 1. 전체 흐름 한눈에

```
┌──── 강사 ─────────────────┐    ┌──── 학생/학부모 ────────────┐
│ 1. 로그인 (admin)         │    │ A. 로그인 (parent)          │
│ 2. /admin/cal 으로 이동   │    │ B. /my/timetable 으로 이동  │
│ 3. "+ 일정 등록" 클릭     │    │ C. 등록된 수업 클릭         │
│ 4. 화상 미팅 = BODA 선택  │    │ D. "수업 입장" 버튼 클릭    │
│ 5. 참석자(학생) 추가      │    │ E. 자동으로 /web/classroom/.. │
│ 6. 저장                   │    │ F. BODA 룸에 입장           │
└──────────────────────────-┘    └─────────────────────────────┘
            ▼                                      ▲
   ACM 백엔드가 BODA 룸을 PENDING 상태로 선발급
   강사가 강의실 입장하면 BODA Webhook → OPEN 전이
   학생이 입장 가능한 상태가 되면 자동 새로고침
```

## 2. 사전 준비 (운영자 / 1회만)

> 운영자(ADMIN)가 학원당 한 번 BODA 연동 설정을 등록해야 강사·학생 화면이 동작합니다.

### 2.1 BODA 설정 등록
1. 운영자로 로그인 (`https://acm.amoeba.site/admin/login`).
2. 좌측 메뉴 또는 직접 URL: `https://acm.amoeba.site/admin/config` 의 **BODA 연동** 섹션으로 이동.
3. 다음 값을 입력:

| 항목 | 예시 | 설명 |
|---|---|---|
| BODA Web URL | `https://stg-boda.example.com` | 학생/강사 진입 페이지 베이스 URL |
| SERVER API URL | `https://stg-api.boda.example.com` | 백엔드 호출용 (강제 폐쇄·재동기화) |
| WebRTC URL | `wss://stg-rtc.boda.example.com` | 룸 매체 연결용 |
| Company Code | (벤더 발급) | webhook 페이로드의 `Ccd` 매칭 키 |
| Company ID | (벤더 발급) | BODA 측 회사 식별자 |
| Default Room Code | `r-tac-100` | 신규 룸 기본 코드 |
| Auth Key | (BYTEA 암호화) | SERVER API Bearer 인증 비밀 |
| Event Secret | (BYTEA 암호화) | Webhook 요청 헤더 `X-Boda-Token` 검증값 |
| Webhook 허용 IP | `1.2.3.0/24,5.6.7.8` | BODA 출발지 CIDR / IP 화이트리스트 |

**중요** — `Auth Key`, `Event Secret` 은 한 번 저장된 후 화면에 다시 표시되지 않습니다 (`*IsSet` 플래그로만 노출). 분실 시 벤더 측 재발급이 필요합니다.

### 2.2 검증
- 저장 후 화면에 **`Auth Key 설정됨 ✅`** / **`Event Secret 설정됨 ✅`** 표시 확인.
- BODA 측에 Webhook 수신 URL 등록 요청:
  ```
  https://acm.amoeba.site/api/webhooks/boda
  Header: X-Boda-Token: <Event Secret 평문>
  ```

## 3. 강사 — 화상 수업 일정 등록

### 3.1 캘린더 진입
1. 강사 계정으로 `https://acm.amoeba.site/admin/login` 로그인.
2. 상단 또는 좌측 메뉴에서 **캘린더** 클릭 → `/admin/cal` 로 이동.

### 3.2 일정 등록 다이얼로그 열기
- 화면 우측 상단 **`+ 일정 등록`** 버튼 클릭, **또는** 캘린더에서 원하는 날짜 셀을 직접 클릭.

### 3.3 일정 정보 입력

| 필드 | 입력 예 | 비고 |
|---|---|---|
| 제목 | `중3 영어 - 비교급/최상급` | 필수 |
| 분류 | **수업** 선택 | CLASS / MEETING / EVENT / PERSONAL |
| 시작 / 종료 | `2026-06-15 19:00` / `2026-06-15 20:30` | 필수, 종료 > 시작 |
| 종일 | (체크 안함) | 화상 수업은 시간 지정 필수 |
| 장소 | (선택) | 오프라인 병행 시만 |
| 설명 | "비교급 보충 강의" | 학생에게 그대로 보임 |

### 3.4 화상 미팅 설정 — **BODA 선택**

화상 미팅 섹션에서:

1. **화상 미팅 드롭다운** → **`보다스쿨` 선택**.
2. **미팅 URL 필드는 비워둡니다.**  → 저장 후 ACM 백엔드가 자동으로 `https://acm.amoeba.site/web/classroom/<eventId>` 런처 URL을 채워 넣습니다.

> 💡 다른 vendor (Google Meet 등) 선택 시에는 직접 URL을 붙여 넣어야 합니다. BODA 선택 시에만 자동 생성됩니다.

### 3.5 참석자(학생) 추가
1. 화면 하단 **참석자** 섹션의 **`+ 참석자 추가`** 버튼 클릭.
2. 모달에서:
   - **전체 / 학생 / 강사 / 학부모** 탭으로 필터.
   - 검색창에 이름·이메일 입력 (실시간 검색).
   - 추가할 사용자 옆 체크박스 선택 (다중 선택 가능).
3. **선택 완료** 버튼 클릭 → 메인 모달에 학생 칩(chip)이 추가됩니다.
4. 잘못 추가했다면 칩 옆 **X** 클릭으로 제거.

### 3.6 저장
- **저장** 버튼 클릭.
- 저장 직후:
  - 캘린더에 새 이벤트가 표시됩니다.
  - 알림 결과(이메일 발송 통계)가 모달 하단에 잠깐 노출된 후 자동 닫힘.
  - 백엔드가 BODA 룸을 **`PENDING`** 상태로 발급, 학생들에게 알림 메일 송부.

### 3.7 저장 후 — BODA 룸 상태 확인

기존 일정을 다시 클릭하면 모달 안 **BODA 화상 강의실** 섹션에 현재 상태가 표시됩니다:

| 뱃지 | 의미 | 학생 화면 동작 |
|---|---|---|
| `대기` (PENDING) | 룸은 만들어졌지만 강사가 아직 안 들어옴 | 학생은 "강사 입장 대기 중" 표시 + 10초마다 자동 새로고침 |
| `개설됨` (OPEN) | 강사가 입장 — 학생 입장 가능 | 학생에게 "수업 입장" 버튼 활성화 |
| `진행 중` (STARTED) | 수업 시작됨 | 입장 가능 |
| `일시정지` (PAUSED) | 강사가 잠깐 멈춤 | 입장 가능 (대기실) |
| `종료` (ENDED) | 수업 종료 | 입장 불가 — "이미 종료된 수업입니다" |
| `폐쇄됨` (CLOSED) | 룸 완전 정리 | 입장 불가 |

### 3.8 수업 입장 (강사)
- 캘린더 일정 클릭 → 화상 미팅 섹션의 **미팅 URL** (자동 채워진 `…/web/classroom/<id>`) 을 새 탭에서 열거나, 학원 알림 메일의 링크를 클릭.
- 런처 페이지가 사용자를 **강사(UTy=11)** 로 인식하면 **`수업 시작`** 버튼 노출.
- 버튼 클릭 시 `BodaAppApi.bodaOpen()` 호출 → BODA 클라이언트가 실행되고, 동시에 백엔드 룸 상태가 `OPEN` 으로 전이됨.

### 3.9 ⚡ 즉시 강의 개설 (Instant Classroom)

> 캘린더에 미리 일정을 등록할 시간이 없을 때 — 갑작스러운 보충 수업·1:1 질문·시연 용도. 3-클릭 / 10~15초 내 BODA 룸이 열립니다. (REQ-260610)

#### 3.9.1 진입
- `/admin/cal` 캘린더 헤더 우측의 **⚡ 즉시 강의 개설** 버튼 클릭. 강사·운영자에게만 표시됩니다.

#### 3.9.2 입력
모달이 열리면 다음 3 가지만 입력하면 됩니다 — 시작 시각·분류·장소·종일 토글은 자동으로 처리됩니다.

| 항목 | 기본값 | 비고 |
|---|---|---|
| 제목 | `즉시 강의 - {강사명} HH:mm` | 비워두면 자동 생성. 직접 입력도 가능. |
| 예상 진행 시간 | **90분** (radio) | 30 / 60 / **90** / 120 중 선택. 종료 시각 = 시작 + 선택값. |
| 학생 초대 | (없음) | 추천 12명 그리드에서 다중 선택. 0명도 허용 (시연·테스트). |

추천 학생 그리드는 다음 두 소스의 합집합입니다:
- **CLASS 칩 (배경 강조)**: 강사 본인이 담당하는 활성 클래스의 학생.
- **최근 칩**: 최근 7일 동안 강사 본인의 수업·미팅에 초대된 적이 있는 학생 (출현 빈도 순).

같은 학생이 두 곳 모두에 해당하면 CLASS 우선으로 표시됩니다.

#### 3.9.3 강의 시작
- **`강의 시작 ⚡`** 버튼 클릭.
- 백엔드가 다음을 동시에 수행:
  1. cal_event 생성 (`source=INSTANT`, `provider=BODASCHOOL`, 시작=지금, 종료=지금+선택시간)
  2. BODA 룸 `PENDING` 상태로 발급
  3. 초대 학생에게 알림 (AmoebaTalk + Email) 즉시 송부
- **새 탭** 으로 `…/web/classroom/{evtId}?autoStart=1` 가 자동 열림.
- 런처 페이지가 강사를 인식하고 **BODA 클라이언트를 자동 호출** — `수업 시작` 버튼을 별도로 누르지 않아도 됩니다.
- 약 1~3초 안에 BODA 데스크톱 창이 새로 떠 강의실에 입장됩니다.

#### 3.9.4 즉시 강의의 시각적 구분
- 캘린더 그리드의 일정 칩 앞에 **⚡ 아이콘** 이 표시되어 정규 수업과 구분됩니다.
- 일정 다이얼로그에서 다시 열어볼 때도 동일하게 ⚡ 표시. 시간·참석자 편집은 가능하지만 vendor 변경은 권장하지 않습니다 (이미 BODA 룸이 발급되어 있어 다른 도구로 바꿔도 효과가 없음).

#### 3.9.5 더블 클릭 방지
- 강의 시작 버튼을 빠르게 두 번 누르더라도 백엔드가 자동 멱등 처리 — 강의는 1개만 만들어지고 같은 evtId 가 반환됩니다 (10분간 유효).
- 분당 10건 이상 즉시 개설을 시도하면 일시적으로 차단됩니다 (남용 방지).

#### 3.9.6 학생 입장 흐름 (즉시 강의)
- 즉시 강의는 학생에게 **알림 메시지 (AmoebaTalk / Email)** 가 즉시 전달됩니다. 메시지 안에 `https://acm.amoeba.site/web/classroom/<eventId>` 직접 링크가 포함되어 있어 학생은 클릭만 하면 됩니다.
- 런처 페이지가 학생을 인식하고 다음 상태에 따라 안내:
  - 강사가 아직 BODA 클라이언트를 시작 중인 동안에는 **`강사 입장 대기 중`** 화면 + 10초 자동 새로고침.
  - BODA 룸이 `OPEN`/`STARTED` 가 되면 **`수업 입장`** 버튼 활성화 → 클릭 시 BODA 클라이언트로 입장.

#### 3.9.7 종료 및 정리
- 강사가 BODA 강의실을 닫으면 정규 수업과 동일하게 webhook 이벤트 4·5 가 들어와 룸 상태 `ENDED` → 10분 후 cron 이 `CLOSED` 자동 전이.
- 강사가 닫지 않고 떠나도 종료 시각 (`startAt + durationMin`) 으로부터 약 10~15분 안에 자동 정리됩니다.

#### 3.9.8 데모 모드로 테스트 (Demo)

벤더 (㈜새하컴즈) 의 BODA 클라이언트 데스크톱 앱 / 실제 webhook 설정이 없는 상태에서도 전체 흐름을 시연·검증할 수 있습니다.

**활성화 조건 (운영자가 staging 에 1회 설정)**
- 백엔드 환경변수: `BODA_SIMULATE_ENABLED=true` (스테이징에서만, 프로덕션에서는 절대 활성화하지 않습니다).
- 별도 코드 배포 없이 환경변수 토글 + 컨테이너 재시작으로 활성/비활성 전환 가능.

**사용 방법 (강사)**
1. URL 에 `?demo=1` 을 붙여 캘린더 진입:
   `https://acm-stg.amoeba.site/admin/cal?demo=1`
2. 즉시 강의 개설 모달이 평소와 동일하게 뜨되, 헤더에 노란색 **`DEMO`** 뱃지가 표시됩니다.
3. 모달이 열린 시점에 백엔드가 자동으로 임시 BODA 설정을 발급 (회사코드 = `TAC-DEMO-…`, 데모 secret) — 운영자가 별도로 설정을 입력하지 않아도 됩니다.
4. 학생 1~2명 선택 후 **`강의 시작 ⚡`** 클릭.
5. 새 탭이 열리면 페이지 상단에 `데모 모드` 배너가 뜨고, 실제 BODA 클라이언트 대신 **목업 강의실 창** 이 페이지 내에 렌더됩니다.

**데모 강의실 창에서 사용 가능한 액션**

| 버튼 | 동작 | 백엔드 효과 |
|---|---|---|
| `수업 시작` | room.status `OPEN` → `STARTED` | 이벤트 2 simulate |
| `일시정지` | `STARTED` → `PAUSED` | 이벤트 3 simulate |
| `학생 입장 시뮬레이션` | participant 1명 추가 | 이벤트 11 simulate |
| `학생 퇴장 시뮬레이션` | participant `leftAt` 갱신 | 이벤트 12 simulate |
| `수업 종료` | `STARTED/PAUSED` → `ENDED` | 이벤트 4 simulate · ~10분 후 cron 이 `CLOSED` 로 |

**학생 측 데모**
- 강사가 발송한 알림 메일에 `?demo=1` 이 포함된 링크가 그대로 전송됩니다 (또는 운영자가 직접 학생 계정으로 `?demo=1` URL 을 열어 시연).
- 학생 화면에서도 동일한 목업 강의실 + `데모 모드` 배너가 뜨고, 강사가 시작한 상태에 따라 "수업 진행 중" 안내가 동기화됩니다.

**보안**
- `BODA_SIMULATE_ENABLED=false` (기본값) 일 때 모든 simulate / demo-seed endpoint 는 403 으로 막힙니다.
- 프로덕션 (`acm.amoeba.site`) 의 env 에 위 변수를 추가하지 않습니다 — staging 전용입니다.
- demo-seed 가 발급하는 비밀값은 모두 `demo-…-do-not-use-in-prod` 더미입니다. 실제 vendor 연동 시 운영자가 `/admin/config` BODA 섹션에서 진짜 값으로 덮어쓰면 됩니다.

#### 3.9.9 정규 일정 등록과의 차이 요약

| 항목 | 정규 일정 (3.1–3.8) | 즉시 강의 (3.9) |
|---|---|---|
| 시작 진입점 | `+ 일정 등록` | **⚡ 즉시 강의 개설** |
| 시간 입력 | 강제 (시작·종료 직접 입력) | 자동 (지금 ~ 지금+30/60/90/120분) |
| 분류 선택 | 가능 (CLASS/MEETING/EVENT/PERSONAL) | `CLASS` 고정 |
| Vendor 선택 | 4종 (NONE/GMEET/BODASCHOOL/OTHER) | `BODASCHOOL` 고정 |
| 참석자 검색 | 모든 학생/강사/학부모 통합 검색 | 추천 12명 + (v1.1 검색) |
| 런처 자동 진입 | 수동 (`수업 시작` 버튼 클릭) | 자동 (`?autoStart=1`) |
| 캘린더 아이콘 | 일반 | ⚡ |
| 적합한 상황 | 미리 알려진 수업 / 반복 수업 | 갑작스러운 보충 / 1:1 질문 / 시연 |

## 4. 학생 / 학부모 — 수업 입장

### 4.1 로그인
- 학부모: `https://acm.amoeba.site/parent/login`
- 학생 본인 계정이 있는 경우도 동일 페이지 사용 (학원이 발급한 계정).

### 4.2 수업 시간표 진입
- 로그인 후 상단 메뉴 **수업 시간표** 또는 직접 URL `https://acm.amoeba.site/my/timetable` 로 이동.
- 본인이 참석자로 지정된 수업이 캘린더에 표시됩니다.

### 4.3 수업 입장

화면에 등록된 수업 항목을 클릭하면:

1. **수업 시간 30분 전 ~ 종료 시각 사이** 에만 입장 버튼이 활성화됩니다 (테넌트 설정에 따라 변동, 기본: 시작 전 10분 ~ 종료 후 15분).
2. **`수업 입장`** 버튼 클릭 → `https://acm.amoeba.site/web/classroom/<eventId>` 로 이동.
3. 런처 페이지가 다음 중 하나를 보여줍니다:

| 상태 | 학생 화면 표시 |
|---|---|
| 강사 미입장 (`PENDING`) | "강사가 곧 입장합니다. 잠시만 기다려 주세요." + 10초마다 자동 새로고침 |
| 입장 가능 (`OPEN` / `STARTED`) | **`수업 입장`** 버튼 |
| 종료 (`ENDED` / `CLOSED`) | "이미 종료된 수업입니다." |

4. **`수업 입장`** 버튼 클릭 → BODA 클라이언트가 실행되며 룸에 자동 입장.

### 4.4 에러 안내

| 메시지 | 의미 / 대응 |
|---|---|
| BODA 클라이언트가 설치되어 있지 않습니다 | 안내된 BODA 데스크톱 클라이언트 설치 후 페이지 새로고침 |
| 이 수업의 참석자가 아닙니다 | 강사·운영자에게 참석자 등록 요청 |
| 시간 범위를 벗어났습니다 | 너무 일찍 / 늦게 진입한 경우 — 정해진 시간에 다시 시도 |
| 룸 정보를 가져올 수 없습니다 | 네트워크 일시 장애 — 1~2분 후 재시도, 지속 시 운영자 문의 |

## 5. 운영자 — 사후 관리

> 강사가 수업을 끄지 않고 떠나는 등 예외 상황을 처리하기 위한 도구.

### 5.1 강제 폐쇄
- `/admin/cal` 일정 클릭 → BODA 화상 강의실 패널 → **`강제 폐쇄`** 버튼.
- 진행 중인 룸이면 확인 대화상자가 뜹니다. 확인 시:
  - BODA SERVER API `/svr/meet/close` 호출
  - 룸 상태 `CLOSED` 로 전이
- BODA 측이 5xx 반환해도 ACM 측은 CLOSED 처리됩니다 (다음 reconcile 사이클이 정리).

### 5.2 출결 재동기화
- 같은 패널의 **`출결 재동기화`** 버튼.
- BODA SERVER API `getJoinLog` 를 즉시 호출해 누락된 입·퇴장 기록을 보정합니다.
- 결과 토스트: `재동기화 완료: +N / ~M` (신규 입력 N개 / 기존 행 갱신 M개)

### 5.3 자동 보정 (cron)
- 매 5분마다 백엔드가 `ENDED` 상태로 `reconcile_delay_min`(기본 10분) 이상 지난 룸을 자동 reconcile + `CLOSED` 전이.
- 운영자가 별도 조치 없이도 학부모 화면의 출결이 자동 갱신됩니다.

## 6. FAQ

**Q1. 학생이 시작 시각 한참 전인데도 입장이 가능합니까?**
A. 기본 정책은 시작 10분 전부터 입장 가능, 종료 15분 후까지 입장 허용. 이 값은 운영자가 `/admin/config` BODA 섹션의 `graceBeforeMin` / `graceAfterMin` 으로 조정합니다.

**Q2. 학생이 중간에 네트워크가 끊겨 다시 입장하면 출결이 어떻게 기록됩니까?**
A. 각 입장이 별도 행으로 저장되고, 강제로 끊긴 기록은 가장 최근 행의 `leftAt` 으로 자동 닫힙니다. 학부모 화면의 총 수강시간은 합산되어 표시됩니다.

**Q3. BODA 측에서 webhook 을 잠시 못 보내면 출결이 비어 보일 수 있나요?**
A. 일시적으로는 그럴 수 있지만, ACM 의 5분 cron 이 SERVER API 를 권위로 삼아 자동 보정합니다 (NFR-2: 출결 반영 지연 최대 10분 이내 보장). 운영자가 즉시 보고 싶다면 **`출결 재동기화`** 버튼으로 강제 트리거 가능.

**Q4. 다른 화상 도구 (Google Meet 등) 를 같이 쓸 수 있나요?**
A. 가능합니다. 일정 등록 시 **화상 미팅** 드롭다운을 `Google Meet` / `기타` 로 선택하고 URL 을 직접 입력하면 BODA 가 아닌 해당 도구의 링크로 동작합니다. BODA 자동 발급은 `보다스쿨` 선택 시에만 발생합니다.

**Q5. 같은 수업을 매주 반복 등록할 수 있나요?**
A. 현재 v1 에서는 캘린더 등록 시 단건만 지원합니다. 반복 일정은 CLS(수업관리) 모듈의 세션 자동생성 기능을 사용하시고, 각 세션이 캘린더로 자동 연동됩니다. (REQ-CLS-005 참조)
