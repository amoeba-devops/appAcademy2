# Admin Console UI Consistency — Audit & Proposal (운영 콘솔 UI 일관성 — 분석·개선안)

요청 원문: "tpiyeri@tpiglobal.network 사용자로 로그인한 화면에서 전체 메뉴 화면을 체크하여 일관된 UI / Layout 으로 정리해야한다. 먼저 각 화면 분석 후 제목, 설명, 기능내용 박스등의 디자인 개선안을 제시하라"

## 1. Scope & Method (범위·방법)

- 대상 사용자: tpiyeri — 역할 ADMIN + 서비스 운영자(CONFIG_ADMIN), 테넌트 Trinity Academy. 운영 DB 의 테넌트 메뉴 허가·등급별 노출을 읽어 보이는 메뉴를 확정했다.
- 보이는 메뉴(15 + 하위 13 화면 = 28 화면):
  - 학원관리: 대시보드, 신규 상담(+상세), 학생 관리(통합·TPI·Trinity·Santa Croce·퇴원·상세), 학부모, 교사, 수업통계, 고객불만, 수납관리, 수업일정
  - 업무: 채팅, 내 업무, 이슈(+상세), 프로젝트(+상세), 드라이브 (문서 메뉴는 ADMIN 등급 숨김)
  - 설정: 서비스 설정(사용자 초대·메일·광고매체·Google Drive), 비밀번호 요청
  - 기타: 마이페이지, 알림함
- 방법: tpiyeri 비밀번호로 운영에 로그인하지 않고(자격 증명 보호), **같은 권한 구성의 로컬 계정 + 테스트 DB 사본**으로 1440px 화면을 열어 28 화면을 캡처하고, 제목·설명·상자·표·버튼의 실제 계산값(글자 크기·굵기·모서리·배경색)을 측정했다. 코드 사용 빈도도 함께 집계했다.

## 3. Proposal (개선안)

### 3.1 화면 틀 표준 — `PageHeader`

모든 메뉴 화면 맨 위를 같은 틀로 만든다.

```
[← 목록으로]                                         (상세·하위 화면만)
[아이콘] 제목                                [보조 버튼] [주 버튼]
설명 한 줄 — 이 화면에서 하는 일
─────────────────────────────────────────────────────────────── (탭이 있으면 밑줄 탭)
 통합 | TPI | Trinity Academy | Santa Croce
```

| 요소 | 규칙 |
| --- | --- |
| 아이콘 | 사이드바 메뉴와 **같은 아이콘**, 20px, 강조색 |
| 제목 | **20px / 600**(text-xl font-semibold), 메뉴 이름과 같게(예: "신규 상담", "채팅", "알림함", "서비스 설정") |
| 설명 | 제목 아래 14px 보조색 1줄(4개 언어). 상세 화면은 설명 대신 요약 메타(상태·담당·수정일) |
| 동작 버튼 | 제목 줄 **오른쪽 끝**: 주 버튼 1개(강조색 채움) + 보조 버튼 최대 2개(테두리). 그 이상은 "⋯ 더보기" 메뉴 |
| 뒤로 | 상세·설정 하위 화면만 제목 위 "← {상위 메뉴}" |
| 탭 | 화면 안 보기 전환은 **밑줄 탭** 하나로 통일 |

### 3.2 상자 표준 — `Section` / `StatCard` / `FilterBar`

```
┌ 섹션 제목 ──────────────────────────── [동작] ┐   Section: 모서리 8px, 테두리 gray-200,
│ 섹션 설명(선택, 13px 보조색)                    │            배경 surface, 안쪽 여백 16~20px,
│ 내용                                            │            섹션 제목 15px/600
└─────────────────────────────────────────────────┘

┌ 라벨 ─────────┐   StatCard: 라벨 12px 보조색 / 값 24px 600 숫자 고정폭 / 보조 설명 12px
│ 42            │             강조가 필요한 카드만 왼쪽 4px 색 띠(상태색)
│ 재원 · 삭제 제외 │
└───────────────┘

┌ 🔍 검색 [              ]  상태 [▼]  기간 [  ~  ]           [초기화] ┐  FilterBar: 한 상자, 입력 높이 36px,
└──────────────────────────────────────────────────────────────────┘             라벨은 입력 안 placeholder 또는 위 12px
총 42명                                                     1 / 3 페이지    결과 수·페이지는 표 바로 위 한 줄
```

| 규칙 | 값 |
| --- | --- |
| 모서리 | 상자 8px(rounded-lg), 버튼·입력 6px(rounded-md). 12px·16px·0px 제거 |
| 배경 | 페이지 canvas, 상자 `bg-surface` 하나(`bg-white`·gray/slate/zinc-50 제거) |
| 중첩 | 상자 안 상자는 1단계까지. 안쪽은 테두리 없이 구분선 |
| 경고·안내 | `Notice` 하나(정보 파랑·주의 노랑·오류 빨강, 아이콘+문구) |

### 3.3 표 표준 — `DataTable`

| 항목 | 규칙 |
| --- | --- |
| 머리글 | 배경 gray-50, 12px/600 보조색, 높이 40px. 정렬 가능한 열만 화살표 |
| 행 | 높이 48px, 구분선만(줄무늬 없음), 마우스 오버 gray-50 |
| 필터 | 머리글 안 드롭다운(상담 목록) → FilterBar 로 이동 |
| 빈 상태 | `EmptyState`(아이콘·문구·주 동작) 하나 |
| 휴대폰 | 기존 `ResponsiveTable` 로 카드 전환 |

### 3.5 "이용 팁" 패널

- 현재: 대부분 같은 일반 문구 + 1440px 에서는 본문 아래로 떨어져 화면이 길어짐.
- 제안: **패널 제거**하고 화면 설명을 PageHeader 의 설명 한 줄로 옮긴다. 화면별 자세한 안내가 필요한 곳(수납·대시보드 집계 기준 등)만 제목 옆 **[?] 도움말**(누르면 작은 창) 으로 제공.
